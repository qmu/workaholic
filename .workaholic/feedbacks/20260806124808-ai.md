# コマンド/スキルの記述量を大幅削減しAIエージェント向けにプラグインを再設計する

コマンドはClaude Code専用仕様であるにもかかわらず、スキルへのエイリアスに留まらず処理本体を抱えてしまっている。各スキルの記述量も過大で、形骸化したルールや過去のトラブル対応の名残がそのまま残り、Markdownの強調(Bold)も過剰。加えてプラグインの想定利用者をこれまでの「開発者向け」から、今後は「Claude Code Web RoutineのようなAIエージェント向け」に転換し、開発者利用は副次的な想定とする。

対応事項:

1. コマンドは数行程度に留める: コマンドはスキルのエイリアスとして扱い、処理の本体はスキル側に記述する。Claude Code Web RoutineのInstruction(/propose, /implement)についても、実処理は対応するスキル側に記述し、そこから呼び出す形にする。
2. 各スキルの記述量を削減する: 形骸化したルールを削除する / 過去に起きた問題への対処と見られる記述は個別に残さず「注意書きリスト」としてまとめる / 本当に必要な箇所以外のBoldを外す。
3. 分量の目安: plugins/workaholic/skills/drive/SKILL.md 程度のスキルであっても100行以内を目指す。単なる圧縮ではなく、不要な記述そのものの削除で達成する。
4. テスト・シェルスクリプトの削減: 現状テストおよびシェルスクリプトが多すぎるため、削減する。
5. 利用対象者の転換: プラグインの主対象を「開発者向け」から「Claude Code Web RoutineのようなAIエージェント向け」に転換する(開発者による利用も引き続き想定するが副次的)。
6. ドキュメント再構成: READMEから辿れるドキュメント群を、現在の仕様に即して体系的に構成し直す。
7. Ticketのfront matter整理: type, layer, effort, commit_hash, category の各フィールドを削除する。

Source: Slack thread https://qmu.slack.com/archives/C0BLL9J7FMY/p1786020128769189 、GitHub issue #278 (tamura_yoshiya)。
