# Slim commands and skills and redesign the plugin for AI-agent use

Commands are Claude-Code-only, yet they carry processing bodies instead of being thin aliases to skills. Skills have grown too verbose — formalized/obsolete rules and leftover past-incident narration remain, and Markdown bold is overused. The plugin's assumed audience should shift from "developers" to "AI agents such as Claude Code Web Routine," with developer use kept but secondary.

Work items:

1. Keep commands to a few lines: treat each command as a skill alias and put the processing body in the skill. The Claude Code Web Routine instructions (/propose, /implement) should likewise keep their real work in the corresponding skill and call it from there.
2. Reduce each skill's volume: delete formalized/obsolete rules; fold past-incident notes into a single "caveats" list rather than scattering them; remove bold except where truly needed.
3. Volume target: aim for under 100 lines even for a skill the size of plugins/workaholic/skills/drive/SKILL.md — by deleting unnecessary content, not merely compressing.
4. Reduce tests and shell scripts: there are currently too many; pare them down.
5. Shift the audience: make the plugin's primary target "AI agents such as Claude Code Web Routine" rather than "developers" (developer use is still supported, but secondary).
6. Restructure documentation: reorganize the README-reachable docs systematically to match the current spec.
7. Tidy ticket front matter: remove the type, layer, effort, commit_hash, and category fields.
