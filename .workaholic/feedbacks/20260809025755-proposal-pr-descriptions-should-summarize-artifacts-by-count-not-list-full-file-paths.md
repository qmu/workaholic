# Proposal PR descriptions should summarize artifacts by count, not list full file paths

Currently, pull requests generated by the propose pipeline include an "Artifacts" section that enumerates every touched file by its full path. This is unnecessarily verbose and does not help reviewers understand the change at a glance.

Desired behavior: replace the full file-path listing with a concise summary — counts of how many feedback items, missions, and tickets were added or touched by the PR (e.g. "3 feedbacks added, 1 mission added, 2 tickets added") — rather than exhaustively listing every file path involved.

This should apply to the PR description template/generation logic used by the propose pipeline.
