# Tighten the bar for filing [FB] issues

In dev-workaholic Slack, tamura_yoshiya reported that too many "[FB] ***" issues are being filed in qmu/workaholic — 7 filed in the last 48 hours alone, out of 35 total — and asked where the bar currently sits, since he expects registration for genuine user feedback or things that must not be overlooked, not for every clear ask surfaced in conversation. The session auditing the volume confirmed the cause: it had been filing an issue for every clear ask down to minor points, and proposed narrowing to real feedback/must-not-miss items only, which tamura_yoshiya confirmed as the right bar and asked to have it filed as an FB itself rather than just acted on in-session. The current filing convention (workaholic:feedback's capture workflow and the /fb command) does not state a threshold for when to create an issue in the first place, only how to classify one once the decision to file has already been made. The ask: tighten that criterion so an [FB] issue is filed only for genuine user feedback (a real problem, bug, or improvement idea a user wants addressed) or something important that must not be overlooked — not for every request, question, or passing remark.
