# A blocking check-in question is asked once and then never again

`/moderate` の check-in が投げた質問が、本文自身で「これが決まるまでループに開始点が無い」と述べていたにもかかわらず、20時間以上・約20 tick にわたり未回答のまま一度も再掲されなかった（導入先リポジトリのチャンネルで実測）。毎時のティックはその間すべて自分を健全と報告している。

設計の字面では何も壊れていない。already-asked ゲートは ticket 20260819062058 が直したとおりに動いており、鍵から導いた step id で照合して同じ鍵を二度聞かない。その修正が閉じた欠陥は逆向きのもの — 未回答のまま毎時再掲される — だった。

しかし修正は失敗を消したのではなく反対側に移しただけで、両者は対称ではない。過剰に聞く質問は注意力を消費するが自己修復する（人が見て、うんざりして、答える）。一度だけ聞いて誰も答えない質問は、その質問が守っていたものを、無音で、上限なく失う。実測ではそれがループの開始点そのものだった。ゲートは「聞いたか」しか見ておらず、「答えられたか」も「対象がまだ生きているか」も読んでいない。

直してほしい形: ゲートに第二の軸を与える。何もそれに依存していない間は asked-once のままとし、聞いた対象がまだ生きている場合に再問可能とする。ティックは毎時所見を再導出しているので blocker が続いているかは既に知っている。足りないのは二度言う許可だけ。

形は2案あり、どちらかを推奨と断言できない実トレードオフ: (a) 継続時に間隔を広げながら再掲（時間→日→打ち切り）— 修正が除いたノイズを、意図的に、上限付きで一部戻す。(b) 再掲はせず、ティックのルートに「未回答 N 件、最古 <経過>」の常設行を持たせる — 何も繰り返さないが経過が見え、blocker が一日見過ごされることはなくなる。

いずれにせよ、未回答の質問が回答済みの質問と区別できない状態は終わらせる必要がある。
