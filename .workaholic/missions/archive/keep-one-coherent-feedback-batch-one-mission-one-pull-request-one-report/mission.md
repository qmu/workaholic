# Keep one coherent feedback batch one mission one pull request one report

## Goal

One continuation thread became nine loose tickets and four implementation pull requests. Two seams
produced it: the ingest judgement wants a mid-term plan before it holds a mission, and the driver's
grouping bar names only `depends_on` as grounds. Neither is wrong alone; together they maximize
atomicity against the developer's review unit.

## Experience

A batch a person reviewed as one pass arrives as one mission, one claim, one pull request and one
report, every feedback-to-ticket link intact. A correction to the grain is honoured on the
remaining work. Neither seam loses its brake: independent work still splits.
