# Add the feedback stream and retire the strategy layer

## Summary

Phase 1 of the loop-engineering reorganization: `feedbacks/` becomes the first-class, immutable inbound stream of project context, mission ownership returns to the mission's own plural `assignees`, and the strategy layer is retired with a living migration that preserves every strategy document as feedback.

## Key Changes

- `feedbacks/` is live: one immutable record per entry (`kind` + `source` axes, `supersedes` instead of status flips), with an internal skill, a `/feedback` command, a write-time validator, OKF indexing, and closed-layout registration
- Mission ownership is carried on the mission itself (`assignees`, creator-seeded, co-ownable) through the unchanged single oracle — no consumer needed any change
- The strategy layer is retired end to end: living migration (strategy → verbatim feedback record, assignees folded down), validator floors and `/mission` flows updated, skill deleted, docs swept

## Changes

### Added
- The `feedbacks/` artifact: `feedback` skill (`create.sh`/`list.sh`), thin `/feedback` command, `validate-feedback.sh` PostToolUse floor, OKF area indexing, and same-commit allowlist + rules registration; the reorganization's own conclusion registered as the first entry

### Changed
- `mission-owners.sh` resolves the mission's own plural `assignees` first (creator-seeded by `create.sh`; legacy singular `assignee` as fallback); every ownership consumer reads through the unchanged oracle

### Removed
- The strategy artifact layer: skill, validator floor requirement, `/mission` strategy-resolution steps, and the `strategies/` directory — retired via an idempotent living migration that keeps every strategy's direction verbatim in the feedback stream and folds its assignees into linked missions
