# Merge concerns into feedback and add the proposal loop

## Summary

Phase 2 of the loop-engineering reorganization: the concern corpus merges into the feedback stream (`kind: concern` records, superseding-record resolution, computed open set), and the proposal loop goes live — a headless `/propose` batch that turns feedback merged to main into unowned draft missions, announced to Slack by an env-driven bot notifier, with a one-page 15-minute cron runbook.

## Key Changes

- Concerns are feedback now: ship-time extraction appends `kind: concern` records (every severity, id-keyed, append-only), `/report` resolves by superseding record, and the triage/demote/merge/re-grade machinery is deleted — with a living migration that folded the real corpus in place
- `/propose` is headless by contract: runner-local cursor with a safe cold start, an exact added-records window, mission→feedback dedup, an unowned `status: draft` scaffold, and a written conservative judgment bar
- The outbound half is wired: a never-load-bearing Slack bot notifier plus `docs/proposal-loop-runbook.md` for standing up the cron

## Changes

### Added
- The `propose` skill (cursor / window / dedup / draft scaffold / notifier) and the headless `/propose` command; `status: draft` as a first-class mission state; `proposal-cursor` as a registered `.workaholic/` root file; `docs/proposal-loop-runbook.md`

### Changed
- Ship-time concern extraction and `/report` resolution now operate on the feedback stream (`feedback/scripts/list-open-concerns.sh` is the single open-set reader; `apply-deferred-concern-verdicts.sh` writes superseding records); the feedback `source` enum gains `development`

### Removed
- The `concerns/` artifact directory and its lifecycle machinery (triage, merge-concerns, re-grade, close-concern, propose-demotions, demote-concern, concern-identity migration, the promotion floor, and the `(carried from PR #N)` convention) — retired via the idempotent `migrate-concerns.sh` living migration
