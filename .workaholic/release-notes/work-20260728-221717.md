# Collapse execution to one autonomous /drive with pushed-branch claims etc

## Summary

Execution collapses to a single command. `/drive` now surveys, partitions, claims, drives, and routes all work on its own, coordinating concurrent runners through pushed git branches instead of a lock, so the same command serves a developer's terminal and a 5-minute cron tick identically.

## Key Changes

- The mission lifecycle is one status axis (`draft|approved|achieved|abandoned|carried`) with an executable approval flip and a per-artifact `merge_policy` decided at approval or ticket creation
- A claim protocol makes the repository itself the coordination medium: a runner claims work on a pushed branch, and every runner reads in-flight claims from unmerged remote branches
- `/drive` routes each finished unit by its merge policy — automatic units ship through the full evidence-gated doctrine, everything else stops at a pull request announced to Slack

## Changes

### Added

- Claim protocol scripts: `claim.sh`, `list-claims.sh`, and `release-claim.sh`, with stale claims reported but never broken automatically
- `docs/drive-loop-runbook.md` documenting the 5-minute cron entry, its observables, and its failure modes

### Changed

- Mission and ticket frontmatter carry one `status` axis plus `merge_policy`; `approve.sh` is the only path from draft to approved, and a legacy `drive_authorized` stamp migrates on first touch
- `/drive` became the sole executor, gaining autonomous unit partitioning, per-unit worktrees, agent-hour accounting, and an honest completion signal

### Removed

- `/monitor`, `/trip`, and `/carry`, along with the three-agent Agent Teams surface and the reflection channel — every capability they carried now lives in `/drive` or the feedback stream
