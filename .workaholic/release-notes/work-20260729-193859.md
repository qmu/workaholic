# Rename the feedback command to /fb and spec publishing artifacts to main etc

## Summary

The `/feedback` command is now **`/fb`**. Claude Code 2.1.220 ships its own built-in `/feedback` that sends feedback to Anthropic, so the old name did not fail — it silently did the wrong thing with your project context. Only the trigger changed: the skill, the artifact type, and the `.workaholic/feedbacks/` stream all keep the full word. This release also records, as four dependent ticket specs, the direction that `/ticket` and `/mission` should publish artifacts straight to `main` rather than cutting a branch or worktree at creation time.

## Key Changes

- `/feedback` is renamed to `/fb` — refresh your installed plugin, because a stale copy still offers `/feedback`, which now resolves to Claude Code's built-in and sends project context to Anthropic
- Four ticket specs record the publish-to-main direction: a publish-tree primitive that writes an artifact to `origin/main` without touching the caller's checkout, `/ticket` and `/mission` migrated onto it, and a `/drive` survey that fast-forwards before reading the queue
- The specs complete decision I6, which already ruled that worktrees are claim-born but never migrated the creation flows — so a ticket or mission written today is stranded on an unpushed local ref that no cron runner or second machine can see

## Changes

### Changed

- `plugins/workaholic/commands/feedback.md` became `fb.md` with `name: fb`, and the command body now carries the collision rationale plus an explicit instruction not to propagate `fb` into the vocabulary
- `CLAUDE.md`, `README.md`, and `.workaholic/README.md` reference `/fb`; the `workaholic:feedback` skill, `type: Feedback`, and `.workaholic/feedbacks/` are deliberately unchanged

### Added

- Four queued ticket specs under `.workaholic/tickets/todo/`, all `merge_policy: review`, forming a strict `depends_on` chain from the publish-tree primitive through `/ticket` and `/mission` to the `/drive` survey
