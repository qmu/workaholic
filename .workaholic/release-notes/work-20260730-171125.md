# v1.0.109 — Artifacts publish to main; /drive surveys a current main

`/ticket` and `/mission` no longer cut a git ref before writing. Both now publish their artifacts straight to `main` from whatever branch you happen to be on, and `/drive` brings its checkout up to date before it surveys the queue. The executor's claim is now the only thing in the plugin that creates a branch or a worktree.

## Refresh your installed plugin

**Do this before relying on `/ticket` or `/mission`.** A pre-refresh session still cuts a branch and builds a worktree at creation time, and its `/drive` will not fast-forward before surveying — so it can report "nothing to do" while queued work sits on `origin/main`.

## What changed for you

- **A ticket or mission is claimable the moment you create it.** Previously it landed on a local, unpushed branch that no other runner, machine, or fresh clone could see — which is why an approved mission could exist while `/drive` reported nothing to claim.
- **`/ticket` and `/mission` no longer disturb your work.** Run either mid-edit on a dirty feature branch: your branch, staged changes, untracked files, and file contents are left byte-identical. The artifact is written, committed, and pushed inside a dedicated, git-ignored `.publish/` checkout of `origin/main`.
- **One prompt fewer.** `/ticket`'s "Continue here or switch to worktree?" guard is retired — every ticket goes to `main` by construction, so both answers produced the same outcome.
- **`/mission` reports where the mission actually is.** It names the path on `main` and the pushed commit instead of a worktree path that no longer exists at creation time. `/drive` creates the worktree when it claims the mission.
- **A mission publishes as one commit or not at all.** Statement, full ticket set, and approval land together; an abandoned interrogation publishes nothing and says so.
- **`/drive` will no longer silently survey a stale queue.** It fast-forwards first, reports the base SHA it surveyed, and refuses to answer `ok` over a survey it could not confirm was current. A runner on a branch, with a dirty tree, or with a diverged `main` now terminates `pending` with a named reason instead of surveying the wrong thing.

## Upgrade notes

- **No migration.** No artifact schema changed, and nothing on disk needs moving.
- **Keep the `/drive` runner's checkout a clean `main`.** The new freshness step reports `not_on_main` / `dirty_workspace` / `diverged` and stops rather than surveying a branch. A runner checkout used for other work will now halt instead of quietly doing nothing.
- **`create-mission-worktree.sh` keeps its name** even though `claim.sh` is now its only caller; it ships in the generated `outputs/workflows` bundle, where the name is public API.
- **Skills may now relocate detail into a companion `reference/` directory** and the build carries it — see the next release for the first user.
