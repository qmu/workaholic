# v1.0.110 — The mission skill loads lighter

`plugins/workaholic/skills/mission/SKILL.md` was 562 lines, and every agent invoking `/mission` read all of it before it could act. It is now 380 lines. Nothing was deleted — the reference-only material moved into a companion `reference/` directory the skill indexes and links.

## What changed for you

- **`/mission` loads a third less text.** The per-script contracts and the six schema subsections now live in `skills/mission/reference/scripts.md` and `reference/schema.md`. `SKILL.md` keeps an index table naming each script and each field, with a link to the full detail — so what you need to *decide* stays inline and what you need to *run* is one hop away.
- **Nothing about `/mission` behaves differently.** No script contract, schema field, or lifecycle rule changed. Every fact in the old file is still in the skill's own directory, verified line by line rather than by eye.
- **Two long-misfiled sections found their homes.** The closing doctrine (worktree lifecycle, outcomes, reorganize-and-carry) had accreted *inside* `## Scripts`; it is now its own `## Ending a mission` section. The mission body-section list had been appended to `### Duration`; it now sits under `## Schema`.
- **Cross-agent bundles gained a link that was broken.** `mission/SKILL.md` pointed at `../feedback/SKILL.md`, which resolves in the source tree but not in the generated bundle — so it had been 404-ing for every Codex / OpenCode / `skills`-CLI consumer. It now references the skill by name.

## For skill authors

**A skill may now relocate detail into a companion `reference/` directory, and the build carries it.** When a `SKILL.md` outgrows the ~50-150 line guideline, move the reference-only material to `skills/<name>/reference/<topic>.md` and leave an index that links to it. The build copies that directory into the generated bundle, rewrites its script references with the extra `../` its depth requires, publicizes it like a `SKILL.md`, and reads it when computing the cross-skill closure. `verify.mjs` now asserts that every intra-bundle markdown link resolves, so a relocated file that fails to ship is a build failure rather than a silent 404.

## Upgrade notes

- **No migration.** No artifact schema changed and nothing on disk needs moving.
- Comments in `validate-mission.sh`, `mission-owners.sh`, and `create.sh` that cited *"`mission/SKILL.md`'s Ownership section"* now point at `mission/reference/schema.md`.
