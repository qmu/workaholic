# v1.0.111 — /drive stops offering work it cannot or should not take

Two coordination defects in `/drive`, both found by driving this repository with its own loop, both fixed.

## Refresh your installed plugin

Until you do, a `/drive` tick keeps using the old reader and the old floor — it will report tickets already in flight as claimable, and it will offer a mission with an empty queue.

## What changed for you

- **A claim keeps protecting its tickets for the whole drive.** The claim reader used to lose a batch unit's entire artifact list the moment `archive.sh` renamed its first ticket from `todo/<user>/` to `archive/<branch>/` — the stamp travelled with the file, but the reader looked up the old path. From then until merge the survey offered work already in flight, which is the double-pick the claim protocol exists to prevent. Measured side by side over identical state: the old reader reported **0** artifacts where the new one reports **2**.
- **A mission is drivable when it has tickets, not when it has acceptance items.** `/propose` writes a provisional acceptance *sketch*, which satisfied an item count with zero tickets — so an approved mission carrying `merge_policy: auto`, `tickets: []` and an acceptance block reading *"PROPOSED sketch for discussion — not a plan"* was offered as a claimable PR-unit. Claiming it would have created a branch and a worktree for an empty queue, under a policy authorising the run to merge.
- **The survey says which of the two applies.** `no_plan` means write the acceptance criteria; `no_tickets` means emit the ticket set (`/mission <instruction referencing it>` replans it). Distinct reasons, because they call for different actions and both are read straight out of cron logs.
- **`approve.sh` refuses a mission no ticket names.** Approval asserts that every judgement call about *these exact tickets* was answered, which is vacuous when there are none. A mission whose tickets are all already driven stays approvable — the floor asks whether a plan exists, while the survey asks whether anything is left to drive.

## Upgrade notes

- **No migration.** No artifact schema changed.
- **One existing mission is affected on this repository.** `adopt-a-git-flow-branching-model-with-durable-ship-records` is `approved` + `auto` with no tickets, so it is now excluded `no_tickets` instead of offered. It is deliberately **not** demoted — flipping another actor's approved mission back to `draft` from inside a drive would be a run overriding a human ruling. Replan it to emit its ticket set.
- New script: `mission/scripts/queue-size.sh` reports `todo` / `archive` / `total` tickets naming a mission, and is the single counter both drivability floors read.
