# v1.0.112 — The ship path works from a claim worktree

`/drive` ships every `merge_policy: auto` unit from that unit's claim worktree, and the ship path could not run there. Both halves are fixed.

## Refresh your installed plugin

Until you do, an `auto` ship from a claim worktree will still report failure on a merge that succeeded, and still send its concern records to the wrong branch.

## What changed for you

- **A merge that succeeded now reports success.** `merge-pr.sh` ended with a bare `git checkout main`, which git refuses inside a linked worktree while the primary tree holds the base — so it exited non-zero *after* the merge had landed, and a caller could not tell that from a failed merge. The exit status now reflects the merge and only the merge; the post-merge checkout is a reported field (`checked_out` plus `checkout_reason`), and it is skipped outright when another worktree holds the base.
- **Deferred concerns reach the base branch, from any checkout.** `extract-deferred-concerns.sh` used to commit and push on whatever branch it was standing on, assuming the step before it had checked the base out. When that assumption broke, a merged PR's four concern records went to the *already-merged claim branch* while the script truthfully reported `pushed: true` — the push worked, the destination was wrong, and the open-concern set (computed from records on the base) never saw them. It now takes the base explicitly, publishes through a publish tree when it is not already on it, and reports the `destination` on **every** exit path.
- **`pushed: true` is no longer the whole answer.** Read `destination` beside it. A count without a destination does not say whether the records became visible.

## Upgrade notes

- **No migration.** No artifact schema changed.
- `merge-pr.sh` and `extract-deferred-concerns.sh` both take an optional trailing base-branch argument (default `main`). The ship flow passes it; a hand-invocation without it behaves as before.
- If you script around `merge-pr.sh`, note that it can now exit 0 with `checked_out: false` — read the field rather than assuming you landed on the base.
