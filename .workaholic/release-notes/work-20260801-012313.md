# The proposal batch now reads the missions, the todo queue, and the commits since the cursor etc

## Summary

`/propose` could read only feedback and could write only to `main`. It now surveys the repository's recent state, proposes a draft mission together with the ticket set it implies, and — like `/ticket` and `/mission` — publishes onto a `work-*` branch behind a pull request.

## Key Changes

- The batch reads the missions, the todo queue, and the commits since the cursor alongside the feedback window, with the judgment bar restated so those inputs can only *constrain* a proposal, never originate one.
- A proposal now carries its ordered ticket set. This needed no new gate: `plan-units.sh` already excludes any ticket carrying a `mission:` relation, whatever the mission's status.
- `publish-tree-pr.sh` lands artifacts on a branch behind a pull request, and `/ticket`, `/mission`, and `/propose` all use it. Decision J1 is amended in writing rather than silently contradicted.

## Changes

### Changed
- `/propose` surveys the repository state and proposes a mission with its tickets on a `work-*` branch behind a pull request, instead of reading feedback alone and pushing a bare draft mission to `main`.
- `/ticket` and `/mission` publish through the same pull-request path. An artifact is no longer claimable the moment it is written — *published* and *queued* are now distinct states, and each source reports which one it reached.
