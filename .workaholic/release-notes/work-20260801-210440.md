# v1.0.125 — the per-commit size ceiling counts added implementation

`too-large-commit` had stopped measuring anything. Three feedback records from three
separate pull requests said so, one of them outright: *"a rule that is always overridden
stops measuring anything, and this is now the pattern rather than the exception."*

## Changed

- **The ceiling counts added lines only.** A relocation is no longer charged twice for
  moving content that already existed.
- **`.workaholic/` artifact prose is excluded.** Tickets, stories and records are not
  implementation throughput, and counting them made the ceiling fire on documentation.

The decision is recorded with its evidence where the rule lives, so the next reader can see
what the number is supposed to mean rather than inferring it from the threshold.
