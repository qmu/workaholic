# Non-ASCII concern titles get stable hash ids

## Summary

The ship-time concern extraction derived every `concern_id` from an ASCII word slug, so a Japanese-only section-6 title degenerated to the colliding literal `concern` and the concern was silently dropped from the feedback stream. Titles the word slug cannot represent now get a stable hash id, and fallback usage is reported instead of silent.

## Key Changes

- A concern title carrying non-ASCII characters (or yielding no slug words) derives its id as `c-<sha1[:8]>` of the NFC-normalized title; distinct titles get distinct ids and dedup across PRs works unchanged.
- ASCII titles keep their historical word slugs byte-identical — ids are the stream's permanent keys, so no existing concern is re-keyed.
- The extraction JSON gains `fallback_ids`, riding every exit, so a fallback id is a visible event rather than a silent divergence.

## Changes

### Fixed
- `extract-deferred-concerns.sh` no longer drops Japanese-titled concerns: a real story whose two live concerns extracted zero records now extracts both under stable ids.

### Changed
- `ship/SKILL.md` documents the two-rule identity (historical ASCII slug, hash fallback), and the hermetic suite pins both paths plus the fallback report.
