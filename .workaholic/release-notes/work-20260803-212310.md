# A release tier with durable ship records

## Summary

Between "merged onto `main`" and "released to production" there was no named place to stage a batch for QA, and no durable record of what a release actually carried. The repository gains exactly one extra branch form — `release/YYYYMMDD-HHMMSS`, a commit-less pointer cut from `main` — and a derived, additive ship record under `.workaholic/releases/`.

## Key Changes

- `branching/scripts/cut-release-branch.sh` mints and pushes a `release/*` pointer at a `main` commit without checking it out; the branch carries no commits of its own, so the carried range stays answerable by `git log <previous>..<tip>` forever. Cutting one is batch-level and explicitly invoked — `/drive` neither cuts nor confirms one.
- `ship/scripts/record-release-cut.sh` and `confirm-release.sh` write the durable record `.workaholic/releases/<release-branch>.md` on `main`, derived from git, with `since_reason` recording how the carried range was chosen.
- A promotion adds a second confirmation and never weakens the per-unit one; a failed confirmation deletes nothing — the next attempt cuts a fresh release branch.
- Full Git Flow (a `develop` base) was rejected in the recorded decision: one merge target per unit is what keeps the claim protocol and `merge_policy` unambiguous. `guard-git-branch.sh` now permits exactly two literal branch patterns.

## Changes

### Added
- The `release/*` tier, its cut/record/confirm scripts, the `.workaholic/releases/` registered artifact directory, and the design record in the feedback stream.
