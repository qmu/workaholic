# The branch story is concise by default

## Summary

A branch story padded every empty section with "None" and repeated itself across nine numbered sections, so the document reviewers actually read was mostly boilerplate. The story is now short by default: a section with nothing to report is omitted, numbering runs over the sections that survive, and every consumer matches the Concerns heading by name instead of by number.

## Key Changes

- Omit, never pad: an empty section is absent rather than "None", Historical Analysis folds into Motivation, and Release Preparation flattens to one labelled list.
- Both story consumers (`shrink-pr-body.sh`, `extract-deferred-concerns.sh`) match the Concerns section by name, because with sequential numbering a number-keyed miss is indistinguishable from a branch that raised no concerns.
- Low-severity concerns are filtered at render, kept at extract: the PR body drops them and states how many, while the committed story file — the extractor's only source — keeps every severity.

## Changes

### Changed
- The story template in `report/SKILL.md` and its mirror in `review-sections/SKILL.md` state the concise structure once, with the omit rule named ("Omit, never pad").
- `report/scripts/filter-low-concerns.sh` renders the PR body from the story, dropping `low` blocks with a visible count and a pointer at the story file.
