# v1.0.124 — the coordination layer stops lying about itself

Five units shipped together. Four of them are one theme: a script that reported something
other than what it did, in a way no gate could see. The fifth checked whether the rest of
the gate layer has the same problem.

## Fixed

**A claimed ticket is no longer offered again as fresh work** ([#178](https://github.com/qmu/workaholic/pull/178))

Two separately-reported defects — a survey offering already-driven tickets as untouched
backlog, and a finished unit reported as resumable — were one cause. The claim reader
followed `archive.sh`'s rename with git's *similarity-based* detection, which does not fire
when the appended Final Report drops the file under 50%; the artifact then vanished from the
claim, and both consumers misread the empty list. Resolution now falls back to an exact
lookup on the ticket filename, scoped to tickets and to an unambiguous match.

**A no-op commit and a read leave your index alone** ([#179](https://github.com/qmu/workaholic/pull/179))

`git commit --allow-empty` only *permits* a changeless commit — it still commits the index —
so a heartbeat fired mid-ticket over a staged `git rm` produced a `Refresh heartbeat` commit
carrying three real deletions. The commit is now built against a scratch index seeded from
`HEAD`. Separately, `migrate-concerns.sh` no longer stages anything: it runs as a side effect
of a documented pure read and used to turn a deliberate two-file commit into one of 154.

**`/request`'s backstop matches an identifier, not a substring** ([#180](https://github.com/qmu/workaholic/pull/180))

A repository whose name is an ordinary English word could not submit *any* request whose body
listed paths embedding that word — including directories belonging to the target repository.
The refusal arrived after the developer had already confirmed the body verbatim, and told
them to mask something that could not be removed. The bare name now matches only as a
standalone identifier, the `owner/name` and clone-URL forms are matched exactly, and every
refusal cites the text it matched and its line.

**The hourly drive routine stops repeating the same red alert** ([#181](https://github.com/qmu/workaholic/pull/181))

Measured 2026-08-02〜04: one near-identical "drive blocked" post per hour for two days from a
single root cause. The routine now reads the channel before posting, suppresses a repeat
carrying the same failure signature inside a 24-hour cool-down, posts immediately on a changed
signature, and **fails open** — an unreadable history posts the alert.

## Added

**Gate audit** ([#182](https://github.com/qmu/workaholic/pull/182))

`docs/gate-audit-shape-dependent-green.md` records a verdict for each of seven gates, citing
the implementing code and carrying a count over live artifacts. **No gate reproduces the
failure mode** that broke `tick-acceptance.sh`, and the reason sharpens it: most gates do
depend on a shape, but the defect is narrower — the shape must make a real condition
*unreachable*. Two gaps are recorded rather than fixed (56 of 102 stories carry no `type:`;
`size.sh`'s norm is met by 0 of 10 missions ever written).

This completes the mission *Make acceptance ticking measure satisfaction, not marker shape*
at 7 of 7.

## Action required

Editing a routine template does not change the routines already running. Run `/workaholify`
(or `/setup-routines`) and confirm the refresh for each `[Drive]` routine; until then the live
routines keep posting duplicate alerts and will report as drifted.
