# A no-op commit and a read now leave your index alone

Two operations documented as changing nothing were quietly mutating the git index, so the
caller's next commit silently grew and its message stopped describing its own diff.

## Fixed

- **`commit.sh --allow-empty` now commits nothing, whatever is staged.** Git's own flag
  only *permits* a changeless commit — it still commits the index — so a heartbeat fired
  mid-ticket over a staged `git rm` produced a `Refresh heartbeat` commit carrying three
  real deletions. The commit is now built against a scratch index seeded from `HEAD`, so
  its tree equals `HEAD`'s by construction and your index is left byte-identical. Beating
  over a dirty index is still allowed: that is exactly when a missed beat makes a working
  unit look abandoned.
- **`migrate-concerns.sh` no longer stages anything.** It runs as a side effect of
  `list-open-concerns.sh`, a documented pure read, and used to `git add` every record it
  wrote — turning a deliberate two-file commit into one of 154. Its work now waits in the
  working tree for you to stage.

## Changed

- `migrate-concerns.sh` reports `{migrated, had_tree, staged, root}`, and
  `list-open-concerns.sh` carries `migrated` in its envelope — the write it performs is
  reported rather than discovered.

No command interface or artifact format changed.
