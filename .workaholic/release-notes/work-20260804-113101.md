# The hourly drive routine stops repeating the same red alert

Measured 2026-08-02〜04: one near-identical "drive blocked" post per hour for two days, all
from a single root cause, with no new information in any repeat. An alert stream like that
trains the operator to stop reading alerts.

## Changed

- The `[Drive]` routine template now **reads the channel before posting a red alert**. If
  the latest red alert carries the same **failure signature** (the failed precondition plus
  its reason class) and is younger than 24 hours, no new top-level alert is posted.
- A **changed** signature posts immediately, and a condition that recurs after the cool-down
  posts again — the rule suppresses repeats, never first reports.
- A suppressed tick **names the suppression and the signature** in its own terminal report,
  so quiet-because-healthy and quiet-because-known-repeat are distinguishable in the log.
- It **fails open**: if the channel history cannot be read, the alert is posted. Silence
  must never be produced by a failure of the mechanism that decides to be silent.

The start, PR-opened, handoff and merge announcements are untouched — they report events the
session itself produced, which are new every time.

## Action required

Editing a routine template does not change the routines already running. Run `/workaholify`
(or `/setup-routines`) and confirm the refresh for each `[Drive]` routine; until then the
live routines keep the old behavior and will report as drifted.
