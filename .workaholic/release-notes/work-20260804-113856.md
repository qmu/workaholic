# Gate audit: no other gate reports on a shape instead of a failure

`tick-acceptance.sh` failed because its green depended on a marker convention rather than on
a real quality failure — measured at 0 of 37 acceptance items. This is the generalization
the reporter asked for: which other gates share that failure mode?

## Added

- `docs/gate-audit-shape-dependent-green.md` — a verdict for each of seven gates
  (`validate-mission.sh`, `validate-ticket.sh` and its `resume-*` lint, `validate-story.sh`,
  `validate-feedback.sh`, `layout-doctor.sh`, the branch-safety `leak` rule and
  `mission/scripts/size.sh`), each citing the implementing code and carrying a count over
  live artifacts. The reproduction commands are in the document.

## Result

**No gate reproduces the failure mode, and the reason sharpens what that mode is.** Most of
these gates *do* depend on a shape; the defect is narrower — the shape must make a real
condition **unreachable**, which none of them does. Nothing was changed, per the ticket's own
bar of fixing only a measured misreport.

Two gaps are recorded rather than fixed:

- **56 of 102 stories carry no `type:`**, so the OKF conformance claimed for the live
  `.workaholic/` tree is false for 55% of that area — and nothing measures it, because the
  conformance pass covers `outputs/okf/` instead.
- **`mission/scripts/size.sh`'s norm is satisfied by 0 of 10 missions ever written** (the
  smallest is 2646 bytes against a 2048 ceiling; four were closed as achieved while outside
  it). A pass/fail field that has never been `true` carries no discriminating power.

This completes the mission *Make acceptance ticking measure satisfaction, not marker shape*
at 7 of 7 acceptance criteria.
