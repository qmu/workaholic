# Two routines, one behaviour per command

The loop is reduced to what one person can maintain across a fleet: **two routines**, each a
four-line prompt, and **one behaviour per command**. A ticket's owner moved out of its
directory and into a field, which is what lets several developers share a repository without
racing for the same work.

**This release exists to make the new commands reachable.** `/implement` and `/mission-close`
landed under the previous version number, and a container that already had it installed would
skip the update and start a routine whose command does not exist — firing on time and doing
nothing, which reads as healthy.

## Added

- **`/implement`** — the unattended executor. Same survey → claim → drive → report → route as
  `/drive`, with no prompt at any step. This is what a routine and any `/goal /implement ok`
  loop invoke.
- **`/mission-close <slug>`** — ending a mission, as its own command.
- **`gather/scripts/owners.sh` / `owns.sh`** — one ownership oracle for every artifact kind,
  answering `mine` / `unowned` / `other` / `unresolved`.
- **`gather/scripts/migrate-todo-owners.sh`** — the living migration that flattens
  `todo/<user>/` and stamps `assignees`.
- **`branching/scripts/read-notify-target.sh`** — reads the notification target a pull request
  body carries, so the next routine replies where the ask arrived instead of searching for it.

## Changed

- **`/drive` is interactive again.** The `auto` and `night` first words are retired: a
  behaviour selected by an argument is one a caller can forget to pass, and forgetting it
  parks an unattended tick on a prompt nobody will answer.
- **A ticket's owner is its `assignees` field, not its path.** The queue is flat. A runner with
  no `git config user.email` now reads the whole queue and reports `owner_unresolved` with its
  size — before, it found no directory and reported an empty backlog over a full queue.
  Claiming still needs an identity and still fails loudly without one.
- **Two routine templates instead of three**, each four lines, identical in every repository.
  `[Drive]` became `[Implement]`; `[Consent]` is retired.
- **A proposal's pull request** carries the `[Proposal]` title prefix and the notification
  target in its body, and `/propose` acts only on an ask assigned to it.
- **No command dispatches on the first word of its argument.** `/mission summary`,
  `/mission approve` and `/ticket summary` are gone.

## Removed

- `create-ticket/scripts/sweep-todo.sh`, which routed strays *into* the per-user directories.
- The `[Consent]` routine template. **A pull request a human merges out of band is now
  announced by nobody** — `[Implement]` posts only for units it ran. That is the accepted cost
  of one fewer standing process per project.

## Upgrading

A checkout still carrying `todo/<user-slug>/` converges on its own: every reader tolerates
both layouts, and the migration runs at the write seams. Nothing needs doing by hand.

**Routine operators**: recreate the two routines from `/setup-routines`. Neither trigger
narrows to a person — the routines UI offers no assignee filter — so every developer's copy
fires on every matching event and the artifacts' `assignees` decide whose work it is. **On a
public repository, set Issue and Pull request permissions to `Collaborators only` first**: a
routine feeds an Issue or pull-request body to an unattended agent holding Bash, Write and a
Slack connector.
