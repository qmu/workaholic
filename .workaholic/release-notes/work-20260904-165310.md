# Prove Codex loop readiness and expose durable status

## Summary

The Codex CLI loop now treats its first completed tick as the readiness proof instead of
calling a live shell process healthy. Operators can inspect the latest outcome, evidence,
transport state, transcript, and next due time without starting another loop.

## Key Changes

- Gate startup on a successful first tick with a completed report and usable report transport.
- Classify execution, missing-report, absent-transport, and blocked-work failures explicitly.
- Atomically retain current status while preserving immutable tick evidence and transcripts.
- Add a read-only status mode that never creates a second cadence source.
