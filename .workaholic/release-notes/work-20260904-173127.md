# Ship the Codex clock inside the installed plugin

## Summary

Codex CLI and IDE users can now start the development clock from the installed Workaholic
plugin without keeping a Workaholic source checkout beside every project. The same launcher
also retains first-tick readiness proof and durable status introduced in v1.0.308.

## Key Changes

- Move the maintained Codex supervisor beside the published `work` skill.
- Keep `scripts/codex-loop.sh` as a compatibility shim onto the single implementation.
- Diagnose missing plugin skill, tick command, repository, CLI, and wrapper layers separately.
- Prove the installed topology through an isolated dry-run fixture.
- Preserve first-tick classification, atomic status, transcripts, and `--status` after the merge.

- Plugin build, generated-output consistency, self-containment, and metadata checks passed for v1.0.309.
- The merged readiness fixture passed all 26 focused checks.
- Shell parsing and cached-diff checks passed.
- The release scan found only the existing overridable size finding for the cumulative loop drill.
