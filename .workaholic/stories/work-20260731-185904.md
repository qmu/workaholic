## 1. Overview

This branch retires `status: draft` from the mission lifecycle. Since decision J4 every mission reaches `main` behind a pull request, so **merging that pull request is the approval** — and a second status-word gate re-asked the question the review had already answered, requiring a manual `/mission approve` whose only remaining job was to undo the first gate. The observable cost was six active missions on `main`, every one unclaimable, with `/drive` reporting `pending` tick after tick.

**Highlights:**

1. **One in-flight state.** `status: active | achieved | abandoned | carried`; `draft` and `approved` fold into `active` through a living migration, and `close.sh` is the only status flip left.
2. **`approve.sh` and `/mission approve` are gone**, with their three payloads redistributed rather than dropped — `merge_policy` to creation, ownership seeding deleted, the write-time floor kept and re-aimed.
3. **The floor moved from a status word onto the active *area*** — the thing that is actually claimable — so it survives the vocabulary change that removed the word it used to key on.

## 2. Motivation

`draft` made sense in the world it was designed for: `/propose` pushed a mission straight to `main` (J1), so *something* had to stop `/drive` claiming work nobody had looked at, and `status: draft` was that something. J4 replaced the premise — the review moved to the pull request — and the flag stayed. Today `/propose` opens a reviewable PR **and** marks its content unapproved: the same gate twice, with the second one requiring a human to type a command.

The cost was not theoretical. At the start of this branch `plan-units.sh` excluded five of six active missions with reason `not_approved`, and the unattended runner had nothing it was permitted to touch.

## 3. Changes

### 3-1. Retire the mission draft gate ([43ae8234](https://github.com/qmu/workaholic/commit/43ae8234))

**The decision first.** `docs/loop-engineering-workflow.md` gains a sixth round (K1/K2/K3) recording the surviving vocabulary, the redistribution of `approve.sh`'s payloads, and the rejected alternative — keeping `draft` as an *optional* marker, which loses because an optional gate that only some artifacts carry is a gate nobody can rely on. K3 also records the deliberate reversal of I2's note *"do not reintroduce `active` as a status word"*: that note existed because `active` was ambiguous between `draft` and `approved`, and with one in-flight state the ambiguity is gone.

**Drivability stops being a status word.** `plan-units.sh` no longer reads `status` for the mission offer at all — the *area* is the authority, since a mission reaches `missions/active/` on `main` only by merging its PR. The `not_approved` exclusion is gone from the reason vocabulary; `no_plan` and `no_tickets` remain, because neither re-asks the PR's question — both ask whether there is anything to drive.

**The floor is kept and re-aimed.** `hooks/validate-mission.sh` fired on `status: approved`; it now fires on **any** mission under `missions/active/`. Its ownership half is dropped (an unowned mission is claimable by anyone, which is already how `list.sh`, `summary.sh` and the mission lens treat it); its `## Experience` and `## Acceptance` halves are unchanged and are the load-bearing part of this change. An end state written into `active/` is exempt — that is a placement problem for `close.sh`, not a claimable mission.

**`merge_policy` moves to creation.** `create.sh` takes it as an optional third argument and refuses an unrecognized value (`bad_merge_policy`); `scaffold-draft.sh` leaves it empty. **Absent means `review`**, exactly as on a ticket, so one creation-time rule now covers both artifact kinds and `effective-policy.sh` needs no special case.

**Readers re-keyed in lockstep:** `list.sh` (`ready_reason` loses `draft`), `summary.sh`, `mission-lens.sh`, `close.sh`, `drive-authorized.sh` (its `not_authorized` becomes `not_active` — that reason meant "not `status: approved`", which stopped being a distinguishable state), `queue-size.sh`, `effective-policy.sh`, and `lib/resolve.sh`'s living migration, which folds both retired spellings and drops the long-retired `drive_authorized` key line.

**Docs in the same change:** `CLAUDE.md`, `mission/SKILL.md` and both its `reference/` files, `propose/SKILL.md`, `drive/SKILL.md`, `commands/mission.md`, `commands/propose.md`, `rules/workaholic.md`, `docs/drive-loop-runbook.md`. `outputs/` regenerated.

### 3-2. Reconcile with `main`'s claim-resumption work ([8814c924](https://github.com/qmu/workaholic/commit/8814c924))

`main` advanced under this branch with the resumable-claim work (PRs #151/#152): `plan-units.sh` gained `resumable[]`, `backlog_error`/`user_slug`, the `owned_by_other` ownership filter, and the three-way split of `claimed` into `claimed_active` / `claimed_by_other` / `claimed_resumable`; `/drive` gained the `handoff` terminal state. Both sides edited the same survey, so the merge conflicted in `plan-units.sh`, `drive/SKILL.md`, `docs/drive-loop-runbook.md` and `CLAUDE.md`.

**The two changes are orthogonal and both are kept.** `main` changed *who* may take a mission and *what happens to a claim whose run stopped*; this branch changed *whether a status word gates the offer at all*. The resolution keeps every reason `main` added and drops only `not_approved`, so the mission loop reads: the area is the authority (K1), ownership decides whose it is, and the claim scan decides whether it is already in flight. The `status != approved` early-return is gone from the mission loop; the ownership check it used to precede now runs first, as `main` intended.

Three prose spots that outlived the vocabulary were corrected in the same pass — `plan-units.sh`'s header ("approved missions" → the active missions), `drive/SKILL.md`'s *"offered by ownership, **not by approval alone**"* (there is no approval left to contrast with), and `CLAUDE.md`'s *"the approver is the default owner"* (the creator is). `outputs/` was regenerated rather than hand-resolved, which is what settled its three conflicted files.

## 5. Historical Analysis

This is the third contraction of the same axis, and the pattern is consistent. Decision I2 (2026-07-28) folded a `drive_authorized` boolean into `status` because two fields for one concept can disagree. K1 folds two status words into one because, after J4 moved review into the pull request, the second word named no distinction the rest of the system could express. Each step removed a concept whose justification had been quietly transferred elsewhere — and in both cases the giveaway was the same: a field that only ever mirrored a decision recorded somewhere more authoritative.

## 6. Concerns

### The write-time floor now refuses a half-filled intermediate edit

`hooks/validate-mission.sh` fires on any mission under `missions/active/`, so an agent editing a mission must land the `## Experience` and `## Acceptance` content in a **single** write — an Edit that fills Goal first and Acceptance later is refused in between. This is the intended trade (the ticket names step 4 as the load-bearing step), and the scaffold writers are unaffected because `create.sh` and `scaffold-draft.sh` write with a shell heredoc, which a `PostToolUse` hook never sees. The exposure is `/propose`'s fill step and any hand-editing session. If it proves annoying in practice, the fix is to make the batch's fill a single Write rather than to relax the floor — `propose/SKILL.md` now says so explicitly.

### `drive-authorized.sh` was kept where the superseded mission's sketch proposed removing it

The abandoned mission's acceptance sketch listed removing `drive-authorized.sh` outright. This branch keeps it and re-aims it, because `drive/SKILL.md` still names it as the authority for any caller needing a per-ticket answer, and the unified run's unit-level floor is documented as an application of the same rule rather than a replacement for it. Recorded so the divergence is a decision rather than an oversight; revisit only with a reason to remove the per-ticket entry point itself.

### The commit exceeds the per-commit size ceiling

`scan-branch-safety.sh` reports `block` on the `too-large-commit` rule for three commits — the two vocabulary commits and now the merge that reconciled with `main`. This is a lockstep vocabulary change across every reader plus its docs and tests, which the ticket required to land in one commit; splitting it would have shipped intermediate states where readers disagreed about the status vocabulary. The merge commit inherits the same size for the same reason: it reconciles that lockstep change against `main`'s own lockstep change to the identical readers. `size` is the overridable tier and no `secret` or `leak` finding exists, so the unit routes to the PR path — which its recorded `merge_policy: review` selected anyway.

### `gh` is absent in the cloud runner, so the sanctioned PR seam cannot run there

`report/scripts/create-or-update.sh` shells out to `gh`, which exits `127: gh: command not found` in the Claude-Code-on-the-web container this unit was resumed in. The branch story and this PR body were therefore published through the GitHub API by hand instead of the sanctioned script. Ticket `.workaholic/tickets/todo/a-qmu-jp/20260731220639-gh-is-absent-in-the-cloud-runner.md` is queued on this branch: every cloud `/drive` tick hits it, `ship/pre-check.sh` swallows the same 127 into "this branch has no PR", and a PR seam that only works on a developer's laptop is not a seam the unattended loop can depend on.

## 7. Successful Development Patterns

**Key a gate to the thing that is real, not to a word that describes it.** The floor keyed on `status: approved` and would have silently evaporated when that word was retired — a gate keyed to nothing still exits 0. Re-aiming it onto the *area* (`missions/active/`) ties it to the property that actually matters, "can this be claimed", which no vocabulary change can delete without also changing the layout.

**Record the rejected alternative at the moment of the decision.** K3 exists because the tempting middle path — keep `draft` as an optional marker — is exactly what a later session would re-propose. Writing down why it loses, next to what was chosen, is cheaper than re-deriving the argument.

**Let a fold be a fold.** The living migration rewrites one key and leaves every other byte alone, which is what makes it idempotent and safe to run from every script seam. The test asserts this directly (`the fold keeps the file and its other fields`), so a future rewrite-shaped "migration" fails loudly.

**Resolve a stale branch by asking what each side changed, not which side is newer.** This merge looked large (95 files, 4 conflicts) but reduced to one sentence: `main` changed *who may take* a mission, this branch changed *whether a word gates the offer*. Naming the two axes made every hunk mechanical, and made the three stale prose spots findable by grepping the retired vocabulary rather than by re-reading the diff.
