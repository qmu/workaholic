## 1. Overview

A machine running this workflow across four repositories hit 100% disk. `.worktrees/` held 53 GB, **31 GB of it fully merged and clean**. Teardown was not missing — it existed three times over — but every instance was conditioned on some run reaching its end. This branch adds the sweep that catches what those calls structurally cannot, and makes the cost visible before it is an incident.

**Highlights:**

1. `survey-worktrees.sh` reports every worktree's size, `ahead`, `dirty`, `merged` and `reclaimable` state, with repository totals.
2. `reap-worktrees.sh` removes only worktrees that are **both merged and clean**, dry-run by default, naming every skip with its reason.
3. `prune-worktree-artifacts.sh` reclaims build output *without* removing the worktree — the safety rule is git-ignored **and** a named build directory.

## 2. Motivation

The failure surfaced somewhere unrelated: a container build died with "no space left on device" because its build context was the repository root — 6.2 GB, of which 5.7 GB was `.worktrees/`. Nothing in the workflow had ever reported a byte of that growth, so it was invisible until it broke something else.

## 3. Changes

### 3-1. Reclaim worktrees instead of only creating them ([0f5e22c8](https://github.com/qmu/workaholic/commit/0f5e22c8))

Three new scripts plus size reporting at creation, and the documentation that states the in-repo location's consequences. Both destructive scripts default to a dry run; both take `--apply` to act.

## 4. Outcome

A repository's worktree footprint is now measurable in one read-only command, and the reclaimable subset can be removed with a predicate that provably cannot take unmerged or uncommitted work. A merged worktree someone wants to keep can shed its build output separately.

## 5. Historical Analysis

The `.worktrees/` location was chosen deliberately and stays — the change here is to state its consequences rather than move it. Same treatment as the claim protocol's other trade-offs: the cost is recorded next to the design, not argued away.

## 6. Concerns

### The sweep has no scheduled caller

- **Severity:** moderate
- **Description:** The ticket asked for teardown that "does not depend on one caller surviving", and the sweep delivers the mechanism — but nothing invokes it yet. A developer must run it by hand (`plugins/workaholic/skills/branching/scripts/reap-worktrees.sh`).
- **How to Fix:** Call the dry-run survey from `/drive`'s tick and report the reclaimable total, so growth is visible every run; the `--apply` decision stays a human one. The open mission *Make scheduled routines a configurable, inspectable part of a repository* is the natural home for wiring it to a schedule.

### The archive commit is again over the changed-lines ceiling

- **Severity:** low
- **Description:** 551 non-generated lines against a 500 ceiling on [0f5e22c8](https://github.com/qmu/workaholic/commit/0f5e22c8) — marginal, and the second consecutive branch to hit it, because `archive.sh` emits exactly one commit per ticket.
- **How to Fix:** Belongs to the open mission *Make the per-commit changed-lines ceiling a rule that holds*; the pattern across two branches is now evidence for that decision rather than a one-off.

### Consuming projects must add the ignore entries themselves

- **Severity:** low
- **Description:** `.worktrees/` and `.publish/` land in any build context, archive, or index rooted at the repository. The scripts add both to `.git/info/exclude`, which covers git and nothing else (`plugins/workaholic/skills/branching/SKILL.md`).
- **How to Fix:** Documented with the recommended `.dockerignore` entry. `/workaholify` is where an automated check for it would belong if this recurs.

## 7. Successful Development Patterns

- Running a new read-only script against the real repository before writing anything that acts on its output. The first smoke run reported the **main checkout as reclaimable** — `git rev-parse --show-toplevel` answers "the tree I am standing in", so inside a worktree it excluded the current one and nominated the primary tree. Had the reaper been written first and tested only in fixtures shaped by the same assumption, it would have deleted a developer's main checkout.
- Choosing the conjunction over the obvious single condition. "Delete what git ignores" is the natural pruning rule and would take `.env` and local credentials; "delete named build directories" would take a tracked `dist/`. Requiring both bounds the blast radius to things a build regenerates, and the test asserts the negative case so a later simplification fails loudly.
- Asking why an existing cleanup path leaks before adding another one. Three teardowns existed and all were correct; they shared a precondition, not a bug. That diagnosis is what made a sweep the answer instead of a fourth call in the same conditional structure.
