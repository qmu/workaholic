## 1. Overview

`/setup-routines` answers one question — *what runs against this repository* — and it answered
it wrong for any checkout whose remote is written in SSH form: **zero routines, every template
missing**, for a repository with three live, working ones.

The cause is that a repository has several interchangeable spellings and the match compared raw
strings. This branch introduces one canonical comparison form and applies it on both sides of
the match — **and on the render side too**, which is where the more expensive half of the defect
was hiding.

## 2. Motivation

Measured during the 2026-08-05 `/setup-routines` run. `resolve-repo-url.sh` returns the remote as
git holds it — `git@github.com:qmu/workaholic` — while every live routine records
`git_repository.url` as `https://github.com/qmu/workaholic`. `norm_url` reduced only a trailing
slash and `.git`, so the two forms never met.

The failure mode is the one the command exists to prevent. Its audience is a developer who cannot
tell a wrong answer from a right one; told "nothing runs against this repository" they will believe
it. The workaround in use was passing the https form by hand — which only works if you already know
the answer is wrong.

Reproduced on this branch's fixture against the pre-fix code:

```
https://github.com/qmu/workaholic   -> present=3 missing=0
git@github.com:qmu/workaholic       -> present=0 missing=3
ssh://git@github.com/qmu/workaholic -> present=0 missing=3
```

## 3. Changes

**`compare_routines.py`** gains `canon_url`, reducing `git@host:owner/name`,
`ssh://git@host/owner/name` and `https://host/owner/name` (each ± `.git`, ± trailing slash) to
`host/owner/name` with the host lowercased. It is applied at both membership sites — the
`this_repo` match and the `other_repos` grouping key — while `norm_url` stays as the *display*
form, so every reported value keeps the caller's own spelling.

**`render-routine.sh`** canonicalizes `{repo}` to the https form. This was not in the ticket's
steps and is the load-bearing half: `{repo}` builds the `…/pull/123` links, so matching alone
would have relocated the bug rather than fixed it (see §5).

A scheme that is already present is passed through untouched, so a proxied `http://…` remote is
never rewritten and stays a distinct repository.

## 4. Outcome

Both acceptance criteria hold, end to end against a fixture of three https-form routines:

| caller spelling | present | missing | drift |
| --------------- | ------- | ------- | ----- |
| `https://github.com/qmu/workaholic` | 3 | 0 | 0 |
| `git@github.com:qmu/workaholic` | 3 | 0 | 0 |
| `git@github.com:qmu/workaholic.git` | 3 | 0 | 0 |
| `ssh://git@github.com/qmu/workaholic` | 3 | 0 | 0 |
| `https://github.com/qmu/other` | 0 | 3 | — |

The reverse direction holds too (an https caller against SSH-form routine sources), and the three
spellings now render **byte-identical** prompts.

`node scripts/test-workflow-scripts.mjs`: **2195 passed, 1 failed** (2176 before — 19 new
assertions). The single failure is pre-existing on `main`, is the `/request` clone-URL rule under
this container's SSH→HTTPS rewrite, and belongs to ticket
`20260804160921-smoke-suite-is-red-under-a-git-insteadof-rewrite`, claimed by another runner as
`batch-20260804194804`. `verify.mjs`, `validate-metadata.mjs` and a `build.mjs` rebuild are clean
with no `outputs/` diff; `workaholify` does not ship in the generated bundle.

## 5. Concerns

**The render side was the more expensive half, and the ticket did not name it.** (medium)
Fixing only the match would have left `{repo}` substituting the caller's URL verbatim. Two
consequences: every routine would read as `prompt` drift under an SSH-form caller — turning a
"zero routines" wrong answer into an "everything is broken" one — and a routine *created* from
that render would carry `git@github.com:qmu/workaholic/pull/123` into a live, standing,
outward-facing process. That is a worse defect than the reported one, and it was reachable only
by asking what else consumes the caller's URL.

**A proxied remote stays a different repository, deliberately.** (low)
`http://local_proxy@127.0.0.1:41729/git/qmu/workaholic` does not canonicalize to the github.com
form, and a test pins that. Whether a rewritten remote should resolve back to its canonical origin
is a real question — it is the open ruling in the `resolve-target.sh` half of ticket
`20260804160921` — and silently equating them here would have prejudged it.

**Host case is folded, path case is not.** (low)
`github.com/Qmu/Workaholic` and `github.com/qmu/workaholic` remain distinct. Hosts are
case-insensitive by specification; repository paths are not provably so, and folding them would
trade one confident wrong answer for another.

## 6. Successful Development Patterns

**Reproduce the pre-fix behaviour before trusting the post-fix behaviour.** The fixture was run
against the original `compare_routines.py` restored from `HEAD`, which produced the exact
`present=0 missing=3` the ticket described. Without that step, a passing test proves only that the
test agrees with the code it was written beside.

**Ask what else reads the same input.** The ticket scoped the fix to the comparer. Following the
caller's URL to its other consumer — `render-routine.sh` — is what surfaced the broken-link defect,
which no amount of care inside the comparer would have found.
