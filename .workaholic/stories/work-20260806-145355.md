## 1. Overview

`/drive`'s one pre-flight stop — the superseded-plugin-binding gate — could not fire in a local session, because it read a variable the harness never exports there. It now accepts the script's own cache path as the binding when the variable is absent, reports which case decided, and keeps its deliberate silence for every caller that is not the harness's own install.

**Highlights:**

1. `loaded_root_source: env | cache_path | none` — the resolution is reported, never guessed at.
2. The cloud runner was already covered (it exports the variable and fired the gate at 02:59 JST); this closes the local half.
3. The pre-existing silence for checkouts and bundles is preserved byte-for-byte and still pinned.

## 2. Motivation

The gate exists because a session bound to a superseded plugin build answers the survey wrongly and then pushes on that answer — the measured 2026-08-04 double-pick. But `check.sh` computed the loaded-vs-registry axis only when `CLAUDE_PLUGIN_ROOT` was in the shell environment, and the harness expands that token inside plugin markdown rather than exporting it, so the sanctioned local invocation always landed in the silent branch. The stop protecting the pushed refs never armed on the machine a developer actually types `/drive` on.

## 3. Changes

### 3-1. Reach the binding gate from a local session ([dbe3b471](https://github.com/qmu/workaholic/commit/dbe3b471))

When the env var is absent but the script's resolved path sits inside the harness's plugin cache, that path is taken as the binding — the caller reached it through the expanded token, so "where is this file" and "what is running" coincide. `CLAUDE_PLUGIN_CACHE` exists as the hermetic test seam; the suite proves `cache_path` + `behind: true` on a fake cache and `none` + silence from a checkout.

## 4. Outcome

The gate is now reachable in both environments it guards. It arms locally once a build carrying this change is installed; until then the live cache copy predates the field and stays silent, which is the known absence-counts-as-the-condition case.

## 5. Concerns

### The gate still guards an unrepairable condition

- **Severity:** low
- **Description:** A stop that fires more often on a condition nothing can repair in-session (`bootstrap/session-start.sh` header) means more terminated runs; the threaded-reply alert rule is what keeps that visible rather than silent.
- **How to Fix:** Nothing here — the fix is a fresher container image or a harness rebind, recorded as an ask.

## 6. Successful Development Patterns

- Extending a pinned silence rather than replacing it: the defect was never the silence, only that the sanctioned caller landed in it — the new branch is scoped to exactly that caller.
