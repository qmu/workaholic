## 1. Overview

The web container ships no `gh`, and fourteen plugin scripts shell out to it — so every cloud `auto` unit was demoted to the PR path and every routine-published artifact waited for a human to open its pull request by hand. The bootstrap hook now provisions it, non-fatally.

**Highlights:**

1. Guarded on `command -v gh`: a provisioned container pays nothing, a refire is a no-op.
2. Non-fatal in every branch — `gh` still absent afterwards is the status quo, said once.
3. All four paths exercised against a hermetic PATH, plus a second run proving idempotence.

## 2. Motivation

`publish-tree-pr.sh` pushes the artifact branch and then reports `no_gh` instead of opening the pull request; `merge-pr.sh` cannot run at all. Two earlier records asked for the **container image** to ship `gh` — which nobody in this repository can change. This moves the remedy to the one startup seam the repository does own, where the measured facts make it a package away: `gh` 2.45.0 in the distro archive, the session running as root, `GH_TOKEN` already injected.

## 3. Changes

### 3-1. Provision gh from the bootstrap hook ([22fe0fec](https://github.com/qmu/workaholic/commit/22fe0fec))

Step 0 of the hook, before the plugin work so a container that cannot get `gh` learns it at the top of the log. Root-only, `command -v gh`-guarded, and every branch falls through to a successful session start; the failure line names the `no_gh` consequence rather than staying quiet. The installed copy is mirrored in the same commit.

## 4. Outcome

A cloud session that reaches the hook has `gh`, so the `auto` route and the merge seam work as designed there. Nothing changes where `gh` was already present or where the install cannot succeed.

## 5. Concerns

### The install depends on two facts that hold today and are not guaranteed

- **Severity:** low
- **Description:** It needs `gh` in the distro archive and a root session. Both were measured in the container, neither is promised; if either changes the hook degrades to today's behavior.
- **How to Fix:** Nothing to do now — the failure path already names the consequence, which is what makes the degradation legible rather than silent.

## 6. Successful Development Patterns

- Exercising all four branches with shimmed `claude`/`id`/`apt-get` on a hermetic PATH: the "install succeeded but the binary is unexecutable" case shows up as `gh installed ()` with empty parentheses, which no amount of reading the diff would have surfaced.

## 7. Notes

`check-bootstrap.sh` resolves the canonical copy relative to its **own** location, so running the installed plugin's copy against a worktree reports a false `hook_stale` on byte-identical files. Run the worktree's own copy when verifying a hook change there.
