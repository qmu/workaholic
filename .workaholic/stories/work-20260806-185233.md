## 1. Overview

The loop is reduced to **two routines and one behaviour per command**. The unattended executor became `/implement` and `/drive` went back to being the interactive command; a ticket's owner moved out of its directory and into an `assignees` field; the routine set went from three templates to two four-line ones; the proposal chain now hands its notification target forward in the pull request body; and no command's behaviour depends on the first word of its argument any more.

**Highlights:**

1. **Ownership reaches the artifacts.** A proposal carries the triggering issue's assignee, so on a repository with several developers a merged proposal is one person's work rather than a race between everyone's runners.
2. **One run, two entry points.** `/drive` and `/implement` share every step below the selection prompt — the knowledge stayed in one skill, and the step-0 tables moved *into* it so two commands could not each carry a copy.
3. **The queue is flat and readable by anyone.** A runner with no `git config user.email` now reads the whole queue and reports `owner_unresolved` with its size, instead of finding no directory and reporting a healthy idle tick over a full backlog.
4. **The chain stopped guessing.** `/propose` writes `Notify-Thread: <url>` into the pull request body; `/implement` reads it back instead of re-deriving the thread from a search.

## 2. Motivation

Every field a developer sets by hand multiplies by the number of projects, so the loop's shape is set by what a person can maintain across a fleet — not by what the plugin can express. Four forks had accumulated against that: a `/drive auto` first word carrying the contract every unattended caller depends on; a ticket queue whose per-user directories made "could not read" and "nothing queued" the same observation; three routine prompts a developer configures by hand; and several commands dispatching on a literal word.

Two of them had already produced measured failures. The `todo/<user-slug>/` layout let an hourly runner report an empty backlog over a full queue, and the proposed fix was a `git config` line in the routine prompt — an environment expectation layered over the flaw, the third patch in that area in a week. Re-deriving a notification thread by `fb:<stem>` search put a reply in the wrong place on 2026-08-05.

## 3. Changes

### 3-1. Split the executor into drive and implement ([ced2572b](https://github.com/qmu/workaholic/commit/ced2572b))

`/implement` is the unattended executor and `/drive` is attended only; the `auto` and `night` first words are retired. Both are thin entry points over the one Unified Run, and the step-0 freshness table moved from the command into the skill so the split produced one copy rather than two. The optional `<unit>` argument is a **scope, not a mode** — the distinction that keeps this a split rather than a new fork.

### 3-2. Carry ticket ownership as a field ([b5663942](https://github.com/qmu/workaholic/commit/b5663942))

`.workaholic/tickets/todo/` is flat and a ticket carries plural `assignees`, empty meaning team-owned and claimable — the mission's model, verbatim. One reader (`gather/scripts/owners.sh`, with `owns.sh` for the `mine`/`unowned`/`other`/`unresolved` verdict) answers ownership for every artifact kind. `plan-units.sh` reports `backlog_size` and `owner_unresolved` where it reported `identity_unresolved`: it reads the queue whatever its identity, offers the unowned half, and forbids `ok` rather than terminating. The claim protocol's identity use is deliberately unchanged — claim authorship still keys on `git config user.email`, because that asks "is this my own run" and fails loudly.

### 3-3. Cut the routines to two four-line templates ([55e08933](https://github.com/qmu/workaholic/commit/55e08933))

`[Propose]` and `[Implement]` ship, each prompt four lines: the environment, the payload to read the target out of, the one command, and the channel and post shape. `[Consent]` is retired. Each prompt carries only what the plugin cannot know; the channel and shape are the exception, because they *are* the routine's output contract and no skill can state them.

### 3-4. Hand the notification target down the chain ([f501540a](https://github.com/qmu/workaholic/commit/f501540a))

A proposal's pull request carries `Notify-Thread: <url>` in its body (`WORKAHOLIC_NOTIFY_TARGET`) and the `[Proposal]` prefix on its title (`WORKAHOLIC_PR_TITLE`). `/implement` reads the target back with `read-notify-target.sh` and replies there; `reason: "absent"` is the documented fallback to the existing search, kept for every pull request opened before this change.

### 3-5. Carry the proposal's owner from the trigger (`P6`)

Found in review by the developer: P2 moved a ticket's owner into a field but left the **emitting** seam silent, so `/propose` wrote every artifact unowned — which correctly means "claimable by anyone", and therefore meant every developer's runner raced for the same merged proposal. Both scaffolds now take `--assignee` and stamp the triggering issue's assignee; `[Implement]`'s trigger also narrows to `author = the developer`. The two are not redundant: the filter bounds the cost (N developers no longer means N sessions per merge) but is a UI setting nothing can verify, while ownership lives in the repository and holds even when a trigger is misconfigured.

### 3-6. Abolish subcommands across every command ([b0edd46c](https://github.com/qmu/workaholic/commit/b0edd46c))

Ending a mission is `/mission-close <slug>`; the `/mission summary`, `/mission approve` and `/ticket summary` interceptions are gone. Every fork was inventoried and decided separately, and the inventory is recorded rather than summarized.

## 4. Outcome

The mission's four acceptance criteria are met (4/4) and its queue is drained. `node scripts/test-workflow-scripts.mjs` reports **2402 passed, 0 failed**, up from 2259 at the branch point — the new coverage is the ownership oracle and its migration, the proposal ownership chain, the two-command attendance split, the template count and four-line shape, the notify-target writer and reader, and a whole-surface pin that greps every command file for a literal-word dispatch. `build.mjs`, `verify.mjs`, `validate-metadata.mjs` and `layout-doctor.sh` are all green.

Two behaviours were deliberately given up, each recorded where a reader meets it. A **human-merged pull request is now announced by nobody** — `[Implement]` posts only for the units it ran — which is the accepted price of one fewer standing process per project. And a **runner with no git identity still cannot claim**, only survey; that half of the identity dependency is intentional, because "is this my own run" is a question that must fail loudly.

## 5. Concerns

### The branch is large, and two size findings are unresolved

`scan-branch-safety.sh` reports `verdict: block` on two `size` findings, both override-tier: **184 files** against a ceiling of 100, and commit `b5663942` at **956 added lines of implementation** against 500. Neither is a credential or a leak.

The file count is mostly `outputs/` — the generated bundle is committed and CI-guarded, so a change touching six skills regenerates a large closure. The commit size is the ownership refactor, which had to move a reader, a parser, a migration, five call sites, two hooks and the queue layout **in one commit** because the lockstep rule requires the allowlist, the rules table and the writers to change together. Splitting it would have published a tree whose readers and writers disagreed.

Recorded rather than overridden: the unit's effective policy is `review`, so a human sees the diff either way, and `commit-size.sh`'s header asks that this rule be *decided* rather than overridden a fifth time.

### The ownership chain was half-shipped and caught in review, not by a test

P2 landed the *reading* side of ownership (the field, the oracle, the survey filter) and left the *writing* side silent — `/propose` stamped nothing. Every test passed, because each half was correct in isolation: the oracle answered `unowned` truthfully, and the survey correctly offers unowned work to anyone. The defect only exists when several developers run the loop, which no fixture had. It was found by the developer reading the design, and the ticket had named it as Implementation Step 6 all along.

The lesson worth keeping: **a field is not shipped until something writes it.** A reader plus a schema plus a migration can all be green while the value is never set.

### A Slack thread URL is disclosed in a public repository, and it was accepted rather than fixed

The routine chain carries the notification target in an Issue body and a pull-request body; on this repository both are public. The developer accepted it after review (P9). It discloses the workspace subdomain, the channel id and a microsecond timestamp — not a credential, and useless to an outsider without workspace membership — so the residual value is post-compromise convenience and metadata accumulation.

What makes it worth a Concerns entry rather than a footnote is that a public issue body is permanently archived and scraped: the exposure is small but **not retractable**, so "notice later and edit" does not work. Revisit if the channel starts carrying customer material or the repository starts taking issues from outside the collaborator set.

**The adjacent risk was not accepted and is now a stated precondition**: a routine feeds an Issue or pull-request body to an unattended agent holding Bash, Write and a Slack connector, so a public repository must set Issue and Pull request permissions to `Collaborators only`. That requirement existed in the developer's own memo but lived only in a feedback record; it is now in the workaholify preconditions and on every rendered setup sheet, which is where someone setting a routine up will actually meet it.

### `/fb`'s cross-repository mode survives the subcommand sweep

It routes on a *destination* — an `owner/name`, a URL, an explicit "to \<repo\>" — never on a first word, so it is outside the acceptance criterion. It is still a second behaviour on one name. It was kept because the substance of that flow is its non-skippable masking confirmation, and splitting the command would relocate a human gate — a different decision from this one. Named here so it is a deferred judgement rather than an oversight.

### Bare-versus-argument was read narrowly, on purpose

`/ticket` with nothing described reports rather than writes; `/mission` with nothing named plans over all of yours. Those are scopes, not modes selected by a word, and the acceptance criterion is literally about the first word. A wider reading would have added two more commands on the widest-blast-radius ticket of the mission. The reading is recorded as decision P5 so a reviewer can disagree with it explicitly.

## 6. Successful Development Patterns

**Two states that share an action are still two facts.** This came up three times independently and the answer was the same each time: `other` versus `unresolved` in the ownership oracle, `absent` versus `no_gh` in the notify-target reader, and `no_tickets` versus `queue_drained` in the survey before this branch. Each pair implies the same conservative behaviour, which makes collapsing them tempting — and each collapse hides from an operator exactly which question could not be answered.

**A migration that gates is a migration that reproduces the bug.** The queue flatten made every *reader* tolerate both layouts and ran the migration only from the *write* seams. Had readers required the flat form, an unmigrated checkout would report an empty queue — precisely the failure being removed.

**Relocating prose is when you find out it is false.** Extracting `/mission close` into its own command surfaced a successor flag the ticket floor has refused since 2026-08-04, still being offered to developers.

**A contract nothing exercises is a contract that may not work.** `/propose`'s documented `[Proposal]` prefix could not actually be written: one string went to both the pull request title and the commit subject, and `check-subject.sh` forbids a bracket prefix, so a conforming proposal would have died at `commit_failed` before any pull request existed. The prose had been correct-looking for a day; the test that exercised it is what found it.
