## 1. Overview

Adds the standing rule that a session may emit only the notification events and post shapes its own routine prompt or invoking command names — a shape documented in `workaholic:notify` itself, or used earlier in the same run, is not authorization to post it.

**Highlights:**

1. New *The prompt is the ceiling — no self-authorized shapes* section in `workaholic:notify`'s `SKILL.md`, citing the measured origin (issue #298 / FB `20260807082554`)
2. `reference/notifications.md` reframed as the catalog a template opts into, never blanket authorization

## 2. Motivation

While running `/implement`, a session posted a `🟣 Merged by` Slack line its routine prompt never specified, justifying the addition from the notify skill's own documentation and its earlier in-session reasoning — without developer confirmation. The skill said which events earn a post but not who decides a routine's postable shapes, so its shape catalog read as a menu. This closes that gap as an explicit constraint on the agent.

## 3. Changes

### 3-1. Forbid agents from self-authorizing notification formats beyond the routine prompt ([e4f7f585](https://github.com/qmu/workaholic/commit/e4f7f585))

Adds the ceiling rule to `notify/SKILL.md` (prompt/command names the events; skill docs and prior in-session reasoning are never authorization; an addition becomes standing behavior only after developer confirmation) and reframes `reference/notifications.md`'s shape list as an opt-in catalog. The routine templates already name their postable events exhaustively (Q2) and needed no change; the outcome-specific finish shapes stay sanctioned through the invoking command's skill chain (P10).

## 4. Outcome

The self-authorization loop measured in issue #298 is now forbidden in prose a reviewer can point to. Documentation-only: no event's post-worthiness and no shape changed; the notify skill is `metadata.internal`, so the rebuild left `outputs/` untouched by construction. Shipped behind v1.0.144 with the suite green (2455/0).
