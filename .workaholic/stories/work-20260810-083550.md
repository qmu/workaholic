## 5. Concerns

### Test suite inherits ambient environment, producing false failures in issue-triggered sessions

- **Severity:** moderate
- **Description:** `test-workflow-scripts.mjs`'s `run()` helper spawns fixtures with `execSync` without stripping ambient env, so a session started by a GitHub `issues.*` trigger carries a real `CCR_TRIGGER_ISSUE_NUMBER` into `propose/scripts/extract-issue-number.sh` fixtures that assert an empty or argument-derived value — 4 spurious failures measured in this session (see [67d54860](https://github.com/qmu/workaholic/commit/67d54860), `scripts/test-workflow-scripts.mjs`). The risk is not the latent gap itself (a `pull_request.closed`-triggered `/implement` container never carries the variable) but that the repository's own Local Verification gate reports failures unrelated to the change under test, which trains a reader to dismiss its output.
- **How to Fix:** Have `run()` spawn fixtures with an explicitly constructed env rather than inheriting `process.env`, or at minimum delete the `CCR_TRIGGER_*` keys before spawning, so the suite's answer does not depend on which trigger started the session.

## 6. Successful Development Patterns

- Treat a wording change as having a machine-checked shadow: the retired literal lived in two pinned regexes as well as the prose, so grepping the test suite for the old string alongside the docs is what kept the catalog and its assertion from disagreeing.
- When a substitution makes a file's surrounding instruction line contradict its own corrected example, fix the neighbouring line in the same pass — a self-contradictory template is worse than the original drift, and the inconsistency is invisible to any grep keyed on the retired string.
