# work-20260810-164914

## 1. Overview

Softened `workaholic:notify`'s red-alert dedup so a scheduled run stopping at a known, self-healing precondition — `unbound_in_claude_session` or `loaded_version_behind_registry` — posts a calm root on its first occurrence instead of the same alarming shape a genuine block wears, escalating to the ordinary red alert only if the same signature persists.

**Highlights:**

1. Defined the precondition-stop class as a named, closed list (`unbound_in_claude_session`, `loaded_version_behind_registry`) in `workaholic:notify`
2. A first-occurrence signature posts `⚪ Paused - <signature>`; the same signature found again in the dedup's existing history read escalates once to `🔴 Blocked`, after which the standing cool-down and `↳ still failing` replies apply unchanged
3. Named the shape in the `[Implement]` routine template as a clause on its existing first instruction, keeping the template's pinned two-instruction, one-fenced-format shape intact

## 2. Motivation

The developer's ruling (FB `20260810212924`) held that these stops are the loop's expected cost — the bootstrap has typically already repaired the environment by the time the post is read, and the next tick proceeds — so the first report of such a condition should read calm, reserving the alarming form for persistence: the same failure signature recurring on a consecutive tick, which is exactly the case that does not self-heal (a stale container image reproducing the condition every tick, measured four-in-a-row on 2026-08-05). The visibility guarantee holds in both directions: a broken fleet must never read as healthy idle, and a known one-tick condition must never read as an emergency.

## 3. Changes

### 3-1. Post precondition stops calm, escalate on persistence ([e451118d](https://github.com/qmu/workaholic/commit/e451118d))

Added the precondition-stop class and the calm-first/escalate-on-persistence rule to `notify/SKILL.md`, next to the red-alert dedup rule it narrows, and documented the exact `⚪ Paused` shape and its escalation in `notify/reference/notifications.md`'s new *Precondition-stop* subsection. Named the shape in the `[Implement]` routine template per *the prompt is the ceiling* — a session may post only shapes its own routine prompt names — folding the mention into the existing first instruction rather than adding a third, since a pinned test holds the template's Prompt section to exactly two top-level instructions and one fenced post format (`[Propose]`'s template names no failure shape, so it needed no change). Every genuine-failure shape (`🔴` blocked finish, a `secret` hard stop, `🟢`/`🚀`/`🟡`) is untouched. The content itself landed in the prior commit ([fad76943](https://github.com/qmu/workaholic/commit/fad76943), swept in by `commit.sh`'s `git add -u` alongside an unrelated version bump); this commit is the archive move.
