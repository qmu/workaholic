## 5. Concerns

### A shell cwd reset caused a direct, unreviewed push to main

- **Severity:** urgent
- **Description:** Mid-run, a Bash tool call's working directory silently reverted from the claim's worktree (`.worktrees/batch-20260810170054`) to the main checkout between two otherwise-sequential commands. `archive.sh`, invoked with a cwd-relative ticket path, resolved and archived the **main checkout's** copy of the ticket (the version merged via PR #363, without this run's Final Report) and pushed the resulting commit ([8d300a04](https://github.com/qmu/workaholic/commit/8d300a04)) straight to `origin/main` — bypassing the claim protocol, the PR, and the branch-safety scan gate entirely. The commit is content-neutral (a pure rename, 0 insertions/deletions) and landed the ticket at `.workaholic/tickets/archive/main/` rather than the per-branch `archive/work-20260810-170054/` convention. Caught immediately by inspecting `archive.sh`'s own "Pre-commit check on branch: main" output; corrected by merging `origin/main` into this claim's branch (git's rename detection carried this run's Final Report onto the already-moved file cleanly) rather than force-pushing or resetting `main`, which would have risked losing other work that had landed on `main` in the interim.
- **How to Fix:** Never invoke a claim-branch script with a cwd-relative path without first confirming the shell's cwd — prefer absolute paths or an explicit `(cd <worktree> && ...)` subshell for every script call in a claim worktree, since a bare `cd` earlier in the same run is not guaranteed to persist across every subsequent tool call. Worth a repository-level defense too: `guard-repo-confinement.sh` already checks `Write`/`Edit` targets against the toplevel and every worktree, but nothing currently stops a `Bash`-invoked git command from committing to the wrong checkout when several worktrees are open in one session — consider whether a PreToolUse guard could detect a `git commit`/`git push` whose branch doesn't match the tool call's expected worktree.
