## 1. Overview

`workaholic:notify`'s stateless thread lookup kept posting new Slack roots instead of finding an item's real thread. The measured cause was not an unreliable search — it was the wrong search: `dev-<repo>` is a private channel, and the default Slack search tool covers public channels only, so an exact `fb:<stem>` query against it can never succeed. This branch fixes the lookup's search surface.

**Highlights:**

1. Specified in `workaholic:notify` that the `fb:<stem>` and Issue/PR-URL searches run through the private-inclusive Slack search (`slack_search_public_and_private`, `include_bots: true`), not the public-only default, as a standing developer consent.
2. Reverted a first implementation attempt (a `thread_ref` field committed to the feedback record) that a live developer ruling barred the same day, before it merged.

## 2. Motivation

Issue #360 kept reporting the same symptom a prior fix (Q1, 2026-08-07) was meant to have resolved: a lookup that found nothing and posted a new root. Two developer corrections landed on `main` while this ticket's first attempt was already open as a pull request. The first ruled that a Slack thread coordinate must never be committed to this public repository — the exposure the P9 withdrawal already found irretractable. The second measured, live, that the actual defect was the search surface: `slack_search_public` cannot see a private channel's messages by construction, so the query was guaranteed to miss regardless of how faithfully a root carried its key. Q1 pinned the query shape but never pinned which channels it could see; that gap read as unreliability when it was scope.

## 3. Changes

### 3-1. Persist the notify thread key at root-post time instead of re-deriving it by search ([afefc277](https://github.com/qmu/workaholic/commit/afefc277))

The linked commit is the ticket's archiving commit ([`ticket-commits.sh`](https://github.com/qmu/workaholic/blob/main/plugins/workaholic/skills/report/scripts/ticket-commits.sh) links the add-event, by design, and never re-points on a later edit). Its content was superseded within this same branch by [dc3b52a5](https://github.com/qmu/workaholic/commit/dc3b52a5): reverted the barred `thread_ref`/committed-frontmatter design and specified the private-inclusive search surface in `workaholic:notify` instead, with the correction's history recorded in `reference/notifications.md`.

## 4. Outcome

The `fb:<stem>` and Issue/PR-URL searches now read the repository's own private `dev-<repo>` channel by construction, so a thread that genuinely carries its key is found instead of duplicated. Nothing new is committed to the repository; the persisted-key idea stays deferred, and is constrained — should it ever be needed — to a store outside the repository entirely.

## 5. Successful Development Patterns

- Catching the developer's concurrent correction before merging rather than after: the merge attempt failed on a git conflict (main had moved), and reading *why* it moved — rather than mechanically resolving the conflict and forcing the original merge through — surfaced that the branch's whole design had been overruled. A conflict is sometimes a signal to read, not just an obstacle to clear.
