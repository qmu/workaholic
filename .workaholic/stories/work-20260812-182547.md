## 1. Overview

Seven scripts reached GitHub through GraphQL-backed `gh` subcommands, and a Claude Code Web session is not guaranteed to serve that surface — measured HTTP 403 in this repository's own routine tick, 80 minutes after the same path had worked. Two of the mission's three tickets are done: the inbound issue inbox and the entire publish/merge path now go through REST via one shared transport, so a restricted session ingests and publishes normally instead of stopping.

**Highlights:**

1. One transport for six skills — `gather/scripts/gh-rest.sh`, REST-only, no GraphQL ladder.
2. `pr_failed` now names its underlying cause; it used to be hidden behind `2>/dev/null`.
3. `merge_reason` distinguishes `merge_not_allowed` (405) and `head_moved` (409) from a generic failure.

## 2. Motivation

The capability is a property of the **session**, not of the repository or the credential, and the scripts treated it as static. So a restricted session did not degrade — it stopped, in two different ways. Discovery reported `list_failed` and the hourly routine ingested nothing. Worse, a publish committed and pushed its artifact and *then* died at `pr_failed`, leaving work pushed-but-unpublished for a human to open by hand, in a session nobody was reading.

Both halves were invisible for the same reason: the scripts' error contracts were honest. They reported a failure rather than inventing an empty inbox or a fake PR, so nothing looked broken — which is exactly why the defect needed a measurement rather than a review to surface.

## 3. Changes

### 3-1. Read the inbound issue inbox through REST ([f856f6ee](https://github.com/qmu/workaholic/commit/f856f6ee))

The restriction cannot be summoned on demand, so the reproduction was built: a stub `gh` that 403s `issue`/`pr`/`search` and proxies `api` to the real binary. Localization confirmed the credential and the assignment filter were fine and only the GraphQL surface was refused, which is what made a transport conversion the fix. Two REST differences are handled deliberately — the issues endpoint returns pull requests (filtered, or a routine would propose against its own PRs), and `per_page` carries the cap that `--limit` used to.

### 3-2. Open and merge pull requests through REST ([6440c705](https://github.com/qmu/workaholic/commit/6440c705))

Diagnosability was fixed before the transport, as the ticket directs: the create call's stderr now rides `pr_failed`'s `detail` instead of being discarded. PR creation, both merge paths and the merge confirmation moved to REST, with the body passed on **stdin** rather than argv — a story-sized body would otherwise have traded a transport bug for the 128 KiB argv ceiling.

## 4. Outcome

Discovery and publishing survive a GraphQL-restricted session; every documented contract around them is unchanged, including the auto-merge scan gate and `pr_failed`'s meaning. The mission is two-thirds complete, and what remains is named in the Handoff above rather than left to be discovered.

## 6. Successful Development Patterns

- Building the reproduction as a stub when the real condition is per-session and cannot be summoned: the 403 stub made an environment-dependent failure testable, and it became the hermetic regression pin rather than being thrown away.
- Fixing diagnosability before transport, in that order: capturing the swallowed stderr would have made the original incident self-describing even if the conversion had never happened, so it is worth having independently of the fix it preceded.
