## 1. Overview

The cross-repository backstop that refuses an outbound body still naming this repository now
recognises a *reference* rather than a *word*. For a repository whose basename is ordinary
English, a standalone occurrence is usually just the language, and refusing it fired after the
developer had already confirmed the body verbatim — sometimes on text that could not be masked
at all.

**Highlights:**

1. The bare name refuses only when backticked or beside `repo`/`repository`/`checkout`/`worktree`/`project`, in either order.
2. The four exact rules — each clone-URL form, `owner/name`, the absolute path — are byte-unchanged, and no flag can bypass the check.
3. Both pinned test sites were rewritten rather than deleted: eight qualified forms still refuse and cite matched text plus line; prose now asserts a pass.

## 2. Motivation

Measured on qmu/workaholic#384, a generated publish plan of about seventy path pairs was
refused on two lines naming no repository: the plan's own heading, and a line carrying a
published article's title that had to be reproduced verbatim because it doubles as the
destination's sidebar label. The refusal instructs "mask it and re-confirm", and for that title
the instruction named an action that does not exist — masking it would mean editing a live
page's title to satisfy a lint.

This is the second narrowing of the same rule and the second time it was driven by a refusal a
human could not act on. The 2026-08-02 pass fixed adjacency to *identifier* characters
(`<name>-reports/`, `site-<name>/`) after a body that was seventy path pairs could not be sent
at all. It did not address prose. Because this backstop is the one place a legitimate ask can
still be refused past the human gate, its false-positive rate is a usability property as much
as a safety one — which is why the answer both times was adjacency, never a dropped check.

## 3. Changes

### 3-1. Refuse the bare repo name only where it reads as a reference ([27375db2](https://github.com/qmu/workaholic/commit/27375db2))

`check-outbound-body.sh`'s final rule now requires a qualifier in addition to the existing
identifier-adjacency exclusion: a backtick on either side, or one of five repository-indicating
nouns directly before or after the name, possessives allowed, case-insensitive, both orders.
The reproduction was recorded before the fix and the firing rule identified by its own emitted
message, per the ticket's diagnosis-first gate.

## 4. Outcome

A body using this repository's basename as ordinary prose now passes, while every qualified
mention and all four exact forms still refuse and still cite the matched text and its line. The
script header, `feedback/SKILL.md` and `feedback/reference/crossing.md` were updated in the same
change, and `outputs/` was regenerated for the six bundles carrying the feedback closure.

## 5. Concerns

### The bare-name rule now passes an unqualified prose mention

- **Severity:** low
- **Description:** An unqualified mention ("a ticket that still says `<name>` in the text"), and any qualifier outside the five-noun list including its plurals, is no longer refused (see [27375db2](https://github.com/qmu/workaholic/commit/27375db2) in `plugins/workaholic/skills/feedback/scripts/check-outbound-body.sh`). This is the true positive the change deliberately trades away.
- **How to Fix:** Nothing to fix pre-emptively — the exact rules carry the real weight and the developer's verbatim confirmation remains the actual control. Grow the noun list only on a real missed refusal, never on speculation.

### archive.sh moves the ticket before the commit-subject gate runs

- **Severity:** moderate
- **Description:** `archive.sh` moves the ticket into `archive/<branch>/` and only then calls `commit.sh`, so an off-policy subject leaves a staged rename with no commit and an identical re-run fails with `Ticket not found`. Hit on this branch; recovery needed a hand-written `git mv` in the seam the drive workflow says must never be done by hand.
- **How to Fix:** Ticket `20260812184734-validate-the-archive-subject-before-moving-the-ticket.md`, minted on this branch, calls `check-subject.sh` before anything moves.

## 6. Successful Development Patterns

- Identifying the firing rule by its **emitted message** rather than by reading the source caught that the script resolves the source repository from the caller's cwd — the first control run looked like a clean pass when it had checked the wrong repository entirely.
- Rewriting the pinned assertions into an explicit qualified/prose pair, rather than deleting the ones the change invalidated, keeps the give-up as legible in the suite as the refusals.
