## 1. Overview

`archive.sh` moved the ticket into `archive/<branch>/` and only then ran the
commit-subject gate, so an off-policy subject left the tree half-archived: the rename
staged, no commit, and the obvious retry impossible. The gate now runs before anything
moves, so a refusal leaves the tree byte-identical.

**Highlights:**

1. The canonical `check-subject.sh` runs as `archive.sh`'s first act — a call to the one validator, never a second copy of the rule.
2. The audit found no other refusal reachable after the move, and says why for each one.
3. Ten assertions pin all-or-nothing, including that the retry works with no manual `git mv` in between.

## 2. Motivation

This was hit, not foreseen — while driving an unrelated ticket earlier in the same
`/implement` run. The subject was 60 characters, `commit.sh` refused it after
`archive.sh` had already reported `==> Archiving ticket...`, and the identical re-run died
on `Ticket not found` because the path it was given no longer held a file.

Recovery required a hand-written `git mv` back into `todo/` — the one operation the drive
workflow explicitly forbids (`NEVER manually archive`). That is the whole argument for
fixing the seam rather than documenting the recovery: when a failure mode can only be
undone by a banned action, and the runs that hit it are unattended ones nobody is reading,
a staged-but-uncommitted rename is not a state any later run can act on.

## 3. Changes

### 3-1. Validate the archive subject before moving the ticket ([17cb37e7](https://github.com/qmu/workaholic/commit/17cb37e7))

The subject gate moved to the top of `archive.sh`, before `mkdir -p`/`mv`, emitting the
same policy text `commit.sh` prints plus the line the caller needs: *"Nothing was moved and
nothing was staged."* The reproduction and the localization-by-emitted-message were both
recorded before the fix, per the ticket's diagnosis-first gate.

## 4. Outcome

An off-policy subject now refuses with `git status` and `git rev-parse HEAD` identical to
before the call, and the same command with a shorter subject succeeds immediately after.
`commit.sh` keeps its own check, so the validator still has one source and four callers
that cannot drift.

## 5. Concerns

### The reachability audit is scoped to today's call shape

- **Severity:** low
- **Description:** "No other refusal can strand the ticket" rests on `archive.sh` passing `--skip-staging` with no file list, which makes `commit.sh`'s "named path cannot be staged" refusal unreachable (see [17cb37e7](https://github.com/qmu/workaholic/commit/17cb37e7) in `plugins/workaholic/skills/drive/scripts/archive.sh`).
- **How to Fix:** If a future change gives `archive.sh` an explicit file list, that refusal becomes reachable after the move and the audit needs redoing. The table is recorded in the ticket's Final Report so the next reader can check it rather than re-derive it.

## 6. Successful Development Patterns

- Auditing *every* refusal reachable after the mutation, and writing down why each one is or is not, turned "this cannot happen elsewhere in this seam" from a hope into a checked claim — the one-line fix was the easy half.
- Pinning the **retry** rather than only the refusal caught what actually hurt: the half-archived tree's real cost was that the obvious next command could not run at all.
