## 1. Overview

`workaholic:notify` now owns the **transport** as well as the notification model: the account's Slack connector is primary, the tokened `notify-slack.sh` is the machine fallback, and the fallback's inability to thread is stated where a call site will read it. The `/implement` run report gained a per-unit **notification outcome**, so a finish line that never reached Slack is reported as unposted instead of vanishing into a clean `ok`.

**Highlights:**

1. One transport rule, stated once; five call sites now defer to it instead of naming the script.
2. A post that did not happen is visible from outside the run — without moving the terminal token.
3. Two drift assertions pin the relationship between the transports and between report and token.

## 2. Motivation

A routine session carries the Slack connector and no `SLACK_BOT_TOKEN`, but the skills named `notify-slack.sh` as the way to post a finish line. Taking that path returns `{"notified": false, "reason": "no_token"}` and exits 0, so the post silently never existed — the feedback item's thread lost its root and later replies rooted new top-level lines. Nothing downstream said so, because the run report carried no notification field at all: a tick whose entire Slack output vanished was byte-identical to one whose posts landed.

This is the week's third instance of one shape — a capability the writing environment had and the running one did not, previously met as the superseded plugin binding and the GraphQL-restricted `gh`. The repository's answer is the same each time: state the rule once in the skill that owns it, have the call sites defer, and pin the relationship with an assertion rather than the phrasing.

## 3. Changes

### 3-1. Make notify own the finish-line transport ([bfb0ffcd](https://github.com/qmu/workaholic/commit/bfb0ffcd))

Specified diagnosis-first and measured before writing: the `no_token` no-op was reproduced live, `notify-slack.sh`'s payload was read to confirm it carries no `thread_ts` and runs no search, and `#dev-workaholic` was searched to confirm every finish line in the channel came from the connector as the operator's own user. The rule that followed — connector primary, tokened script the keyed-root-only fallback — lives in `workaholic:notify`; `drive/SKILL.md`, `drive/reference/routing.md`, `propose/SKILL.md`, `propose/reference/workflow.md`, `CLAUDE.md` and the proposal-loop runbook defer to it.

### 3-2. Report an unposted finish line as unposted ([601231fa](https://github.com/qmu/workaholic/commit/601231fa))

The `/implement` run report now names, per unit, the surface each finish line used and whether it landed (`posted`, `posted_as_root`, or the failure reason), alongside the existing PR URL / `pr_error` pair it is modelled on. The terminal-token table gained a row ruling an unposted line non-decisive: a notification is never load-bearing, so the `/goal /implement ok` contract does not move — only the report gets more honest.

## 4. Outcome

Both mission acceptance criteria are met. A connector-only session now has a documented surface to post on, and any session that cannot post says so in its own report. The tokened fallback's limits are written down rather than assumed, and the whole transport question has one home.

## 5. Concerns

### The fallback still cannot reply into a thread

- **Severity:** moderate
- **Description:** `notify-slack.sh` posts a keyed root only — teaching it `thread_ts` also requires the exact-token search and therefore a `search:read` scope the bot token lacks (see [bfb0ffcd](https://github.com/qmu/workaholic/commit/bfb0ffcd) in `plugins/workaholic/skills/notify/SKILL.md`). A connector-less runner will fragment a feedback item's thread into repeated keyed roots.
- **How to Fix:** Rule on the deferred option: expand the bot token's scopes and teach the script to thread, or accept keyed roots as the fallback's permanent contract.

### The notification outcome is prose, not a checked field

- **Severity:** moderate
- **Description:** The report is markdown specification, so nothing at runtime rejects a run that omits the outcome (see [601231fa](https://github.com/qmu/workaholic/commit/601231fa) in `plugins/workaholic/skills/drive/SKILL.md`). The new assertions pin the specification, not any particular run's compliance.
- **How to Fix:** If omissions are observed in live tick logs, have the finish-post step emit a machine-readable line a log check can grep, rather than widening the prose.

## 6. Successful Development Patterns

- Measuring the live surface settled step 4 in one search: a connector post carries the operator's user identity, a bot-token post would not — so "which transport posted this" is answerable from Slack's own history months later, with no instrumentation.
- Two assertions, not one, when a rule says "report it but do not act on it": pinning only the report lets the token drift, pinning only the token lets the field vanish again.
- Deciding the `## Open Decisions` fork against a concrete provisioning cost (a scope the token does not hold) kept an unattended run from guessing, and left the expensive option open rather than foreclosed.
