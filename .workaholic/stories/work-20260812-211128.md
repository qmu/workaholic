## 1. Overview

`docs/drive-loop-runbook.md` still told an operator that `loaded_version_behind_registry: true` terminates a tick before it surveys — a rule the skills retired the same day, in favour of resolving the newest plugin tree and driving from it. The runbook's two `check.sh` rows now carry the warning and the reason it replaced the stop, and two stale back-references elsewhere were corrected with them.

**Highlights:**

1. The operator page and the skill contract now give one answer to the same condition.
2. The measured history is kept and extended with the project-scope pin that made the gate self-perpetuating.
3. The only termination left in §1, `no_plugin_source`, is named where the retired ones were.

## 2. Motivation

The tick that found this was the failure: it ran on a bound plugin at 1.0.133 against a 1.0.166 registry, and its own command markdown carried the retired hard stop — so it had to consult the checkout's newer skill to learn whether it was allowed to survey at all. Anyone reading the runbook today would get the retired answer, and that answer has a measured cost on the record: four consecutive ticks stopped in 2026-08-05 and twelve in 2026-08-12, all with a claimable queue.

Documentation drift is a defect in this repository by policy, and this is the shape that hides best — a troubleshooting table row reads as a fact about the world rather than as an instruction a behavior change had to update.

### 3-1. Reconcile the runbook's version-binding rows ([34e745cc](https://github.com/qmu/workaholic/commit/34e745cc))

## 4. Outcome

An operator debugging a stalled loop now reads the same rule the run executes. `notify:SKILL.md`'s precondition-stop class was cross-checked and needed no edit: it is still `no_plugin_source` alone, and already records that the other two members left by ceasing to be stops.

## 5. Successful Development Patterns

- When a rule changes, grep the operator docs for the *symptom* — `pending`, "stop" — not only for the identifier: the identifier was already correct in eight of ten places while the instruction beside it was wrong.
- No tripwire was added, deliberately: a word-level check for "stop" near the field would fire on exactly the history both documents must keep, and the structural fix is that the rule now lives in one place with the runbook referencing it.
