## 1. Overview

The `/fb` cross-repository crossing now stamps an `[FB] ` marker onto every issue title it opens, mechanized in one idempotent script rather than left to whoever composes the title. This reverses a rule the repository had stated since the crossing was built — and the reversal was settled by measuring what the crossing actually sent, not by re-arguing the rule.

**Highlights:**

1. `feedback/scripts/fb-title.sh` is the single implementation of the title's wire shape; `open-issue.sh` and the confirmation step both render through it.
2. The stamp is idempotent across every spacing and case an agent plausibly writes, so a hand-written marker can never become `[FB] [FB] …`.
3. `/propose`'s no-title-filter boundary kept its behavior and was re-anchored on a reason that survives the reversal.

## 2. Motivation

Issue #411 reported that an issue opened by `/fb` does not always carry the `[FB]` prefix, and asked that it always do so. Discovery found the repository pointing the other way: `open-issue.sh` carried a comment explicitly declining to add a prefix, `crossing.md` stated the same rule normatively, and four other places nevertheless described the originating issue as `"[FB] ***"`. The ticket shipped with an `## Open Decisions` fork rather than a design, because honoring the ask meant reversing a written cross-repository courtesy rule.

The measurement dissolved the fork. Of the 26 issues this repository has received, **17 of 17** opened through the crossing already carried `[FB]`; only **1 of 9** filed directly by a human did. The written rule had never once described the shipped behavior — every composing agent stamped the marker by hand. What the reporter observed as "doesn't always" was the absence of a guarantee, not a run of misses, so mechanizing changes no observable output and only makes a 100%-applied convention true by construction.

## 3. Changes

### 3-1. Stamp the [FB] marker on crossing issue titles ([a8f8a98c](https://github.com/qmu/workaholic/commit/a8f8a98c))

Added `fb-title.sh` as the one writer of the title's wire shape and called it from `open-issue.sh` on the way to the wire, then brought every document stating the old rule into line in the same commit — the sender's header comment, `crossing.md`, `feedback/SKILL.md`, `commands/fb.md` and `CLAUDE.md` — each stating the reversal where the old rule stood rather than deleting it.

## 4. Outcome

The crossing's issue title is now produced in exactly one place and cannot be stamped twice. The confirmation step renders through the same script, so the developer still confirms the exact string that ships — the property that decided the script's location. `/propose`'s inbound discovery still applies no title filter, now justified by the inbound mix (humans and other tools never carry a prefix) rather than by our own outbound shape.

## 5. Concerns

### The reporter's own inbound sample was never measured

- **Severity:** low
- **Description:** The 17-of-17 measurement counts issues *this* repository received; the reporter observes issues arriving at their own repositories, which repository scope put out of reach (see [a8f8a98c](https://github.com/qmu/workaholic/commit/a8f8a98c) in `plugins/workaholic/skills/feedback/scripts/fb-title.sh`). The same crossing produced both, so the sample is representative rather than direct.
- **How to Fix:** If a miss is ever observed at a target after this change, capture it against the stamped path — the guarantee now lives in one script, so a miss would be a defect there rather than an agent's omission.

## 6. Successful Development Patterns

- Measuring a hand-applied convention before mechanizing it decided both the fork *and* the implementation: 17-of-17 made "prepend" obviously wrong and "normalize idempotently" obviously right, because the common case is a title that already carries the marker.
- Locating the shape by asking which callers must agree — the sender and the human confirmation — rather than by where it is used, kept "exactly one implementation" and "the developer saw the wire string" from trading off against each other.

## 8. Notes

The four places already describing the originating issue as `"[FB] ***"` needed no edit; the change makes them true rather than merely lucky. `extract-issue-number.sh` keys on the issue number, never the title, so nothing ever depended on the convention.
