## 1. Overview

The loop-drill runbook kept every pass's artifacts but offered no way to see *which* passes had
run. This branch adds `## 8. Drill log` — an index over the history §7 already preserves — and
records its first row, for run `20260812-215314` (issue #419).

**Highlights:**

1. A run id / date / issue / outcome table, readable without opening GitHub.
2. The section states who appends a row, so its shape is not re-invented each pass.
3. The log indexes the artifacts §7 keeps; it never restates a rule that lives in a skill.

## 2. Motivation

A pass deliberately leaves its artifacts on `main`, and §7 argues that this immutable residue
*is* the loop's history. What it withheld from an operator was the index over that history:
reconstructing which passes ran, when, and how each ended meant walking closed issues and
merged pull requests by hand. The one fact genuinely unrecoverable that way is the run id — it
appears in the issue marker (`drill:<run-id>`) and nowhere in a listing of merged pull
requests — so the log carries it rather than duplicating what the artifacts already say.

## 3. Changes

### 3-1. Add the drill log and its first row ([30600177](https://github.com/qmu/workaholic/commit/30600177))

Appends a `## 8. Drill log` section to `docs/loop-drill-runbook.md` after §7: one paragraph
saying what the log indexes and that a row is appended by whoever ran the pass, then the
four-column table carrying run `20260812-215314`, 2026-08-12, issue #419, and its end-to-end
outcome. One edit to one documentation file — the drill's own ask, not a redesign of the drill.

## 4. Outcome

The runbook now answers "which passes ran, and how did each end?" from the outside. The
ticket's open decision resolved to *operator writes the row*, stated in the section itself.

## 5. Concerns

### The `## Policies` pillar in a ticket can misname the policy's directory

- **Severity:** low
- **Description:** The driven ticket cited `workaholic:operation` / `policies/observability.md`, but the hard copy lives at `plugins/workaholic/skills/implementation/policies/observability.md` — `skills/operation/policies/` holds only `ai-production-investigation.md`, `ci-cd.md` and `no-customer-support-in-repo.md`. A driver following *Per-ticket steps* §3 literally ("open each named `policies/<slug>.md`") gets a file-not-found on a policy that exists.
- **How to Fix:** Treat a `## Policies` line as a slug to resolve across the four pillars' `policies/` directories rather than a path to open — or have the ticket writers derive the pillar from the policy index (`plugins/workaholic/hooks/policy-index.md`) instead of naming it by hand.

### The drill log accretes one row per pass forever

- **Severity:** low
- **Description:** `## 8. Drill log` grows by a row on every pass, inside an operator page that is otherwise fixed in size (see [30600177](https://github.com/qmu/workaholic/commit/30600177) in `docs/loop-drill-runbook.md`).
- **How to Fix:** If it outgrows the runbook, move the section under `.workaholic/` — which needs a layout-allowlist registration (`hooks/workaholic-layout-allowlist.txt` plus `rules/workaholic.md`) in the same commit. Not worth doing for one row.
