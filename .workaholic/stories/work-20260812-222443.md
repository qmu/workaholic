## 5. Concerns

### Plugin source can move under a run at the freshen step

- **Severity:** moderate
- **Description:** `plugin-src.sh` prefers the checkout on a version tie, justified by a header comment that holds only *after* the run's freshen — but the resolver runs before it. This run resolved `src` to the checkout at 1.0.172, then reaching a surveyable state checked out a stale baked-clone `main` (77c462d, 200 behind) and the plugin source silently reverted with it, to a `sync-main.sh` predating its own §5 realignment; that copy answered `diverged`, which the command reads as terminate. The tick would have been lost to the failure §5 exists to prevent, while reporting a version it did not run (see [b5c54e10](https://github.com/qmu/workaholic/commit/b5c54e10) in `plugins/workaholic/skills/check-deps/scripts/plugin-src.sh`)
- **How to Fix:** Prefer an immutable candidate (the version-addressed registry cache) over the checkout when both report the same version, and expose `src_immutable` so a caller spanning a tree-moving step has a field to read. Specified in ticket `20260812223046-pin-the-plugin-source-across-the-freshen-step.md`
