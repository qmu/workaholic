## 1. Overview

`/drive`'s freshen step refused any checkout not standing on the base branch, which silently cost the cloud runner whole ticks: the harness hands each session its own branch and checks that out, so `sync-main.sh` answered `not_on_main` and the run was finished before it could survey. The refusal now narrows to what it was actually protecting against.

**Highlights:**

1. A checkout parked off the base but on its **exact tip** with a **clean tree** passes, reported as `off_base: true` — the tree it would survey is byte-identical to the base's.
2. Every way that proof fails — dirty, behind, ahead, divergent, no origin — still refuses `not_on_main`, reason unchanged.
3. The exception rests on a proof, never on a `claude/*` branch-name pattern.

## 2. Motivation

Measured twice on 2026-08-12 inside one hour, by two independent runners that did not know about each other: at 21:38Z (this ticket's own provoking run) and at 22:24Z, the tick that minted `20260812223046-pin-the-plugin-source-across-the-freshen-step` for a different consequence of the same start. A third session's `claude/*` branch reached `main` as PRs #394 and #395.

The refusal's cost was invisible by construction, which is why it went unnoticed: a tick that stops there never claims (so it leaves no branch), never surveys (so it files no report), and `not_on_main` is not in `workaholic:notify`'s precondition-stop class (so it posts nothing). A lost tick and an idle tick over an empty queue look identical from outside.

This is the third instance of one class, after the superseded plugin binding and the image-baked base branch: a harness artifact wearing a developer's clothes. All three were written as "a human decided this, so stop" and all three were really "the container arrived like this, so proceed on proof".

## 3. Changes

### 3-1. Pass a checkout parked on the base tip ([f62af285](https://github.com/qmu/workaholic/commit/f62af285))

Added `sync-main.sh` §1a, deliberately mirroring §5's evidence-gated shape: it proves the checkout stands on the base's exact tip with a clean tree, then reports `ok` with `off_base` and the parked branch. It mutates nothing — there is no branch to fast-forward and moving the caller's checkout is not this script's licence — and the two documents stating the old rule were narrowed where they stood.

## 4. Outcome

A cloud tick handed a harness branch now surveys and drives instead of ending before it starts, while a developer's topic branch is refused exactly as before. The narrowing is visible in the JSON rather than silent, so a run reports the state it was in.

## 5. Concerns

### The off-base rate is not recoverable from any artifact

- **Severity:** low
- **Description:** How often the container parks off the base cannot be counted after the fact — a tick terminating on `not_on_main` leaves no branch, no report and no Slack post (see [f62af285](https://github.com/qmu/workaholic/commit/f62af285) in `plugins/workaholic/skills/branching/scripts/sync-main.sh`). Two confirmed occurrences from independent runners is the whole evidence base.
- **How to Fix:** If a pre-survey gate is ever added again, give its termination an artifact — the precondition-stop post class exists for exactly this and `not_on_main` was never added to it.

## 6. Successful Development Patterns

- Asking "what could the container alone have produced?" is what distinguishes a genuine developer decision from a harness artifact — the question that resolved all three cases in this class, and the one that turns a blanket refusal into a proof.
- Building a test fixture from the *reason* a rule exists, not from its cheapest instance: two existing cases asserted the off-base refusal on a branch created at the base's tip, pinning a boundary nobody intended and breaking the moment the rule was correctly narrowed.
