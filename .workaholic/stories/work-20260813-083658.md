## 1. Overview

The `okf` skill told sessions that tickets carry a `type:` from a vocabulary retired eight
days earlier, contradicting `CLAUDE.md`, `.workaholic/README.md`, and every shipped ticket.
This branch corrects the two sentences that said it, closing the documentation-refresh mission.

**Highlights:**

1. The direction of the error was proven before editing — no code reads a ticket `type:`.
2. `okf/SKILL.md` now states the ticket exception in both places it was wrong.
3. `outputs/` came back byte-identical: `okf` is in the build closure but not the bundle.

## 2. Motivation

`okf/SKILL.md` is what a session reads before touching the OKF bundle indexes, so a stale
claim there could have stamped a `type:` onto a ticket or folded `tickets/` into the index —
both forbidden by the layout rules. The skill was also self-contradicting: line 15 listed
tickets as `type`-bearing while line 34 said the refresh script "deliberately does not touch
anything inside `tickets/`".

The claim survived the 2026-08-07 `type`/`layer` retirement because that change swept the
ticket *writer* and its validator. `okf/SKILL.md` owns none of the ticket schema — it merely
describes it, and a describer is invisible to a search for the writer's code paths.

## 3. Changes

### 3-1. Reconcile the okf skill's ticket type claim ([5e90b713](https://github.com/qmu/workaholic/commit/5e90b713))

Confirmed first that the skill, not the exception, was the stale side: `refresh-index.sh`
never reads ticket frontmatter, `okf.mjs` handles only `type: Engineering Policy`, and
`validate-ticket.sh:244` records the fields as retired and deliberately unvalidated. Then
corrected the opening OKF-bundle sentence and the per-file conformance list, which now drops
tickets, forbids re-adding them, gains the missing `releases (type: Release)` entry, and
names the trip artifacts as legacy.

## 4. Outcome

The `okf` skill agrees with the three sources that already stated the ticket exception, and the
correction is verified prose-only: `refresh-index.sh` rewrote all eight indexes byte-identically
and the build produced no `outputs/` diff.

## 5. Concerns

### Retiring a schema field does not sweep prose that merely mentions it

- **Severity:** low
- **Description:** The 2026-08-07 retirement swept the writer and validator, leaving this
  describer stale for eight days (see
  [5e90b713](https://github.com/qmu/workaholic/commit/5e90b713) in `okf/SKILL.md`).
- **How to Fix:** When retiring a field, grep all of `plugins/`, not just writer and validator.

## 6. Successful Development Patterns

- Proving *which* of two contradicting documents is stale, by checking whether any code reads
  the field, before editing either — what separates a prose fix from an accidental schema change.
- Reading a skill's exclusion list against its conformance list: exclusions track the script's
  real behavior, the conformance list describes other workflows and drifts.
