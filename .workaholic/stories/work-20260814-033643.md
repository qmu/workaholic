## 1. Overview

When `/propose`'s stateless thread lookup finds nothing, the run now posts a readable
description root first and threads its `🔵 Proposed` line under it, rather than making the
status line the thread's own root. Stated once in `workaholic:notify`, worded verbatim in
the shape catalog, and named in the `[Propose]` template so a session may emit it.

**Highlights:**

1. Case 4 posts two messages on the connector; a found thread still takes exactly one.
2. The root carries the `fb:<stem>` key and no Claude mention token — the lookup keeps working and the routine cannot re-trigger itself.
3. A hermetic assertion compares the catalog's and the template's wording byte for byte.

## 2. Motivation

The developer read a `[Propose]` thread that opened with a status line and asked for a
short, human-readable header carrying the feedback's URL, with the status line replying
into it. Reading `#dev-workaholic` before changing anything showed the complaint is real
and narrower than it looks: three roots on 2026-08-13 were legitimate case 4 — asks that
arrived as GitHub issues and were never pasted into Slack — while a fourth was the
separate case-3 query defect already recorded in the feedback stream, and the most recent
tick threaded correctly. The root is a fix for the not-found branch alone, never a
replacement for the reply path.

## 3. Changes

### 3-1. Post a thread root for a proposal that has no linked FB ([8bd5f8ac](https://github.com/qmu/workaholic/commit/8bd5f8ac))

`workaholic:notify` states the two-message shape once and scopes it to `/propose`;
`reference/notifications.md` carries the root's exact wording and the reasoning for
linking the feedback record rather than filing an issue; the `[Propose]` template names
the post so the ceiling rule is satisfied; `workaholic:propose` reports both messages and
their outcomes separately.

## 4. Outcome

`/propose`'s case-4 threads now open with something a human can answer. Both of the
ticket's Open Decisions are ruled with their reasoning in the ticket's Final Report: no
issue is auto-filed, and "no linked FB" means the lookup's case 4.

## 5. Concerns

### The live [Propose] routine prompt was not re-synced

- **Severity:** moderate
- **Description:** The repository's copy of the root shape is complete, but this session carries no `RemoteTrigger`-family tool, so the account routine still names only the finish line — and *The prompt is the ceiling* means no session may post the root until that changes (see [8bd5f8ac](https://github.com/qmu/workaholic/commit/8bd5f8ac) in `plugins/workaholic/skills/workaholify/routines/fb.md`)
- **How to Fix:** An operator runs `/setup-routines` from a session that exposes the tool, or edits the `[Propose]` routine's prompt by hand to match the template.

### The root's record link is briefly unresolvable

- **Severity:** low
- **Description:** The root links the feedback record's `main` blob URL, which 404s until the proposal's pull request merges; that is seconds in the normal case, but indefinite when a release-scan finding holds the PR open (see [8bd5f8ac](https://github.com/qmu/workaholic/commit/8bd5f8ac) in `plugins/workaholic/skills/notify/reference/notifications.md`)
- **How to Fix:** Accepted and documented; if it proves annoying, link the record at the pull request's head instead of `main`.

### Case-4 frequency is over-counted while the case-3 defect is open

- **Severity:** low
- **Description:** FB `20260813121647` (case 3 composing an issue reference form that exists in no message) is still open, so some runs reach case 4 that should have found a thread — any measurement of how often the root is needed, taken now, is inflated (see [8bd5f8ac](https://github.com/qmu/workaholic/commit/8bd5f8ac) in `plugins/workaholic/skills/notify/SKILL.md`)
- **How to Fix:** Land the case-3 fix, then re-read the channel before drawing conclusions about the root's frequency.

## 6. Successful Development Patterns

- Reading the live Slack channel as the reproduction surface worked where the drill could not — `qfs` was absent and the drill only verifies after an hourly tick, but the channel itself is the record, and it separated two failure modes that share one symptom.
- Pinning two documentation copies with a byte-comparison assertion beats a prose instruction to keep them in sync: the ceiling rule makes the template copy load-bearing, so drift there ships an unpostable shape.

## 7. Release Preparation

**Verdict**: Ready for release

- **After release:** Run `/setup-routines` from a session exposing a `RemoteTrigger`-family tool so the live `[Propose]` prompt names the description root; until then the shape is documented but unauthorized.
