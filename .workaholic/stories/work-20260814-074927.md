## 1. Overview

`/propose` gains a fourth artifact form. A dated, owned direction with no decomposable
plan now comes out as a **strategy** in the proposal pull request rather than a mission
nobody can decompose — and that pull request is the one proposal that does not auto-merge.

**Highlights:**

1. Precedence: mission → loose ticket → strategy → record-only.
2. The strategy bar is all three parts present in the ask; a missing part is record-only naming which.
3. Announcements match by explicit slug only: *ended* reaches `close.sh`, *changed* is record-only.

## 2. Motivation

The ask (`20260814064431`, from issue #450) wanted Strategy as a fourth `/propose`
artifact type, and a strategy's lifecycle announceable from Slack. The artifact and its
writers already existed — `workaholic:strategy` was revived on 2026-08-13 — so what was
missing was the selection rule, the emit path, and the recognition of an announcement.

The first ticket carried an Open Decision this session had to resolve: **does `/propose`
become a strategy writer at all?** One day before the ask, three documents had said no
command, hook or routine writes one.

## 3. Changes

### 3-1. Add the Strategy form to /propose's judgment and emit path

The Open Decision resolved as **(a), repaired**. Option (a) rested on "the proposal only
reaches `main` when the operator merges the PR" — a premise the 2026-08-11 auto-merge
change had already falsified, so taking it verbatim would land a machine's reading of an
ask on `main` as the operator's resolved decision. The repair restores that premise: a
strategy-bearing proposal leaves `WORKAHOLIC_AUTO_MERGE` unset, so the operator's merge is
the authorship. Commit `b9cc2dd4`.

### 3-2. Recognize strategy lifecycle announcements

A new step 5b reads the actual set through `list.sh`; step 7 recognises an announcement
before the four forms; step 9c closes an *ended* one through `close.sh` and writes nothing
else. The exemption generalised to any proposal writing under `.workaholic/strategies/`.
Commit `4dc61d6c`.

## 4. Concerns

### Nothing bounds how many strategies a run may emit

**Severity:** moderate

**Description:** A mission's two-ticket floor is a script; a strategy has no analogue, so the three-part bar is prose only.

**How to Fix:** Add a publish-seam check the way `check-floor.sh` bounds missions, if the loop over-emits.

### An announced change has no writer by design

**Severity:** low

**Description:** `create.sh` creates, `close.sh` ends, nothing edits — so a *changed* announcement depends on the operator applying it.

**How to Fix:** Leave it; a third writer could rewrite the operator's standing decision.

### Slug-only matching makes a title-only announcement unmatchable

**Severity:** low

**Description:** An announcement naming only a title is reported `strategy_not_found`, so the outbound composer must carry the slug.

**How to Fix:** None wanted; a wrong similarity match would be silent.

## 5. Successful Development Patterns

- A decision record's justification goes stale without the record changing; checking the premise beat picking a side.
- Test a write floor on an **untracked** file — `validate-strategy.sh` grandfathers tracked ones and `create.sh` git-adds.
- A skill reference is a bundle-size decision: one `skills:` line pulled eight script copies into every propose-bearing bundle.
