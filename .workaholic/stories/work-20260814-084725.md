## 1. Overview

Routine templates now declare a **scope** — `developer` (one copy per person) or `repository`
(exactly one for the team) — and `/setup-routines` splits along it into `/setup-dev-routines`
and `/setup-repo-routines`. The first repository-scoped routine, `[Release Status]`, ships with
it, and it is a **reader**.

**Highlights:**

1. The scope is a template field, so both commands and both setup sheets read one source.
2. `/setup-routines` is removed, not aliased — an alias would have had to pick a scope.
3. The hourly-`/ship` ask resolved to a reader, each writer design refused on a measurement.

## 2. Motivation

`/setup-routines` converged every template the plugin ships, but the templates are not alike in
one respect that matters: `[Propose]` and `[Implement]` need a copy per developer, while a
routine belonging to the repository needs exactly one for the team. Six people running one
command left six copies of anything repository-shaped, firing every hour, and the templates
carried nothing that said which kind they were.

The trial repository routine landed on a question already answered in the opposite direction:
on 2026-08-13 a third routine was refused for costing every consuming repository a setup step.
The repository scope removes that cost, so the objection needed answering rather than
contradicting.

## 3. Changes

### 3-1. Split routine setup by routine scope ([138e6fd0](https://github.com/qmu/workaholic/commit/138e6fd0))

Every routine template gained `scope: developer | repository`; `list-routine-templates.sh`
reports and filters on it, and `render-setup-sheet.sh` renders per scope, naming the scope in
each sheet. `/setup-routines` became `/setup-dev-routines` (today's behaviour unchanged,
including the `no_transport` refusal and its sheet recovery path) and `/setup-repo-routines`,
neither touching the other's scope.

### 3-2. Add the repository-scoped release status routine ([ac7c8a8b](https://github.com/qmu/workaholic/commit/ac7c8a8b))

`[Release Status]` (`45 * * * *`, configured only by `/setup-repo-routines`) runs the new
`/release-status`: per deployment target, what is waiting, whether a confirmation method exists,
and what a human would have to do. It opens no pull request, carries no `Write`/`Edit`, and posts
one line only when something is waiting **and** that answer is not already posted.

## 4. Outcome

The per-developer setup burden is unchanged at two routines; the repository's third is configured
once, by one account. `[Implement]` still refreshes each shipping unit's plan inside its own pull
request, and between ships the new routine says when a human's hand is needed.

## 5. Concerns

### The release notes are still not updated automatically

- **Severity:** moderate
- **Description:** The ask was to update the release notes hourly; what shipped checks and
  reports instead. Each unit-less writer was refused on a measurement (see
  [ac7c8a8b](https://github.com/qmu/workaholic/commit/ac7c8a8b) in
  `plugins/workaholic/skills/ship/SKILL.md` §7), but the operator may still want the write.
- **How to Fix:** Rule on whether a write is wanted; if so, the design must answer the
  self-reference — a datum other than the base sha, or a home outside the branch it measures.

### The single-owner rule for a repository routine is unenforceable

- **Severity:** moderate
- **Description:** A routine is an account-level record no account can list on another's behalf,
  so N members each converging the repository's single routine is undetectable (see
  [138e6fd0](https://github.com/qmu/workaholic/commit/138e6fd0) in
  `plugins/workaholic/commands/setup-repo-routines.md`).
- **How to Fix:** No repository-side fix exists. If duplicates appear, raise a product ask for an
  account-visible routine owner rather than building a gate here.

### `/setup-routines` disappears without an alias

- **Severity:** low
- **Description:** A runbook still naming `/setup-routines` now hits a missing command (see
  [138e6fd0](https://github.com/qmu/workaholic/commit/138e6fd0) in
  `plugins/workaholic/commands/`). Deliberate: an alias would converge one scope and report
  success, the quieter failure.
- **How to Fix:** Nothing to fix — the rename is in `CLAUDE.md`, `README.md`, the workaholify
  SKILL and both loop runbooks. Re-render the sheets from the new names.

## 6. Successful Development Patterns

- **Test a periodic writer for self-reference first**: does the refresh's own commit change a
  value the refreshed document reports? Here it did, which settled the design in one step.
- **Assert a read-only contract in three places, because prose decays**: `allowed_tools`, a drill
  row on the working tree, and the command body.
- **Put the discriminator on the data, not in the callers**: two commands each listing template
  ids would be one list written twice, drifting invisibly.
