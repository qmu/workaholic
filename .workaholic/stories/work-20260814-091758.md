## 1. Overview

`commit.sh` now stamps `Claude-Session: https://claude.ai/code/<id>` on every commit made
inside a cloud session, so a commit says **which run** produced it. The routine's *name* stays
unrecoverable — measured, not assumed — and the author email is deliberately untouched.

**Highlights:**

1. One writer reads the environment, so every seam inherits the trailer with no edit.
2. Nothing in the container's environment names the routine; the session id resolves to it.
3. Half the report was already false: the person was always attributable, the run was not.

## 2. Motivation

The report was that every web-routine commit reads as `Claude` and cannot be attributed.
Reproducing it in a live `[Implement]` container — the reading the proposal was missing — showed
the name comes from the container's **global** git config while `user.email` is the developer's
own, set repo-locally by the web bootstrap from `.claude/git-identities`. Commits read
`Claude <a@qmu.jp>` on both routines, so the **person** was always attributable.

What was genuinely unrecoverable is which **run** produced a commit: `[Propose]` and
`[Implement]` were indistinguishable in `git log`, and neither could be traced back to the
session that could explain it.

## 3. Changes

### 3-1. Stamp the producing run onto every commit ([1fbca2c8](https://github.com/qmu/workaholic/commit/1fbca2c8))

`commit.sh` emits the trailer when `CLAUDE_CODE_REMOTE_SESSION_ID` is in its process
environment, and omits it otherwise rather than faking one. Because it reads the environment
instead of an argument, `archive.sh`, `claim.sh` and the scratch-index heartbeat all gained it
without an edit. The commit skill's SKILL and `CLAUDE.md` document the whole trailer block.

## 4. Outcome

A routine-produced commit is now traceable to the run that made it, and from there to its
routine in the routines UI; `git log --format='%(trailers:key=Claude-Session,valueonly)'` reads
it back exactly.

## 5. Concerns

### The routine's name is still not on the commit

- **Severity:** low
- **Description:** The report asked which routine; the commit answers which run (see
  [1fbca2c8](https://github.com/qmu/workaholic/commit/1fbca2c8) in
  `skills/commit/scripts/commit.sh`). Nothing in the container's environment names the routine.
- **How to Fix:** Nothing repository-side. If the product ever exposes a routine identifier, add
  a `Routine:` trailer beside this one, from the same single writer.

### The trailer is stamped by the plugin the run executes, not the branch under change

- **Severity:** low
- **Description:** This branch's own archive commit carries no trailer: a drive run executes
  `commit.sh` from the resolved immutable plugin tree (`plugin-src.sh`), not from the worktree it
  edits. The absence is correct, not a failure.
- **How to Fix:** Nothing — it is the protocol working. Verified live against this container's
  real environment instead.

## 6. Successful Development Patterns

- **Reproduce before proposing a mechanism**: it split one report into a false half (the person)
  and a true half (the run); only the true half needed code.
- **Prefer a source no caller can forget**: the one writer reading the environment beat both a
  per-call flag and an exported variable, neither of which survives N seams.
- **Test the seam most likely to be missed**: the scratch-index heartbeat builds its own index.
