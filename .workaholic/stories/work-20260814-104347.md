## 1. Overview

`/workaholify` now prepares a repository instead of describing what is wrong with it: both wiring halves apply their own repair, and the converge seam gained a stated, mechanically-checked obligation on every future migration.

**Highlights:**

1. `apply-claude-md-reference.sh` and `apply-bootstrap.sh` — one repair per named check finding, each refusing by name rather than half-writing.
2. `converge-layout.sh` is now the declared living-migration registry, enforced by the smoke suite.
3. Report-only survives as a refusal's recovery path, never as the ordinary outcome.

## 2. Motivation

The layout half of `/workaholify` already converged a repository's tree, but the two wiring halves stopped at audit-and-offer: `audit-claude-md.sh` reported `conformant: false` and the command offered to add the gateway reference, while `check-bootstrap.sh` named every bootstrap problem and left the repair as a manual follow-up nobody performed. The developer's ruling (issue #445) is that `/workaholify` is the preparation command — running it should leave the repository prepared.

The second half of the mission answers how that state stays converged. `converge-layout.sh` composed its two migrations as a hardcoded list with no obligation on the next structural change, which is exactly how consuming repositories ended up on a layout the plugin misreads while `/workaholify` called them conformant (issues #444, #445).

## 3. Changes

### 3-1. Apply the wiring and bootstrap in workaholify ([cdf0dd93](https://github.com/qmu/workaholic/commit/cdf0dd93))

Adds the two apply scripts and wires them into `commands/workaholify.md` and `SKILL.md` §3/§4 behind one confirmation each. `apply-claude-md-reference.sh` composes the audit rather than re-deriving conformance, and appends rather than rewrites; `apply-bootstrap.sh` maps one repair to each `check-bootstrap.sh` problem id and refuses atomically — an unparseable `.claude/settings.json` leaves the hook uninstalled too.

### 3-2. State the living-migration registry contract ([e4a1af8f](https://github.com/qmu/workaholic/commit/e4a1af8f))

States in `workaholify/SKILL.md` and `rules/workaholic.md` that a structural change ships its `gather/scripts/migrate-*.sh` and its `converge-layout.sh` registration in the same commit, and backs it with a walk in `test-workflow-scripts.mjs` that fails on a migration which is neither composed nor excluded with a reason.

## 4. Outcome

A repository that runs `/workaholify` now leaves with its `CLAUDE.md` gateway reference and its web-bootstrap hook actually in place, and the next migration author is told by the build — not by a downstream repository — that their script must register at the converge seam. Both mission acceptance items are met.

## 5. Concerns

### The branch-safety size gate blocks this branch

- **Severity:** moderate
- **Description:** `scan-branch-safety.sh` reports `too-large-commit` on [cdf0dd93](https://github.com/qmu/workaholic/commit/cdf0dd93) — 527 added implementation lines against a 500 ceiling. `archive.sh` stages with `git add -A`, so the second ticket's already-written test and doc changes rode into the first ticket's archive commit; neither ticket alone approaches the ceiling. The finding is real (the commit is genuinely that large), the attribution is not.
- **How to Fix:** Drive a unit's tickets strictly one at a time — implement, archive, then start the next — or teach the drive workflow to archive before the next ticket's edits begin. The gate itself is correct and was not overridden; the PR stays open.

### The bootstrap apply writes into a consuming repository's settings

- **Severity:** moderate
- **Description:** `apply-bootstrap.sh` edits `.claude/settings.json` in whatever repository `/workaholify` runs in (see [cdf0dd93](https://github.com/qmu/workaholic/commit/cdf0dd93) in `plugins/workaholic/skills/workaholify/scripts/apply-bootstrap.sh`). It parses rather than regexes, refuses an unparseable file, and preserves unrelated keys, but it is the first write this command makes into a file the repository's owner maintains by hand.
- **How to Fix:** Keep the confirmation attended-only, as the command now states. If an unattended caller ever invokes `/workaholify`, it must stay on the report-only path — no caller does today.

## 6. Successful Development Patterns

- Composing the check the apply is derived from (`audit-claude-md.sh`, `check-bootstrap.sh`) rather than re-deriving its rule: the apply and the audit cannot disagree about what conformance means, which is the same two-lockstep-sources reasoning the closed-layout rule already uses.
- Refusing across both halves of a repair rather than per write: `apply-bootstrap.sh` checks settings parseability before touching the hook file, so a refusal leaves the state the operator found rather than one the run created.
- Factoring the registry check's verdict into one function used by both the real walk and the fixture proof, so "the check would have failed" exercises the real code path instead of restating the rule.
