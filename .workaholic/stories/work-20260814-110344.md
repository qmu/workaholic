## 1. Overview

A ticket still sitting in the pre-P2 per-user queue directory read as *unowned* — team-owned, claimable by anyone — so the unattended runner was offered every colleague's backlog and merged it. The directory that used to *be* the ownership record is now read as such, the layout drains through ordinary use, and a unit taken out of somebody else's queue says so.

**Highlights:**

1. `owners.sh` gains a third, ticket-only tolerance tier; the survey excludes a colleague's legacy ticket as `owned_by_other`.
2. `archive.sh` converges the todo layout before it moves anything, so a driven queue stops needing `/workaholify`.
3. `unit-authors.sh` discloses foreign authorship on the run report and as one appended finish-line body line.

## 2. Motivation

P2 moved a ticket's owner out of its path and into `assignees:`, and left the old layout tolerated in every reader — `list-todo.sh` is `-maxdepth 2` on purpose, so the migration converges rather than gates. What nobody wired was the ownership half of that tolerance: `owners.sh` had two field tiers and no path tier, so an un-migrated ticket reached the oracle, answered empty, and `owns.sh` called it `unowned`. The directory that encoded the owner was being read as the *absence* of one — the exact inverse of the `owned_by_other` exclusion the survey promises. Measured overnight 2026-08-13→14: roughly ten PR-units driven and merged under one developer's identity out of colleagues' queues.

That state was self-perpetuating, because the migration's own header named `archive.sh` as one of its seams and `archive.sh` was the one that never called it: a queue that predated P2 never converged through ordinary use, so the tolerance had no end date.

## 3. Changes

### 3-1. Resolve a legacy path-owned ticket to its owner ([8e0cf1bf](https://github.com/qmu/workaholic/commit/8e0cf1bf))

Adds the third tier to `owners.sh` — a queued ticket at `tickets/todo/<user-slug>/<file>.md` with neither field resolves to that slug. A tier on the one oracle rather than an exclusion rule in the survey, so every consumer is fixed at once and the runner's *own* legacy tickets keep answering `mine` instead of disappearing with everyone else's.

### 3-2. Converge the todo layout at the archive seam ([fdb42751](https://github.com/qmu/workaholic/commit/fdb42751))

`archive.sh` now runs `migrate-todo-owners.sh` on the archived ticket's own tree, **before** the move so the ticket being archived is stamped too, and outside the mission branch so an un-missioned ticket converges as well. A legacy path the migration just flattened is re-resolved rather than failing as `Ticket not found`.

### 3-3. Name a unit whose tickets are not the runner's ([667bac88](https://github.com/qmu/workaholic/commit/667bac88))

`unit-authors.sh` answers `foreign` / `unresolved` / `mine` by slug, through the one comparison `owns.sh` already makes. The first two add one appended body line to the existing finish shape — no fifth shape, no second post, no mention token — and name the authors in the per-unit run report.

## 4. Outcome

An unattended runner on an un-converged repository now sees a colleague's legacy ticket excluded rather than offered, converges the queue it touches without anyone running `/workaholify`, and discloses whose work it took when the tickets were not its own. All three mission acceptance items are met.

## 5. Concerns

### Whether `/implement` should take team-owned work at all is still open

- **Severity:** moderate
- **Description:** The third ticket's `## Open Decisions` asked whether to keep "empty `assignees:` = claimable by anyone" (A) or narrow the unattended runner to `mine` only (B). This branch took (A) and shipped the disclosure the ticket scopes, recording (B) as the operator's ruling (see the Final Report in [667bac88](https://github.com/qmu/workaholic/commit/667bac88)). An unattended runner can still merge work its operator did not write; what changed is that it says so.
- **How to Fix:** Rule on (B) with the disclosure's evidence in hand. The surprise (B) was reacting to is largely removed by 3-1 and 3-2, so the remaining question is narrower than the one the report raised.

### The archive seam now relocates queued tickets a caller may hold paths to

- **Severity:** moderate
- **Description:** Wiring a tree-wide migration into a per-file seam moves files other in-flight machinery refers to. Placing it after the move failed eight assertions across three unrelated tests, and they were reporting a real hazard: a queue is listed once and driven ticket by ticket, so the first archive invalidated every remaining path and a drained unit read as resumable — the 2026-08-04 double-pick class (see [fdb42751](https://github.com/qmu/workaholic/commit/fdb42751) in `plugins/workaholic/skills/drive/scripts/archive.sh`).
- **How to Fix:** Covered for the paths `archive.sh` itself is handed, by the lexical re-resolution. Any *future* caller that caches queue paths across an archive needs the same tolerance or a re-list; the migration's header and the seam's comment both say so now.

### The branch-safety size gate blocks this branch

- **Severity:** low
- **Description:** `scan-branch-safety.sh` reports `too-large-commit` on [8e0cf1bf](https://github.com/qmu/workaholic/commit/8e0cf1bf) — 509 added implementation lines against a 500 ceiling. `archive.sh` stages with `git add -A`, so the two later tickets' already-written changes rode into the first ticket's archive commit.
- **How to Fix:** Implement and archive one ticket at a time rather than writing a unit's changes ahead of its archives. The gate was not overridden; the PR stays open.

## 6. Successful Development Patterns

- Reproducing each ticket's claim in a throwaway repository before touching code: all three reports were accurate, but the first one's fix landed differently once the actual `owners.sh` resolution order was in front of the change.
- Reading eight failing assertions in unrelated tests as a hazard report rather than as stale fixtures — the cheap reading ("legacy-layout fixtures, update them") would have shipped a real double-pick regression as a plausible three-line addition.
- Extending the one oracle instead of adding a rule at the consumer: one tier fixed the survey, the claim path and every other reader at once, and kept the runner's own legacy tickets visible to their owner.
