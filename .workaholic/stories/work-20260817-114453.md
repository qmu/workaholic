## 1. Overview

`/housekeep` gives the loop a maintenance tick: nine steps in one hourly unattended run that find what has gone stale, stuck or drifted around `[Propose]` and `[Implement]`, file it through the seams that already exist, and say what needs a human. It writes nothing on its own but its tick log, which it commits to the base as its closing act — and the one step that would reverse a standing decision ships gated rather than guessed.

**Highlights:**

1. A new `.workaholic/housekeeping/` area — one file per UTC day, append-only, never machine-pruned — and the second deliberate exception to the OKF floor after `tickets/`.
2. Eight of nine steps report, file or ask; step 8 emits nothing and names the three operator rulings it waits on.
3. `[Housekeep]` ships **repository**-scoped against the ask's own wording, because seven of its nine steps read the repository rather than the developer.
4. The tick commits its own log through the publish tree, unioning by section so two containers on the same day both land — which is what makes the routine safe to switch on.

## 2. Motivation

`[Propose]` turns asks into work and `[Implement]` drives it, and nothing kept the space *around* them tidy: stale issues, drift between GitHub and `.workaholic/`, pull requests stuck after a failed auto-merge, documentation still describing a retired design. The ask (issue #471) named nine steps for an hourly routine that would find those and file them.

Five of those steps met decisions the loop had already made — proposing from repository state, a retired start post, rebasing another runner's branch, asking a question with no question mechanism, and a scope that multiplies repository-wide work by the number of developers. The mission's own acceptance settled how to treat them: ruled on by the operator, or left unbuilt, never inferred. That is why this branch reads as much like a set of refusals as a set of features — each one is the standing decision applied, with its reasoning answered rather than dropped.

The log came first because the closed `.workaholic/` layout hard-blocks a write into an unregistered directory, so the tick's own evidence had nowhere to land until the area existed. The spine fixed the step list in a script rather than in prose, so a step that goes missing is reported instead of disappearing. The steps then filled in behind that contract — two of them deliberately as gates — and the routine template next, once the decomposition itself answered the scope question the ask had prejudged. The persist came last because it is the only thing here that writes to the base, and it could not be judged until the log's shape and the routine's scope were both settled.

### 3-1. Register the housekeeping tick log area ([7f95ddca](https://github.com/qmu/workaholic/commit/7f95ddca))

Registered `housekeeping/` in both lockstep sources and added the append-only writer and its reader. Both Open Decisions were resolved before anything was written: the log is an **operational log, not knowledge** (no `type:`, no `index.md` — 24 entries a day would rewrite the bundle indexes hourly), and retention is **one file per UTC day with no machine pruning**, because a run that deleted its own audit trail would be choosing which evidence of itself survives.

### 3-2. Add the housekeep command and skill spine ([4141b636](https://github.com/qmu/workaholic/commit/4141b636))

The thin `/housekeep` command, the `workaholic:housekeep` skill, and `run.sh` driving nine ordered steps with one log line and one report row each. The failure an hourly tick actually dies of is a step going *quiet*, so a missing script, a non-zero exit, empty output and an off-vocabulary status are four separately named degradations — and a step that ran out of the tick's budget is reported as unreached.

### 3-3. Implement the inbound sweep steps ([185151c7](https://github.com/qmu/workaholic/commit/185151c7))

Steps 2 and 3. GitHub is read over the sanctioned REST transport since the last sweep tick; Slack, Gmail and Drive are session connectors and are handed back with the bound each is read under, named individually so an absent one is never rendered as an empty one. Findings become **feedback records**, not issues — a self-filed assigned issue would be re-discovered by `[Propose]` every hour forever — and quoting is **pointer and subject line only**.

### 3-4. Implement the housekeep hygiene steps ([d93749cb](https://github.com/qmu/workaholic/commit/d93749cb))

Steps 4 to 7, sharing one bounded reader of open pull requests. Step 4 reports conflict state and **never rebases**: a `work-*` branch is a claim, and a third party pushing to it races the claim holder. Step 5 reports drift and closes nothing. Step 6 posts at most one reminder per distinct state, naming the decision each pull request needs. Step 7 reuses the existing drift checkers and files tickets rather than editing documents.

### 3-5. Gate the housekeep strategy proposal step ([686abe90](https://github.com/qmu/workaholic/commit/686abe90))

Step 8 would reverse `/propose`'s bar that repository state never originates a proposal, so it ships as a gate: it reads the strategy set, emits nothing, and names its three outstanding rulings in every report. The propose skill is left byte-identical and a test asserts its wording is unchanged, so the reversal cannot be slipped in later without a decision.

### 3-6. Implement the housekeep human check-in step ([92e2ac3d](https://github.com/qmu/workaholic/commit/92e2ac3d))

Step 9 asks in Slack, never through `AskUserQuestion`. The script owns the mechanical half — quiet hours in the workspace timezone, asked-once dedup, five per tick and ten per day — and the model owns the judgement of whether an item is worth asking at all. A suppressed question is **held, not dropped**, and an unanswered one is never re-asked: silence is not consent, and repeating a question hourly is nagging.

### 3-7. Ship the Housekeep routine template ([044627fe](https://github.com/qmu/workaholic/commit/044627fe))

The `[Housekeep]` template at `:50`, **repository**-scoped, with both post shapes named in its prompt and mirrored byte-identically in the notify catalog. The ask said `/setup-dev-routines`; the decomposition answered it — seven of nine steps read the repository, and step 8's proposal race, the one real argument for per-developer copies, is moot while step 8 emits nothing. `loop-drill.sh verify-housekeep` makes the tick checkable on demand.

### 3-8. Commit the housekeep tick log to the base ([612219bb](https://github.com/qmu/workaholic/commit/612219bb))

The tick's closing act. A routine container is discarded after the run, so a log left in the checkout took every dedup's memory with it and left an hourly unattended process with no audit trail — invisible in a hand-run, where the checkout survives. `persist-log.sh` puts the day's sections on the base through the **publish tree directly**, leaving the caller's checkout byte-identical and creating no branch the claim scan could see. Concurrent ticks **union by section** against a freshly fetched base rather than replaying a patch, because a textual rebase of two end-of-file appends conflicts; a `--root` outside the repository is refused by name, which is what keeps the drill's throwaway root out of the operator's history.

## 4. Outcome

The repository has a maintenance tick that is honest about its own coverage: every step reports, a degraded read is named rather than rendered as an empty result, and the two steps that could not be built without an operator's ruling say so in machine-readable output instead of guessing. Nothing in the tick merges, pushes to another runner's branch, closes an issue, or rewrites a document on `main` — its own append-only log is the single thing it commits there, and a persist that missed the base is reported by name with the log left behind for the next tick.

## 6. Successful Development Patterns

- Building the gate instead of the feature made "waiting on a human" a first-class reported state — the same move `verification_handoff:` makes for a unit, and it beats both guessing the ruling and omitting the step.
- Writing the trap into the script that hit it (`tr` cannot split JSON onto lines; a skill's scripts must sit exactly one directory below the skill) put each finding where the next reader will be standing.
- Deriving every window from the tick log or from git — never from `date` arithmetic — kept the steps behaving identically on a laptop and in the routine's container.
- Testing the concurrency claim with a real race rather than two sequential writers — a `pre-push` hook that lands the other clone's section mid-push — proved the retry re-derives its content, which two ordered writers never would have.
