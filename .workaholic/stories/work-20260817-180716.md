## 1. Overview

`/release-status` is now `/fullfill`, for the one-word slash-command convention. The
behaviour is untouched — still the pure reader `workaholic:ship` §7 defines — and the two
things that look like the command but are not, the `[Release Status]` routine record and
the `📦 Release status` post shape, deliberately did not move.

**Highlights:**

1. Every command-level reference followed the rename; the eight surviving `release-status` hits are template ids and filenames, each correct to leave.
2. The routine record keeps its name, because renaming it would create a duplicate routine rather than rename the operator's existing one.
3. The spelling is the one the ask named, resolved out loud rather than silently corrected.

## 2. Motivation

The ticket arrived with two forks it refused to pick a side of, and both were about the
same confusion: a command, a routine record and a Slack post shape had all been carrying
one name. Separating them is what made the rename safe. `/setup-repo-routines` converges
an account's routines *by name*, so a renamed template does not rename anything — it
creates a second routine beside one that no other account can list or delete. And the
`📦 Release status` prefix is the notify lookup's exact-string dedup key, so renaming the
event would post one duplicate line at the cutover for nothing.

## 3. Changes

### 3-1. Rename release-status to fullfill ([1dd2d8f8](https://github.com/qmu/workaholic/commit/1dd2d8f8))

`git mv` on the command file plus its `name:` and heading, then the sweep: the routine
prompt and its `<src>/commands/…` fallback path, `ship/SKILL.md` §7, `notify/SKILL.md` and
its shape catalog, `CLAUDE.md`, `README.md`, the drill runbook, `loop-drill.sh`, and the
two reader assertions. Both Open Decisions are resolved in the Final Report and, for the
routine one, in the template itself.

## 4. Outcome

`/fullfill` is the registered command and `/release-status` no longer resolves. The
routine, its schedule, its `allowed_tools` and its post shape are byte-unchanged, so the
repository's single hourly tick is unaffected by the rename it invokes.

## 5. Concerns

### The command name is spelled fullfill, not fulfill

- **Severity:** moderate
- **Description:** the English word is *fulfill* / *fulfil*; `fullfill` doubles the first `l` (see [1dd2d8f8](https://github.com/qmu/workaholic/commit/1dd2d8f8) in `plugins/workaholic/commands/fullfill.md`). The ask and the ticket title both name that string, so this run followed the operator's chosen identifier rather than correcting it silently — but the choice is the operator's to confirm, and a shipped command name is read for a long time.
- **How to Fix:** if the dictionary spelling was meant, re-run the identical sweep for `fullfill` → `fulfill`; the split it followed (a command reference renames, an event or record reference does not) holds unchanged, so it is one mechanical pass.
