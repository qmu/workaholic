## 1. Overview

The stateless reply-thread lookup gained the clause it was missing: case 3 searches the
**originating** Issue or pull-request URL — a string that existed before the run began — and
never one the run itself created. A query-source specification, not a mechanism change.

**Highlights:**

1. `notify/SKILL.md` case 3 now prohibits querying a self-created URL, in the one place that owns the rule.
2. The lookup's history records PR #484's miss and states what was deliberately not changed.
3. Both call sites were audited and needed no edit — they defer rather than restate.

## 2. Motivation

An `/implement` run merged PR #484 and posted its `🟢 Implemented` line top-level, mentioning the
developer, while a live thread for the same feedback item already existed. Case 2's `fb:<stem>`
could not match a human-written root that predates the record; case 3 searched the URL of the
pull request the run had just opened — a string no Slack message could contain. The `/propose`
run that wrote the ticket corroborated it from the other side, finding the developer's thread by
searching the *originating issue* URL.

It is the second correction of this shape: ticket `20260810163359` fixed the search *surface*,
this one the query *source*. Both left the lookup's mechanism untouched.

## 3. Changes

### 3-1. Never query a URL this run created in the lookup ([ce2ed86d](https://github.com/qmu/workaholic/commit/ce2ed86d))

Case 3 of *One thread per feedback item* now names the originating Issue or pull-request URL and
states that a URL this run created is never a query, keeping the `#<number>` substitute clause
and the "never an extra query" wording intact. The lookup history in `notifications.md` gained
the failure entry; the audit of `propose/reference/workflow.md` step 12, `propose/SKILL.md`
*Notifier contract* and `drive/SKILL.md` §3/§7 found nothing to correct, since each defers the
lookup rather than restating it.

## 4. Outcome

The lookup's normative statement now covers the failure that produced it; the two reversals the
ask also raised remain the operator's, recorded and unresolved. `outputs/` is unchanged — `notify`
is outside the `workflows` bundle's closure, so this contract reaches no non-Claude agent.

## 5. Concerns

### The fixed case is one half of the measured miss

- **Severity:** moderate
- **Description:** A human-rooted thread carries no `fb:<stem>` and offers case 3 no pre-existing
  URL, so it stays unfindable and a run still posts a new root beside it (see [ce2ed86d](https://github.com/qmu/workaholic/commit/ce2ed86d) in `plugins/workaholic/skills/notify/SKILL.md`)
- **How to Fix:** The operator rules on the two reversals recorded in feedback `20260818062639` —
  lifting the two-query ceiling, or letting `/propose`'s reply carry the key into a root it did
  not write.

### check-version-bump.sh answered wrongly on this branch

- **Severity:** moderate
- **Description:** It returned `already_bumped: true` for a branch carrying no bump, reading local
  `main` (`6e0cb9e9`) instead of `origin/main` (`671aa8e4`) — ticket `20260818065258`'s defect,
  reproduced live (see [36bafad1](https://github.com/qmu/workaholic/commit/36bafad1) in `plugins/workaholic/skills/branching/scripts/check-version-bump.sh`)
- **How to Fix:** Drive ticket `20260818065258`: resolve the base as `origin/main` and report an
  unresolvable base by name rather than as `already_bumped`.

## 6. Successful Development Patterns

- Auditing a call site and changing nothing is a result worth reporting: two statements of one
  rule eventually disagree, so "defers correctly" is the outcome the acceptance criterion wanted.
- Reading the version files directly rather than trusting the predicate caught a false
  `already_bumped` that would have shipped plugin changes on a stale version.
