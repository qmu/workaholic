## 1. Overview

`check-version-bump.sh` answered "has this branch already bumped?" from a local `main` nothing
keeps current, and matched "Bump version" anywhere in a message. Both errors point one way — the
false `true` that skips the bump. It now measures against the resolved base, matches on the
subject, and says which base it used.

**Highlights:**

1. The base comes from the one resolver every other base-reading script uses (`base-ref.sh`).
2. An unresolvable base is a named degraded read answering `false`, never `true`.
3. A commit body discussing a bump is not a bump.

## 2. Motivation

A claim worktree is cut from `origin/main` and nothing in the unified run moves local `main`; in
a cloud container it is whatever the image was baked with. `git log main..HEAD` swept up every
`Bump version to vX` landed on the base since, so a branch carrying no bump was told it had
bumped — measured 2026-08-18 in worktree `batch-20260818063646`, local `main` at `6e0cb9e9`
against `origin/main` at `a871103d`. The failure is one-directional and silent: a stale base can
only produce the answer that *skips* the bump, and nothing afterwards says so.

## 3. Changes

### 3-1. check-version-bump reads a stale local main ([2b093dc1](https://github.com/qmu/workaholic/commit/2b093dc1))

The base is resolved through `gather/scripts/base-ref.sh` — `origin/<default>` as last fetched —
and reported in a new `base` field; an explicit argument still wins. An unresolvable base is
`ok: false` with the reason named and `already_bumped: false`, so the caller bumps.
`report/SKILL.md` Phase 0 states that contract.

### 3-2. Match the bump predicate on the subject ([a6d4dd9c](https://github.com/qmu/workaholic/commit/a6d4dd9c))

Matching moved to the subject, which CLAUDE.md fixes as `Bump version to v{new_version}`. Found
by running the fixed predicate on this branch, where it still answered `true` — the base fix
alone would have shipped with its own acceptance criterion unmet.

## 4. Outcome

The predicate answers from the base the pull request is diffed against, names it, and degrades
toward the cheap wrong answer rather than the silent one. It reads and never fetches — freshness
stays the caller's act, made inspectable by the `base` field.

## 5. Concerns

### Past unbumped merges are measured but not remediated

- **Severity:** low
- **Description:** 21 of the last 29 plugin-touching merged units carry no `Bump version` commit; consistent with the blast radius but not proof, since not every such merge runs `/report` Phase 0 (see [2b093dc1](https://github.com/qmu/workaholic/commit/2b093dc1) in `plugins/workaholic/skills/branching/scripts/check-version-bump.sh`)
- **How to Fix:** Nothing mechanical — recovering skipped patch bumps after the fact has no meaning. Whether the gap matters for published releases is the operator's call.

## 6. Successful Development Patterns

- Running the fixed predicate on its own branch caught the second defect — a workflow script's
  first real fixture is the branch that changes it.
- Pointing a degraded state at the cheap wrong answer beat making it right in every state.
