## 1. Overview

The `/housekeep` tick log's `<step>-filed` lines — the record of what a tick actually filed — could never reach the base, so the dedup memory those lines exist to feed was permanently empty in every routine-fired container. The persist now unions by `(tick, step)` instead of by section, and the agent persists once more after recording what it filed.

**Highlights:**

1. A hermetic regression asserts against the *base*, not the checkout — the only place the defect was ever visible.
2. Two containers sharing one tick section now both land, entry by entry, with no rebase and nothing overwritten.
3. The one open fork was resolved in the script's own header, answering the two rejected alternatives rather than dropping them.

## 2. Motivation

`run.sh` runs `persist-log.sh` as its closing act, but the agent acts on `needs_agent` only *after* `run.sh` returns — so every `<step>-filed` line was appended to the checkout after the persist had already landed the section. A second persist could not carry them either: a union by section asks only whether the base has `## <tick-id>`, it does, and the script reported `already_current` and was correct by its own rule while the lines died with the container. Measured on tick `20260818-063819`, and invisible to a hand-run, whose checkout survives.

The cost was three dedups the design leans on: `doc-drift` re-reporting the same file every hour forever, `inbound-sweep` unable to skip what an earlier tick filed, and the check-in's asked-once gate. An hourly unattended process was left with an audit trail missing exactly the half that says what it *did*.

## 3. Changes

### 3-1. Carry the tick log step-filed lines to the base ([c159a2ae](https://github.com/qmu/workaholic/commit/c159a2ae))

The union in `persist-log.sh` became line-wise: a section the base lacks is still appended whole, and a section it already carries gains only the steps its copy lacks, in the checkout's order, at the end of that section. A `(tick, step)` already on the base is never rewritten, which keeps the log append-only in substance and keeps two containers from clobbering each other. The skill's contract gained the second, idempotent persist that makes the line-wise union reachable at all.

## 4. Outcome

A `<step>-filed` line written after `run.sh` returns now reaches the base within the same tick, proved by an assertion that failed before the change. The concurrency property is stronger than before, not merely preserved: sections *and* entries within a shared section both survive. The caller's checkout stays byte-identical, no `work-*` branch is created and no `publish-main` ref reaches origin.

## 5. Concerns

### The second persist is a prose contract, not a code path

- **Severity:** moderate
- **Description:** The line-wise union only carries late lines if something runs the persist again, and that second run lives in `SKILL.md`'s prose rather than in `run.sh` (see [c159a2ae](https://github.com/qmu/workaholic/commit/c159a2ae) in `plugins/workaholic/skills/housekeep/SKILL.md`). An agent that files its lines and stops still loses them, and nothing mechanical notices.
- **How to Fix:** Give the drill a case that runs a tick, appends a `<step>-filed` line and asserts it on the base — turning the prose step into something `verify-housekeep` can fail on.

### `verify-housekeep` cannot reach the late-line path

- **Severity:** low
- **Description:** The drill runs the tick against a throwaway root outside a repository, where the persist correctly skips as `not_a_repo` (see [c159a2ae](https://github.com/qmu/workaholic/commit/c159a2ae) in `scripts/e2e/loop-drill.sh`). Its 5/5 pass therefore proves the tick is write-free, never that anything reached a base.
- **How to Fix:** Seed a throwaway origin inside the drill for a persist-only stage, keeping the operator's own checkout untouched as today.

## 6. Successful Development Patterns

- Reproducing against the *base* rather than the checkout is what made the defect visible at all — a hand-run's surviving checkout is precisely what hid it, so the regression models the discard instead of the run.
- Recording why the two rejected forks were rejected, in the script's own header beside the existing concurrency rationale, keeps the next reader from re-litigating a decision whose reasoning would otherwise live only in a merged pull request.
