## 1. Overview

The web bootstrap now stamps the developer's own name on the git identity it provisions, so a routine's commits stop rendering on GitHub as authored by Claude. The line that was meant to do this had shipped dead since 2026-08-07: its guard read git's effective scope, which in a container is the global `Claude` and never empty, so it never once executed.

**Highlights:**

1. The `user.name` guard reads `git config --local user.name`, on the same seam and under the same conditions as the email.
2. The value prefers the account's real name (`gh api user --jq .name`) and falls back to the GitHub login.
3. Four hermetic fixtures pin it, including the exact container shape the old code fails.

## 2. Motivation

Issue #453 added the `Claude-Session:` trailer and recorded that the person behind a routine commit "was always attributable" through the author email, which the bootstrap sets repo-locally from `.claude/git-identities`. The reporter's follow-up is that attributability in the commit object is not what a reader sees: GitHub renders the author **name**, and that name was `Claude` for every commit the fleet produced. Nothing in the earlier decision argued the name should stay — it simply was never changed.

The cause turned out to be one word. Step 0b of `bootstrap/session-start.sh` already carried a `user.name` line beside its working `user.email` line, guarded by `[ -z "$(git config user.name)" ]`. `git config <key>` reads the effective value across system, global and local scopes, and a web container's global scope is `Claude` — so the guard read "the developer already chose a name" on every session and skipped the write, while `git config <key> <value>` had been writing repo-locally all along. The read crossed scopes; the write never did.

## 3. Changes

### 3-1. Stamp the developer's name on commits, not Claude ([212458aa](https://github.com/qmu/workaholic/commit/212458aa))

The guard now tests `git config --local user.name`, so a container's global default no longer masks an unset local name while a developer's own repo-local choice is still never overwritten. The name is resolved from `gh api user --jq .name` where the login is already in hand, falling back to the login when the account publishes none — `--jq` prints the literal `null` for that case, which the fallback names explicitly. This repository's applied copy at `.claude/hooks/session-start.sh` was refreshed from the canonical source in the same commit, and the version was bumped to v1.0.187 ([9df5a154](https://github.com/qmu/workaholic/commit/9df5a154)) so a consuming repository's version-gated `/workaholify` refresh picks the hook up.

## 4. Outcome

A session starting after this change ends with a repo-local `user.name` naming the developer and the mapping's email untouched, so commits read `<developer> <a@qmu.jp>` where they read `Claude <a@qmu.jp>` before. The repair is forward-only and cosmetic to every mechanism: ownership, claims and resumption all key on `user.email`, which did not move.

## 5. Concerns

### The identity step is gated on the email, so a set email skips the name repair

- **Severity:** low
- **Description:** Step 0b runs only when the effective `user.email` is empty or an `@anthropic.com` default, so a checkout that already carries a repo-local email skips the whole block, name included (see [212458aa](https://github.com/qmu/workaholic/commit/212458aa) in `plugins/workaholic/skills/workaholify/bootstrap/session-start.sh`). It costs nothing in the cloud, where each tick is a fresh container whose email is still the container default when the hook fires.
- **How to Fix:** Only if a real case appears: admit "email already correct, repo-local name unset" as a second entry condition, accepting that the block then runs on every session of a correctly-configured repository.

### The fix cannot be observed until the next session starts

- **Severity:** low
- **Description:** The hook fires at session start, so the container that made this change keeps the name it started with; the first commit rendering the developer's name comes from the next routine tick (see [212458aa](https://github.com/qmu/workaholic/commit/212458aa) in `.claude/hooks/session-start.sh`).
- **How to Fix:** Read `git log -1 --format='%an <%ae>'` on a commit from the next `[Implement]` or `[Propose]` tick; a name still reading `Claude` there means the applied hook copy is stale, not that the guard is wrong.

## 6. Successful Development Patterns

- Running the pre-change and post-change hook head-to-head against a scripted container shape (global `Claude`, local unset) proved the fixture is meaningful — a green suite alone cannot show that a new test would have failed before.

## 7. Notes

Existing history is not rewritten: every commit already on `main` keeps `Claude` as its author name.
