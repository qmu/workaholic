## 1. Overview

The routine tooling never carried a completion-notification field, so the loop created
recurring routines and left that setting to the server's default while every one of them
reports through Slack by design. Five templates, three renderers and both setup commands
now carry it.

**Highlights:**

1. `notifications: none` on all five templates, converged on existing routines too.
2. Confirmed by reading the record back — the API silently drops unknown fields.
3. The five routines were **not** shown to be the source of the reported notifications.

## 2. Motivation

Issue #514 asked for the cause of the app's push/email notifications to be found and
prevented. Two things were conflated in it, and the split matters more than either half.

The cause was traced to persistent-session-bound check-ins, a class whose whole parameter set
carries no notification field — so this is a real gap closed and **not** the fix for the
reported symptom. What was missing here: no template declared the field.

## 3. Changes

### 3-1. Turn off routine completion notifications ([a824c899](https://github.com/qmu/workaholic/commit/a824c899))

The field is declared once per template and carried by the same renderer the setup sheet and
the convergence both read, so a hand-configured routine cannot silently differ from a
converged one. Its API-side key and vocabulary are stated as unverified everywhere they
appear, and the convergence confirms by read-back rather than by a 200.

## 4. Outcome

A routine created by this loop now states what it wants from the app instead of inheriting a
default nobody chose, and a refused value is reported by name. What remains is a platform
surface outside this repository, named in the Handoff.

## 5. Concerns

### The declared value is unverified against the API

- **Severity:** moderate
- **Description:** No session reachable from here carries a `RemoteTrigger`-family tool, so neither the accepted field set nor the server's default could be read, and the API silently drops unknown fields (see [a824c899](https://github.com/qmu/workaholic/commit/a824c899) in `plugins/workaholic/skills/workaholify/reference/routines.md`)
- **How to Fix:** Read a record back after the first convergence from an account that has the tool; if `notifications` did not stick, the field name is wrong and the templates should carry whatever the record does.

### The reported symptom may survive this change

- **Severity:** moderate
- **Description:** The notifications the developer received came from a different mechanism, so closing this gap need not stop them (see [a824c899](https://github.com/qmu/workaholic/commit/a824c899) in `plugins/workaholic/skills/workaholify/reference/routines.md`)
- **How to Fix:** The platform half needs a human's crossing; it is named in the Handoff so it is not addressed by nobody.
