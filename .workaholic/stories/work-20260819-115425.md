## 1. Overview

`.workaholic/stories/` is now a generated OKF flat area like every other one. A story's index entry comes from its own `description:` frontmatter; `/report` writes that field instead of inserting a bullet; and the existing index opted into generation by gaining the `okf:generated` markers.

**Highlights:**

1. The stories index has a **repairer** for the first time — regenerating it recovered 22 stories that had been written to disk but never added to the index.
2. Two narrow, named per-area knobs (`order`, `skip`) instead of a special case inside `build_region`.
3. The README exclusion is **per-area**, not global — the ticket said global was safe, and it was not.

## 2. Motivation

`refresh-index.sh` deliberately excluded `stories/index.md`, and the exclusion was well-founded when written: a story's description existed nowhere but the index itself, so the generic derivation had nothing to read and `/report` composed the bullet by hand.

The cost was that the stories index was the one ledger index with **no generator**. Nothing repaired it after a merge disturbed it; nothing detected a run that wrote its story file and never added the bullet; and ordering degraded monotonically because every run inserted at the top and nothing normalized afterwards. This matters more since consumers mark the ledger indexes `merge=union` in `.gitattributes` — union never reports a conflict, so correctness rests on regeneration, which stories alone could not use.

The defect was not hypothetical. Generating the area for the first time took the index from **189 entries to 211**: 22 stories existed on disk with no index entry at all.

## 3. Changes

### 3-1. Generate the stories index like every area ([03cbf262](https://github.com/qmu/workaholic/commit/03cbf262))

`stories` joins the flat-area loop. `build_region` gains two per-area knobs — `order` (`asc` default, `desc` for stories, so the index still reads newest-first) and `skip` (an extra basename to omit, `README.md` for stories) — each named by the caller rather than branching on the area inside the function. The story frontmatter schema gains `description:`; `report/reference/story-structure.md` and `orchestration.md` now forbid editing the index by hand and explain why a stray bullet is actively harmful rather than merely redundant. `okf/SKILL.md` records why the exclusion existed and what changed about its premise, and its stale flat-area enumeration (which still listed the retired `specs`) is corrected in the same commit.

The first regeneration also repaired a pre-existing drift in the bundle root index, where the `housekeeping/` line still called the tick `/housekeep`.

## 4. Outcome

Adding a story file and running `refresh-index.sh` produces its entry with no `/report` run involved; running it twice leaves the tree byte-identical; a disturbed index is repaired by regenerating it. Every one of the 189 existing hand-written descriptions survived the first regeneration through the prior-region fallback — measured, not assumed: 0 lost, 0 links dropped. The 22 recovered stories come through as bare links, the documented fallback, and gain descriptions as anyone touches them.

## 5. Concerns

### Regenerating changed 25 entry titles

- **Severity:** low
- **Description:** `title_of` resolves frontmatter `title`, then the first H1, then the basename. 24 stories carry a meaningful H1 and now show it as their entry title; the remaining 186 show `work-<timestamp>` without the `.md` suffix the hand-written index used. Link targets are unchanged, so nothing resolves differently (see [03cbf262](https://github.com/qmu/workaholic/commit/03cbf262) in `plugins/workaholic/skills/okf/scripts/refresh-index.sh`).
- **How to Fix:** Left as the generic behaviour deliberately — a third stories-only knob for a purely cosmetic property would undercut the reason stories were made a normal area. If uniformity is wanted, give stories a `title:` field rather than a knob.

### Descending filename order is not full chronology

- **Severity:** low
- **Description:** Newest-first holds for the `work-YYYYMMDD-HHMMSS` shape. The area also holds legacy names (`drive-*`, `feat-*`, `claude-lucid-tesla-4yz3ob.md`), which sort by prefix rather than date.
- **How to Fix:** Nothing to fix — determinism plus newest-first for current stories is the property that matters. Stated so it is not read as a full chronological guarantee.

## 6. Successful Development Patterns

- The ticket's step 1 demanded two facts be confirmed before any edit, and both held — but checking the *third*, unlisted assumption (step 3's "no area indexes a README") is what prevented a silent regression: `deployments/`, `release-notes/` and `terms/` each carry a README entry inside their markers. A step that says "confirm before changing" is worth extending to the neighbouring claims in the same step.
- Verifying the migration numerically rather than by eye — parsing both index versions and diffing the link→description maps — turned "descriptions survive" from a hope into 0-lost, and surfaced the 22 missing stories as a by-product.
- Resolving the field-name fork toward the key the generic reader already uses kept the change to two knobs; picking the ask's preferred word would have added a stories-only branch to `entry_line` for a synonym.

## 8. Notes

`refresh-index.sh` stages what it writes, so `git diff` looks empty after a run — the diff is in `git diff --cached`. Both the idempotence check and the description-survival check were run against the staged content for that reason.
