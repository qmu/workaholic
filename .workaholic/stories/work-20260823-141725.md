# Tell an unanswered question from an answered one

## Motivation

`ask-question.sh` read exactly one fact — was this key asked before — and refused a second ask.
That is what it was fixed to do and it must keep doing it. What it could not express is the
difference between **asked and settled** and **asked and still blocking**: a question whose blocker
cleared itself and one that has held a unit for a week were the same state at the gate.

Measured: a question saying the loop could not start went unanswered for **twenty hours across
twenty ticks**, every tick reporting itself healthy, with no surface anywhere carrying its age.

## Outcome

**The reading.** `question-liveness.sh` answers `live` / `settled` / `unknown`, re-derived from the
tick's own run report — the owning step ran this tick, so its `needs_agent` *is* the set of subjects
still live. No stored state, no field added to the append-only log, and **no repository scan**,
which the Considerations named as the thing that turns an hourly tick into a scan. The owning step
is an argument rather than a guess from the key's prefix, because a wrong guess would answer
`settled` about a subject nobody looked at.

**The asking.** A still-`live` question first asked on an earlier day is re-asked **once**, at the
next working day, then never — logged under its own step id so a third is impossible by
construction. It is the same `🙋 <@U…>` reply, with its age in the question's own sentence.

## Journey

**The Open Decision was a real fork and is ruled in writing.** (b) — a standing
`N questions outstanding, oldest <age>` line on the root — is refused because the one property both
retired status roots lacked is being **addressed to a person**; a count addressed to nobody
reproduces exactly that lack, and an age does not change who it reaches. (a) is taken with the
smallest interval that answers the measurement. Ticket `20260819061902` removed *unbounded*
re-asking and that removal stands: this is one extra ask, ever, and the boundary is the working day
the quiet-hours gate already owns, so no constant is invented.

**Two defects were caught by exercising the code, not by reading it.** The day was read from the
wall clock, so a tick dated yesterday re-asked itself on its own first run — it now comes from the
tick id, putting both sides on one axis. And the re-ask was decided *before* the hold gates, because
`already_asked` returns ahead of the off-day and quiet-hours checks: it would have posted at 03:00
on a Sunday, the exact failure `WORKAHOLIC_WORK_DAYS` exists to prevent.

## Concerns

**`unknown` is the answer that must never drift.** A step that degraded, was never reached, or is
absent from the run cannot report its finding, and every one of those answers `unknown` with its
reason named. If a later change lets any of them read as `settled`, this mission is undone — the
silence it removed comes straight back, and quietly.

**One re-ask is a floor, not a proof of sufficiency.** If a question survives its single re-ask the
loop is again carrying an open blocker with nothing to say about it. That is deliberate for now —
the alternative measured worse — but it is the edge to watch.

**The liveness reading only covers subjects a step still produces.** A question raised by a step
that has since been retired or renamed reads `unknown` forever, which is honest but never resolves.

## Successful Development Patterns

- **Ship the reading inert, then spend it.** The first ticket changed no observable behaviour,
  which made the three-valued answer provable before anything depended on it.
- **Refuse the shape that repeats a retired mistake, and say which mistake.** "A line addressed to
  nobody" had already been retired twice; naming that is what made the fork decidable.
- **Exercise a gate across the boundary it claims to respect.** Reading the code would not have
  shown that `already_asked` returns before the quiet-hours check.
