# Give the tick a route for the records it writes

## Motivation

`/moderate`'s inbound sweep and issue triage hand candidates back, the agent applies the
materiality bar and writes a feedback record through `create.sh` — which **stages the file and
stops**. A routine's container is then discarded, so the record never reached the base.

Three shipped rules made it unsatisfiable: the tick "writes nothing else anywhere" but its log,
`create.sh` ends at a staged file, and `guard-git-branch.sh` permits only `work-*` and `release/*`,
so the one writer that could publish a record creates exactly the branch shape the tick may not
create.

And the loss compounded. On the measured tick `persist-log.sh` reported both records `filed` and
`persisted` and the 17-line log reached the base — while the base carried the log section and **not
one record**. Every mechanism reported success. The next tick read `inbound-sweep-filed` and
`issue-triage-filed` out of the log, concluded both findings were captured, and did not re-derive
them: the finding was neither published nor recoverable, and the dedup actively prevented a second
chance at it.

## Outcome

**A route, in one argument.** `persist-log.sh --record <path>` carries the tick's own records on the
log's own commit — no `work-*` branch, no claim, no pull request, no merge, exactly how the log has
travelled since 2026-08-17. Records are named one by one, never swept: a staged `unrelated.txt` does
not reach the base. A record already there is left untouched, because a feedback record is
immutable, so concurrent ticks land and nothing is rewritten. Each is reported `carried` /
`already_on_base` / `missing` / `unreadable`.

**A claim is no longer a fact.** `filed-records.sh` takes the paths a `<step>-filed` line names and
asks the tree: `landed` may be deduped, **`unlanded` reads as not filed** so the next tick re-derives
the finding.

## Journey

**The tree is the oracle because it works on lines that already exist.** Making the `-filed` line
truthful at write time was the obvious fix and would have repaired only the future — the log is
append-only and the lines already on the base cannot be corrected. Asking the tree needs no network
call, no second store, and reads a container's fresh clone as what it is: a copy of the base.

**One defect was caught by exercising the reader rather than reading it.** The first implementation
answered `readable: true` with empty sets for a root that does not exist — the identical conflation
of *could not look* with *nothing there* that the ticket exists to end, one level up.

**The cheaper alternative was refused in writing, not silently.** The report named it — stop writing
records on a tick and route findings into the check-in — and it drops the inbound-sweep half of the
feedback stream. The primary route turned out to be reachable in one argument, so it was never
needed.

## Concerns

**The writer's half of the contract is prose.** A `<step>-filed` summary must name the
repo-relative path of each artifact it filed; a line naming none proves nothing and is not honoured.
That is the safe direction — an uncheckable claim is ignored rather than trusted — but it means a
composer who omits the path silently loses the dedup rather than being told.

**Paths are extracted from the summary, not parsed at a position.** A summary is prose a human also
reads, and pinning a column in it is exactly the free-text dependency the already-asked gate was
fixed off. The cost is that the extraction is heuristic: it takes anything shaped like a
`.workaholic/**.md` path.

**Widening the persist seam widens what an unattended tick can put on the base.** It is bounded by
naming — the caller lists the records — and the test pins that an unrelated staged file does not
ride. That pin is the guard; if a future caller ever passes a glob, the bound is gone.

## Successful Development Patterns

- **Widen the seam that already exists rather than adding one.** The route was one repeatable
  argument on a script whose reasoning already covered why a direct commit is owed no approval.
- **Pick the fix that repairs the past, not only the future.** Both halves were defensible; only one
  could do anything about the lines already on the base.
- **Exercise the degradation, not just the happy path.** `readable: true` on a missing root looked
  right in the code and was the very bug under repair.
