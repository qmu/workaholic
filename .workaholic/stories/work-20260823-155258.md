# Tell describing work from advancing work

## Motivation

The sibling tickets stopped a describing proposal being *made*. This one stops describing work
already in flight from **blocking** the proposal that would have built something.

`attributed-work.sh` attributes work through `strategy.feedback[] ∩ artifact.feedback[]`, and a
page *about* the work cites the same ref the work would — so the two are indistinguishable by
construction. `survey-strategies.sh` then read `waiting_count > 0` as `work_waiting` and proposed
nothing further until the queue drained.

That is what made the measured loop self-sustaining: each documentation mission queued
documentation tickets, which kept `work_waiting` true, which prevented any proposal that might have
been the build; when they merged, the gate lifted and the next documenting move was named.

## Outcome

`strategy/scripts/work-kind.sh` reads each queued ticket's own `## Key Files` — every path under a
documentation area is `describing`, any path outside them is `advancing`, no section or no path is
`unknown`. `attributed-work.sh` reports `waiting_kind` / `waiting_describing` / `waiting_advancing`
beside `waiting_count`, and the survey's gate reads the advancing count when the caller says the Aim
is to build.

**`unknown` counts toward advancing.** Mislabelling build work as descriptive lets parallel
proposals accumulate — the failure the gate exists to prevent — while the opposite error delays one
proposal by a tick.

**The Aim stays a judgment where it is already made.** No script can read an Aim and say whether it
is to build or to document; `/propose` makes that call for `describing_move` and now passes the
answer in (`--aim-kind`). Absent the flag the gate is byte-for-byte what it was.

## Journey

The Open Decision offered three shapes and the reasoning turned on the **residue**, exactly as the
Considerations asked. Carrying the proposal's `move` forward is the tidier data model and can label
only work the loop itself produced — and on the same day, on a consuming repository, seven
documentation asks entered the queue as hand-filed issues carrying no marker at all. A mechanism
that cannot see those is not a mechanism for this problem. Dropping the gate outright removes the
brake it was added to be.

Deriving from paths is a heuristic, and its inversion — a repository whose product *is*
documentation — is not a new problem: it is the same inversion the sibling already exempts **by
Aim**, and the exemption covers this because the distinction is consulted only for a building aim.
Stating that was a condition of ruling (b), and it is what makes (b) a narrowing of an existing rule
rather than a second one.

## Concerns

**It is a heuristic and will misread something.** A build ticket whose Key Files list only a
configuration file under `docs/` reads as describing; a documentation ticket that touches one script
reads as advancing. The bias is deliberate — one product path is enough to call it a build — so the
errors fall on the side of keeping the brake on.

**The Key Files section is prose.** The classifier extracts backticked paths from it, so a ticket
that names its files in a sentence instead of a list reads as `unknown` — which gates, so it fails
safe, but it also means the distinction quietly stops working for a writer who formats differently.

**`--aim-kind` is a caller's assertion, not a checked fact.** A run that passes `building` for a
documentation strategy lifts that strategy's brake. Nothing here can catch that; the judgment and
its consequence sit in the same place, which is the best available arrangement but not a guarantee.

## Successful Development Patterns

- **Choose the mechanism against the residue, not the backlog.** The tidier option handled every
  case the loop generates and none of the ones a person files.
- **When a heuristic has a known inversion, check whether an existing rule already exempts it.**
  It did, and that turned a new rule into a narrowing of one.
- **Leave a judgment where it is already made and pass its answer in.** A second place guessing the
  Aim would have been a second thing to keep true.
