## 1. Overview

`queue_drained` answered two questions with one word, and one answer stranded real work.
The claim scan now consults the story file it already computes: a drained unit that
**reported** stays untouchable, one that **died before reporting** is offered as
`report_incomplete`.

**Highlights:**

1. A third resumable tier, `report_incomplete`: drained queue, no story at the tip, no pull request — a dead run's remains, mandatory to take over and forbidding `ok` when left.
2. The 2026-08-01 drained gate is narrowed, not reversed: a unit with a story at its tip keeps `queue_drained` and `claim.sh resume` still refuses it.
3. `claim.sh resume` was reading the claim row's artifact list one column short of where it moved on 2026-08-23, and reported `true`/`false` as a unit's files.

## 2. Motivation

The 2026-08-01 fix told a run that died from a unit that finished by asking whether
anything was left to drive — correct as far as it goes, and it folded a third state in
with the first. A run that archived its last ticket, pushed, and then died before writing
its story reports a drained queue too, so it was equally untouchable *and* its tickets
were excluded `claimed_reported` at every later survey — reached by no path, `/moderate`
included: its relevant steps read pull requests, and this branch has none.

Measured 2026-08-19: unit `batch-20260819063000`, two tickets pushed at 06:48 UTC with no
story and no pull request, and four `[Implement]` ticks that each surveyed a clean,
current checkout and drove nothing while that work sat undelivered.

## 3. Changes

### 3-1. Tell a dead unit from a reported one ([cf94aeed](https://github.com/qmu/workaholic/commit/cf94aeed))

The drained arm of `claims_scan` splits on `claims_has_story`: present keeps
`queue_drained` / `resumable: false`, absent reports `report_incomplete` /
`resumable: true`. `_cs_reported` moved above the verdict block — already computed on
every row, now an input rather than a fact beside one — so one call answers both forks
and no git call was added. The takeover re-drives nothing and enters at §5.

## 4. Outcome

`batch-20260819063000` now reads `report_incomplete` and is offered; every unit with a
story at its tip keeps `queue_drained`, and `parked_with_pr` is untouched. `claim.sh` and
`plan-units.sh` needed no new branch — the refusal ladder runs only when
`resumable != true`, and the exclusion classification keys on `resumable` first.

## 5. Concerns

### Two claim tests were asserting the protected case through the wrong fixture

- **Severity:** low
- **Description:** `testResumeSkipsDrainedUnit` and `testClaimSurvivesUndetectedRename` reached `queue_drained` by archiving every ticket and never writing a story, so their fixtures were the *unprotected* state all along and only this split could expose it (see [cf94aeed](https://github.com/qmu/workaholic/commit/cf94aeed) in `scripts/test-workflow-scripts.mjs`)
- **How to Fix:** Both now commit a branch story before asserting; when a verdict gains a new input, re-read every fixture that reaches that verdict rather than only the ones that fail.

### A fixed `cut -f<N>` index does not benefit from the row's last-field rule

- **Severity:** moderate
- **Description:** `claim.sh resume` read the claim row's artifact list at `cut -f8`, which has been the `reported` column since it was inserted on 2026-08-23, so every takeover reported `artifacts: ["true"]` or `["false"]` (see [cf94aeed](https://github.com/qmu/workaholic/commit/cf94aeed) in `plugins/workaholic/skills/drive/scripts/claim.sh`). The header's defence of the artifact list's position protects the three consumers that read named fields with `while IFS= read -r`; it does nothing for the one fixed-index reader.
- **How to Fix:** Fixed to `-f9` and asserted here. A column added to a TSV whose readers are mixed-style needs every fixed-index reader audited in the same change — a check worth adding to the shared reader's header.

## 6. Successful Development Patterns

- Reproducing against the *real* stranded unit as well as the fixture caught nothing extra but made the Gate checkable from outside: `batch-20260819063000` flipping `queue_drained` → `report_incomplete` is evidence a reviewer can re-run in one command.
- Reading the verdict's existing fork before writing a new one: the signal this ticket needed was already computed one branch below, so the change is a hoist and a nested `if` rather than a second derivation the protocol would then have two answers to.
