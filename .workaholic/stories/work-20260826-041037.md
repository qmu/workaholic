## 1. Overview

A claim is in flight iff its branch carries commits not on the base — the right question
for outstanding work and the wrong one for a branch whose *content* landed by another
route. Such a claim now reports **`superseded`** and is excluded rather than offered.

**Highlights:**

1. The signal is *every one of the unit's tickets archived on the base*, under any branch directory — matched by filename, one `git ls-tree`, offline.
2. Diff-containment was refused by the reproduction: the measured recovery landed **refined**, not verbatim, so containment would have answered `false` on the branch that provoked the rule.
3. Reported, never acted on — nothing deletes a branch, closes a pull request or releases a claim, and it does not forbid `ok`.

## 2. Motivation

The gap was harmless while `queue_drained` made every drained claim untouchable. It stopped
being harmless the moment `report_incomplete` shipped in the same run: a drained, unreported
claim became a **mandatory** takeover, so the first run to hold that tier resumed
`batch-20260819063000` exactly as designed — five days after the unit had been recovered by
hand onto `work-20260821-221006` — and spent a full story-and-pull-request cycle producing a
pull request whose only correct outcome was to be closed. Ten merge conflicts, three of them
`modify/delete` against a directory the base had deleted in a rename.

That run finished the tier honestly, which is what a run should do when it cannot tell the
two apart. This lets the reader tell them apart instead.

## 3. Changes

### 3-1. Tell a superseded claim from a live one ([fe9a9252](https://github.com/qmu/workaholic/commit/fe9a9252))

`claims_superseded` reads whether every one of the unit's tickets is archived on the base;
the verdict sits after `claim_active` — liveness is what gates a takeover — and before the
drained fork, whose two answers would both be wrong here. `plan-units.sh` gains
`claimed_superseded`. `claim.sh` needed no arm: its refusal ladder runs only when
`resumable != true`.

## 4. Outcome

`batch-20260819063000` now reads `superseded`; the three mission claims keep `queue_drained`
and `parked_with_pr`, and the live claims keep theirs. The verdict answers for **batch**
units and leaves mission units on today's reading, stated in the script header, the
reference and the runbook rather than left to be discovered.

## 5. Concerns

### A resume attempt on a superseded claim refuses through the wrong arm

- **Severity:** low
- **Description:** `claim.sh resume`'s refusal ladder only runs when `resumable != true` and has no case for the new reason, so a hand-typed resume falls through to the `identity_unresolved` default and is refused with a message about a missing `git config user.email` (see [fe9a9252](https://github.com/qmu/workaholic/commit/fe9a9252) in `plugins/workaholic/skills/drive/scripts/claim.sh`). The refusal is correct; its stated reason is not.
- **How to Fix:** Add a `superseded)` case beside `queue_drained)` naming the real reason. It was left out here because the ticket scoped the change to the reading and nothing offers a superseded unit, so only a hand-typed command reaches it.

### The exclusion row is invisible on a real recovery

- **Severity:** low
- **Description:** `excluded[]` is keyed by artifact for a batch unit, and the artifacts are base-side `todo/` paths — which a genuine move-based recovery removes. So `claimed_superseded` appears only when the recovery *copied*; otherwise the claim row's own verdict is the sole surface (see [fe9a9252](https://github.com/qmu/workaholic/commit/fe9a9252) in `plugins/workaholic/skills/drive/scripts/plan-units.sh`).
- **How to Fix:** Nothing here is wrong — the survey correctly reports only what it saw and dropped. The test says so in a comment so a later reader finding no row does not read it as the classification failing.

## 6. Successful Development Patterns

- Walking the whole verdict ladder on **one** claim, moving one input at a time, is what proves a new rung did not make the rung below unreachable — asserting only the new verdict would have proved nothing about the four beside it.
- Letting the reproduction pick between two candidate signals: the fixture writes the recovered tickets with deliberately *different* content, which is what ruled out diff-containment on evidence rather than on taste.
