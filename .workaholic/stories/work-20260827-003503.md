# Let a fresh claim take a superseded claim's work

## 1. Overview

`claim.sh`'s refusal loop read each claim's verdict and threw it away, so a unit the survey
re-offered behind a `superseded` claim was reachable by neither claim path. It now skips a
superseded row.

**Highlights:**

1. The reading comes from `lib/claims.sh`, never re-derived, so the offer and the refusal
   cannot disagree again.
2. `superseded` stays reported-never-acted-on: no branch deleted, no pull request closed.
3. Only a claim already **proved** to hold nothing is claimable over.

## 2. Motivation

The 2026-08-26 `superseded` change shipped half its own intent. `plan-units.sh` learned to
resurvey the work behind such a claim, and `workaholic:drive` §1 says *a fresh claim drives
them, because the old branch cannot land* — but `claim.sh` answered `already_claimed`, and
`resume` refused the same unit as `superseded`, by design.

Found mid-drive by an `/implement` run and reproduced here: mission
`make-workaholify-converge-the-account-s-routines` was offered and named in `resurveyed[]`
while its only holder had read `superseded` since the day before. That is worse than a unit
nothing offers, because it forbids `ok` on every later tick — the shape `report_incomplete`
was added to remove one layer up.

## 3. Changes

### 3-1. Let a fresh claim take a superseded claim's work ([a9b253c2](https://github.com/qmu/workaholic/commit/a9b253c2))

The refusal loop skips a row whose verdict is `superseded`, before both the unit-id check and
the artifact-overlap check. The verdict comes from the same `lib/claims.sh` derivation the
survey reads, so no second reading exists to drift.

## 4. Outcome

Work behind a claim proved to hold nothing is claimable again, on a fresh branch beside the
old one. The mission that surfaced this is drivable on the next survey.

## 5. Concerns

### An accidental claim was left standing during verification

- **Severity:** moderate
- **Description:** the fix was first checked against the live repository, which created a real claim — `work-20260827-003544` on `make-workaholify-converge-the-account-s-routines` — and `release-claim.sh` resolved the unit to the older branch instead, so it outlived the check (see [a9b253c2](https://github.com/qmu/workaholic/commit/a9b253c2) in `plugins/workaholic/skills/drive/scripts/claim.sh`)
- **How to Fix:** the claim is this runner's own and active, so the next survey offers it for takeover and the mission can be driven on it. Separately, `release-claim.sh` resolving a unit held by two branches to the older one is worth a look.

### This session cannot delete a remote branch

- **Severity:** low
- **Description:** `git push origin --delete` answers *the remote end hung up unexpectedly*, so merged claim branches and the accidental one above stay on the remote (see [a9b253c2](https://github.com/qmu/workaholic/commit/a9b253c2))
- **How to Fix:** harmless for the claim oracle — a merged branch is not ahead of the base and drops out of the claim set — but an operator or a session with delete rights should sweep them.

## 6. Successful Development Patterns

- Reproducing a two-reader disagreement by running both readers and quoting both outputs made the fix a three-line skip rather than a redesign.
