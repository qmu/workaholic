## 1. Overview

The `superseded` verdict let one PR-unit be held by two claim branches — a dead one and the live
one a later run took its work on. Every writer resolved a unit by taking the first row out of
`claims_scan`, which walks refs in name order, so first-match was always the dead branch.

**Highlights:**

1. `resume` and `release-claim.sh` reach the live branch; one claim stays byte-identical.
2. Two live claims are refused by name (`ambiguous_claim`), never picked between.
3. `ensure-worktree.sh` refuses a name that exists on origin instead of shadowing it.

## 2. Motivation

Reproduced at 2026-08-27T00:55Z on `make-workaholify-converge-the-account-s-routines`, held by
`work-20260819-113836` (`superseded`) and `work-20260827-003544` (`claim_active`): `resume`
refused on the dead branch's verdict so the live claim was resumable by nothing;
`release-claim.sh` tore the dead branch down, reported `half_released`, and left the live claim
standing; `ensure-worktree.sh` minted a local branch at the base tip shadowing a remote branch
carrying live work, where the next push would have clobbered it. The shape is new — until a
fresh claim could be taken over a superseded one, a unit had one branch and first-match was right.

## 3. Changes

### 3-1. Resolve a unit to its live claim branch ([6c2030cb](https://github.com/qmu/workaholic/commit/6c2030cb))

Added `claims_unit_resolution` / `claims_unit_row` / `claims_unit_live_branches` to
`lib/claims.sh` as the single derivation, read by `claim.sh resume`, `release-claim.sh` and
`plan-units.sh` instead of three first-match lookups. Two live claims are refused rather than
chosen between, and `ensure-worktree.sh` refuses a branch already published on origin.

## 4. Outcome

A unit's live branch is the only branch a writer can reach when a superseded one sits beside it,
and the survey no longer offers work another run is driving. Both bounds hold: a single-claim
unit behaves exactly as before, and `superseded` stays reported and never acted on.

## 5. Concerns

### The ambiguous_claim refusal has no traffic behind it

- **Severity:** low
- **Description:** Two live claims cannot arise from the sanctioned path, so the refusal is proved
  only by a fixture (see [6c2030cb](https://github.com/qmu/workaholic/commit/6c2030cb) in
  `plugins/workaholic/skills/drive/scripts/lib/claims.sh`)
- **How to Fix:** Nothing unless observed; both writers stopping until a human rules is the cost

### ensure-worktree.sh narrowed its contract with no caller to prove it

- **Severity:** low
- **Description:** No in-plugin caller passes it an existing remote branch name, so the refusal
  runs only in its own fixture (see
  [6c2030cb](https://github.com/qmu/workaholic/commit/6c2030cb) in
  `plugins/workaholic/skills/branching/scripts/ensure-worktree.sh`)
- **How to Fix:** Leave it; an external caller wanting a published branch uses
  `create-mission-worktree.sh --branch`, which the refusal names

## 6. Successful Development Patterns

- Reproducing all three reported symptoms before fixing any surfaced a fourth — the same defect in
  `plan-units.sh`, where a wrong answer double-drives rather than refuses — because the
  reproduction ran the real survey, not only the named scripts.
- Asserting the single-claim case byte-identically beside the two-branch case is what let one
  derivation replace three lookups without arguing about regressions.
