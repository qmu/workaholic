## 1. Overview

A ticket queued at 11:05 UTC named four failing assertions on a base whose CI reads green. By the time a survey offered it, the same defect had already been met and fixed inside the unit whose own Quality Gate it was blocking, and merged as [#717](https://github.com/qmu/workaholic/pull/717). This branch verifies the gate rather than re-implementing it, and writes down the judgment the ticket explicitly asked to have decided.

**Highlights:**

1. The gate is checked in both environments the ticket names — variable declared and `env -u` — and they agree at `5036 passed, 0 failed`.
2. The ticket's step 5 (name one variable, or strip the whole `WORKAHOLIC_*` family?) was answered the broad way, and the reasoning is recorded in the code beside the strip rather than only in a commit body.
3. The Consideration about `/propose`'s sweep slice is answered by construction: a family-wide strip covers every slice at once, so there was no second site to find.

## 2. Motivation

`main`'s suite had been red since #713 merged, and invisibly so: the suite is a local gate, not a check run, so the base's own checks stayed green over it. The cost was not untidiness — `catch-up-claim.sh` runs the suite as its pre-push validation, so every catch-up on this repository would refuse `validation_failed:test-workflow-scripts.mjs` over a branch whose work was sound. Two `/implement` runs met it within the hour and answered differently: one queued this ticket, the other fixed it inside the unit it was blocking.

## 5. Concerns

### Two runs paid for the same defect an hour apart

- **Severity:** low
- **Description:** One run queued the ticket at accounting time; another fixed it inside the unit whose named Quality Gate it blocked. Both were correct under the failure contract — the second reads a blocking gate failure as inside its own scope, the first reads an unqueued problem as a ticket. The duplication cost one verification pass.
- **How to Fix:** Nothing mechanical. If it recurs, the rule worth writing is that a defect blocking a unit's *own* named Quality Gate is in that unit's scope by construction.

## 6. Successful Development Patterns

- A local-only gate can be red on `main` indefinitely while every check run reads green. When a verification command is load-bearing for another script — here `catch-up-claim.sh`'s pre-push validation — its redness is a build outage with no build signal.
- When a ticket asks for a judgment to be *recorded either way*, the durable place is the code beside the decision, not the commit body: the next person to meet the same class reads the file, not the log.
