## 1. Overview

`gh-rest.sh available` authenticated a *person* as a proxy for *is REST reachable*, so every
script guarded by it refused `gh_unavailable` under a workflow's own token. It now probes
`GET /rate_limit`, which every token type can call.

**Highlights:**

1. The CI-side branch delete reaches its transport instead of refusing before its proof gate
2. No refusal word moved — only when `rest_unreachable` is true
3. `ci_retirement_actions_credential` is the drill row that would have caught it

## 2. Motivation

`claim-retirement.yml` holds `contents: write` and had deleted **nothing** since it shipped.
`GET /user` is not accessible to a GitHub App installation token, which is what `GITHUB_TOKEN`
is inside a workflow, so `delete-retired-claim-branch.sh` refused `gh_unavailable` before its
proof gate, before every bound, and before the delete it was permitted to make.

Nothing pointed at the transport: the act reported `gh_unavailable` about *itself*, and the
sibling mission that made the turn's answer readable is what surfaced the word at all. This
ticket was minted mid-run by that mission, as work outside the driving ticket's scope.

## 3. Changes

### 3-1. Probe REST reachability, not identity ([0ca941a8](https://github.com/qmu/workaholic/commit/0ca941a8))

All seven callers of `available` were read first: every one tests `"ok": true` and nothing else,
and the four scripts needing an identity call `gh api user` themselves. So the probe became
`GET /rate_limit` and `login` is kept as a documented, always-empty field.

## 4. Outcome

A workflow's own credential now reads as a working transport. The CI retirement turn reaches its
act, and whatever it then answers is recorded and read back by the machinery the same mission
shipped — so the next tick reports `taken` or `refused:<word>` rather than inferring either.

## 5. Concerns

### The three standing branches are not yet gone

- **Severity:** low
- **Description:** CI's next turn fires on the push that merges this unit, after the run that
  made the change ended, so the delete of the branches standing since 2026-08-18/19/21 is not
  observed here (see [0ca941a8](https://github.com/qmu/workaholic/commit/0ca941a8) in
  `plugins/workaholic/skills/gather/scripts/gh-rest.sh`).
- **How to Fix:** Nothing to do — the turn now records what it attempted, so the next
  `/moderate` tick reads the outcome per unit instead of inferring it.

## 6. Successful Development Patterns

- Reading **every** caller before changing a shared seam turned a risky-looking transport edit
  into a bounded one: none read the field that looked load-bearing.
- The fixture's own `gh` stub matched `user*` against an `ARGS` of `api user --jq .login`, so it
  never exercised the probe — a stub falling through to a generic success cannot drill a
  credential, and the new row had to teach it the two endpoints apart first.
