# Follow the pull requests the loop opens for a person

## 1. Overview

The loop opens pull requests **for a person** — the ones the publish seam refuses to auto-merge,
where merging is the ruling and closing is the refusal — then stopped following them. This branch
derives which open pull requests those are from the seam's own refusal word, reads back what
became of each, and asks the operator about the ones nobody has acted on.

**Highlights:**

1. One shared rule the seam and the new reader both compose
2. A 28th `/moderate` step asking once per pull request
3. Four readings classified as judgements, reported as evidence, gating nothing

## 2. Motivation

Measured 2026-08-29: PR **#694** had been open **18 hours** with nothing naming it to a person.
No step could see it. `stuck-prs` and `merge-conflicts` find such a pull request perfectly
healthy — it is not stuck, it is **waiting**, which is what it was opened to do. Every
claim-side verdict is bounded to a **claim**, and a publication carries none: the seam pushes
`publish-main` to a `work-*` name with no `Claim` commit, which is exactly what keeps a
publication invisible to the claim protocol. So the loop had a careful refusal to merge the
operator's work automatically, and no way to tell them it was waiting.

## 3. Changes

### 3-1. Derive the operator-facing pull requests from the seam's refusal word ([fe8b9f30](https://github.com/qmu/workaholic/commit/fe8b9f30))

Moves the refusal test into `branching/scripts/lib/publication-refusal.sh`, composed by both
`publish-tree-pr.sh` and the new `list-operator-facing-pulls.sh`; each caller owns only an
adapter into a normalised stream. Membership is the **shape of the change**, never a title, so a
retitled ruling is still the operator's; `list-open-rulings.sh` is byte-identical.

### 3-2. Read back whether an operator-facing pull request was acted on ([6ccca341](https://github.com/qmu/workaholic/commit/6ccca341))

`publication-effect.sh` answers `merged` / `closed` / `open:<age>` / `unreadable` per pull
request, exit 0 always, through the one REST transport. `unreadable` carries a named reason and
a **null** age — a zero would read as *just opened* for a read we could not make.

### 3-3. Ask the person who must act on an unanswered pull request ([0d3c1d80](https://github.com/qmu/workaholic/commit/0d3c1d80))

`step-operator-pulls.sh`, the tick's 28th step, addressed to the operator resolved from the
active directions' assignees. `merged` and `closed` are settled and draw nothing; `unreadable`
draws no question and is counted. No candidate means no `event` and no root line.

### 3-4. Classify every pull-request reading as a judgement in the one home ([ed64ae6b](https://github.com/qmu/workaholic/commit/ed64ae6b))

One sub-table beside the existing four in `drive/reference/claims.md`, every row a judgement: a
pull request is designed to change state, so every reading can become false by looking again.
The existing pin was extended rather than duplicated, and both consumers are enumerated.

### 3-5. Release a ruling hold the ruling's own silence has outlived ([e5a083f5](https://github.com/qmu/workaholic/commit/e5a083f5))

Keeps the hold and lets the new question break the silence, with both readings composing
`ruling-suppression.sh` so they cannot diverge. Releasing the hold as well would ask one person
twice about one pull request; releasing on a timer would add a threshold this layer has refused.

### 3-6. Report the pull-request reading in the run reports as evidence ([7dd6ff52](https://github.com/qmu/workaholic/commit/7dd6ff52))

Names the reading once per run in `/implement`'s and `/propose`'s reports, with its own row in
the token table saying it moves no token. `survey-strategies.sh` is unmodified, so every gate is
byte-identical by construction rather than by assertion.

### 3-7. Drill the operator-facing pull-request reading offline ([f1063bab](https://github.com/qmu/workaholic/commit/f1063bab))

`verify-operator-pulls` over a throwaway repository with a local origin and a stubbed `gh`,
registered `hermetic` with its own CI matrix leg. Its breaker wires the derivation at the pull
request's **title** and must lose the retitled ruling.

## 4. Outcome

The operator is told once per pull request that a publication waits on them, what it would
unblock and how long it has waited; both run reports name the reading as evidence and gate
nothing. Verified live: the derivation names exactly #694 of 7 open pull requests, the reader
returns all four values against real ones (#694 `open:19`, #732 `merged`, #612 `closed`, #999999
`not_found`), and the step yields one candidate addressed to `a@qmu.jp`. Suite 5168/0; the drill
16 rows / 1 proved breaker; `layout-doctor` conforming; `drive`'s closure byte-identical.

## 5. Concerns

### `#694` holds no subjects, so the hold it was cited for is not reproducible

- **Severity**: moderate
- **Description**: It holds nothing — its body carries **no** `ruling: … / subject: …` markers,
  because `publish-tree-pr.sh` composes the body from a fixed template, so
  `ruling-suppression.sh` answers an empty `held`. Silent and safe (every question it should
  have suppressed was asked instead), which is why it survived.
- **How to Fix**: ticket `20260829200500-carry-the-ruling-s-subject-markers-into-its-pull-request-body`.

### The claim was resumed by another runner mid-drive

- **Severity**: moderate
- **Description**: The heartbeat was not beaten during the long implementation phase, so it
  lapsed past the 30-minute window and another `[Implement]` container legitimately resumed the
  claim, pushing an empty `Resume a PR-unit` commit (`c2266cf5`).
- **How to Fix**: recovered by **merge**, never a rebase or force-push, and beaten after every
  archive since. Nothing was lost or rewritten — the protocol worked; the run's discipline did not.

### The measured ask was wrong about which pull requests are the operator's

- **Severity**: low
- **Description**: The mission named #694 plus #688 and #625 as strategy publications. Neither
  #688 nor #625 touches `.workaholic/strategies/`; only #694 is the operator's by the seam's word.
- **How to Fix**: nothing in code — ticket 2's localization caught it before anything rested on
  it, and this block is the durable correction.

### The readers live beside the seam, not beside the step that asks

- **Severity**: low
- **Description**: Tickets 1 and 2 name `moderate/scripts/` as the home; both ship in
  `branching/scripts/`. A `drive/SKILL.md` reference into `moderate/` dragged that skill's whole
  closure into the public bundle — `verify.mjs` failed with 12 unresolved references.
- **How to Fix**: deliberate and recorded; after the move the closure is byte-identical to the
  base's.

## 6. Successful Development Patterns

- The breaker is written against **behaviour**, so a refactor keeping the JSON shape still fires it.
- The build's closure report caught an architectural mistake no test would have.
