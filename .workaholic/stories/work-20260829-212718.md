# Carry the ruling's subject markers into its pull request body

## 1. Overview

`draft-standing-rulings.sh` composed its `ruling: <kind> / subject: <subject>` markers into the
seam's **third** argument, which reaches the commit message and never the pull-request body — so
`list-open-rulings.sh` read the body, found none, and every open ruling held nothing. The
markers now ride the one argument the body template already renders.

**Highlights:**

1. Localized verbatim on #694: four markers in the commit message, none in the body
2. `publish-tree-pr.sh` is byte-identical — no body-fragment parameter was added
3. The drill's fixture now derives its markers from the **captured body**, closing the chain

## 2. Motivation

Minted mid-run while building the operator-facing pull-request reading. The hold
(`ruling-suppression.sh`) is documented as holding a subject's hourly question while an open
ruling already carries the ask; it was holding **nothing**, because the markers it reads never
reached the surface it reads them from. The failure is **silent and safe** — every question it
should have suppressed was asked instead — which is exactly why it survived, and why
`verify-rulings` passed straight over it.

## 3. Changes

### 3-1. Carry the ruling markers into the PR body ([46292c01](https://github.com/qmu/workaholic/commit/46292c01))

The markers move from `BODY_CHANGES` (argument 3, forwarded to `commit.sh`) to `BODY_WHY`
(argument 2, rendered as `## Overview`). One caller, one variable; the seam gains no
body-fragment parameter, which its own header rules out — its positionals are `commit.sh`'s and
end in an open-ended `[files...]`, so a new one could not be told from a filename. The drill's
stub captures the pull-request payload, a new row asserts the body carries one marker per judged
subject, and the suppression rows' `open.tsv` marker field is derived from that captured body
instead of being hand-written.

## 4. Outcome

`ruling-suppression.sh` can now hold what an open ruling actually names. Preserved provably: the
markers stay **visible text** each on its own line, `list-open-rulings.sh` is byte-identical and
still decides membership by the `[Ruling] ` title, and `BODY_CHANGES` keeps its readable bullet
list in the commit message. Proved able to fail: with the pre-repair composition restored,
`verify-rulings` reports `fail` on exactly `rulings_markers_reach_the_body`; restored, 11
load-bearing rows / 0 failed / 2 breakers. Suite 5168/0, `verify.mjs` clean, `layout-doctor`
conforming. Acceptance 3/3 with an empty queue, so the archive gate closed the mission.

## 5. Concerns

### #694's own body is not retrofitted

- **Severity**: low
- **Description**: The repair is forward-only. The pull request already open carries no markers
  in its body, so the hold stays empty for it until it is merged or a later ruling is drafted.
- **How to Fix**: nothing — merging #694 removes it from the candidate set by itself, and the
  hold's own rule is that an unreadable or absent reading suppresses nothing, which is the safe
  direction.

### The drill passed over this for as long as the defect existed

- **Severity**: low
- **Description**: `verify-rulings` drove `open.tsv` from a hand-written marker field, so the
  rows that assert the hold tested the fixture rather than the chain.
- **How to Fix**: fixed here by deriving that field from the captured body. The same shape is
  worth looking for wherever a drill fabricates the input its own subject is supposed to produce.

## 6. Successful Development Patterns

- The localization named the exact argument, not just the symptom, so the repair was one line.
- The breaker was run in both directions — pre-repair fails on exactly the new row, post-repair
  passes — rather than asserted.

## 7. Notes

- `publish-tree-pr.sh` and `list-open-rulings.sh` are both byte-identical across this change.
