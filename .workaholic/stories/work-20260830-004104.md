## 1. Overview

Every reader in `workaholic:moderate` wraps its jq program in `2>/dev/null || echo '[]'` — a fallback that is right for a data problem and catastrophic for our own, because a program that does not *compile* discards identically and the step then reports `ok` over an empty finding. This branch tells the two cases apart by jq's own exit status, reclassifies the step in one place, and compiles all 491 extractable embedded programs as a suite row so the defect fails the commit that introduces it.

**Highlights:**

1. A step whose embedded jq does not compile reports `degraded` / `jq_compile_error`, never `ok`.
2. A runtime or data failure is untouched — every existing fallback keeps its behaviour byte-for-byte.
3. `every embedded jq program compiles` extracts and compiles 491 programs; the 14 built by interpolation are counted, not skipped silently.

## 2. Motivation

The defect was measured, not predicted. While shipping *Show a direction's stage where directions are read*, `step-direction-health.sh` reported `"status": "ok"` with `1 expiring … 1 to ask` — and the expiring direction's own question was silently gone, from one missing parenthesis inside its embedded jq program. It survived because it is invisible twice over: `sh -n` passes (the shell parses fine; it is the embedded jq that does not), so the `every shipped shell script parses` row added earlier in the same mission provably cannot see it, and the `|| echo '[]'` fallback is *legitimate* for a data problem, so it cannot simply be deleted.

That collapse is the one thing every header in this skill forbids: *a read we could not make must never render as a reading we made*. The step was doing exactly that, in the vocabulary of a step that looked.

## 3. Changes

### 3-1. Stop a swallowed jq error reading as ok ([0056fa5b](https://github.com/qmu/workaholic/commit/0056fa5b))

The two cases are separated by jq's own exit status — `3` is a compile error (our defect), `5` a runtime or input error — so no convention is invented and no fallback changes its data behaviour. `lib/jq-guard.sh` is a shadowing `jq` function, sourced at one line by each of the 30 jq-bearing scripts in the skill: it calls `command jq`, captures and redirects nothing, and *records* a status 3. `run.sh` is the one place that reads the record and reclassifies the step `degraded` / `jq_compile_error`, beside the `step_missing` / `step_error` / `no_output` / `bad_output` it already owned. Beside it, the suite gains `every embedded jq program compiles`, which finds each `jq` in command position across `plugins/workaholic/`, `scripts/` and `hooks/`, redeclares every `--arg` name, and compiles the program with `jq -n`.

## 4. Outcome

A `/moderate` tick can no longer report a healthy hour over a reading it could not make, and a compile error introduced tomorrow fails the suite rather than one unattended tick at 03:00. The repair is applied to the shape rather than to the file that exhibited it: 58 call sites across 18 scripts are covered by one sourced library, and any call site added later is covered by construction.

## 6. Successful Development Patterns

- Reproducing first paid for itself: the one-character break showed the broken step reporting `1 expiring … 1 to ask` with a *different* question firing in place of the missing one, which is what identified the real blast radius — a downstream guard reading the list the broken program was supposed to build.
- Restricting the extractor to `jq` in **command position** cut false positives from 92 to 14 in a single step, and is what makes a permanent build-time gate trustworthy enough not to be disabled.
- Two suite fixtures broke because they copy a step into an empty directory to prove it degrades without its sibling readers. Carrying `lib/` with the script was the right fix; making the source line tolerant would have reintroduced the silent-fallback shape inside the repair itself.

## 8. Notes

The 14 programs assembled by string interpolation cannot be extracted without evaluating the shell; their count rides the assertion's own name so it is visible on every run and is never a number anybody must keep current. Scripts outside `workaholic:moderate` get the build-time row only — they report no step status for anything to reclassify.
