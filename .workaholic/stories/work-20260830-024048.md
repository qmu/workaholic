## 1. Overview

Every reading in this repository was **instantaneous**. `stalled`, `report_undelivered`,
`retire-blocked`, an undrivable unit, `overdue`, `dormant`, `arrived` — each says **what** is
stuck and none said **how long**. Since the asked-once gate tells a person exactly once either
way, a condition that started this hour and one that has been true for eleven days arrived
looking identical. This branch adds one bounded reader, puts its answer on the four questions
that name a standing blocker, names it in both run reports, and classifies every value it emits
as a judgement no gate may read.

**Highlights:**

1. `moderate/scripts/condition-age.sh` answers a subject's age from the **question ledger** the
   tick log already writes — no new store, no cursor, no field on any artifact, no second walker.
2. `undrivable-unit`, `retire-blocked`, `undelivered-unit` and `stalled-unit` carry it, with
   **every summary and every key byte-identical**, so nothing is re-asked by the changed wording.
3. A sixth sub-table in `drive/reference/claims.md` classifies all six values a **judgement**,
   pinned both ways and proved able to fail four different ways.

## 2. Motivation

The case that measured it is this repository's own: five queued tickets stamped with an address
the identity mapping does not name have been undrivable since **2026-08-19**, each asked about
once — days ago — and never again, because the asked-once gate is doing exactly its job. The
person who could act saw one question, once, with nothing in it to say the queue had been stuck
for a week.

The live claim set shows the same shape from the other side, and it is what makes the *two ages*
rule concrete rather than theoretical. Measured while driving this branch:
`batch-20260818215156` reads `stalled_hours: 269` with `ticks: 102` since `20260826-015129` —
stuck for eleven days and asked about for four. `deploy-the-docs-site-on-merge-to-main` reads
`stalled_hours: 85` with `first_seen: null` — stuck for three and a half days and asked about by
**nobody, ever**. One number could not have said both, and the second is the situation a person
most needs to hear about.

## 3. Changes

### 3-1. One reader, over the ledger rather than the step summary ([738c2e64](https://github.com/qmu/workaholic/commit/738c2e64))

The obvious source is the owning step's own log summary, and it is satisfiable for exactly one
of the four steps. `undrivable-units`, `undelivered-units` and `stalled-units` carry counts only,
and each of those steps' headers records that putting per-unit detail or an age in a summary is a
**correctness violation** — `render-tick-post.sh`'s changed-step diff would then mark the step
changed every tick, which is the retired `📦 Release Preparation` shape. So the age is read from
the **question ledger** the subject key already writes (`human-checkin-ask-<slug>` and
`human-checkin-reasked-<slug>`, written once by `ask-question.sh --record-ask` and never moved),
composing `log-read.sh` and `lib/question-id.sh` and owning nothing else.

Three states have to stay apart, and the third is the whole point: a key first named days ago; a
key nobody has ever asked about (`first_seen: null`, `ticks: 0`, and **no `readable` field at
all** — an ordinary absence); and a log that **exists** and could not be read (`readable: false`,
a named reason, **null** counts, never zeroed ones). Collapsing the third into the second renders
an eleven-day blocker as one that just started.

### 3-2. The walk is bounded, and a bounded walk says so ([76f965f2](https://github.com/qmu/workaholic/commit/76f965f2))

The tick log is append-only and never pruned by a machine, so an unbounded walk gets more
expensive forever. `WORKAHOLIC_CONDITION_AGE_MAX_DAYS` (default 30) caps it as **the newest N day
files**, selected lexically and handed to `log-read.sh`'s existing `--since` — no date arithmetic
(`date -d` is GNU-only, `date -v` BSD-only) and no `--last-days` added to the reader every other
consumer shares. A **cut** walk reports `truncated` and, over a date it did have,
`first_seen_is_floor`, so a consumer renders *at least* rather than a date it could not
establish; an uncut one is byte-identical to an unbounded read. `truncated` is **not** a
degradation, and the bound's error is one-sided: it can only make an age look **younger**.

### 3-3. The four questions carry it ([d10d4746](https://github.com/qmu/workaholic/commit/d10d4746), [42c387d9](https://github.com/qmu/workaholic/commit/42c387d9), [8a569b14](https://github.com/qmu/workaholic/commit/8a569b14))

Each step calls the reader with the key it **already composes** and attaches the answer verbatim
— a normalised word would send a reader to a string no script printed. `lib/read-age.sh` holds
that call once, because four copies of the same fallback are four chances to write the
degradation differently. **No key moves**, so `already_asked` is byte-identical; **no summary
moves**, for the correctness reason above.

Two of them carry a second age, and the two are named as **two facts with two sources**, never
blended: `undelivered-unit` has the pull request's `open_hours` beside the log age, and
`stalled-unit` has the claim tip's `stalled_hours`. `operator-pull` deliberately keeps reading
`created_at` alone. A source table in `drive/reference/claims.md` records every row for the rule
it exists for — **nothing derives an age twice** — and the suite checks each named step in both
directions.

`retire-claims` is the one age consumer that also **acts**, on a proof, so the age is attached
after the key is settled, after both suppressions, and after the act: a judgement must never sit
in front of the proof `retire-claim.sh` reads, and the suite pins that ordering by position.

### 3-4. Every value is a judgement, and the pin was broken on purpose ([e46bfe7f](https://github.com/qmu/workaholic/commit/e46bfe7f))

A **sixth vocabulary** in `drive/reference/claims.md`'s *Proofs and judgements*, parsed apart
from the fifth exactly as the five are parsed apart from each other. The tempting error is to
call `first_seen` a proof — it is read straight off an append-only log that never rewrites a
line, which is `superseded`'s property. It is not: the log **grows**, so `ticks` rises every hour
and a bounded walk's `first_seen` moves as day files pass out of the bound, and a proof is a
reading that cannot become false by looking again.

The vocabulary is parsed by **running the reader** over its four shapes rather than from a list
the test carries, with the echo fields dropped by comparing values per shape. All four failure
modes were introduced on the unmodified tree and each turned exactly one row red; they are
recorded in the test's own header.

### 3-5. Named in both run reports, and drilled offline ([caa4cacb](https://github.com/qmu/workaholic/commit/caa4cacb), [93031095](https://github.com/qmu/workaholic/commit/93031095))

`/implement` and `/propose` name the age once per run as **evidence, never a verdict**, in the
voice `pace`, `overdue`, `expiring` and `arrived` already use. §7's token table gains **no row**:
an old blocker does block the queue, and `/implement` may not ask, so a withheld token would
report a failure hour after hour into a report nobody opens while `/moderate`'s own questions
reach the person who can act.

`verify-condition-age` walks log → reader → bound → question → report over a fixture whose ledger
lines are written by the **real writer**, with no network, no `gh` and no Slack post: 13
load-bearing rows and a breaker written against the **behaviour** (the walk wired at a single
tick, so every age must collapse to 1).

## 4. Outcome

A person asked about a standing blocker is now told how long it has been standing, and — where
two clocks exist — which clock each number came from. A blocker nobody has ever been asked about
is visibly that rather than silently indistinguishable from one asked about last week, and a log
we could not read is named as unreadable rather than rendered as *this just started*. Nothing
gates, holds, re-asks, escalates, sorts or merges on any of it.

## 5. Concerns

- **severity: low** — The reading is the age of the **question**, not of the condition, so it
  understates: a blocker that existed before anybody asked reads younger than it is. This is the
  safe direction (it asks a person to look sooner than the truth would) and it is stated in the
  script's header, in `claims.md`'s source table and in every composer's instructions. A future
  ask that wants the condition's own age needs a different source, not a re-reading of this one.
- **severity: low** — Only one of the four age consumers is exercised end to end by the drill;
  the other three read the claim oracle, which fetches, so a hermetic drill would end up drilling
  the oracle rather than the age. Those keep a composition assertion in the drill and the
  acting-call-site bans in `testProofJudgementSplit`.

## 6. Successful Development Patterns

- **Running the reader to derive the pinned vocabulary, rather than listing it.** The first
  version compared each shape's fields against a single key's echo values and let `key`/`slug`
  through for the shape built with a *different* key. Computing the echo set per shape fixed it
  and left the pin with nothing hand-maintained in it.
- **A `grep`-based "never reaches X" row must check the file exists.** The gate row was written
  against `strategy/scripts/survey-strategies.sh`; the script lives under `propose/scripts/`, and
  `grep` over a missing file matches nothing — so the row reported *gates nothing* about a script
  nobody had read. The suite caught it by throwing `ENOENT` on the same typo; the drill needed an
  explicit `[ ! -f ]` arm to be equally honest.
- **The bundle boundary is a real constraint on where a script may be named.** Writing
  `${CLAUDE_PLUGIN_ROOT}/skills/moderate/scripts/condition-age.sh` in `drive/SKILL.md` resolved
  into that skill's script closure and copied `moderate`, `standup` and `workaholify` wholesale
  into every cross-agent bundle, surfacing `workaholify`'s `../bootstrap/session-start.sh` as
  twelve unresolved references. The bare path form fails `verify.mjs` twice over. The SKILL.md
  names the reader and its owning skill, `reference/routing.md` carries the path, and the reason
  is written in both so a later reader does not "fix" it back.
