## 1. Overview

`/specificate`'s strategy form needed three parts **from the ask itself** — a date, an owner, an
aim with no decomposable plan — so an ask carrying two of them was record-only, `no_target_date`.
That refusal was traced only by a parenthetical addressed to nobody, and **three announced
directions all died there** while the loop went on planning from the directions that already
existed. The operator ruled the default: **one week from the ask**.

**Highlights:**

1. `strategy/scripts/default-target-date.sh` is the one derivation — the constant **7** lives
   there and nowhere else, named as the operator's ruling rather than left a bare number.
2. The date is counted from the **triggering issue's own date**, not this tick's clock, so a tick
   ingesting a week-old issue does not date a direction from the hour it ran.
3. `no_target_date` is **narrowed, not deleted**: it answers exactly one case now — an ask that
   *stated* a date the run could not resolve. Defaulting over the operator's own words is the
   failure this must not introduce while removing the other one.

## 2. Motivation

Taking a default here would be indefensible on any artifact whose write is the decision. On this
one it is defensible for a reason the exemption already carries: **the operator's merge is the
authorship**. A drafted strategy sits at a pull request that never auto-merges, so editing the
date before merging is how they set their own and closing it is the refusal. The default is a
proposal a person answers, never a decision a machine made.

That is also the whole reason the third ticket exists. A merge is only an authorship if the
person merging can **see** what they are being asked to author, and nothing on the artifact would
have said the date was ours — a direction the loop dated would have read exactly like a direction
the operator dated, and the veto would have been one nobody knew they held.

## 3. Changes

### 3-1. One derivation, and why it is a script ([ef5b5062](https://github.com/qmu/workaholic/commit/ef5b5062))

Every other date term in this layer — `days_to_target`, `overdue`, `expiring` — is derived in
exactly one place and read by everything else. A "week" computed at two call sites is two clocks,
and the second one is wrong the first time somebody edits it. So `default-target-date.sh` owns the
arithmetic and nothing else: it reads no strategy, writes nothing, and never says whether a
default *should* be taken.

Three decisions inside it are worth naming. It counts from the **ask's own date** when the caller
supplies one, reporting which basis it used, so a caller never has to guess whether its argument
was honoured. A malformed `<ask-date>` is refused `bad_ask_date` with **no date emitted** — a
plausible answer hiding a malformed input is the shape that makes a defect invisible, and
`create.sh` would accept the fallback without complaint. And the arithmetic is **jq over epoch
seconds**, matching `survey-strategies.sh`'s own `days()`: `date -d` is GNU-only and `date -v`
BSD-only, so a shell-native computation works on the runner and not on a developer's machine, or
the reverse.

### 3-2. The bar, and the refusal it narrows ([d59319ac](https://github.com/qmu/workaholic/commit/d59319ac))

The three-part bar becomes: an **owner** and an **aim** from the ask, both still never inferred,
plus a **date** the ask states or the default supplies. `SKILL.md` states the ruling and its date
so the default is traceable to a person rather than to a preference, and `workflow.md`'s step 9b
calls the derivation only when the ask states **none at all** — when it states a resolvable date,
that is the date and the default is never consulted.

`no_target_date` survives for the one case a default must never cover. This is the asymmetry the
whole change turns on: removing a refusal that killed three real directions is worth doing, and
extending it into *overwriting a date the operator wrote* would be a strictly worse defect than
the one being fixed.

**The owner requirement is what still brakes the artifact.** A strategy has no floor and no
ceiling — the bar was the only thing stopping a run emitting them indefinitely — so it matters
that the half doing the braking is the half that did not move: an unassigned or unmapped issue is
record-only exactly as before, and a stray ask cannot mint a direction.

### 3-3. Visible on three surfaces, and a field on none ([050e12f2](https://github.com/qmu/workaholic/commit/050e12f2))

The `## Schedule` prose names the date as the default, what it was counted from, and that editing
it before merging sets their own — one sentence, in the artifact's existing prose. The
pull-request body names it in the clause step 10 already reserves for what the run decided and
why. Step 13's run report reports `target_date:default` or `target_date:stated`, so the two are
told apart without a new field anywhere.

**No frontmatter key was added, and the reason is not tidiness**: once the operator edits the
date, a field saying "default" would be a lie nothing clears. Keeping it in the prose the operator
reads whole means an ordinary amendment replaces it along with the date it describes.
`create.sh`, `read.sh`, `list.sh`, `amend.sh` and `survey-strategies.sh` are all byte-identical,
and `create.sh` learns nothing about where its date came from.

### 3-4. The pin, and why it is a suite row ([9b9d366a](https://github.com/qmu/workaholic/commit/9b9d366a))

Everything above is prose plus one small script, and prose regresses silently — the measured
failure this mission answers was itself a correct rule producing a silent outcome. The last
ticket left the drill-versus-suite choice to what the assertion actually needs to touch: the whole
chain is one script and three documents, with **no fixture repository anywhere in it**. The suite
already runs on every push, and a new drill would have cost a register row and a CI matrix leg for
a walk that touches no git state.

The row asserts the arithmetic against a **supplied basis** (a test computing "a week from now" on
both sides proves nothing), the bar's three outcomes, the narrowed refusal, the wording on all
three surfaces, and what must not move — including that the never-auto-merge rule still derives
`strategy_touching` from the path in `lib/publication-refusal.sh`, so a defaulted strategy is left
open by the same mechanism as a stated one rather than by a second copy of the exemption.

**Two breakers, each proved red and reverted.** The script made to ignore its argument and count
from today turns the three arithmetic rows red; the step-9b guard reworded so the default is taken
unconditionally — the ticket's own breaker — turns exactly its own row red.

## 4. Concerns

- **The default lowers the bar on the one artifact that has no floor and no ceiling.** The owner
  requirement still holds it and is unchanged, and the pull request still never auto-merges, so a
  drafted direction reaches `main` only by a person's merge. Recorded because the brake is now one
  clause rather than two, and a later change that loosens the owner half would remove the last
  one. (severity: low)

- **The ask offered a second ending and this takes one, deliberately.** Its option (1) was a
  directed in-thread question naming the missing part. `/specificate` may not ask at any step, so
  that question would have to be `/moderate`'s — and no step there can see a record-only,
  strategy-shaped outcome without a new store or a new field on an artifact, which this repository
  refuses by name elsewhere. The ask's own *done means* is satisfied by the default. If the
  operator wants the question as well, it is a separate ask with a separate cost. (severity: low)

## 5. Successful Development Patterns

- **Narrowing a refusal instead of deleting it.** `no_target_date` covered two cases that look
  alike and are opposite: no date at all, and a date the operator wrote that we could not read.
  Keeping the second is what stops the fix from being a worse defect than the bug.
- **Deciding the drill-versus-suite question from what the assertion touches**, and saying which
  was chosen and why, rather than reaching for a new drill because the previous mission added one.
- **Running the new script against every boundary before wiring a caller to it** — the month
  rollover and the leap day are exactly what a naive `+7` on the day field gets wrong, and both
  are in the pin rather than in a comment.
