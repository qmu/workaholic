# Ask a person about a claim race

## Overview

A claim race reached nobody. `ambiguous_claim` — two or more **live** claims for one unit — is
refused by every writer in the protocol that meets it, and was **asked about by no step at all**,
so the hour of duplicated implementation measured on 2026-08-30 was recorded nowhere. This branch
adds the two surfaces that name it: `/moderate`'s `raced-units` step asks the claim holders, and
the run report names a race the run itself met. Neither gates, merges, closes or touches a claim.

## Motivation

`work-20260830-055314` and `work-20260830-055318` were both claimed for one unit four seconds
apart and each drove the same four tickets for over an hour. The run that lost reported an
ordinary undelivered unit. No sibling step could see the shape: `stalled-units` finds one claim
that has not moved, `undelivered-units` one refused merge, `catchup-blocked` one conflicted
branch — each a **consequence** whose question hides the cause, because each of the two rows is
individually healthy and what is wrong is that both exist.

## Key Changes

- **`drive/scripts/list-raced-units.sh`** ([f93953b6](https://github.com/qmu/workaholic/commit/f93953b6)) — the reader. Composes `list-claims.sh` (one walk of the refs, never a second oracle) and `lib/claims.sh`'s own `claims_unit_resolution`. No new verdict word, no second walker, no store, no field on any artifact; a degraded read yields no candidates, a named reason and **null** counts.
- **`moderate/scripts/step-raced-units.sh`** — asks the claim holders, keyed `raced-unit:<unit>` so one unit costs one question however many ticks see it, naming **both** branches with their verdicts and picking between neither. `ask-question.sh` is byte-identical.
- **`moderate/scripts/lib/raced-units.sh`** — the one filter three siblings share (`stalled-units`, `undelivered-units`, `catchup-blocked`), over the scan each has already made. No second walk of the refs, and no second definition of a race.
- **`drive/reference/claims.md`** — a seventh vocabulary in the one home, *Whether a unit is being driven twice*: every value a **judgement**, consumers enumerated, and the deliberate exclusion argued rather than left as a gap.
- **`lib/claims.sh`** — the `ambiguous` comment still asserted the premise this mission corrected three days ago. A third occurrence the correcting ticket's grep did not reach.

## Decisions

**The candidate set is `ambiguous` and nothing else.** The ticket's wording described the
*aftermath* — one live claim beside a `superseded` one — and that shape is byte-identical to the
**sanctioned** recovery in which a superseded claim's work is resurveyed and taken on a fresh
claim. Separating a race from that recovery needs a clock threshold or a stored field, both
refused by name here, so the aftermath stays where it is already handled: the loser reads
`superseded`, `retire-claims` retires it, `stalled-units` counts it.

**One step asks and three filter and count**, settled explicitly for all four candidates rather
than left to whichever runs first. `retire-claims` needs no change: its candidates are
`superseded` rows and an `ambiguous` unit has none by definition, so the sets are disjoint by
construction.

**Where a run loses a race is stated rather than assumed.** The ticket keys the run report on the
lost-race word its sibling ticket would have added at the claim *push*. That word rests on an
arbitration this container cannot perform, so the report is keyed on the refusals that exist —
`archive.sh`'s re-check answering `claim_taken_over` or `ambiguous_claim` at the first write the
base would see, with the tree byte-identical. If the arbitration ever becomes available, this
surface takes the other word with no other change.

## Concerns

**Three of this mission's four remaining tickets are blocked on a transport refusal, and every
later tick will re-measure it** — severity: moderate

`make-the-claim-contend-for-one-ref-per-unit`, `refuse-the-losing-claim-by-its-own-word` and
`extend-the-drill-to-prove-the-repair` all rest on an arbitration this container cannot perform.
Re-measured this run, both write transports agree:

```
$ git push origin <sha>:refs/claims/probe-1
error: RPC failed; HTTP 403 curl 22 The requested URL returned error: 403
$ git ls-remote origin 'refs/claims/*'      # empty — nothing was created

$ gh api repos/qmu/workaholic/git/refs --method POST -f ref=refs/claims/probe-2 …
403 {"message":"Write access to this GitHub API path is not permitted through this proxy."}
```

`refs/heads/*` is the only writable namespace and its **delete** is refused identically
(`retire-claim.sh`'s Act 2, three branches standing on origin since 2026-08-21), so a ref there
would satisfy the ticket's own prohibition: *a ref nothing deletes makes every unit claimable
exactly once, forever*. The ticket's Considerations anticipate this and say such a result is a
finding for the mission, not a workaround to invent.

Nothing unattended can clear them, so each `[Implement]` tick will claim, re-measure and re-block
them. The two rulings only the operator can make: whether the arbitration moves to a namespace CI
releases (accepting that a unit is unclaimable between its release and CI's next turn), or
whether the three tickets carry `verification_handoff:` so the loop stops re-claiming them — a
run may never declare that for its own unit.

## Successful Development Patterns

**A drill row asserting a sibling is silent passes vacuously unless the fixture puts that
sibling's candidate set within reach.** The raced claims in `verify-claim-race` are fresh, so with
the protocol's own staleness threshold `stalled-units` would not have listed them whatever the
filter did. Forcing `WORKAHOLIC_CLAIM_STALE_HOURS=0` for that one probe is what makes the row fail
when the filter is removed — demonstrated by removing it, not reasoned about.

**Inserting a section into a document parsed by a chain of `indexOf` splits silently moves its
rows into the preceding section's parse window.** The new classification table landed inside the
publication table's slice and the suite still passed, because its row shapes did not match that
table's regex. The split was added deliberately rather than left to luck.
