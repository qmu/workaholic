## 1. Overview

The claim-race finding said the proxy permits writes to `refs/heads/*` "and to nothing else", and
that a ref there could never be released either. Neither clause had been probed to its end: the
first was an inference over two namespaces, the second was carried over from `retire-claim.sh`'s
branch-delete row. Both are now readings.

**Highlights:**

1. `refs/tags/*` — the last candidate namespace — is refused for create and delete alike.
2. A `refs/heads/*` create succeeds while its delete is refused by *both* transports, with
   `ls-remote` confirming the ref survives.
3. The finding now names why an asynchronous CI-side release does not rescue the repair.
4. And it now names the **grain** the mechanism could never reach even in a permitted
   environment: a ref keyed on the unit id arbitrates the mission grain and not the batch
   grain, because `claim.sh` mints `batch-$(date +%Y%m%d%H%M%S)` inside the claim act itself.

## 2. Motivation

Three consecutive runs took this unit over and reported it blocked, each citing the recorded
measurement rather than making one. Ticket 1 asks the run to *choose* the contended ref, so the
choice is only closed when every candidate namespace has been read. `refs/tags/*` had never been
probed, and the decisive term — whether the one writable namespace can be released — rested on a
different script's precedent. A block whose decisive term is cited rather than measured is the
shape this repository calls a self-certifying claim.

The transport was measured to its end; the *mechanism* had not been. Records in `claims.md`

racers name the same unit**, which is the mission grain and not the batch grain: `claim.sh` step

same unclaimed tickets mint two different unit ids and push two different refs — both creates
succeed and the loser is refused by nothing. Step 3's **artifact-overlap** check already
anticipated a cross-batch scoop, but it reads `claims_scan`, so it closes the *sequential* case
and is defeated by the same window as the unit-id check. Arbitrating the batch grain would need
a ref per **artifact** — N create-only pushes with no atomicity across them, in a container whose
ref deletes are refused. Recorded rather than designed, on ticket 1's own instruction to *say so
and re-scope rather than forcing the named mechanism*.

## 4. Outcome

The mission's remaining acceptance item is now blocked on **two** measured facts rather than one
inherited one: a transport that permits no releasable atomic ref, and a mechanism that reaches

## 5. Concerns

### A probe branch was created on origin and cannot be deleted

- **Severity:** moderate
- **Description:** `wk-transport-probe-1788104778` was pushed to origin to measure whether
  `refs/heads/*` can be released, and both delete transports refused — the refusal *is* the
  finding, so the branch survives (see [8c68220d](https://github.com/qmu/workaholic/commit/8c68220d)
  in `plugins/workaholic/skills/drive/reference/claims.md`). It is not a `work-*` branch, so no
  claim reading sees it and `claim-retirement.yml` does not touch it.
- **How to Fix:** Delete it from the GitHub UI, or from any executor holding `contents: write`.

### The mission cannot reach its first acceptance item in this environment

- **Severity:** moderate
- **Description:** Acceptance item 1 requires a contended ref that wins at the remote; no
  namespace this container can create atomically can also be released, so the three tickets
  behind it are unreachable here rather than merely hard. Since
  [fb8ef4b6](https://github.com/qmu/workaholic/commit/fb8ef4b6) there is a **second, independent**
  half: the mechanism the item names reaches the mission grain only, so unblocking the transport
  would still leave the batch grain unarbitrated.
- **How to Fix:** Rule on an asynchronously released ref and its named cost, re-scope the
  mechanism to a per-artifact arbiter (and price its lack of atomicity), or declare the tickets
  `verification_handoff:` so no further tick claims them.

### Every tick takes this unit over and can drive none of it

- **Severity:** moderate
- **Description:** The claim reports `parked_with_pr`, so the survey offers a takeover on every
  tick; the takeover then finds three tickets it has already proved unreachable and publishes an
  empty `Resume a PR-unit` commit for nothing. Four ticks have now done this. The declared-handoff
  path (`awaiting_verification`) exists for exactly this and does not fire, because the tickets'
  `verification_handoff:` is empty — and a run may never declare it for its own unit, which is
  what keeps `handoff` from becoming a soft landing.
- **How to Fix:** An operator or `/specificate` declares `verification_handoff:` on the three
  tickets, which moves the claim to `awaiting_verification` and stops the re-offer at the oracle.

## 6. Successful Development Patterns

- Probing the *last* candidate rather than stopping at the first refusal is what turned a
  three-tick citation loop into a closed question — a block is only finished when the alternative
  it did not try has been read too.
- Re-reading the *mechanism* after the *environment* had been closed found the second half of the
  block. A measurement that answers "can I write this ref" is not the same question as "would
  this ref decide the race", and only the first had been asked.
