## 1. Overview

`thread-reconcile` used to post `🟢 Implemented` whenever a candidate's pull request had merged,
without asking which status it merged under — so a merged `🔵 Proposed` announced the opposite of
what happened. The behaviour was repaired under issue #787 before this unit was claimed; what
remained was the fourth document, which still stated the old rule, and every test row.

**Highlights:**

1. `moderate/reference/workflow.md` §23 now states the **pair** rule for all three transitions.
2. Nine hermetic rows pin the four cases, the no-fifth-emoji gate and the agreement of all four copies.
3. The rows assert the **instruction** handed to the agent — which is where the defect lived.

## 2. Motivation

Merging a proposal lands a feedback record and a ticket set: it is the moment the work becomes
**queued**, the start of the item. Measured on a consuming repository, an operator read the green
circle as their ask being done while the ticket was still in `todo/` and the thing they complained
about was byte-identical. The step and three of its four documents were corrected; the spec was
not, so a reader of §23 was still told that a merge means `🟢 Implemented` — and nothing anywhere
would have failed if the script had drifted back to agreeing with it.

## 3. Changes

### 3-1. Pin the merged-proposal narrowing and its spec ([c81c1275](https://github.com/qmu/workaholic/commit/c81c1275))

§23 step 3 now names the three transitions as pairs of (latest status, pull request state),
carries the measurement, the *saying nothing is strictly better than saying the opposite*
reasoning, the no-fifth-emoji ruling and the stated cost; step 5's outcome list gains
`proposal_merged_is_not_a_finish`. Nine rows in the suite hold each transition, the emoji gate and
the four copies' agreement.

## 4. Outcome

All four surfaces state one rule, and a change that drifts any of them back fails by name rather
than silently. The thread of a merged proposal keeps its last true status until the work is
actually driven.

## 5. Concerns

### A queued item whose ticket is never driven has a thread that simply stops

- **Severity:** low
- **Description:** With the merged `🔵 Proposed` reply removed, a proposal that merges and is then never driven leaves its thread at the proposal shape forever (see [c81c1275](https://github.com/qmu/workaholic/commit/c81c1275) in `plugins/workaholic/skills/moderate/reference/workflow.md`). That is a true last word rather than a false one, but it is still a silence.
- **How to Fix:** Nothing yet. The additive shape — one saying the tickets are queued — is the operator's to ask for, and the catalog reasons against growing the finish vocabulary without one.

## 6. Successful Development Patterns

- Read the base before driving a ticket whose subject is a rule the repository already states somewhere: this one had landed under a different issue while its ticket was still queued, and the check turned a duplicate implementation into the two halves nobody had done.
- Pin a prose contract against the prose. Three of these rows assert on a string handed to an agent, which reads like testing a comment — but that string *is* the mechanism here, and the emoji-set assertion turns a ruling the ticket made on itself into something that fails when a later change adds a fifth shape.
