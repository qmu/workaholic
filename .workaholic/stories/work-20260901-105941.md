## 1. Overview

`verification-handoff.sh mission <slug>` read the mission file's frontmatter and nothing else,
so a mission unit whose member **ticket** declared `verification_handoff:` answered
`handoff: false` and routed as an ordinary unit. It now reads the mission's tickets too.

**Highlights:**

1. A mission unit hands off when any ticket relating to it declares the field.
2. Queued and archived tickets both count — archived is where they are at route time.
3. The `mission:` relation stays read by `read-relation.sh` alone; `grep` only narrows.

## 2. Motivation

Both places that state the contract said the opposite of what the script did. `drive/SKILL.md`
§6: *a unit whose mission or any member ticket declared `verification_handoff:` at creation
takes the handoff route*. The script's own header: *any member declaring it wins, for the same
reason `review` wins in `effective-policy.sh`: the unit is one merge*. In `mission` mode the
member set was the mission file alone, so the rule could not fire for the artifact that most
often carries the declaration. The consequence is exactly what the axis exists to prevent — an
`auto` mission whose ticket declared work nobody can verify here would merge unattended. The
run that found it escaped only because that mission's `merge_policy` was absent and the driving
session read the axis a second time by hand.

## 3. Changes

### 3-1. Read the verification axis over mission tickets ([5dd0cf31](https://github.com/qmu/workaholic/commit/5dd0cf31))

`mission` mode classifies the mission file first — so a mission-level declaration still wins and
the old behaviour is a strict subset — then every ticket whose `mission:` relation names the
slug, across `todo/` and `archive/<branch>/`. `read-relation.sh` decides each candidate;
`grep -rlF` only supplies them, because a per-file read of 1202 archived tickets is the
whole-archive walk the ticket's Considerations refuse by name.

## 4. Outcome

The measured case replays correctly: `mission deploy-the-docs-site-on-merge-to-main` now answers
`handoff: true`, names the declaring ticket and quotes the Cloudflare reason verbatim, in 87 ms.
Three other live missions were spot-checked and still answer `false`.

## 5. Concerns

### `effective-policy.sh` keeps the same shape in its mission arm

- **Severity:** moderate
- **Description:** Its `mission` arm also classifies the mission file alone, and its header
  states "any review member wins" generally (see
  [5dd0cf31](https://github.com/qmu/workaholic/commit/5dd0cf31) in
  `plugins/workaholic/skills/drive/scripts/effective-policy.sh`)
- **How to Fix:** Left alone deliberately: `CLAUDE.md`'s table sources a mission unit's policy
  from the mission's own field, and widening it would resolve every explicitly-`auto` mission
  whose tickets record nothing to `review`, stopping `auto` units from shipping. A ruling to
  widen it is the operator's.

## 6. Successful Development Patterns

- Separating the prefilter from the decision kept the one-reader rule intact under a
  performance constraint that forbids reading every file, and the test asserts the separation
  so a later "optimisation" that trusts the grep fails.
