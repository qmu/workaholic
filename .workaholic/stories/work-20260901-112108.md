## 1. Overview

`create.sh`'s collision check reads the tree it is writing into — a publish tree cut from the
base — so it is right when that tree is built and arbitrarily stale by the time it merges. It
now consults the unmerged branches too, refusing `exists_on_branch` and naming the ref.

**Highlights:**

1. The check composes `/specificate`'s existing branch walk; no API call, no second walk.
2. Only a walk that completed may refuse; a degraded one reports and creates anyway.
3. `close.sh` and the local both-areas check are untouched — neither was the defect.

## 2. Motivation

`main` carries two records with the slug `say-when-the-loop-has-run-out-of-direction`. Walking
git showed the local check was **right at both moments**: record A was created 2026-08-26
07:19:28 and record B at 08:19:15, each in its own publish tree, and the base carried no such
mission either time. B merged at 08:25:18; A merged six days later and landed beside it, with
no git conflict because B had been archived and the two occupy different paths. Two premises
the ticket originally carried were false and were corrected rather than implemented against:
`create.sh` already covers both areas, and `close.sh` already answers `archive_slug_conflict`
deliberately. The seam is the staleness, and nothing anywhere was looking at it.

## 3. Changes

### 3-1. Check a mission slug against unmerged branches ([14028be8](https://github.com/qmu/workaholic/commit/14028be8))

`create.sh` reads `.workaholic/missions/*/<slug>/mission.md` across the unmerged branches
through `lib/unmerged-branches.sh` and refuses `exists_on_branch`, naming the ref, with nothing
written. A shallow clone, a missing base ref or a non-repository reports on stderr and creates
anyway: that walk over-reads on every ambiguity by design, which is right for a dedup and wrong
for a gate.

## 4. Outcome

The measured shape is now caught where it is cheap to catch — before the second record is
written, rather than after both are on `main`. The two existing pairs are history and their
disposition stays the operator's ruling; neither record was touched.

## 5. Concerns

### A dead publication holds its mission slug until its branch is deleted

- **Severity:** moderate
- **Description:** The refusal keys on *unmerged*, so an abandoned branch counts; eight mission
  paths live on such branches here, some from 2026-08-14 (see
  [14028be8](https://github.com/qmu/workaholic/commit/14028be8) in
  `plugins/workaholic/skills/mission/scripts/create.sh`)
- **How to Fix:** Delete the dead branch — the walk's own stated semantic, and the same
  invariant the claim protocol uses. `delete_branch_on_merge` already covers the merged case.

### `mission_resolve` still answers a two-match slug with the first area it searches

- **Severity:** low
- **Description:** Scoped out deliberately: changing its return shape touches every reader that
  composes it and no acceptance criterion named it (see
  [14028be8](https://github.com/qmu/workaholic/commit/14028be8) in
  `plugins/workaholic/skills/mission/scripts/lib/resolve.sh`)
- **How to Fix:** `layout-doctor.sh` already reports each colliding pair as an advisory, which
  is the reporting need. Reopen it if a reader is measured making a wrong choice.
