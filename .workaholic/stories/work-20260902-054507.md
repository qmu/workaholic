## 1. Overview

An `[Implement]` tick walked past a full day of the developer's own work and reported `ok` every
hour. Both tickets in this mission close that state from opposite ends: one makes it **loud** at
survey time, the other makes it **visible** at preparation time.

**Highlights:**

1. `plan-units.sh` emits **`placeholder_identity`** — a fifth trustworthiness fact that forbids
   `ok`. Reproduced first: 68 artifacts excluded `owned_by_other`, nothing offered, and every one
   of the four existing fields passing.
2. `check-bootstrap.sh` reports **`identity_map_no_entry_for_account`** — the lookup the web
   bootstrap's step 0b actually performs, which the existing tree-facing audit does not imply.
3. The gating ruling deferred to this mission on 2026-08-26 is **made**: `identity_map_missing`
   does not gate `ok` either, and the reasoning is written down where it was deferred.

## 2. Motivation

Ownership is compared against `git config user.email`. A container with no resolving
`.claude/git-identities` mapping keeps `noreply@anthropic.com`, so `owns.sh` answers `other` for
every artifact and the survey returns empty `missions[]` and empty `backlog[]` — the exact
envelope the terminal-token table calls `ok`.

The survey's four trustworthiness fields all pass on that state. `owned_by_other` is its
**confident** answer and `owner_unresolved` is its *cannot tell*; this was a third state neither
covers — it could tell, and the thing it compared against stands for nobody.

`/workaholify` had the same shape of blind spot one layer up. It installs the hook and, since
2026-08-26, audits whether the mapping exists and whether it covers the addresses the tree uses.
Step 0b asks neither of those questions: it resolves the session's GitHub **login** and looks up
`^<login>=`. A repository can pass both existing checks and still leave a routine's own account
unmapped.

## 3. Changes

### 3-1. `placeholder_identity`, and the token consequence

Derived in `plan-units.sh` beside `ME`, from an **empty** identity or a **known placeholder
domain**, with the domain set as one shell list so a future default is a word to add rather than a
field to wire. It **excludes nothing of its own**, drops no artifact, and leaves `owns.sh`'s
comparison untouched — the whole change is a named fact and a token consequence. §7's table gained
its row, §1's "four conditions" is now five, and both §7 and `CLAUDE.md` require the report to
**name the fact** rather than emit a bare `pending`.

### 3-2. `identity_map_no_entry_for_account`, extending one set rather than adding a rival

The 2026-08-26 audit's header asked a later session to extend its named-problem set, and this is
that extension. The login is **passed in** (`--account`), so the audit stays a pure local read and
the whole set stays hermetically testable; `check-bootstrap.sh` resolves it. The check is
**three-valued** — with no login the account reads `checked: false` with its own reason and raises
nothing, because a check that could not run is neither a pass nor a finding — and an absent map
stays `identity_map_missing` rather than being reported twice about one file.

`apply-bootstrap.sh` proposes the account's line as a **comment**, with the placeholder on the
**address** side, since here the login is the known half and the address is the one only a person
has.

### 3-3. `WORKAHOLIC_BOOTSTRAP_ACCOUNT`, an override rather than a default

The check now asks a question only the network can answer, so every fixture running it would have
made a real `gh api user` call — breaking this suite's standing promise to touch no network, which
surfaced immediately as two pre-existing assertions going red. The variable is tri-state on
**presence** (exactly as `WORKAHOLIC_CLAIM_IDENTITY` is), set to empty once at the top of the suite
so every fixture reads the honest *unchecked* answer. One case leaves it unset behind a stubbed
`gh`, so the resolution itself stays covered rather than routed around.

## 5. Concerns

### The placeholder domain list is a bet on somebody else's default

- **Severity:** low
- **Description:** `anthropic.com` is matched because that is what the container keeps today. If
  that default changes, the field silently stops firing on the state it was built for — and it
  fails *open*, back to reporting `ok`.
- **How to Fix:** The set is one shell list on one line in `plan-units.sh`, so a new default is a
  word to add. The empty-identity half is not a bet and keeps working either way.

### The mapping's advisories can persist indefinitely, by design

- **Severity:** low
- **Description:** None of the three mapping problems gates `ok`, so a repository can carry all
  three for as long as nobody writes the line. That is deliberate — each is settled by a human
  fact this plugin does not have — but it means `/workaholify` can report `ok` over a repository
  whose next routine tick will still run under a placeholder identity.
- **How to Fix:** The survey half of this mission is what catches that at the moment it matters:
  the tick itself now refuses `ok` and says why.

## 8. Notes

The two tickets were written as complements and read that way when driven: neither replaces the
other, because a repository can be missing the mapping for hours before a tick runs, and a tick can
run in a repository nobody has re-workaholified. Ticket 1's fix fires where the cost is paid;
ticket 2's fires where the repair is made.
