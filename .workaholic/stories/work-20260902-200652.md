## 1. Overview

`base-health` reported `base_unreadable:tip_no_checks` every tick for a day while the base was
green throughout: this loop's bookkeeping commits are excluded from every workflow's path filter,
so the tip is *usually* a commit nothing ran on, and the walk returned before it began. The
mission's three tickets close that from the walk, the report and the drill.

The mechanism itself had already reached `main` through issue #785 while these tickets sat queued
— the shape `/moderate`'s `unrecorded-missions` step exists to notice. This branch verified each
acceptance criterion against the checkout rather than rewriting it, and wrote the halves that were
genuinely missing.

**Highlights:**

1. Verified the walk: `no_checks` continues, keyed on the reader's own `reason` read out of its
   JSON; every other unanswerable stays terminal; a skipped commit never becomes an attribution;
   `read-base-checks.sh` is byte-identical.
2. Wrote the reader-facing half of the distance — `drive/SKILL.md` §7 and `CLAUDE.md` now name
   **which commit the colour was read at and how far behind the tip**, absent when it was read at
   the tip itself, stated and never thresholded.
3. Gave `verify-base-health`'s two walk-past assertions their **blame rows**, so a red drill sends
   a reader to the file rather than to the drill's body.

## 2. Motivation

One word was doing two jobs. `no_checks` is a fact about the **commit** with a defined answer one
step back; `reader_failed`, a rate limit or a refused transport are facts about **us**. Collapsed
into a single terminal `unanswerable`, they made the reading unreachable exactly where the loop is
busiest — the step that exists to notice a broken base was dark for a day and a half, and looked
from the outside like a healthy quiet step.

Once the walk continues, the answer is about an **ancestor**. A reader not told so reads it as the
tip's, which is the guess the three-valued reader exists to prevent.

## 3. Changes

### 3-1. The walk, verified rather than rewritten

`attribute-base-red.sh`'s tip `case` continues only on `no_checks` and emits `tip_<reason>` for
everything else; inside the walk a `no_checks` commit is skipped and any other unanswerable emits
`walk_<reason>` and stops. The bound is untouched — an exhausted walk still answers
`bound_exhausted` rather than guessing — and `oldest_red` only ever holds a commit the reader
answered `red` for.

### 3-2. Where the colour was read, on both report surfaces

`drive/SKILL.md` §7 and `CLAUDE.md`'s run-report clause now carry `checked_at` / `checked_behind`
beside the colour, in one wording: which commit, how far behind, **both absent at the tip** so a
repository whose tip carries checks reports exactly what it reported before. The distance is
**stated and never thresholded** — a threshold nobody chose is how a reading becomes a verdict —
and it moves no token and gates nothing, exactly as the colour does.

The script halves were already right and were verified, not touched: the walk emits both fields,
and `step-base-health.sh` renders them in its `summary` only, with no timestamp and no age, its
`event` staying empty for a green base whatever the distance.

### 3-3. The drill's blame rows

The two assertions live in `verify-base-health` rather than in a new arm — the ticket's own
Considerations ask for exactly that ("reuse whatever seeder the first ticket's reproduction built"),
and that drill already seeds a bare origin, a five-commit base and a per-commit `gh` stub. What was
missing was the runbook's failure-reason to file mapping, so `base_health_walks_past_a_checkless_tip`
and `base_health_only_no_checks_is_walked_past` each gained a row written against the behaviour and
naming the measured failure it guards. The operator-procedure line and the drill's own
`WHAT IT PROVES` header now name the bookkeeping tip.

No matrix leg was added and none was needed: `loop-drills.yml` derives its matrix from
`verify-all --list --kind hermetic`, and this drill is already in it as `hermetic` with a breaker.
