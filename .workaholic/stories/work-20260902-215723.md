## 1. Overview

`validate-ticket.sh` decided whether a written file lives inside `.workaholic/` by looking for that
segment **anywhere in the absolute path**. Since the loops moved into clones under
`~/.workaholic/loops/<repo>/<loop>`, every path in a loop clone carries `.workaholic/` before the
repository root is even reached — so the hook read the clone's own directory name as an
undesignated area and warned on **every** edit a loop session made.

**Highlights:**

1. The classification is now **repository-relative**: the root is resolved through
   `git rev-parse --show-toplevel` and the path expressed against it, with today's answer kept
   whenever no root resolves.
2. The **same defect one layer down**: `missions_root_from_artifact` used `%%` and so cut at the
   *earliest* `.workaholic/`, resolving a loop-clone artifact to `/home/<user>/.workaholic`.
3. Four hermetic rows, driven from a fixture that actually nests — the shape no ordinary checkout
   reproduces.

## 2. Motivation

The warning blocked nothing, which is why it looked harmless. What it cost is the signal: a guard
that fires on every edit makes *you wrote outside the layout* mean nothing, and a session that
trusted it would stop. Measured on `work-20260902-193702`: an `Edit` to
`plugins/workaholic/skills/drive/scripts/lib/claims.sh` — a file with nothing to do with
`.workaholic/` — answered `undesignated subdirectory 'loops/'`.

## 3. Changes

### 3-1. `rel_path`, derived once

The nearest **existing** ancestor is resolved to a repository root (a `Write` creates directories
that do not exist at hook time), and the path is expressed relative to it. The three tests that ask
*where does this file sit inside the repository* — ticket shape, layout gate, ticket location — read
`rel_path`; the `Got:` line keeps the absolute path, which is what a person needs.

**A path with no resolvable root keeps today's answer.** Falling silent there would trade a noisy
false positive for a quiet false negative, which is the worse of the two.

### 3-2. `missions_root_from_artifact` cuts at the last `.workaholic/`

`${1%%.workaholic/*}` removes the *longest* suffix, so it cuts at the **earliest** occurrence — the
artifact's own tree only while nothing above the repository root is called `.workaholic`. `%` cuts
at the last; on a path with one occurrence the two are identical, so no ordinary checkout changes
behaviour. The deriver is reached from this hook **and** from `archive.sh`, so repairing only the
hook would have left the loop's own archive path resolving into a directory that is not a
repository.

### 3-3. What was checked and left alone

`layout-doctor.sh` takes a root and enumerates its children — it never classifies an absolute path
by string. The sibling validators anchor on a **designated area name**
(`*.workaholic/missions/*/mission.md`, `*.workaholic/stories/*.md`, …), which a loop clone's outer
path cannot match. Only `validate-ticket.sh` matched on the bare `*.workaholic/*`.

**Moving the loop home is not the repair** — a ruling, not an omission: a clone may sit anywhere a
developer puts it, so the next such path would reopen this.

## 4. Outcome

The false positive is gone and the true positive is unchanged, both demonstrated rather than
asserted — the ticket's own gate.

- `node scripts/test-workflow-scripts.mjs` → **6219 passed, 0 failed** (4 new rows)
- The three acceptance cases reproduced offline under a real `.workaholic/loops/...` path
- `layout-doctor.sh` clean; `outputs/` regenerated; `verify.mjs` and `validate-metadata.mjs` clean

## 5. Concerns

### The `%%`-versus-`%` class was fixed at two sites, not swept

- **Severity:** low
- **Description:** Both forms read as "strip from `.workaholic/`" and are identical on every
  ordinary checkout, so the defect is invisible to review until a fixture nests. Two sites were
  found by reading this hook's call graph; the repository was not swept for the class.
- **How to Fix:** Grep for `%%.workaholic` and `#*.workaholic` as a class. Not done here because a
  sweep is its own ticket and this one asked for a classifier that reads the root.

## 6. Successful Development Patterns

Reproducing first, in a fixture that actually nests, is what turned a one-line hook change into a
two-site repair: the second defect was only visible from a path the ordinary checkout can never
produce.
