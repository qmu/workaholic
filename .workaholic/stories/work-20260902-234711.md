## 1. Overview

`scripts/test-workflow-scripts.mjs` registered every test **twice** — a `function test…()` body,
and a row in a single `const tests = [` array 22,000 lines away. Every unit this loop drives adds
both, so **two units driven concurrently collided by construction**, at the same two anchors,
whatever they had actually changed. Measured: three pull requests (#890, #899, #900) unmergeable
for a day, on exactly one file, two hunks, both disjoint appends.

**Highlights:**

1. The array is gone. A test is now one function plus one adjacent `T("<label>", testFn);` line —
   **one region of the file** per new test.
2. The conversion surfaced two real defects that both produced a **green run with 115 tests
   silently not executing**; both are fixed and recorded in the file's own header.
3. The 400 labels are byte-identical to the array's, compared mechanically against `HEAD`.

## 2. Motivation

`conflict-class.sh` calls this collision `content` and is right to — a hand-written file can carry
a real disagreement, and `.gitattributes`'s own header argues against extending `merge=union` here.
So the repair removes the **occasion** rather than widening the classifier, which is exactly what
the union driver did for the generated indexes. The array is the anchor with no information in it:
a row is mechanically implied by its function.

## 3. Changes

### 3-1. Registration beside the declaration

`const tests = []` and `function T(label, fn)` are declared once near the top; each test's row moved
to a `T(…)` call on the line **above** its own `function test…()` declaration. The 400 bodies are
otherwise untouched, and the label survives because a function name cannot carry a sentence.

### 3-2. Two defects the conversion found

**A column-0 `}` is not a function boundary in this file.** The first attempt registered *below*
each body by scanning for the next unindented closing brace — but 115 of the 400 bodies contain one
inside a template literal (a shell snippet, a JSON fixture), so the call landed mid-body and only
ran if that test ran. Measured: 285 of 400 registered. Anchoring on the declaration is unambiguous
and works because a function declaration is hoisted.

**The runner had to move to the end of the file.** Registration now happens in file order at module
load, and 115 tests are declared *below* where the array sat — so leaving the loop in place ran 285
and skipped the rest. That is the failure the file's own `await` note was already written against:
*a test that does not run is worse than one that fails.* The header now states that anything
appended after the runner never executes.

Both produced a **green** run. The check that caught them was the section count against the array's
length, not the pass count.

## 4. Outcome

- `node scripts/test-workflow-scripts.mjs` → **400 sections, 6236 passed, 0 failed**
- The 400 labels compared mechanically against `HEAD`'s array: **0 missing, 0 added**; the array no
  longer exists
- `build.mjs`, `verify.mjs`, `validate-metadata.mjs` clean; `layout-doctor.sh` reports only the
  pre-existing advisories
- `CLAUDE.md`'s *Local Verification* section is unchanged — the invocation did not move

**The Open Decision is ruled**: remove the array alone, not name-ordered placement. The array is the
anchor *every* unit touches; append-at-end-of-file only collides when two units append in the same
window, and its residue is a genuine "keep both functions" a person resolves in seconds. Name
ordering buys rarer collisions at the price of a convention nothing enforces and a diff that no
longer shows new tests together. Splitting the suite per area stays the operator's call.

## 5. Concerns

### The remaining anchor is the end of the file

- **Severity:** low
- **Description:** Two units that both append a test still collide there. The conflict is now a
  keep-both rather than a four-way one, but it is not zero.
- **How to Fix:** Nothing here. If it proves to bite, the operator's fork — one file per area —
  removes the occasion entirely.

### This unblocks none of the three stuck pull requests

- **Severity:** moderate
- **Description:** #890, #899 and #900 still need a person to merge `origin/main` while keeping both
  sides in the suite file. That judgement is reserved to a person by the claim protocol and an
  unattended run must not take it.
- **How to Fix:** A person merges those three. After this lands, the *next* units will not
  reproduce the collision.

## 6. Successful Development Patterns

Counting what actually ran, rather than trusting a green exit code, is what turned a "successful"
conversion into two found defects. A refactor that changes *when* code executes should always be
checked against the count it was supposed to preserve.
