## 1. Overview

An unattended routine that waits on a person is worse than one that fails, and `[Propose]` was
doing exactly that — parking hourly on a permission prompt while leaving no trace anywhere,
because it wrote no log at all. This branch closes both halves of that: the tick is now visible as
parked, and the reach that raises the prompt is removed from the surfaces a routine session reads.

**Highlights:**

1. `/propose` writes `propose-open` and `propose-close`, and `step-blocked-tick.sh` reads that pair
   as a second subject under its own question key — one step, two subjects, no second reader.
2. The stateless thread lookup is carried **byte-identical** inside `/implement` and
   `/specificate` rather than named, so a routine session never resolves a reference at run time.
3. The prompt-raising shape — `sed`, `grep`, `cat`, `head` over a plugin path — is named in
   `CLAUDE.md`'s enforcement gate, not merely implied by a principle.

## 2. Motivation

The mission was written against a measured failure: `[Propose]` sat at `requires_action` hourly on
records recreated fresh the day before, and the same class had been measured on `[Moderate]` — three
consecutive ticks parked on a prompt raised by two reads. A parked tick spends its fire, produces
nothing, and reads as scheduled and healthy, which is the half of the failure that let it run for
hours. Worse, the routine that parks is the one that *originates* the loop's work.

The diagnosis ticket had already ranked two candidates it could not separate, and named a scope
correction: `[Propose]` absorbed `[Specificate]`, so the routine that parks runs two commands in one
session. What this branch does is remove the reach on both of their ceilings and make a recurrence
legible within two ticks — rather than working around a prompt, which the operator's instruction
explicitly refuses.

The repository had already learned the shape of the repair from the language rule: a ceiling
outranks a general document read earlier. Issue #865's own fix walked into the trap it was closing —
it moved the reach off `sed` and onto the Read tool, which the repository's allowlist covers *less*.
That is why the answer here is to remove the lookup rather than to permit it.

## 3. Changes

### 3-1. Pin that no command sends a session to read a plugin file by reference ([67e51583](https://github.com/qmu/workaholic/commit/67e51583))

Added the suite scan over every command body and every skill body for the measured must-read shape
— *see `workaholic:notify`, *section** — with the four cases asserted together, so a row that only
proves it fires proves nothing about what it would stop.

### 3-2. Make a parked routine tick visible as parked ([77da2dd2](https://github.com/qmu/workaholic/commit/77da2dd2))

`/propose` now opens with `propose-open` and closes with `propose-close`, and `step-blocked-tick.sh`
reads that pair as a second subject of the step it already runs, keyed `blocked-tick:propose:<tick>`
so the two arms are asked and settled separately. The decision to widen `/propose`'s pure-reader
contract is recorded with its cost where that contract is stated.

### 3-3. Name the prompt-raising read shape in the gate ([d133c995](https://github.com/qmu/workaholic/commit/d133c995))

`CLAUDE.md`'s enforcement gate stated the principle and named no shape, so the repository's own
statement was weaker than the plugin's. It now names the readers, the reason, the measured line and
that no hook enforces it.

### 3-4. Carry the thread lookup in the commands running it ([2f9c5092](https://github.com/qmu/workaholic/commit/2f9c5092))

The two commands whose runs perform the stateless lookup carry its ordered cases and its two bounds
verbatim, pinned against the source; the two that never run the search deliberately do not, asserted
in both directions.
