## 1. Overview

The base was red for about an hour and nothing surfaced it, through two independent mechanisms.
Both are now closed, and neither fix touches what the loop *does* about a red base — it still
drives onto one, deliberately.

**Highlights:**

1. **A suite that never ran is named, not absorbed.** `read-base-checks.sh --declared` answers
   `unverified[]` — the declared workflows with no run on the commit — **beside** the colour.
2. **Both surfaces report it**, on the green, red and `unanswerable` paths alike, because a tip can
   carry a green verdict and an unverified suite at once.
3. **A red base is a `🔴 Blocked` report, not a question.** The `base-red:<commit>` question is
   retired; the announcement now rides the existing failure-signature cool-down, which is composed
   rather than re-derived.

## 2. Motivation

The colour was taken over the verdicts a commit **carries**. A declared workflow that did not fire
leaves none, so it contributed to no branch of the reader and the answer came from whatever else was
there — the final `emit green` asks only *did anything fail*, never *did everything run*. Measured:
a path-filtered workflow did not run on a commit that broke the suite it guards, the newest verdict
there was a different, green one, and the base read `green` for about an hour.

Separately, a red base that *was* caught correctly was announced as a `base-red:<commit>` question,
and `ask-question.sh` holds questions under `WORKAHOLIC_QUIET_HOURS` — rightly, because a question
addresses a named person and nobody should be paged at 23:00 to choose between two dates. So the
loop built on the broken base all night while its own announcement waited for morning.

## 3. What changed

**The reader.** `--declared` is opt-in because it costs a second REST call; `attribute-base-red.sh`
walks commit after commit and passes no flag, so the attribution walk's cost does not move. The
declared set is *a workflow whose `on:` block names `push`*, read with `awk` over that block alone.
A degraded declared-read answers `unverified_readable: false` with a reason and a **null** set —
never an empty array, which means *every declared suite ran*.

**Both surfaces**, and the token decision made out loud: an unverified suite **moves no token**, on
the base colour's own long-standing reasoning — it is a fact about the repository, not about the
unit this run drove, and withholding `ok` would put the token out of reach for as long as a path
filter keeps a workflow from running, which is indefinitely.

**The report.** The step's payload now names `report_the_red_base_as_a_blocked_alert` with the
`🔴 Blocked` shape and a signature of the failing check names. The attribution walk is untouched:
who broke it is still `attribute-base-red.sh`'s answer and rides the report's sentence.

## 4. Concerns

**A path-filtered workflow will read `unverified` on most commits.** That is deliberate and is the
measured defect rather than an exemption — its filter is *why* it did not run, and *it did not run
here* is the fact that went unseen. What is exempt is a workflow that structurally cannot run on a
base commit. The cost is a recurring clause on the tick's summary; the alternative was exempting the
one case the mission exists for.

**The signature deliberately collapses distinct red commits.** Two commits failing the same suite
produce one alert, because the cool-down's own rule forbids a SHA in a signature — a key that
changes every commit suppresses nothing. A newly broken suite still opens a fresh root.

**Retiring the `base-red` question is a judgement, not a mechanical consequence.** The ticket asked
for it to be decided out loud: keeping both would be two announcements of one fact, which this
repository has twice retired status roots for, and the report reaches the channel when the base
breaks rather than the next working morning.

## 5. Successful development patterns

**The new word did not fit the vocabulary check, and the fix was to teach the check the shape rather
than to hand it a list.** The base-checks table is pinned by parsing the two scripts' own `emit`
calls — proving the scripts say what they emit. `unverified` is emitted as a **field** rather than a
state, so the extraction learned that form explicitly; adding the name to a literal list would have
proved only that the list matches itself.

**Three suite rows pinned the behaviour being retired, which is the mechanism working.** Each was
rewritten to the new contract and each is strictly *more* specific than the one it replaced — the
red-base row now asserts the absent question key, the action word, the shape, the SHA-free signature
and that the bound names the quiet window. A retirement that costs nothing to prove is a retirement
nothing was guarding.

**The live tip proved the reading before any test did.** Running the new reader against this
repository's own `origin/main` answered `Docs Deploy` unverified — because the merge that made that
tip touched no `docs/**`. The defect class reproduced on the first commit it was pointed at.
