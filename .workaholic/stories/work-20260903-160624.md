## 1. Overview

The two `json_escape()` functions left out of the deployment-plan repair now carry the same
three-interpreter chain, so a Japanese squash title and a probe's Japanese output reach their
readers as text. The `sed` fallback was removed rather than patched — measured, it emitted raw
control bytes a JSON string may not hold, so it could never agree.

**Highlights:**

1. `merge-commit-body.sh` and `run-verification-probe.sh` escape non-ASCII as raw UTF-8.
2. Both rungs of each escaper return identical bytes, pinned by a shimmed-interpreter case.
3. A second, unfallbacked `python3` dependency in the same file was ticketed, not widened into.

## 2. Motivation

Both copies sit on human-facing paths: one composes the squash title and body of every merge this
loop makes, writing onto the trunk's permanent record; the other carries a probe's captured output
into `## Handoff` and the `🟡 Handoff` post. And the defect was never the escaping alone but the
**disagreement** — each function's `python3` branch ASCII-escaped while its `sed` branch did not.

Ticket `20260903053345` repaired the same shape across the three `ship/` scripts a day earlier,
after a Japanese deployment title reached a plan as `リポ...`. These two were left alone
deliberately: that sweep named deployment fields and the release-note render, and these carry
neither.

## 3. Changes

### 3-1. Agree the two remaining JSON-string escapers on raw UTF-8 ([e2f596eee](https://github.com/qmu/workaholic/commit/e2f596eee))

Both functions now carry `read-deployments.sh`'s `python3` → `node` → `perl` chain with the outer
quotes trimmed, since these two emit the *interior* of a JSON string and their own `printf`
templates supply the quotes. Each script gained a hermetic case asserting a non-ASCII value
survives as characters and that forcing the second rung returns the same bytes.

## 4. Outcome

Both scripts now emit non-ASCII as characters and control characters as valid escapes, on
whichever interpreter is installed. Nothing that parses their output changed — raw UTF-8 was
always valid JSON — but the consumers that lift a value back out as text now get text.

## 5. Concerns

### The squash body's housekeeping filter has no fallback

- **Severity:** moderate
- **Description:** A second `python3 -c` guarded by `|| true` and no fallback drops housekeeping commits from the subject list; shimming `python3` to exit 127 dropped the whole list while `source` still read `story` (see [e2f596eee](https://github.com/qmu/workaholic/commit/e2f596eee) in `plugins/workaholic/skills/gather/scripts/merge-commit-body.sh`)
- **How to Fix:** Ticketed `20260903162400-give-the-squash-body-s-housekeeping-filter-a-fallback` — give the filter rungs of its own, and make one that could not run say so.

## 6. Successful Development Patterns

- Forcing a fallback rung with a `PATH` shim that exits 127 tests an interpreter chain on any machine — it is what proved the two rungs agree, and what surfaced the unrelated gap beside them.
- Asserting the repair at the script's own JSON boundary rather than at the escaper makes parseability and encoding one assertion: the test must parse the output to read it.
