## 1. Overview

`merge-commit-body.sh` composes the squash title and body of every merge this loop makes. Its
housekeeping filter — the step that keeps a unit's claim stamp and heartbeats off the trunk — was a
`python3 -c` program under `2>/dev/null || true` with no fallback rung, so on a machine without that
interpreter the commit list was dropped in full and the composer still reported `source: story`.

**Highlights:**

1. The subtraction needs no interpreter at all now: the whole body is byte-identical with `python3`
   present and with it shimmed to exit 127.
2. A named reason outranks a story that was read, so a dropped or unwalkable commit range reports
   `unreadable:<reason>` while the story's description is still the body.
3. That reordering also made the pre-existing `no_commit_range` word reachable — it had been
   unreachable whenever a story resolved, which nothing had noticed.
4. A walk that fails now has a word of its own (`commit_walk_failed`) instead of `|| true`.

## 2. Motivation

Ticket `20260903064753` repaired this script's `json_escape()` by pinning three interpreters against
each other, and measured a second `python3` dependency in the same file that it deliberately did not
sweep — writing the non-comparison into the suite and naming the ticket that would close it. This is
that ticket. The defect is the same shape the escaper's was: one behaviour with two paths that
disagree, so which answer a caller gets depends on what is installed.

Reproduced before anything was changed. Against a branch carrying one marked and one unmarked
commit, the composer returned `"A description line\n\n* Add a story\n* Implement the thing"` with
`python3` on `PATH` and `"A description line"` with it shimmed to exit 127 — `source: story` and
`reason: ""` both times, so nothing anywhere said the list had been dropped.

## 3. Changes

### Drop the squash filter's interpreter dependency ([a17d5c66](https://github.com/qmu/workaholic/commit/a17d5c66))

The filter's `python3` program is **removed rather than given rungs**. The escaper one function over
needed three interpreters because escaping a JSON string is beyond `sed`; set subtraction and an
order-preserving dedupe are `case` and string append, so the honest repair is to delete the
dependency — one path cannot disagree with itself, which is the property rungs are bought to
approximate. Both membership tests are exact by construction and the header says why: a 40-character
object name cannot be a proper substring of another, and a `%s` subject cannot contain a newline.

The two `git log` walks are no longer swallowed by `|| true`; a walk that did not run sets
`subject_reason: commit_walk_failed` and is named.

And the assembly now tests the reasons **before** the description. `story` is the word for a
complete read, so a run whose commit list was dropped may not claim it. The body is unchanged by the
reordering — the story's description is still the best body available and is still used — and a
reason only changes what the composer *says* about it, so the merge is still never held on the body.

Five hermetic rows landed with it: the whole body byte-identical across the shimmed rung, the list
still present, the source unchanged, and a story whose range could not be read reporting
`unreadable:no_commit_range` while keeping its description. The suite's deliberate non-comparison
note is gone. Seven prose restatements of the composer's guarantee (`CLAUDE.md`, the `/implement`
ceiling, `drive/SKILL.md` and four caller headers) now say *a body* rather than *a fallback body*,
because a degraded read may now hand back the story's own description.

### Bump version to v1.0.304 ([d630a0aa](https://github.com/qmu/workaholic/commit/d630a0aa))

Patch bump across the four version files, with `outputs/` regenerated. The base had reached
`1.0.303` while this branch was driving.

## 4. Outcome

Every merge this loop makes now composes the same trunk record on any machine that can run `git`,
and a composer that could not read what it needed says so in a word rather than by handing back a
shorter body. The gap the escaper's repair left open in the same file is closed, and the suite
compares the whole body across the rungs instead of writing down why it does not.

## 5. Concerns

### `json_escape()` still returns empty with all three interpreters absent

- **Severity:** low
- **Description:** The escaper's last rung (`perl`) is unguarded, so with `python3`, `node` and
  `perl` all absent the composer emits `{"ok": true, "title": "", "body": "", "source": ""}` —
  silently, and `ok` still reads true. Observed while shimming for this ticket; it is the escaper's
  own contract rather than the filter's, and outside this ticket's scope.
- **How to Fix:** Not ticketed deliberately. This repository's own verification requires `node`, so
  the state is unreachable where the loop runs and a ticket would be a diary entry rather than an
  observed problem. Recorded here so a future measurement starts from a known fact.

## 6. Successful Development Patterns

- The two repairs to one file are opposites and both are right. Asking *is this work beyond `sed`?*
  is what picks between adding rungs and deleting the dependency — a later reader meeting a third
  `python3 -c` in this tree should ask it before copying either answer.
- Reproducing first paid immediately. The reproduction is what showed `source` reading `story` over
  the dropped list, which turned a one-function repair into a precedence bug the ticket had not
  known about — and that bug had been hiding the pre-existing `no_commit_range` word too.
