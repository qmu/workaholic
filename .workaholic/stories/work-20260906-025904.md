## 1. Overview

The tick log stopped being committed anywhere on 2026-09-03, but the three tickets meant to
*guarantee* that were written the day before, against machinery the retirement then deleted. This
branch resolves them against the tree as it stands.

**Highlights:**

1. `persist-log.sh` refuses a record naming a `.workaholic/moderations/` path — `log_destination_is_base`, nothing written — keyed on the destination, never on migration state.
2. `step-open-log.sh` reads whether day files are still *tracked* on the base, which a later `.gitignore` never undoes, and raises a finding filed once instead of restated hourly.
3. The writer set is derived from the tree and pinned by the suite and a new hermetic drill.

## 2. Motivation

The measured failure was twelve days of silent hourly accumulation on a consuming repository —
hundreds of `Log the * tick` commits, twelve day files, roughly seven thousand lines — ended only
when the operator ran `/workaholify` by hand. The retirement removed the *mechanism*; these tickets
are what makes it hold: a refusal that cannot be defaulted past, a reading of what was left behind,
and a guard covering every writer. It also deleted the machinery two of them name, so the work was
to find what their acceptance still means here rather than to restore it.

## 3. Changes

### 3-1. Refuse the base as a tick log destination ([77cca890e](https://github.com/qmu/workaholic/commit/77cca890e))

The enumeration the ticket asked for found exactly one road left from this writer to the base: the
`--record` path, which carries whatever a caller names. A record naming a day file would therefore
put the log back on `main` through the publication seam, so `persist-log.sh` now refuses it by name
before the publish tree is opened, writing nothing and exiting 0 so the tick reports it as a named
degradation. `--record`'s ordinary base write for feedback records is untouched.

### 3-2. Cover every writer of the tick log ([c35a2c6df](https://github.com/qmu/workaholic/commit/c35a2c6df))

The accumulation carried two commit vocabularies on one set of day files, so the guard is pinned to
the writer set rather than to a tick's name: every shell script whose *code* names the log is
declared with a role, exactly one is a `writer`, and the roles are proved by running the writer and
the opener rather than by grepping for a redirect. `verify-log-off-base` drills that derived set
offline with a breaker written against the behaviour. The enumeration's own finding was the live
defect: `commands/moderate.md` still told the tick its closing act *puts that log on the base*.

### 3-3. Read whether the tick log is on the base ([ebadb607d](https://github.com/qmu/workaholic/commit/ebadb607d))

A `.gitignore` added after the fact never untracks what is already tracked, so `step-open-log.sh`
now reads it and raises `log_tracked_on_base`. It moves nothing, and that is the design rather than
the fallback: the mover was deleted with the branch, `/workaholify`'s converge seam takes no
migration that reaches the network, and the acceptance is disjunctive — land the move **or** raise a
finding. The reading is three-valued: a root that is no repository is not a degradation.

## 4. Outcome

The log cannot reach the base by the one route that remained, says so when it finds the residue of
the route that used to, and is guarded by an enumeration the tree proves. Suite 6635/0, drills 48/0.

## 5. Concerns

### The drill file is over the per-file size ceiling and every drill grows it

- **Severity:** moderate
- **Description:** `scripts/e2e/loop-drill.sh` is 691,974 bytes against a 524,288-byte ceiling, and the branch-safety scan reports `large-file` on it; this branch added ~117 lines to it (see [c35a2c6df](https://github.com/qmu/workaholic/commit/c35a2c6df) in `scripts/e2e/loop-drill.sh`). The finding is `override`-tier so it holds nothing, but it is now reported on every branch that adds a drill, which is the state in which a warning stops being read.
- **How to Fix:** Split the dispatcher from the drill bodies — one file per drill under `scripts/e2e/drills/`, sourced by the dispatcher — or add the path to the generated/exempt set with the reason stated, so the scan says something true either way.

### The writer-set assertion covers literal paths only

- **Severity:** low
- **Description:** The enumeration finds a log path only where it is spelled literally in a script's code; a path assembled through an interpolated variable escapes it (see [c35a2c6df](https://github.com/qmu/workaholic/commit/c35a2c6df) in `scripts/test-workflow-scripts.mjs`). The limit rides the assertion's own name, following the jq-compilation row's precedent, so it is stated rather than implied.
- **How to Fix:** Nothing mechanical closes it without evaluating the shell. If it ever matters, the honest repair is to make the log directory reachable only through one exported constant and pin *that*.

## 6. Successful Development Patterns

- Enumerating from the tree before writing the guard found the real defect, and it was prose rather than code: a stale command ceiling outranks a correct script, because an unattended session reads the ceiling first.
- Proving a script's declared role by *running* it — the opener must leave the day file unwritten, the writer must write it — survives a refactor that changes which variable the redirect names, where a grep for `>>` does not.
- A step that grows its first finding must be re-classified in the findings table in the same change; the table's unclassified default would otherwise raise the finding and file it with nobody.
