## 1. Overview

`archive.sh`'s close gate refused a mission at full acceptance whenever an acceptance item's ticket
carried a `verification_handoff:` line, reading its **presence** rather than its form — so a
`probe:` declaration the run's own probe had answered `clean` held a finished mission open.

**Highlights:**

1. The measurable/prose split lives in the **consumer**, leaving the one reader unchanged.
2. The refusal names which form held it, and names the probe declarations beside it.
3. The gate deliberately does not run the probe; the three reasons sit with the code.

## 2. Motivation

This mission drained at 3/3 and was held open by its own gate, naming a ticket declaring
`probe: command -v codex` — which `run-verification-probe.sh` had answered `clean` in that same
run, against an installed CLI. The verification was performed and a person was asked to repeat it:
the unfalsifiable-blocker failure this mission exists to end.

It is the presence-versus-probe conflation the mission already fixed one layer down in
`claims_declared_handoff`. The close gate was not part of that change and still read presence.

## 3. Changes

### 3-1. Read the probe before holding a mission open ([a25defd5](https://github.com/qmu/workaholic/commit/a25defd5))

`acceptance-handoffs.sh` reads `measurable` off the one reader's own answer and returns a `probe:`
declaration under a new `measurable_tickets[]` instead of setting `handoff`. Prose holds the close
unchanged, and an unreadable reading holds too — an absence is never a clean probe.

## 4. Outcome

The mission closed `achieved` at its own archive seam, on arithmetic the run had already proved —
the reproduction the ticket demanded, re-run and now closing. `close.sh` stays the only writer of
an end state.

## 5. Concerns

### A blocking probe no longer refuses the close either

- **Severity:** low
- **Description:** The split is by form, not outcome, so a `probe:` that would read `blocking` also
  stops holding this gate (see [a25defd5](https://github.com/qmu/workaholic/commit/a25defd5) in
  `plugins/workaholic/skills/mission/scripts/acceptance-handoffs.sh`). `/drive` §6 has already
  routed such a unit to handoff with its pull request open.
- **How to Fix:** Nothing unless a mission is measured closing over a blocking probe; the repair
  would be to run it at the gate, which this change refuses by name.

## 6. Successful Development Patterns

- Fixing the conflation in the **consumer** let `/drive` §6 keep the answer it routes on — the
  second consumer to take this shape, so the precedent was citable rather than re-argued.
- Recording *why the gate may not run the probe* beside the code turned an omission a later reader
  would have "fixed" into a decision with stated grounds.
