## 1. Overview

`tick-progress.sh` resolved its sibling readers against the repository being *read* rather than
against itself, so on a consumer that does not vendor the plugin both calls failed and the
swallowed failure was rendered as data — in two halves, the second invisible until the first.

**Highlights:**

1. Siblings resolve through `SCRIPT_DIR`; `queue-size.sh` is handed the root it already accepts.
2. An unreadable row carries `readable: false`, a named reason and null counts — never a zero.
3. `propose_gate` is three-valued: an unreadable row can no longer produce `open`.

## 2. Motivation

The operator measured eight consecutive readings over ~50 minutes against two active missions:
every per-mission field `null`, `draining: false` against six archived tickets, `gating_missions`
at 0 against 2, `propose_gate: open`. Two of those were *wrong answers* rather than absent ones —
`draining` read *nothing has ever landed here*, and `gating` incremented only on `.todo > 0`, so a
null todo could never gate. A caller acting on `open` originates work against a queue that is not
draining, the exact state the gate exists to prevent.

## 3. Changes

### 3-1. Make the tick's progress reading see, and name what it cannot ([5b395ac11](https://github.com/qmu/workaholic/commit/5b395ac11))

Resolved the sibling readers against the script's own location, passed `queue-size.sh` the
`.workaholic` root it already accepts, absolutized `ROOT` once where it is assigned, and replaced
the `// null` defaults with a named degradation. Added the script's first coverage in
`test-workflow-scripts.mjs` and stated the degradation shape at the call site.

## 4. Outcome

The reading now agrees exactly with `progress.sh` and `queue-size.sh` run directly, and is
identical whether the process cwd is the target tree or elsewhere. `queue_total` is unchanged.

## 5. Successful Development Patterns

- **Measuring the reporter's proposed one-line fix is what found the second defect** — alone it
  returned plausible `0`s where there had been visible `null`s, so the fix was a hypothesis.
- **The half fix makes the better breaker**: coverage written against it fails on the version
  that silently reports zeros, which coverage against the original defect would pass.
