## 1. Overview

`plugins/workaholic/rules/shell.md` gains one rule: a redirect a run composes must not assume `>`
will overwrite an existing file. Under `noclobber` it may fail and write nothing, and the run that
carries on reads another run's data as if it were fresh.

**Highlights:**

1. The rule states both halves — the write may not happen, and the consequence is a **stale read**, not an empty one.
2. The repair is named in the ask's own terms: `>|`, or a filename unique to the run.
3. Three repairs are refused on the record — the operator's shell configuration, a `PreToolUse` deny, and a scheduled scratchpad clean.

## 2. Motivation

Measured twice in one session before it was filed: a `/moderate` tick parsed a 17-hour-old JSON from
a different tick, and a `/specificate` run carried issue #1012's stale body into a feedback record.
Nothing mechanical caught either — a missing file trips a run up at once, a file that kept its old
bytes does not. `rules/shell.md` already carries two rules about what an agent composes at run time,
both enforced by a human reading them; this is the third of that shape, so it went beside them
rather than among the POSIX conventions.

## 3. Changes

### 3-1. Say a redirect must not assume > truncates ([fa53b1e4b](https://github.com/qmu/workaholic/commit/fa53b1e4b))

Adds *A scratchpad redirect must not assume `>` truncates* after *Composing the call: the path in
full, the reader first, no assignment prefix*, carrying the two measured occurrences and the
reproduction, and names the rule in one clause under `CLAUDE.md`'s *Enforcement gates* so it is
discoverable from the same place as the two rules it joins.

## 4. Outcome

A run composing a scratchpad redirect has a written rule, and a reader who finds a stale parse has a
named cause. Nothing mechanical was added — no hook, no check, no script, no frontmatter change.

## 6. Successful Development Patterns

- Reading the cited section in full before citing it changed what got written: the ticket asked for `rules/interaction.md`, *An unattended run never waits for a person*, as "the wider rule this is an instance of", and that section's axis turns out to be about a composed command reaching a permission dialog — which a `noclobber` redirect never does. The citation went in as a **shape** sibling, saying plainly that the failure is the opposite of waiting.
- Re-running the ticket's own reproduction rather than quoting its recorded output kept the rule's wording honest — the measurement is what distinguishes *may fail and write nothing* from the falsifiable *fails silently*.
