## 1. Overview

A plugin update could delete the tree a running Codex supervisor used, while a delivered relay
or a live process made a tick that executed nothing appear healthy. This change separates
execution from delivery, reads liveness from both records and locks, and recovers the next tick
through the existing plugin resolver when the old tree disappears.

## 2. Motivation

Issue #1052 requested automatic recovery after a cache update and truthful execution/status
readings. These requirements are compatible: name the old and replacement paths, continue only
with a complete resolved tree, and stop with a concrete reason if recovery is impossible.
The remaining ticket preserves the original handoff interpretation and the evidence resolving it.

## 3. Changes

### Refuse a healthy outcome for a tick that executed nothing

Relay envelopes require an `executed` boolean. Delivery acknowledgement cannot promote
`tick_not_executed` or `work_blocked` to `ready`; successful pending relays still complete normally.

### Tell a live supervisor from an unwritten record

A held supervisor lock without a record reads `running_unrecorded`. Role fallback reuses the
existing PID/boot-id liveness reading, and status includes the last tick's completion time.

### Recover after the launch tree retires

The supervisor retains the sanctioned resolver before its installation disappears and executes
it only when required workflow resources go missing. It preserves the original resolver path
and `call_src` choice, rebinds tick/command/worker/schema/relay paths, and records both paths.
No complete replacement means `stopped:clock_wrapper_missing`, exit 2, with no further tick.

## 4. Outcome

All three tickets are archived and the mission is achieved at 3/3 acceptance. The live two-version
fixture proves recovery, the equal-version workspace call path, explicit failure when both trees
are removed, and recurrence of stale-path execution with the repair disabled.

Validation: **6,883 smoke assertions passed, zero failed**; the clock drill passed **19
load-bearing checks and 5 breakers**. Build, self-contained-output and metadata validation passed.
The full 50-drill run had one editor-overlap `standup_writes_nothing` failure; its stable-tree
rerun passed 3/3. Six existing drills lack breakers and two need an external server. The original
aggregate is retained as a failed run with a successful scoped recheck, not rewritten as green.

## 5. Concerns

- The supervisor's loaded shell code remains in memory; the replacement supplies workflow files
  and subsequent detached launches. This is resource recovery, not a hot reload of the shell.
- Removal during an active tick can still race that tick. The next boundary detects missing files;
  this change introduces no installation lease or guarantee against deletion mid-execution.
- The release scan reports only the existing oversized `scripts/e2e/loop-drill.sh` file
  (`override` tier). No secret or leakage findings. The separate test-fixture cleanup repair
  is in PR #993 and is not claimed as part of this PR.

## 6. Successful Development Patterns

- Reproducing the two-version update sequence distinguished supervisor behavior from a model's
  response; the fixture controls worker output and makes no claim about a live model.
- Keeping the resolver's bytes and original script identity preserves one selection policy after
  the installation that provided it disappears.
