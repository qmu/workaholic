## 1. Overview

Two of this mission's three tickets. Both close the same shape from opposite ends: **a reading that
graded a loop doing nothing as healthy**, and **a reading that could not see a loop that was
turning**. Measured 2026-09-06 (#1052) on the operator's own machine, they combined into an
incident where the supervisor recorded `outcome: ready` for a tick that had explicitly reported
nothing ran, while `--status` answered `never_started` for the live supervisor beside it — so the
operator had to notice by hand that development had stopped.

**Highlights:**

1. A relay envelope must now declare `executed`, and a delivered relay may set the relay fields
   without setting a healthy outcome or a reachable transport verdict.
2. `never_started` now means *no record **and** nothing holding the lock*; a held lock with no
   record is the new word `running_unrecorded`.
3. The start decision no longer refuses a role forever on a recycled pid.
4. The third ticket of this mission is **not** here: it declares a `verification_handoff:` for an
   operator ruling this run cannot make. It stays queued.

## 2. Motivation

Both readings were correct about the fact they measured and wrong about the fact they were read
for.

**The acknowledgement branch** rewrote the tick's status from the relay word alone: on
`relay == "delivered"` it set `.outcome="ready"` and `.transport_verdict="parent_connector"`,
discarding whatever `classify_report` had established. *The parent delivered the intents* and *the
tick ran* are two facts, and one writer was setting both from one word. Recorded as a baseline
before the change:

- an envelope declaring `executed: false`, reason *no tick ran*, reconciling to `delivered` →
  `state=sleeping outcome=ready blocked_reason="" transport_verdict=parent_connector`
- a tick already classified `work_blocked` → **upgraded** to `ready` by the same branch
- an envelope carrying no `executed` field at all → validated, and graded healthy

**`supervisor_reading`** answered from `.codex-loop/supervisor.json` alone. A supervisor launched
from a plugin tree since replaced — holding the lock and turning — was reported `never_started`,
on both the human surface and `--status --json`. The operator could neither see it nor start a
working one.

The second half the ticket named turned out **not** to be broken: a record present with a dead pid
already read `stopped_unclean`, because that path already composes `liveness_reading`. The real
second defect was one layer over, in the **start decision** — and the ticket's own Considerations
had named the mechanism without naming the seam.

## 3. Journey

### Ticket 1 — Refuse a healthy outcome for a tick that ran none

Three seams, which is the whole class of writers that can set a healthy outcome:

- `relay-contract.sh` requires `executed` as a boolean. An envelope omitting it is
  `malformed_envelope`, which `classify_report` already grades `relay_malformed`. The relay stops
  being the one path where a run's own execution is unstated — `worker-result.schema.json` has
  required it of every worker since 2026-09-06, on the same wording.
- `classify_report`'s relay branch reads `executed` **before** the outcome and intent rungs. A
  false reading records `tick_not_executed` with `not_executed:<reason>` — `worker_outcome`'s own
  vocabulary, not a second one — and `transport_verdict=unknown`. The relay fields are still
  derived, because the parent may still acknowledge.
- The acknowledgement branch releases a healthy outcome only for an outcome the relay itself was
  withholding (`relay_pending`, or a tick already `ready`). Every other recorded outcome is carried
  through with its own `blocked_reason` and `transport_verdict` untouched, and the state still
  moves to `blocked`.

### Ticket 2 — Tell a live supervisor from an unwritten record

- `supervisor_reading` reads the supervisor lock as **evidence** when the record is absent. The
  probe never creates the lock file, which is what keeps *absent means never started* true for a
  repository that never ran this path.
- `role_state`'s `flock`-less fallback composes `liveness_reading`, taking the boot id from the
  role's own record **only when that record names the same pid**. `gone` and `reboot` are proofs
  and free the role; `unverifiable` stays `running`, because a concurrency answer must never start
  a second worker on an unreadable reading. The `flock` path — including the parent's claim before
  it forks — is untouched.
- The human `--status` tick line carries the `finished_at` the tick already recorded, so *a tick
  recently succeeded* and *a supervisor is turning* are two readings a person can tell apart. No
  second clock, no stored cursor, and no recency threshold anybody had to pick.

## 4. Outcome

Every baseline re-run against the change:

| Case | Before | After |
| ---- | ------ | ----- |
| `executed: false` envelope, delivered relay | `ready` / `parent_connector` | `tick_not_executed` / `unknown` |
| `work_blocked` tick, delivered relay | upgraded to `ready` | `work_blocked` preserved |
| envelope with no `executed` | validated | `malformed_envelope` |
| `relay_pending` tick, delivered relay | `ready` / `parent_connector` | unchanged |
| undelivered relay | `relay_incomplete` | unchanged |
| held supervisor lock, no record | `never_started` | `running_unrecorded` |
| free lock, no record | `never_started` | unchanged |
| record present, dead pid | `stopped_unclean` | unchanged |
| live pid, record proves another boot | `already_running` forever | the role is free |
| live pid, record names this boot | `already_running` | unchanged |
| live pid, no record | `already_running` | unchanged |

`verify-codex-clock` grew from 9 to 15 load-bearing rows and from 3 to 4 breakers; the new breaker
restores the unconditional healthy write and the non-executing tick comes back `ready`, so the
drill can fail. `verify-all`: **48 pass, 2 skipped** (`needs_server`). `node
scripts/test-workflow-scripts.mjs`: **6883 passed, 0 failed**.

`CLAUDE.md`'s *Loops* section, `work/SKILL.md` and `other-agents.md`'s reading table were corrected
in the same change, as ticket 2's gate requires — each stated the reading being replaced.

## 5. Concerns

- **The third ticket of this mission is queued, not driven.** It declares a `verification_handoff:`
  for an operator ruling on its Open Decision — whether a tick that finds its launch tree retired
  refuses or re-resolves. The sources it names were read: #1052 asks the loop to *recover from
  retired cache paths without an unattended confirmation* and also that nothing *appear healthy
  merely because a process exists*, and no merged ruling settles which reading governs the launch
  path. PR #1043 (*Standing rulings for the operator*) is open and unmerged. The limitation is
  present, so the declaration stands and only the members that declared nothing moved.
- **A live relay tick's classification is not drilled**, because it needs a real `codex exec`. The
  new rows drive the acknowledgement branch directly and the classification is covered by the node
  suite's own relay fixture.
- **A genuine reboot cannot be staged hermetically.** The recycled-pid case is exercised by a
  record naming a boot id that is not this one, which is the same evidence `liveness_reading`
  consumes — but it is a stand-in, and that is stated on the drill.

## 6. Successful Development Patterns

- **The baseline step is not a formality when the ticket was written from an incident report.**
  Ticket 2's literal second half named a reader that was already correct; recording what the code
  actually did first is what moved the repair to the seam that was broken.
- **A vocabulary that already exists beats a new one.** `not_executed:<reason>` was already
  `worker_outcome`'s word for a run that did not execute; the relay path needed the reading made
  reachable, not a second set of words invented beside it.
- **Reading a lock as evidence and reading it as authority are separable**, and the repository
  already had the pattern in `role_state`. Saying so explicitly is what stops the next change from
  reintroducing a second allocator.
