# Package nested portable skill assets

## 1. Overview

Portable workflow builds now follow dependency references through nested scripts
and documentation, validate explicit dependency edges, and verify the resulting
isolated consumers.

- Nested helpers, references and schemas remain usable after installation.
- Existing CLI, JSON, exit and claim TSV contracts have executable regressions.
- Agentic-loop contract tests run in CI with no external credentials.

## 2. Motivation

The portable builder only inspected immediate files. A nested reference could run
from the source plugin while its dependency was absent from generated output, so
source verification did not prove that an installed consumer worked. P1 establishes
the distribution and compatibility floor before the new runtime depends on it.

## 3. Changes

### 3-1. Package nested portable assets ([c2d59e6](https://github.com/qmu/workaholic/commit/c2d59e651))

The build and verification tools share a recursive walker and dependency closure.
Companion references are rewritten from their actual directory depth, nested assets
retain their bytes, and a validated explicit catalog covers edges that prose cannot
express. Isolated consumer tests execute source, generated, target-only and detached
portable copies; legacy tests pin unchanged public shapes.

## 4. Outcome

The B01 fixture that failed on the previous builder now passes in every distribution
form. The same four packaging tests fail against the pre-P1 implementation, showing
that the regression detects the missing closure and rewrite behavior.

## 5. Release Preparation

- The safety scan reports only override-tier size findings: 490 generated files and
  579 implementation lines in one commit. The generated fan-out is expected for a
  full portable rebuild and contains no secret or terminology-leak finding.
- Live transport and native-agent behavior belong to later redesign units and were
  not counted as P1 verification.

## 6. Successful Development Patterns

- Executing a copied consumer after deleting its source tree exposed fallback paths
  that file-presence checks could not detect.
