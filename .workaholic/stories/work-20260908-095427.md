## 1. Overview

This branch first reduced the loop's startup context and canonical machinery, then added a shared activity-sensitive observation cadence. Claude Code and Codex now watch Slack and assigned feedback issues promptly during activity and progressively back off through sustained silence.

**Highlights:**

1. Cut the selected first-tick instruction path from 61,054 to 10,379 bytes.
2. Removed unused runtime APIs for a net 1,417-line canonical-source reduction.
3. Added bounded adaptive observation without coupling it to the work clock.

## 2. Motivation

The redesigned loop had grown enough that one Codex tick consumed roughly a quarter of its context window, while fixed polling remained slow during conversation and wasteful during quiet periods. The change removed duplicate instructions and unreachable machinery before introducing one activity-driven transition, so each workspace's observed rhythm determines responsiveness without a timezone rule.

## 3. Changes

### 3-1. Reduce first-tick context and canonical volume ([e6c3adbb3](https://github.com/qmu/workaholic/commit/e6c3adbb3))

Made each operative rule live in one short owner and moved historical evidence off the selected path. Removed production-unreachable runtime APIs and prose-shaped assertions while keeping behavioral coverage at live boundaries.

### 3-2. Adapt inbound observation cadence ([a7d73d552](https://github.com/qmu/workaholic/commit/a7d73d552))

Added persisted activity and quiet transitions over human Slack messages and newly assigned feedback issues, with explicit fixed-mode precedence and separate provider retries. Production sender filtering, maximum clamps, and observation-only wake tests keep the cadence from reacting to its own posts or advancing scheduled work.

## 4. Outcome

The selected first-tick instructions are 83.0% smaller, canonical source is down 1,417 lines, and canonical shell is down 113 lines. All 6,823 workflow assertions pass, including fake-clock coverage for adaptive cadence, feedback issue activity, restart behavior, bot filtering, and independent work deadlines.

## 5. Successful Development Patterns

- Giving each operative contract one owner preserved traceability while removing 83.0% of startup bytes.
- Deriving presence from observed activity kept cadence portable across agents, time zones, and workspace habits.
