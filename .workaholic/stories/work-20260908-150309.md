# Make agentic-loop validation finite and truthful

## 1. Overview

Validate Plugins no longer waits forever for an observation-clock fixture that can never finish. The fixture now presents genuinely distinct provider events, and both its supervisor process and the CI suite have explicit failure deadlines.

**Highlights:**

1. Preserve durable source deduplication while modeling two real inbound events
2. Bound the supervisor fixture at 20 seconds with diagnostic state on failure
3. Bound the complete CI suite at five minutes with a forced-stop backstop

## 2. Motivation

After #1100 correctly derived activity from `capture-inbox.new_input_ids`, the fixture still returned the same source `id` and `ts` on every QFS read. The first observation became durable, every later read was correctly deduplicated, and the fake Codex process never reached the second invocation that terminates its supervisor. With no workflow timeout, one bad fixture held every pull request in `checks_pending` indefinitely.

## 3. Changes

### 3-1. Emit distinct observation activity ([445c20f28](https://github.com/qmu/workaholic/commit/445c20f28))

The QFS stub now advances deterministic source IDs and timestamps on each provider read. The test still requires exactly two coordinator invocations and proves the second is observation-only, without weakening production deduplication.

### 3-2. Bound leaked validation processes ([35b83a2c1](https://github.com/qmu/workaholic/commit/35b83a2c1))

The supervisor fixture fails after 20 seconds with its QFS-read count, Codex-run count, and fake clock. Validate Plugins wraps the full agentic suite in a five-minute TERM deadline and a 30-second KILL backstop, pinned by a contract test.

## 4. Outcome

- The repaired fixture passed three consecutive runs; all 77 agentic-loop tests completed in 13 seconds and the updated runtime file passed 5/5
- Plugin build, bundle and metadata checks passed; mission acceptance reached 2/2 before preparing v1.0.339

## 5. Successful Development Patterns

- A provider fixture should advance the same durable identity fields its production consumer deduplicates; changing the consumer would have hidden the real contract.
- A narrow process timeout plus a wider CI backstop makes the precise failure actionable while preventing any future leaked handle from blocking the repository indefinitely.
