## 1. Overview

The declared QFS Slack route was preferred everywhere and worked nowhere: a jq path error
made every correct preview refuse, thread discovery was hard-coded unavailable, and nothing
checked who would speak — so the loop's posts, when they arrived, came under a person's
account. The route now commits, proves what it can and cannot do, and names where it speaks.

**Highlights:**

1. A preview stating an affected row commits; zero, absent and unreadable counts still refuse.
2. Thread discovery is derived from a describe, so the limitation carries its evidence.
3. A write that cannot speak as the declared sender is refused before a route is chosen.

## 2. Motivation

Four readings pointed at one route. `qfs-native.sh` guarded its commit on `.total_affected`
while QFS answers the count nested at `.preview.total_affected` as `{"exact": N}` — and
`null > 0` is `false` in jq, so a *correct* preview refused and every post fell through to the
connector, which speaks as the operator. `thread_discovery_unavailable` was a constant, so a
reply under yesterday's root could never be seen. The sender checks existed at three seams and
were inert together, each keyed on one optional field. And the report contract asked for *the
declared binding this tick resolved*, which a status envelope satisfies without naming the
channel. Each was measured before it was specified — including 94 messages in one channel from
a person's account against 0 from the declared sender.

## 3. Changes

### 3-1. Commit a post on a correct QFS preview ([d85c2cb7f](https://github.com/qmu/workaholic/commit/d85c2cb7f))

The commit guard reads the affected count where the provider answers it, tolerating both nestings
and a bare number rather than swapping one guess for another. A preview that states no affected
row — zero, absent, or a value no reading can find — still refuses `qfs_preview_refused` and
writes nothing, and the `committed` and `preview.rows` terms are byte-identical.

### 3-2. Prove native thread discovery before claiming it ([cbc733e2e](https://github.com/qmu/workaholic/commit/cbc733e2e))

`describe-native-qfs.sh` now describes the threads collection and reads the driver's own
`verbs.select` as the proof, advertising `list_thread_changes` only then and otherwise declaring
the limitation with the reason the describe gave. `qfs-native.sh` gained the arm that proof
enables, on the same bounded overlap window and returning the sibling adapter's shape.

### 3-3. Refuse a post that cannot speak as the sender ([2c0732af1](https://github.com/qmu/workaholic/commit/2c0732af1))

A declared sender no route can prove is refused `sender_unverified` at resolution instead of being
reported as an unreachable channel, without the caller opting in. On the write path the identity
is settled before a route is chosen, the refusal transitions the outbox to `refused`, and the
result carries `route: null` and `preferred_route_verified: false`.

### 3-4. Name the destination in the tick's report ([8540528ad](https://github.com/qmu/workaholic/commit/8540528ad))

Both tick report contracts carry one wording requiring the workspace, channel and `channel_id`
from the reader's own `binding`, and the command says to read that output whole. The suite pins
the wording on both surfaces and walks the tree for a call site that projects `binding` away.

## 4. Outcome

The declared route can now deliver, and where it cannot it says which capability is missing and
on what evidence. An undeclared binding is untouched: a repository declaring no `sender_id` —
this one included — behaves exactly as before. The mission closed `achieved` at 3/3.

## 5. Concerns

### End-to-end thread discovery is unverified on this provider

- **Severity:** moderate
- **Description:** the `list_thread_changes` arm landed but no bound account exposes a threads collection, so a reply under an older root has never been discovered end to end (see [cbc733e2e](https://github.com/qmu/workaholic/commit/cbc733e2e) in `plugins/workaholic/skills/transport/scripts/adapters/qfs-native.sh`)
- **How to Fix:** re-run the describe once a provider or account exposes `<base>/threads`; `thread_discovery_reason` on every observation says which providers still do not

### The live preview capture was refused by the harness

- **Severity:** low
- **Description:** the preview-shape evidence rests on two measured records plus a shape-tolerant reading, because the container's permission classifier denied a live QFS write-plan preview and no cred-free driver was mounted to preview against (see [d85c2cb7f](https://github.com/qmu/workaholic/commit/d85c2cb7f) in `plugins/workaholic/skills/transport/scripts/adapters/qfs-native.sh`)
- **How to Fix:** capture one real preview body where the classifier permits it and add it as a fixture; the reading tolerates every shape either record describes

## 6. Successful Development Patterns

- Reading the provider's own describe before designing turned two of the four tickets from guesses into proofs — the threads collection was absent, and saying so with evidence was the deliverable.
- Writing the fixtures per *shape* rather than per code path exposed that the pre-existing stub encoded what the code expected instead of what the provider sends.
