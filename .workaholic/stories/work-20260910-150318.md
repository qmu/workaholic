## 1. Overview

`perform.sh`'s write path told a reader that an operation leaves the preferred route on
`capability, authorization, availability` — two lines above the guard that maps the authorization
word to `none`. The comment now cites `qfs_fallback_class()` and enumerates nothing.

**Highlights:**

1. Every changed line in `perform.sh` is a comment line; no mapping, consumer or guard moved.
2. The repair points at the one derivation rather than correcting the list — the smaller fix.
3. Three new assertions, verified to fail against `origin/main`'s copy of the file.

## 2. Motivation

The `CLAUDE.md` half of this defect was repaired on 2026-09-10 by a ticket bound to leave
`skills/transport/scripts/` byte-identical, so the same disagreement survived one layer down — in
the file a reader would open *to settle the question*. The suite row that pins the rule strips
comment lines before asserting on the mapping, deliberately, so *a sentence about the class cannot
stand in for the mapping itself*; that is exactly why the wrong sentence could sit two lines above
the guard while every assertion passed.

## 3. Changes

### 3-1. Name the write path's fallback classes as the code maps them ([8715ea985](https://github.com/qmu/workaholic/commit/8715ea985))

The write guard's comment now cites `qfs_fallback_class()` as the one derivation and names no class,
keeping the *before the provider was asked to commit* distinction that made it worth writing. The
mapping function's own header gained CLAUDE.md's *typed is not the same as fallback-permitting*
sentence, so `perform.sh` alone answers the question CLAUDE.md answers.

## 4. Outcome

A reader settling the fallback question from `perform.sh` reaches CLAUDE.md's answer, and the suite
now fails if a class list returns above the write guard.

## 5. Concerns

### The read path's reachability sentence is true of one word, not the class

- **Severity:** low
- **Description:** `read_fallback_class`'s *"a WRITE may NOT"* is true only of `qfs_connector_failure` — `qfs_fallback_class` admits `qfs_preview_failed` (reachability) on the write path too (see [8715ea985](https://github.com/qmu/workaholic/commit/8715ea985) in `plugins/workaholic/skills/transport/scripts/perform.sh`)
- **How to Fix:** Tighten it to the word, in the same change that tightens CLAUDE.md's identical sentence — one surface alone puts the two out of step.

## 6. Successful Development Patterns

- A new assertion was proved to bite by running its logic against `git show origin/main:<file>`
  rather than by temporarily breaking the working tree — the falsification is evidence in the
  record, and no half-broken state ever existed for another runner to trip over.
