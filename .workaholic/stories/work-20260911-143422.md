## 1. Overview

The native `/work` coordinator ended its loop whenever a person inserted an ordinary question mid-run, because the conversation contract reserved the final response for two events and never said the ordinary path returns to the same instance. This branch states two paths in one wording on the three surfaces that carry the contract, adds a reader that owns the facts of the turn, and pins both paths with tests.

**Highlights:**

1. A routine interruption is handled in commentary and the coordinator returns to the same instance ID, startup anchor and schedule with no second `start` and no final response.
2. A review-required handoff persists `hold` first, asks exactly 「ループを再開してよろしいですか？」 as the final response's own text, and stays held until an explicit `resume`.
3. `work/scripts/final-response-contract.sh` refuses `hold_not_persisted`, `question_mismatch` and `anchor_moved` by name with nothing written.

## 2. Motivation

The operator's ask (issue #1147) was that a mid-loop question, correction or follow-up should be answered and the loop resumed automatically, stopping for confirmation only when the final comment carries something a person must review. The diagnosis found the contract silent rather than the harness at fault: `skills/work/SKILL.md`, `commands/infinite-development.md` and `native-loop.md` each said part of it, and no sentence named the resume of the same instance, the third event, or the criterion between them — so a session that answered with a final response violated nothing it could point to. The reducer already carries the anchor from `start` and refuses a second start, so the repair is the stated contract, its reader and its tests, with no fourth mode and the #1126 hold rule byte-identical.

## 3. Changes

### 3-1. Resume the native work loop after ordinary mid-loop comments ([bd17a189f](https://github.com/qmu/workaholic/commit/bd17a189f))

One wording on the three surfaces states the routine path (same instance, same anchor, no second `start`, no final response) and the review-required handoff (persisted `hold`, the one Japanese question as the final response's text, held until an explicit `resume`), with the final response reserved for exactly three events and the criterion written out as a judgement whose default is routine. `final-response-contract.sh` answers `path: resume | review_handoff` from the turn's facts and carries the coordinator's mode through unchanged, so an ordinary question under a standing hold never resumes it; the guard header and `CLAUDE.md` state that the handoff is never an `AskUserQuestion`. `native-coordinator.test.mjs` pins both paths and every refusal, and `test-workflow-scripts.mjs` pins the wording across the three surfaces.

## 4. Outcome

The final-response contract now has a positive rule for the ordinary case and a named third event, both testable rather than prose-only. The agentic-loop suite (126 tests) and the hermetic workflow suite (7148 assertions) are green, the build verifiers pass, and the layout audit conforms.

## 5. Concerns

### What a session actually emits as its final response is checked by nothing

- **Severity:** low
- **Description:** The reader owns the facts and the suite pins the wording, but whether a live session classifies a comment as routine and returns in commentary is a judgement made at run time that no script can observe (see [bd17a189f](https://github.com/qmu/workaholic/commit/bd17a189f) in `plugins/workaholic/skills/work/SKILL.md`), the same shape as the other prose contracts on this seam.
- **How to Fix:** If a session is again measured ending on an ordinary comment, add the turn's facts file to the tick report so the path the run took is recorded beside the reader's answer.
