## 1. Overview

Plugin source resolver が Codex と Claude の versioned cache を同じ候補集合として扱うようになった。既存の newest-version と immutable tie-break を保ち、host ごとの差は discovery に限定した。

**Highlights:**

1. Codex cache の Workaholic version directories を列挙する。
2. 新しい Codex bundle を古い Claude registry entry より優先する。
3. Host を跨ぐ選択を隔離 fixture で固定する。

## 2. Motivation

Codex 上により新しい Workaholic bundle が存在しても、resolver は Claude registry しか探索せず、古い script tree を選ぶ可能性があった。両 host の cache を一つの chooser に集約し、実行コードの freshness を正しく判定できるようにした。

## 3. Changes

### 3-1. Discover Codex plugin caches ([306e1aed0](https://github.com/qmu/workaholic/commit/306e1aed0))

Codex の version-addressed cache layout を探索対象へ加えた。1.0.349 の Codex cache と 1.0.343 の Claude registry を用いる fixture により、version 優先と実際の `source` / `call_src_source` を検証する。

## 4. Outcome

Resolver は checkout、Claude registry、Codex cache、clone、binding を同じ version と immutability の規則で比較できる。全 7,326 workflow script tests が成功した。

## 6. Successful Development Patterns

- Host 固有の discovery と共通の selection を分離したことで、既存の tie-break を複製せず対象だけを安全に広げられた。
