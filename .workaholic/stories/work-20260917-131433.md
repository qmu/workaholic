## 1. Overview

Feedback publication now converges on one durable branch even when parallel moderation ticks race within the same second. A refused merge is re-read structurally and reported as an existing open publication instead of creating a duplicate branch or losing the record.

**Highlights:**

1. Refresh remote publication refs before allocating a branch.
2. Rebuild publication state after a branch collision or refused open.
3. Parse persisted and carried records structurally in production and drill fixtures.

## 2. Motivation

Concurrent moderation runs intermittently observed stale branch state. One runner could open the publication while another still concluded that no publication existed, producing `branch_collision`, duplicate work, or an incorrect carried state. The repair keeps failure reasons truthful while treating an already-open matching publication as the successful durable handoff.

## 3. Changes

### 3-1. Make publication deduplication race-safe

The persistence path refreshes publication refs before deduplication and performs a second structural read after a collision or failed open. Matching records resolve to the existing branch without allocating a second branch. The hermetic loop drill uses the same structural JSON reading as the production path.

### 3-2. Prepare marketplace version 1.0.352

Mandatory main reconciliation found the branch still targeted the published 1.0.351 tag. The lockstep plugin manifests and generated workflows now use the next free patch version.

## 4. Outcome

Parallel ticks preserve one publication branch and an honest `publication_open` outcome across same-second races. Release artifacts are unique and generated output remains in lockstep.

## 5. Concerns

No unresolved release concern was identified. Production deployment remains separate from this merge and requires the declared release confirmation.

## 6. Successful Development Patterns

- Re-read shared remote state after a uniqueness conflict; a pre-flight read alone cannot close a race.
- Parse record state as structured data in both production code and fixtures so tests exercise the same contract.
