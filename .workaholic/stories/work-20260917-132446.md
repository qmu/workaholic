## 1. Overview

`observe-channel` が inbox capture の失敗を常に typed observation failure として返すようになった。失敗時は cursor を進めず、次の tick が同じ provider page を再試行できる。

**Highlights:**

1. Capture の非ゼロ終了と malformed output を安全に扱う。
2. 空の診断を `capture_unreadable` へ正規化する。
3. `observation_proved:false` と cursor 不進行を fixture で固定する。

## 2. Motivation

Transport read が成功した後に capture subprocess が中断すると、`set -e` により observer も終了し、capture failure の reason と未読 window が失われ得た。Cursor advancing seam 自身が失敗を型付きで返すことで、未読を quiet と誤認しないようにした。

## 3. Changes

### 3-1. Preserve capture failure reasons ([035105ee5](https://github.com/qmu/workaholic/commit/035105ee5))

Capture output を status 判定前に安全に受け取り、既存の reason を top-level outcome と `unreadable` へ伝播する。JSON を読めない失敗は `capture_unreadable` として返し、cursor を保持する。

## 4. Outcome

Capture failure は非空の診断、`observation_proved:false`、`cursor_advanced:false` を伴う。Transport suite は 29 tests すべて成功した。

## 6. Successful Development Patterns

- Cursor advancing seam を fault boundary として直接 fixture 化すると、subprocess failure と state preservation を一つの回帰証明で固定できた。
