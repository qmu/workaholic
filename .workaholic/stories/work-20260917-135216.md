## 1. Overview

Task-level review wait を global coordinator hold から分離した。対象 receipt だけが元 Slack thread の reply を待ち、observation と独立 work は同じ coordinator/anchor で継続する。

**Highlights:**

1. `awaiting_review` を receipt-level state として追加する。
2. 元 thread の reply だけで対象 receipt を再度 eligible にする。
3. Explicit operator hold の timer refusal を維持する。

## 2. Motivation

一つの implementation dependency が解釈待ちになるたび global hold を永続化すると、Slack の回答そのものを読めなくなり、別の resume command が必要になる。Dependency と coordinator control を別の軸にした。

## 3. Changes

### 3-1. Keep observation running during review ([2f3e9cfda](https://github.com/qmu/workaholic/commit/2f3e9cfda))

Coordinator に `await_review` / `review_resolved` events と `waiting_review` projection を追加した。Final-response contract の `task_review` path は final response や hold を出さず、running continuation を維持する。

## 4. Outcome

Review 中も observation と unrelated work が進み、元 thread の reply が対象 unit だけを再開可能にする。Native coordinator suite は 8 tests すべて成功した。

## 6. Successful Development Patterns

- Dependency wait を worker receipt に局所化すると、global control mode を増やさずに observation continuity を守れた。
