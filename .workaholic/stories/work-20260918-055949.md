## 1. Overview

The Slack observer stopped advancing its binding cursor and reported an unreadable source
rather than a cause, so a human mention posted as a reply reached nobody. Both halves were
one seam.

**Highlights:**

1. The inbox dedup key is **declared** in the script's own header: `provider_id` plus the sender.
2. `thread_ts` is a per-operation rendering, so one `thread_broadcast` message is captured once.
3. A capture that cannot complete answers `capture_incomplete` with its cause and the provider id.

## 2. Motivation

The duplicate test required the stored `message` object to equal the newly read one byte for byte,
and `thread_ts` is not a property of the message: the channel listing carries `null` for a
`thread_broadcast` while the thread read carries the root's ts. Its refusal was then unreachable —
the walk runs in a pipeline subshell, `exit 10` failed the pipeline, and `sh -eu` aborted before
`pipe_status=$?` was evaluated. Measured unfixed: exit 10 with empty stdout, and end to end
`unreadable: ["capture_unreadable"]` with the cursor held.

## 3. Changes

### 3-1. Key the inbox dedup and name its refusal ([4f6fc2d77](https://github.com/qmu/workaholic/commit/4f6fc2d77))

The duplicate test compares a declared key — `provider_id` plus `sender_id // user`, each term read
with a normalising default — and every failing branch writes its cause to a file the loop leaves
with status 0, so the seam answers `capture_incomplete` with the cause and the provider id on
stdout, exit 0, cursor held.

## 4. Outcome

A `thread_broadcast` message seen through two operations is one message, the cursor advances, and `unproved_since` clears in the same write. A genuine refusal reaches the observer as the capture's own typed word; both `observe-channel.sh` call sites are byte-identical.

## 5. Concerns

### The dedup key excludes a message's text

- **Severity:** low
- **Description:** An edited message re-read counts as a duplicate, so the inbox keeps the text as first observed (see [4f6fc2d77](https://github.com/qmu/workaholic/commit/4f6fc2d77) in `capture-inbox.sh`); including `text` would stall the cursor on an edit exactly as `thread_ts` did.
- **How to Fix:** Update the stored record on a duplicate rather than widening the key.

## 6. Successful Development Patterns

- A fixture must honour the shebang: `sh capture-inbox.sh` drops the `-eu` and hid the abort, so the first measurement came out clean and had to be redone.
- `|| walk_status=$?` closes the rest of the abort class where `|| true` would let a stopped walk advance the cursor.

## 8. Notes

Thread discovery on the native QFS route is out of scope: the channel node advertises only `messages` and `files`.
