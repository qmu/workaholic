## 1. Overview

The release-safety gate every merge is read through answered `pass` when it had read nothing at
all. It now parses the scan with `jq`, derives `decision` from the severity counts, and answers
a third word — `refuse`, with `null` counts — for every input it could not read.

**Highlights:**

1. Empty stdin, a positionally-passed file path and a finding with no `category` each answered `pass`; all three now refuse or block.
2. `decision` derives from the severity counts, so `pass` beside a non-zero `hard` is unreachable by construction rather than untested for.
3. Both script consumers gained an ordered `case` arm onto the existing `scan_unreadable`; no new vocabulary was minted.

## 2. Motivation

`decision` was gated on a text grep for `"category":` in the raw input, and every way of
arriving here with no reading drove that count to zero — which is what a clean branch looks
like. Two independent callers hit it in one session on 2026-09-18: one passed a file path the
script never reads, one piped in the empty output of a scan run from the wrong path. Both got
`decision: "pass"`.

This is the repository's doctrine pointed at one of its own gates — *an absence of a reading is
never a proof* (`drive/reference/claims.md`), and *readability precedes counting*, stated to the
coordinator that calls this script. It is the shape PR #1200 repaired one seam over.

## 3. Changes

### 3-1. Refuse an unread scan instead of passing it ([90afb3952](https://github.com/qmu/workaholic/commit/90afb3952))

`gate-decision.sh` refuses a positional argument, counts findings structurally with one embedded
`jq` program, and answers `refuse` with a closed six-word `reason` set for every unread input.
Both script consumers map that word onto the existing `scan_unreadable` through an arm above
their others; the four agent-level contracts state that only `pass` or `override_only` passes.

## 4. Outcome

Empty stdin now answers `refuse`/`no_input`, a positional path `bad_argument`, and a `hard`
finding with no `category` a non-overridable `block`. All three answered `pass` before.

## 5. Concerns

### land-unit.sh reads the scan permissively, without this gate

- **Severity:** moderate
- **Description:** `land-unit.sh` defaults `scan_verdict="pass"` and counts findings with the same `grep -o '"category":'` this change removed, so an unreadable scan reads as clean there (see [90afb3952](https://github.com/qmu/workaholic/commit/90afb3952) in `plugins/workaholic/skills/drive/scripts/land-unit.sh` line 193). It is reachable only with `--developer-present` — it refuses `headless_context` first — so a person is always there, which is why it was out of this ticket's scope rather than unnoticed.
- **How to Fix:** Route it through `gate-decision.sh` as the other consumers do, or give it the same `*)` fallthrough `publish-tree-pr.sh` already has.

### The ticket's under-count example is not reachable from today's producer

- **Severity:** low
- **Description:** The ticket describes a `"category":` inside an `evidence` value inflating the count; `scan-branch-safety.sh` escapes every `"` in every string value (`json_escape`, line 75), so that substring can never match the old pattern. What *was* reachable is the opposite direction — a `"category":` key outside `findings[]` producing a false `block` with `override_only: true` (see [90afb3952](https://github.com/qmu/workaholic/commit/90afb3952) in `plugins/workaholic/skills/release-scan/scripts/scan-branch-safety.sh`).
- **How to Fix:** Nothing to fix in the code — the structural count removes both — but a reader citing the ticket's example should cite the measured one instead.

## 6. Successful Development Patterns

- Reproducing all three measured shapes before touching the script, and re-running them after, is what caught that one of them should answer `block` rather than `refuse`.
- Walking each consumer's `case` against the literal refusal object proved the existing fallthrough was safe before the arm was added — the arm makes an incidental safety a property of the word.
- Stubbing the gate through a copy of the plugin tree drives both consumers' real code paths; the discriminating assertion is that neither delivers, where before the change both did.
