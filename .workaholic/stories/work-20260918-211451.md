## 1. Overview

`read-declared-binding.sh` answers `declared: false` on a hard refusal as well as on a repository
that declares nothing, so a consumer keying on `declared` alone reported *I could not look* as
*there is nothing to see*. The reader is correct and untouched; its consumers now read `ok` first.

**Highlights:**

1. Both report contracts: a repository is named as declaring nothing **only** on `ok: true`.
2. `check-slack-binding.sh` names the refusal alone, never `not_declared` beside it.
3. `apply-slack-binding.sh` refuses `declaration_unreadable` and writes nothing.

## 2. Motivation

Two `[Implement]` runs reported this repository as declaring no Slack binding while `AGENTS.md`
declares `qmu` / `dev-workaholic`, quoting `declared: false, reason: no_root`. Neither changed a
delivery outcome — both notifications were undeliverable for separately measured reasons — so what
was wrong was the record. The instance with a consequence was a **write**: against a root whose
`CLAUDE.md` was unreadable and declared a real destination, the scaffold answered
`{"applied":true,"created":true}` and appended a second declaration — the state its own
`already_declared` refusal exists to prevent.

It is the session's recurring family, an absence of a reading reported as a fact, repaired the way
its precedents were (PR #1206/#1209, PR #1200): the refusal gets its own word.

## 3. Changes

### 3-1. Never report an unreadable binding as an undeclared one ([13a635c22](https://github.com/qmu/workaholic/commit/13a635c22))

Adds one byte-identical sentence to the destination clause of `commands/infinite-development.md`
and `skills/work/SKILL.md`, folds `binding_unreadable:<source>` into `<reason>` so a sourceless
`no_root` has a word, and repairs the two scripts that keyed on `declared` alone. The reader's diff
is empty and this repository's audit answer is byte-identical.

## 4. Outcome

A refused binding read is now reportable, auditable and unwritable-against by its own word.
`check-slack-channel.sh` stays untouched: it reads only `.binding.mount`, so an unreadable
declaration degrades there to *no mount* and the probe already answers `channel_verified: false`.

## 5. Concerns

### The reaped-worktree hypothesis was not confirmed

- **Severity:** low
- **Description:** Neither run's report survives its context and `.workaholic/moderations/` holds
  no `no_root` line, so the cause was localized from the tree instead: the only spelled call is
  `--root .`, and its failure vocabulary was `binding_unreadable:<source>`, which a sourceless
  `no_root` cannot use (see [13a635c22](https://github.com/qmu/workaholic/commit/13a635c22) in
  `plugins/workaholic/commands/infinite-development.md`)
- **How to Fix:** If a run reproduces `no_root` live, capture its cwd and raise the
  worktree-lifetime repair as its own ticket.

### Nothing checks what a run actually emits

- **Severity:** low
- **Description:** `testReportNamesDestination` pins one wording byte-identically on both
  surfaces; no check sees whether a session read `ok` first (see
  [13a635c22](https://github.com/qmu/workaholic/commit/13a635c22) in
  `scripts/test-workflow-scripts.mjs`)
- **How to Fix:** Nothing — stated rather than implied; the two scripts are the checkable half.

### The audit asserts nothing beside a refusal

- **Severity:** low
- **Description:** On `ok: false` only the refusal is emitted, so a root declaring cleanly in
  `AGENTS.md` beside an unreadable `CLAUDE.md` no longer also reports `unverifiable_sender` (see
  [13a635c22](https://github.com/qmu/workaholic/commit/13a635c22) in
  `plugins/workaholic/skills/workaholify/scripts/check-slack-binding.sh`)
- **How to Fix:** Intended; a partial audit would need its own field, not a mixed findings list.

## 6. Successful Development Patterns

- Reproducing the *consequence* and not only the defect changed the design: re-reading the fixture
  with both files readable showed `contradictory_declaration` / `binding: {}`, which is why the
  refusal had to precede the write.
