## 1. Overview

An operator turned subagents off because each child inherited the whole conversation. Honouring
that meant implementing in the parent, and the coordinator — still persisted, still `running` —
stopped receiving role ticks with nothing anywhere saying that trade had been made. The loop
exposed a worker **count** and a **cadence** and nothing about what a child inherits, so the
operator had one lever and it was the wrong one.

**Highlights:**

1. `dispatch.context_policy` is a declared dial of its own, read through one script, with absent
   meaning today's behaviour and an unsupported harness reported rather than silently substituted
2. A delegation restriction names **which** of four closed-list guarantees it costs, and the
   coordinator keeps observing instead of becoming an inline implementer
3. A hermetic drill proves the observation clock keeps ticking while a worker is live, asserting
   on recorded events and never on elapsed time

## 2. Motivation

Three dials existed and none was the one the operator needed. Cadence lives in the runtime
config's `polling`; worker count is `WORKAHOLIC_MAX_WORKERS`; context propagation appeared
**nowhere** — a tree-wide walk for `fork_turns`, `low_context` and *context propagation* returned
nothing. The child contract was half-written for the same reason: `work/SKILL.md` specified what a
worker **returns** and never what it **receives**, so how much conversation a child inherited was
a property of whichever harness launched it.

The repository already had a vocabulary for a stop it could *see* — the three reserved
final-response events, and the precondition-stop obligation a degraded tick carries. An operator
**restriction** is a different class of fact: it is not a degraded reading, so no existing word
covered it and the tick had no obligation to name it. From outside, a loop whose observation clock
had stopped looked exactly like a loop that was busy.

## 3. Changes

### 3-1. Declare a context propagation policy beside the worker count ([b4ef095e8](https://github.com/qmu/workaholic/commit/b4ef095e8))

`dispatch` joins `polling`, `target` and `limits` as an accepted top-level key in
`runtime/scripts/read-config.sh`, carrying one sub-key `context_policy` over the closed set
`full_conversation | bounded_task`. Absent resolves to `null` — today's behaviour — and an
unrecognised value, a boolean or a number included, is refused **`invalid_context_policy`** on the
**resolved** config, so a bad value from the profile and one from `--input` are refused
identically. `runtime/scripts/dispatch-policy.sh` is the one reader: `policy`, `declared`,
`harness`, `supported`, `effective`, `support_reason`, `mapping`. `fork_turns=none` appears only
as the harness **mapping**, never as the policy. `lib/coordinator.jq` records `context_policy` on
a `reserve` receipt (refusing an unrecognised one) and projects it on every `live[]` row;
`codex-loop.sh` reads the same one script, carries the effective policy to its detached child
through the environment rather than re-reading it there, and reports it on the dispatch line. The
child input contract is written once in `work/SKILL.md` and cited from the ceiling.

### 3-2. Name the guarantees a restriction costs ([d41bd0b18](https://github.com/qmu/workaholic/commit/d41bd0b18))

The four properties the loop advertises are a closed list written once in `work/SKILL.md` —
`observation_clock`, `acknowledgement_on_cadence`, `work_advances_without_waiting`,
`separable_worker_evidence` — and `work/scripts/delegation-lapse.sh` is the one derivation over
them. A refused delegation lapses the last two and **holds** the first two; a bounded context
holds all four at one stated cost; no restriction announces nothing new. `announce` is true
**only** when `lapsed` is non-empty, and `coordinator_action` is `keep_observing` under every
restriction. The announcement reuses the existing precondition-stop shape under the reader's own
signature — no new shape, no new transport, and no fourth reserved final-response event.

### 3-3. Drill observation during a long implementation ([bcab4f93b](https://github.com/qmu/workaholic/commit/bcab4f93b), [642cf58b6](https://github.com/qmu/workaholic/commit/642cf58b6))

`verify-observation-during-work` is a hermetic drill verb registered in the dispatcher and in
`docs/loop-drill-runbook.md` §9, so `verify-all` and the CI push matrix both run it. It stages the
ask's three conditions — a long-running child under the bounded policy, a Slack reply arriving
**after** it started at the stubbed `qfs` seam, and a declared restriction — and asserts on a
journal of real calls with no `sleep` anywhere.

  `.claude/` path only in a **file** position rather than anywhere in a Key Files sentence — is an
  operator ruling, not a fix to slip into this branch.

## 6. Successful Development Patterns

- Asserting *observation happened while the child was live* from the coordinator's own `live[]` on
  either side of the read needs no clock at all. That is what lets a timing drill be about
  **ordering** rather than duration, and it is the difference between a stable drill and a flaky one.
- A pinned "this phrasing is forbidden" rule cannot be written as a regex ban when both surfaces
  must quote the forbidden sentence in order to forbid it. The pin is a positive assertion that
  each surface carries its own prohibition wording.
- `read-config.sh` validates keys and not values, and its whole jq program sits under a catch-all
  usage refusal, so a value-level word has to be raised in shell against the **resolved** config —
  which is also what makes the refusal source-independent across profile, legacy env and `--input`.
