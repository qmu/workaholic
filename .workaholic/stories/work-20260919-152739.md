## 1. Overview

The loop mentioned the operator when one unit merged while sorting, pagination, forms and
identifiers from the same continuing thread were still queued. Every existing reader answered
correctly about its own grain — `feedback-outcome.sh` folds one feedback item,
`delivery-ledger.sh` folds one item's pull requests — and the grain a person means by *done*, the
**thread**, had no reader at all. Three additions close it: a fold across a thread's items, a
reread of that thread immediately before the mention, and three named post classes where there
had been one.

**Highlights:**

- `work/scripts/thread-completion.sh` composes the existing ledger and answers `complete` only
  when **every** accepted member of a thread is delivered; `incomplete` names the member holding
  it and `unreadable` withholds.
- `work/scripts/mention-reread.sh` gates the mention on a reread that completed — a truncated
  page, an unproved read, a fanout bound or a newly found request each withhold it by name.
- The notify catalog defines a **worker receipt** (no post), **scoped progress** (`📊`, no
  mention token) and a **completion mention** (`🏁`, on the `complete` verdict) once, carried
  byte-identically into the tick ceiling.

## 2. Motivation

Issue #1146 asked for three things: reconcile every accepted request before a completion mention,
reread the thread immediately before sending one, and stop treating a worker's finish as
permission to send it. The reconciliation largely existed; what was missing was the unit it folds
over. `delivery-ledger.sh`'s own header already says a request answered by three pull requests had
no reading at all — the same shape one level up, where a conversation answered by three requests
had none either.

The measured failure is the mention that went out. Its cause is not a bug in any reader: the tick
resolved the thread, read it to check whether it had already posted, found one item finished and
said so. Nothing anywhere asked whether the *rest of that conversation* had landed, and nothing
distinguished *this unit merged* from *everything you asked for is in*.

## 3. Changes

- **The thread-grain fold** (`75f7db2e2`). `thread-completion.sh` calls `delivery-ledger.sh` once
  with the whole item set and groups its rows by the thread coordinate each captured ask already
  carries (`slack-ref: <channel>:<ts>`). `complete` requires **every** accepted member; an item a
  person explicitly deferred or cancelled leaves the set and is named in `excluded[]`; an item
  with no thread key is named in `keyless[]` rather than folded into some other thread. An
  unreadable membership or member answers `unreadable` with **null** counts — incomplete
  discovery is never evidence of completeness (#1132). `feedback-outcome.sh` and
  `delivery-ledger.sh` are byte-identical against `origin/main`.
- **The mention-time reread** (`0a90044a7`). The obligation is carried in one wording in
  `commands/infinite-development.md` and `skills/work/SKILL.md`, pinned byte-identically: reread
  the thread and its **explicitly linked** continuations through the existing
  `observe-channel.sh`, capture anything new through `capture-inbox.sh` first, and advance no
  cursor of your own. `mention-reread.sh` is a pure reader over the coverage that read already
  reported — only `allow` permits the mention, and `no_reread`, `observation_unreadable`, an
  `unsettled[]` term, `capture_unreadable`, `capture_incomplete` and `new_request_found` each
  withhold it. A new request found is the ordinary good case, not an error path.
- **Three post classes** (`53fa753ad`). The notify catalog gains *Three acts: a worker receipt,
  scoped progress, and a completion mention*, with both new shapes, the rule that **a worker
  finish is evidence for the parent, never its permission**, and the scope rule that the accepted
  set narrows **only** on an explicit human defer or cancel. `🟢 Implemented` is untouched and the
  section says so. The tick report now names the class of every post and what held a withheld
  mention.
- **Version bump** to `1.0.374` (`0feec665b`) — the base reached `1.0.373` while this branch was
  driving.

## 4. Concerns

**[moderate] The thread key is an input the caller resolves, not a value this reader derives.**
`slack-ref:` is stamped per *message*, because the sweep's dedup depends on that; a root message's
own `ts` equals its `thread_ts`, so for an ordinary top-level ask the stamped marker **is** the
thread key. A request written as a **reply** carries its root's coordinate, which the observation
knows and the caller must pass. The ticket's own acceptance forbade a new relation or field, so
the key rides the reader's input; if a caller passes the reply's own coordinate instead, that
request folds as a thread of one and can complete early. No script can catch that — it is a
contract in the reader's header and in the ceiling.
*Severity: moderate — the failure is a mention sent one request too early, which is the class this
mission exists to end.*

**[low] The three acts are prose and shapes, with no runtime enforcement.**
Nothing stops a session from composing a `🏁` without reading `thread-completion.sh` first. The
suite pins that the classes exist, are defined once, and are byte-identical across the two
surfaces; what a run actually emits is checkable by nothing, exactly as the language rule already
records about itself.
*Severity: low — the same enforcement every post shape in this catalog has had.*

## 5. Successful Development Patterns

- **Composing rather than re-deriving kept the readers honest.** `thread-completion.sh` calls
  `delivery-ledger.sh`, which calls `feedback-outcome.sh`; every per-item word passes through
  verbatim, so `git diff origin/main` on both existing readers is empty and the unreadable
  asymmetry propagates upward for free — a member row whose `readable` is `false` is what makes
  the thread `unreadable`.
- **`noclobber` is live in this environment.** A smoke fixture using `>` onto an existing scratch
  path silently read the *previous* case's input for all seven rows, which is the stale read
  `rules/shell.md` predicts. `>|` fixed it, and both new scripts write only inside their own
  `mktemp -d`.
