## 1. Overview

`/propose` ended 64 consecutive ticks with `{"proposed": 0}` while eight inbound items sat open
and nothing was queued — every gate correct, and every tick indistinguishable from an idle hour.
This branch closes the three compounding causes: a zero-proposal run is now a named finding where
a person reads it, `open_proposal` stops holding a direction once the tree proves the ingest stage
has not run against its proposal, and an operator ask that answers no direction is named.

**Highlights:**

1. `/moderate` gains two reading steps — `propose-yield` and `unattributed-asks` — neither of which
   proposes, files or lifts anything.
2. `open_proposal` holds on membership **and** a tree proof; `ingested` and an unreadable proof
   both keep braking.
3. No constant, no environment variable and no stored timestamp entered any gate.

## 2. Motivation

The loop's own record said the routine that originates work had stopped producing, and no surface
carried that fact to anybody. `/propose`'s outcome for a tick that originates nothing is a line in
a run report its own skill says three times over is read by nobody on the day it matters, and
`/moderate`'s registry held no step that asked whether propose ticks produce anything — its
nearest one, `blocked-tick`, asks *did the tick close*, by which reading sixty-four refused ticks
are sixty-four healthy hours. Underneath that, two gates were structurally unable to release: the
`open_proposal` rung empties only when `/specificate` merges a proposal's pull request, so a dead
ingest stage held every direction forever, and an ask belonging to no strategy could never be
originated because every move is declared against one.

## 3. Changes

### 3-1. Name the ask that answers no direction ([b7491ab1d](https://github.com/qmu/workaholic/commit/b7491ab1d))

Adds `strategy/scripts/unattributed-asks.sh` beside `unattributed-work.sh` — the ask side of the
same question — composing the inbox reader with the strategy readers and answering only the two
mechanical attribution rungs, reporting everything else `undecidable_here`. `/propose` names it as
evidence and `/moderate`'s new `unattributed-asks` step asks the operator once per ask; nothing
here creates a strategy, amends one or originates anything.

### 3-2. Raise a run of originate-nothing ticks ([b1790e6f3](https://github.com/qmu/workaholic/commit/b1790e6f3))

Adds `/moderate`'s `propose-yield` step, which reads the tick log's own propose finish lines and
raises a **run** of ticks that all closed having originated nothing, naming the survey's own
refusal words so a reader sees which directions were held and why. A single such tick raises
nothing, and an outcome outside its declared token set holds the finding rather than being guessed.

### 3-3. Stop open_proposal holding a dead handoff ([c01d8e5a0](https://github.com/qmu/workaholic/commit/c01d8e5a0))

`open_proposal` now holds on set membership **and** a tree proof — that a feedback record newer
than the proposal exists, which a successful `/specificate` run always writes. A proposal the
ingest stage has provably not run against stops holding its direction and the row names
`open_proposal_uningested`; `ingested` and an unreadable proof both keep braking.

## 4. Outcome

The originating routine can now say why it produced nothing, release a direction whose handoff is
dead, and name an ask no direction claims — three readings, each reported where a person reads it,
none of which originates, files, merges or lifts a gate. Mission
`never-let-the-routine-that-originates-work-converge-on-silence` closed `achieved` at 3/3.

## 5. Concerns

### `propose-yield` classifies a free-text outcome

- **Severity:** moderate
- **Description:** the step decides *originated nothing* from the worker result's `outcome` string
  against a declared token set, because that string is composed by the run rather than drawn from a
  closed vocabulary (see [b1790e6f3](https://github.com/qmu/workaholic/commit/b1790e6f3) in
  `plugins/workaholic/skills/moderate/scripts/step-propose-yield.sh`). An outcome outside the set
  holds the finding, so the failure is silence rather than a false alarm — but a vocabulary drift
  turns the step inert without anything saying so.
- **How to Fix:** give the propose tick a structured outcome field at the finish seam, and have the
  step read that instead of the sentence.

### The documented propose-open/propose-close producer does not exist

- **Severity:** low
- **Description:** `rules/workaholic.md`, `log-read.sh`'s header and the drill fixture all name
  `/propose` as a producer of `propose-open`/`propose-close`, and no script in the plugin writes
  either; `log-read.sh --owner propose` answers zero entries in this repository.
- **How to Fix:** either implement the writer at the propose entry or retire the contract from the
  three places that assert it.

## 6. Successful Development Patterns

- Reproducing the reading before designing against it changed the design twice — the log's real
  carrier was the coordinator's `loop-finish-propose` line, not the documented propose owner.
- Deriving a bound from a reading that already exists (`blocked-tick`'s two-day window) kept a new
  tunable constant out of a step whose whole subject is a gate.
- Adding the relaxation's row key **only where it fires** is what makes "byte-identical with no open
  proposals" provable with `has()` rather than argued.
