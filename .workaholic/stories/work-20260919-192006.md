## 1. Overview

A supervisor pinned to a retired plugin version died on 2026-09-07 in another repository and
nobody saw it for twelve days, while three `worker-*.lock` files read one minute old — written by
the reader's own `--status` call. Three causes, three tickets, one branch: the status surface
stops writing what it reads, a startup that cannot read its own instructions recovers the tree or
leaves a record, and a clock that stopped — or that keeps ticking without executing anything —
reaches a person instead of stderr and a file nobody opens.

**Highlights:**

1. `role_state()` and `supervisor_lock_state()` probe on **read-only** descriptors, so a
   `--status` call leaves every file in the state directory byte-identical, mtime included.
2. The startup's plugin-tree guard is **read** where it always was and **acted on** where the
   recovery already lives, so a refusal has a state directory to record itself in.
3. `announce-stop.sh` gives `workaholic:notify`'s existing precondition-stop shape a caller one
   layer below the tick. No new shape, no new transport, no second liveness authority.

## 2. Motivation

`--status` is documented four times over as a surface that "starts nothing, writes nothing, takes
no lock and needs no `codex` CLI". It did all three. `role_state()` opened each role lock with
`exec 8>"$_lock"`, which **creates and truncates** the file and moves its mtime, and then held
`flock -n 8` for the life of the subshell; `supervisor_lock_state()` did the same to
`.supervisor.lock` under a comment saying in capitals that it must never write. Measured here
against a fixture whose four lock files were stamped to a fixed past: one `--status --json` call
moved all four mtimes and truncated three files from 1 byte to 0.

Beside it, two silences. The running loop has re-resolved a moved plugin tree through
`ensure_plugin_tree()` at the head of every iteration since 2026-09-07 (#1069), but the
**startup** never reached it: the two plugin-tree guards ran above the `REPO_ROOT` / `LOG_DIR`
resolution and exited 2 outright, so such a launch died with no state directory and no record
anywhere, and `--status` then answered `absent` — the reading *never started*, indistinguishable
from a repository that never ran the Codex path. Reproduced exactly that way before the change.
And `executed: false` with a reason is an honest refusal by a worker that reached nobody at all:
the supervisor's whole escalation reach was `write_supervisor stopped <reason>` plus a line on
stderr, and nothing outside `skills/work/` read the status surface.

## 3. Outcome

**Reading a lock no longer writes it.** Both probes open read-only (`exec 8<` / `exec 7<`).
flock(2) ignores the open mode, so a held exclusive lock still reads `running`/`held` and a free
one `idle`/`free` — verified directly against a lock held by another process. `dispatch_claim_role()`
and the `--worker` claim keep `exec 8>`, because they must create, truncate and hold, and they
remain the only concurrency authority. The prose was **narrowed rather than kept** at all three
sites that stated the contract: *takes no lock* was wider than the code even after the repair,
since testing an flock means momentarily acquiring it, so the guarantee is now stated as *writes
nothing and leaves every file byte-identical*. The suite row that was meant to catch this
compared directory **names** only — which a truncation in place can never move — and now
fingerprints size and mtime.

**A startup that cannot read its own instructions recovers or records.** `REPO_ROOT`, `LOG_DIR`
and `SUPERVISOR_FILE` resolve first; the guard is read in its original place with its original
words; the act is deferred. `--ack`, `--dispatch` and `--worker` refuse exactly as before.
`--status` **skips** it — a read-only surface must still answer *is this loop alive* on a retired
tree, and it reads neither the tick prompt nor the command body. A supervisor start calls the
loop's own `ensure_plugin_tree()`, which gained one optional argument (the word to record) and no
second copy of the recovery: it reports `recovered retired plugin tree <old> -> <new>` on success,
and otherwise writes `state: stopped` with the precise guard word and the retired root before
exiting 2 with the same two stderr lines. `--status` then reads `stopped:plugin_skill_missing`
rather than `absent`. `repository_missing` still refuses ahead of every record, and a `--dry-run`
still creates no state directory.

**A stop reaches a person.** `announce-stop.sh` posts `workaholic:notify`'s precondition-stop
shape under the supervisor's own signature, with that skill's dedup, its single escalation from
`⚪ Paused` to `🔴 Blocked`, and its cool-down. Two triggers, both derived from state that already
exists and neither adding a field or a counter: a `stopped` record whose reason is not the
ordinary end (`completed_once`), and a role whose own `consecutive_failures` has reached
`WORKAHOLIC_WORKER_ATTEMPT_MAX` — the threshold `record_worker_attempt()` already crosses. The
transport is `notify-slack.sh`, the one script-level seam a POSIX supervisor can reach, and an
**undeliverable** transport is a recorded refusal and never a post: the line is retained in
`<state dir>/outbox/` with its refusal word, `announced` is false, and the cool-down does not
start, so the escalation ladder stays where the refusal left it.

`scripts/e2e/drills/verify-codex-clock.sh` carries six new load-bearing rows and three breakers:
the state directory's fingerprint around two `--status` calls, a retired-tree startup's record and
its unchanged stderr, a launch outside a repository, one announcement per stop, one alert per wall
across five ticks, and the undeliverable case. Each breaker restores the pre-repair behaviour and
requires the drill to notice.

## 4. Concerns

- **The concurrency criterion is addressed structurally, not by a timing assertion.** Ticket 1's
  quality gate asks that a `--status` run concurrently with a `--dispatch` never make the dispatch
  answer `already_running`. Testing an flock means momentarily acquiring it, so that window is
  microseconds wide both before and after this change; a drill row asserting on it would be flaky
  in both directions, and a flaky row is worse than a stated residue. What the change removes is
  the creation, the truncation and the mtime move — the harm that was actually measured. The
  alternative the reporter named, `fuser`, was declined by the ticket itself in favour of the
  descriptor form, which needs no extra binary on the PATH.
- **The announcement's dedup ledger is local to the state directory.** `workaholic:notify` dedups
  by reading the channel's recent history, which is the connector's surface and not a POSIX
  script's. The stated cost: a ledger a person deletes re-fires one alert, and a wall hit from two
  different state directories is announced twice. Where the speaking-window derivation cannot be
  reached, only the 24-hour term of the cool-down applies and the announcement says so — a longer
  silence, which is the safe direction for a rule whose job is to suppress repeats.
- **Slack is undeliverable in this repository today**, so the announcement is verified on the
  outbox entry and the refusal word rather than on a message anybody reads. That is what the
  ticket asked for, and it is stated here so a later reader does not mistake a green drill for a
  delivered alert.
- **A pre-existing base failure was found and minted, not fixed.** `node --test
  scripts/tests/agentic-loop/*.test.mjs` fails on `P8 maintenance registry is ordered and
  complete` on the untouched main checkout at `d28e34429`: the tick ships `unattributed-asks` and
  `propose-yield` and the test's expected list does not carry them. It is independent of this
  unit and is queued as
  `20260919193000-reconcile-the-p8-maintenance-registry-with-the-steps-it-ships.md`.
- **`--status` now answers on a retired tree where it used to exit 2.** That is deliberate and is
  the reporter's own question, but it is a behaviour change to a surface other things may script
  against; the exit status for the readings themselves (`0` / `4` / `5`) did not move.

## 5. Successful Development Patterns

- **Reproduce before changing anything, and keep the fixture.** Both defects were reproduced
  first — four mtimes moved by one read, and a startup that left no directory — and each
  reproduction became the shape of a drill row rather than being thrown away.
- **A comment stating an intent in capitals is not evidence the code holds it.**
  `supervisor_lock_state()`'s own comment said *IT NEVER CREATES THE FILE. `exec >` would* directly
  above the line that did exactly that. The repair narrowed three prose statements that were wider
  than the code rather than leaving them to be believed.
- **A pinned contract has to compare the thing that can change.** The suite row guarding this
  surface compared directory listings, so a truncation in place and a byte-identical read were one
  answer for as long as the row existed.
- **Defer the act, keep the reading where it was.** The startup guard's words, position and stderr
  did not move; only the act did, down to where the recovery already lived. That is what let the
  refusal keep its exit status and its two lines while gaining a record.
