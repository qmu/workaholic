# Two readers were looking in the wrong place

## 1. Summary

- Default the Slack binding reader's root to the repository etc
- Weigh only live claim worktrees when deciding whether a runner is advancing

## 2. Motivation

Both tickets in this unit are the same shape of defect: a reader whose **evidence set** was wrong,
answering confidently from the wrong place. Neither was a crash and neither reported a degradation —
each produced a plausible-looking wrong answer, which is why both had to be measured before they
could be repaired.

`transport/scripts/read-declared-binding.sh` required `--root` and refused `no_root` without it.
That refusal carries `declared: false`, so a call site that omitted the argument would not fail
loudly — it would read as *this repository declares nothing*, and the loop would fall back to
`WORKAHOLIC_INBOUND_SLACK_CHANNEL` / `WORKAHOLIC_SLACK_WORKSPACE`. That is the exact misdelivery the
declaration mechanism exists to prevent. The call-site walk was re-derived for this change and
**every caller in the tree passes `--root` today**, so there is no live harm; what makes it a defect
anyway is the direction of the failure at the one seam `CLAUDE.md` describes as unconditional.

`loops/scripts/read-runner-advance.sh` decided whether a running loop subagent was still advancing
from the newest mtime under **every** directory in `.worktrees/`, with no test that a live claim
stood behind any of them. Because its escape hatch is keyed on the **count** of worktrees rather
than on their liveness, abandoned residue did not merely add noise — it made `no_claim_evidence`
unreachable and turned the answer deterministic in the wrong direction. Measured 2026-09-19 at
`daff53802`: four worktrees idle 15.2–16.7 days, `frozen_count: 2`, and both running runners read
`not_advancing` while working. `commands/infinite-development.md` frees a fanout slot on exactly
that reading.

## 3. Changes

**The binding reader's root is optional** (`85417ea13`). With no `--root` it defaults to
`git rev-parse --show-toplevel`, resolved **before** the existing validity test, which is
byte-identical. An explicit `--root` always wins. `no_root` stays exact and reachable: outside any
repository with no `--root`, and an explicit `--root` naming something that is not a directory. The
default is the repository **root** and never `pwd`, because the sources are composed against it —
defaulting to the working directory would reintroduce the same silent `declared: false` one level
down. No call site changed, no key was added and no reason word moved.

**The advance reading is bounded to live claim worktrees** (`839c62403`). The walk now weighs a
`.worktrees/<unit>/` row only when its branch exists under `refs/remotes/origin/` — the claim
oracle's own test — read **offline** from the local ref store: one `git worktree list --porcelain`
and one `git for-each-ref`, no fetch, no `ls-remote`, and no call into `list-claims.sh`, which
fetches. An excluded worktree is **not a claim row at all** and is counted in a new
`residue_worktrees` field, so an operator sees the disk holding it without the reading spending it.
A worktree whose branch cannot be resolved is `unreadable` with reason `claim_unresolved` and counts
toward `unreadable_claims` — never flat, because an absence of a reading is never a proof.

Measured in this checkout after the change: the four residue worktrees are gone from `claims[]` and
counted in `residue_worktrees: 4`; only the two live claims are weighed. In the hermetic fixture
that models the ticket's exact state — four residue worktrees, no live claim — the repaired reader
answers `advancing: 0`, `frozen_count: 0` and `unreadable: no_claim_evidence` per name, where the
unrepaired one answered `frozen_count: 2` with both names `not_advancing`.

**Not touched, deliberately**: `survey-worktrees.sh` and `reap-worktrees.sh` are byte-identical,
the `reclaimable` predicate is **not** loosened (the operator's ruling), and the four residue
worktrees remain on disk. They stop corrupting a liveness reading they were never evidence for;
removing them stays the operator's act.

## 4. Concerns

**[moderate] The full `test-workflow-scripts.mjs` run needed `TMPDIR` off `/tmp` to complete here**

This server's `/tmp` is a 3.8 GB tmpfs shared by every concurrent agent, and the suite creates
hundreds of throwaway git repositories under it. Three full runs died mid-suite at three different
points with no failing assertion and no error text; the same tree with `TMPDIR` pointed at local
disk ran to completion and printed `7814 passed, 0 failed`. Nothing here is a defect in this
branch, but a runner that reads a truncated run as a failure — or, worse, does not notice the
truncation — will draw the wrong conclusion. Worth an operator ruling on where the suite's
scratch space should live on this machine.

**[low] Phase 1 concern judging was skipped for time**

The open set is 145 records with `should_triage: false`; none were judged or superseded by this
run. No verdict was applied, so nothing was lost — the set is exactly as it was.

## 5. Successful Development Patterns

- **An escape hatch keyed on a count of evidence rather than on the evidence's standing is a
  reusable defect shape.** `read-runner-advance.sh` did not fail to read; it read the wrong rows,
  and the count-keyed hatch then made the wrong answer *deterministic*. When a reader has a
  "cannot tell" arm, check what disables it.
- **A required argument whose omission answers a plausible value is a defect in the reader, not in
  the caller that forgets it.** Both tickets are that sentence, once about an argument and once
  about a directory listing.
- The join between a `.worktrees/<unit>/` directory and its `git worktree list` row is made on the
  **unit id** — the claim protocol's own key — not on a resolved filesystem path: a path join needs
  `cd` into the directory, which fails for exactly the worktree a `no_files` reading exists to
  describe.
- A linked worktree's `.git` is a **file** at `<worktree>/.git`, so the walk's
  `-not -path '*/.git/*'` does not exclude it and its mtime is weighed. Harmless for real residue;
  fatal for a fixture that backdates only the content files.
