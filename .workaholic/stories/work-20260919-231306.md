# Declare the local proof set a main-bound merge stands on

## Motivation

A pull request based on `main` merges without its check runs ever being read.
`merge-gate-policy.sh` answers `remote_checks_required: false` there and
`drive/scripts/branch-checks.sh` emits `pass development_main_local_proof` before it reaches any
check reader. **That design is not what this change touches** — *`main` is the continuously
auto-merged development branch and quality is gated at the `release/*` QA window* is a recorded
decision (`CLAUDE.md`, *The release tier*), and restoring the remote-CI gate for `main` was
explicitly out of scope.

The defect was in the **substitute**. The word `development_main_local_proof` asserts that a local
proof stood in for the remote one, and nothing anywhere established that any such proof ran, still
less which one. `CLAUDE.md`'s *Local Verification* names six commands in prose for a human to read;
the two places in the tree that actually ran checks before a push each hard-coded their own list of
**three** — `drive/scripts/catch-up-claim.sh:404` and `branching/scripts/prepare-publication.sh:226`,
the same set spelled twice, a strict subset of CI's `validate` job, and no report naming which of it
a given unit executed.

**Measured, 2026-09-19** (workflow `Validate Plugins`, id 223779125, read over REST): seven
consecutive first-parent commits on `main` failed it — `f195a667f`, `915e115fd`, `6dcf73b41`,
`d28e34429`, `52964b8c8`, `eb795c92f`, `3243c1c4f` — from 10:10:40Z to 11:45:28Z. The failing step
on **both ends** of that range is job `validate`, step 9, **"Test agentic loop contracts and
consumers"** — exactly the command neither fast-check set ran. Throughout that window
`read-base-checks.sh` answered `unanswerable` for anything reading the base, so post-merge
detection, the thing the release-tier decision leans on, did not fire either.

## Outcome

`plugins/workaholic/skills/branching/scripts/local-proof.sh` is the **one declaration of the set and
the one runner of it**. The set is the `validate` job's own repository commands
(`validate-metadata.mjs`, the agentic-loop suite carrying **CI's own 5m bound**,
`test-workflow-scripts.mjs`, `layout-doctor.sh`) plus `build-plugins/verify.mjs` — the
`Outputs Freshness` gate both retired lists already carried — and the **hermetic** drill entry point
`loop-drills.yml` runs on push. `verify-all`'s classified set stays a pre-approval gate and is not
in the declaration.

Both of `catch-up-claim.sh`'s rulings moved **into** the runner so they hold at every call site
rather than at one: the checks run with `WORKAHOLIC_CLAIM_STALE_HOURS`,
`WORKAHOLIC_CLAIM_HEARTBEAT_STALE_MINUTES` and `WORKAHOLIC_CLAIM_MERGED_LOOKUP` unset, and each
check's output is kept in a log whose path rides that check's row. `prepare-publication.sh`
discarded its checks' output outright (`>/dev/null 2>&1`) and gains the log by composing the runner —
a side effect of the composition, not an unrelated edit.

Three fields, never collapsed. **`ok`** is *no check ran and failed*, and it is what a caller refuses
on, so every `validation_failed:<check>` word is byte-identical and no caller's `case` arm moved.
**`complete`** is *every required check ran*, and it is **reported, never a refusal**: the retired
lists skipped an absent check silently (`[ -f ] || continue`), and a consuming repository carrying
none of these files must keep pushing exactly as it did — what changes is that the skip is now named.
**`not_run`** carries one line per check that did not run, with its own reason (`check_absent`,
`interpreter_unavailable:<tok>`, `timeout:<n>s`). A check that did not run is its own state and never
a soft pass, the rule `workaholic:ship` already holds for a deployment.

**Every check runs, including after one has failed.** Stopping at the first failure would make
`not_run` mean both *this could not run* and *we stopped early*, which is the confusion the script
exists to end. The stated cost is that a doomed push spends the whole set's wall clock before it is
refused.

The reporting obligation is stated once in `skills/drive/SKILL.md` §7, *And an act that ran the local
proof set names what it proved*, and cited by `commands/implement.md`. `local_proof` rides both
callers' own JSON so a run report and a pull-request body can name every check and every `not_run`.
`scripts/test-workflow-scripts.mjs` pins the declaration against `validate-plugins.yml`'s `validate`
job and **names what it cannot see** — a step whose command is built by interpolation.

**Nothing about the gate moved.** `branch-checks.sh` and `merge-gate-policy.sh` are byte-identical
(`git diff --stat` over both is empty) and every `release/*` behaviour is untouched: a `release/*`
pull request still reads its remote checks and still refuses `checks_red` / `checks_pending`.

**`not_run`, named rather than folded into a pass**: in the set's first full run,
`agentic-loop.test.mjs: timeout:300s` — the suite answered `130 passed, 0 failed, 1 cancelled` at
`duration_ms 299847` and was killed at CI's own bound, while the same suite alone in the same hour on
the same tree answered `163 passed, 0 failed` in 115s. That is the stated cost behaving as designed,
and the bound is deliberately **not** raised past CI's own: a check that needs more time here than
CI will give it has not been proved for the merge CI gates. The run that produced this pull request
re-ran that check alone and it is green.

**Not run, and named**: `sh scripts/e2e/loop-drill.sh verify-all` — the classified drill set. Only
its hermetic part ran, inside the proof set, which is what `loop-drills.yml` runs on push.

## Negative probes

1. **A check made to fail**, over the whole set on a fixture: `ok: false`, `complete: true`,
   `failed: ["validate-metadata.mjs"]`, `not_run: []`, the caller's word
   `validation_failed:validate-metadata.mjs`, and the log kept with the failing bytes.
2. **`node` shadowed away**: `ran: false`, `reason: interpreter_unavailable:node` — never `ok: true`,
   never a silent skip.
3. **A check the repository does not carry**: `not_run: ["loop-drill-hermetic: check_absent"]`,
   `complete: false`, `ok: true` — byte-identical in effect to the retired `[ -f ] || continue`.
4. **A declaration row deleted** while remaining in `validate-plugins.yml`: the new test row fails
   `the declaration covers CI's scripts/tests/agentic-loop/*.test.mjs`. Reverted and green again.

## Concerns

**`--only <name>` was added beyond the ticket's steps.** Without it the set's own behaviour could not
be probed without spending its whole wall clock. A narrowed run reports every other row
`ran: false, reason: not_selected`, so `complete` goes false and the reading can never be mistaken
for a full proof; no call site passes it.

**The log directory moved.** `catch-up-claim.sh` wrote its logs beside the worktree, always under the
git-ignored `.worktrees/`. A bare run from the main checkout has no such parent, and the same default
would have written above the repository, so the default is now the repository's own git directory —
present for a worktree and a main checkout alike, never committed, already hosting
`.git/workaholic/runtime/`.

**The pre-push wall clock grew.** The set now carries the agentic-loop suite and the hermetic drill
set, which the retired lists did not. That is the trade the ticket named by name: excluding the
agentic-loop suite was rejected because it is the exact step whose absence turned `main` red seven
times in ninety-five minutes.

## Successful Development Patterns

**A word that asserts a proof is a defect until something can be asked what the proof was.** The
gate here was correct and the vocabulary was correct; what was missing was any reader able to answer
*which checks*. Declaring the set and reporting `not_run` by name changed no gate and no token, and
it is the whole repair.

**Rulings belong in the thing they are rules about.** The clean environment and the kept log were
written as comments at one call site, and the second call site kept neither for months. Moving them
into the runner is what makes them hold everywhere, and the test row that pinned them at the old
site now pins them where they live.
