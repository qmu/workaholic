# The drill stopped supplying the premise its reader had gained

## 1. Summary

- Supply the runner-advance drill a real claim oracle, and drill the residue exclusion that shipped without coverage

## 2. Motivation

`scripts/e2e/loop-drill.sh verify-runner-advance` was red on the base at `7a6db3d7b`, and
`.github/workflows/loop-drills.yml` runs the hermetic drill set on every push — so every runner in
the loop was building on a red base. Measured before the change:

```
{"ok": false, "verdict": "fail", "load_bearing": {"passed": 5, "failed": 4}, "breakers": 1}
```

Four load-bearing rows failed: `runner_advance_reads_the_worktree`,
`runner_advance_names_a_frozen_runner`, `runner_advance_refuses_the_binding` and
`runner_advance_frees_the_slot`. Every unit came back
`verdict: unreadable, reason: claim_unresolved`, every name
`unreadable, reason: claim_evidence_incomplete`, with `frozen_count: 0` and
`residue_worktrees: 0`.

**The reader was not the defect.** The immediately preceding unit (#1250, ticket
`20260919230800`) bounded `loops/scripts/read-runner-advance.sh` to worktrees a claim can stand
behind: a `.worktrees/<unit>/` row is weighed only when its branch exists under
`refs/remotes/origin/`, the claim oracle's own test, read offline. That repair is correct and it
removed a measured harm — four worktrees idle 15.2–16.7 days had made `no_claim_evidence`
unreachable and read two working runners `not_advancing`.

**The drill's fixture was the defect.** It was built by `mkdir -p` and `touch -d`, so each fixture
root was a bare directory tree and not a git repository at all. Both of the reader's new git reads
fail there — `git worktree list --porcelain` and `git for-each-ref refs/remotes/origin/**` — so
`claim_standing` answered `unresolved` for every unit and the reader, correctly refusing rather
than guessing, answered nothing about anybody. Until `20260919230800` the newest mtime under
`.worktrees/<unit>/` was the reader's **only** premise, and a directory tree with chosen mtimes
supplied all of it. The reader gained a second, git-native premise; the fixture did not.

## 3. Changes

**The fixture is now a real git repository with real claim worktrees** (`4a70f7ca4`). Each fixture
root gets `git init` under the drill's own temp directory, one empty commit, and one
`git worktree add -b work-YYYYMMDD-HHMMSS` per unit; a **live** claim additionally gets
`git update-ref refs/remotes/origin/<branch>` written by hand. It stays hermetic — no remote, no
fetch, no `ls-remote`, no network, and nothing written outside the temp tree.

**The repair is the fixture's, not the reader's — a decision, recorded in the drill beside the
fixture so it is not re-argued.** The reader's answer for a root with no claim oracle is
`unreadable`, which frees nothing; that is the direction this repository requires of it everywhere
else. Teaching it that *no origin remote* means *weigh every worktree as before* would add a code
path whose only caller is a fixture, and would hand back the pre-`20260919230800` reading in
exactly the repository where nothing could contradict it. `read-runner-advance.sh` is
**byte-identical** to the base — `git diff origin/main -- plugins/workaholic/skills/loops/scripts/read-runner-advance.sh`
is empty.

Two details the shape forces, both now written into the drill:

- **The worktree's own `.git` file is aged with the rest of the fixture.** `git worktree add`
  writes it at creation and nothing rewrites it, so in the real loop it carries the claim's birth
  and ages with the claim; in a fixture built this second it is the newest file under the worktree
  and the walk's `-not -path '*/.git/*'` does not exclude it, so every claim would read
  `advancing`. Measured while writing this: the first prototype returned `advancing: 2` on a
  fixture whose content files were two hours old.
- **The `no_files` case is reached by making a live worktree unreadable** (mode 000), not by
  leaving it empty: `git worktree add` always writes that `.git` file, so an empty *registered*
  worktree does not exist. The mode is restored before cleanup, or `rm -rf` cannot descend.

**The coverage `20260919230800` shipped without** is added, because the residue filter it
introduced was drilled by nothing:

- `runner_advance_excludes_residue` — a `residue` fixture, one live claim beside one worktree whose
  branch stands on no origin ref: `residue_worktrees: 1`, exactly one `claims[]` row, the live one
  `not_advancing`.
- `runner_advance_residue_frees_nothing` — an `abandoned` fixture, residue only: `claims: []`,
  `frozen_count: 0`, both names `unreadable: no_claim_evidence`, and the fan-out arithmetic over
  the reader's own output frees **zero** slots. This is the 2026-09-19 defect itself.
- `runner_advance_residue_breaker` — a second breaker written against the behaviour: force
  `standing=live` and the abandoned fixture must then free both slots on claims nobody holds.

`verify-runner-advance` goes from 5 passed / 4 failed / 1 breaker to **12 passed / 0 failed / 2
breakers**.

**Not touched, deliberately**: `read-runner-advance.sh`, `reap-worktrees.sh` (the `reclaimable`
predicate is not loosened — the operator's ruling), `branch-checks.sh` and `merge-gate-policy.sh`
(recorded decisions).

## 4. Concerns

**[moderate] `TMPDIR` must be off `/tmp` on this machine, and a truncated suite is silent**

The concern the previous unit raised is confirmed again here. `/tmp` is a 3.8 GB tmpfs shared by
every concurrent agent, and `test-workflow-scripts.mjs` creates hundreds of throwaway git
repositories under it. It still needs an operator ruling on where the suite's scratch space lives;
a runner that reads a truncated run as a pass draws the wrong conclusion, and this drill now adds
five more throwaway repositories per run to the same budget.

**[low] The drill's five fixture repositories are built serially**

`git init` + one commit + two `git worktree add` per fixture, five fixtures. It is a few hundred
milliseconds and it buys the premise; noted only so the cost is on the record rather than
discovered.

## 5. Successful Development Patterns

- **When a reader gains a premise, every fixture that fed the old one is now under-specified.**
  The previous unit's own Patterns section already recorded that a linked worktree's `.git` is a
  file the walk weighs — the fact that broke this drill was written down by the change that broke
  it, in the same commit, and the drill was never run. A repair that adds a premise should re-run
  the drills that assert on the reader, not only the unit tests.
- **Repair the fixture, not the reader, when the reader's refusal is the direction you want.**
  The cheap road here was a reader arm for *this root has no claim oracle*. Its only caller would
  have been a fixture, and it would have restored the exact reading the previous ticket measured
  as harmful, in the one environment where nothing could contradict it.
- **A breaker is written against the behaviour, not the return shape.** The new residue breaker
  forces `standing=live` — the pre-repair reading — and asserts the drill then frees slots on
  claims nobody holds. A breaker satisfied by keeping the JSON shape proves nothing.
