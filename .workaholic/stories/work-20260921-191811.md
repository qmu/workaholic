## 1. Overview

An operator can now park a queued ticket with one frontmatter line — `deferred: <why>` — and the
loop holds, counts and names it instead of rediscovering the instruction every tick. `status:
icebox` could not: it is filtered out inside the queue walk, so a queue emptied by deferral was
byte-identical to an empty one.

**Highlights:**

1. `deferred: <why>` is the operator's own hold, with one reader and one write floor; `icebox` and every queue reader are byte-identical.
2. `plan-units.sh` names such a ticket `operator_deferred` at its exclusion seam while still counting it in `backlog_size`.
3. A deferred-only queue is a *successful* reading of zero — zero runners, no failure, no alert — while an unreadable declaration still earns one runner.

## 2. Motivation

An operator deferred a queued ticket in prose; prose is invisible to the survey, so every tick
claimed it again. `status: icebox` looked like the answer and is the wrong shape — `list-todo.sh`
drops `done | abandoned | icebox` from the **queue walk**, so such a ticket never reaches the
survey. Measured: one free and one iceboxed ticket answer `backlog_size: 1` with an empty
`excluded[]`, indistinguishable from a queue holding one ticket.

That collapse is the one closed twice before, by `backlog_all_excluded` and `placeholder_identity`.
This instance had a new cause, so it took a new key read where held artifacts are already named.

## 3. Changes

### 3-1. Declare an operator deferral on a queued ticket ([7bcab10b](https://github.com/qmu/workaholic/commit/7bcab10bb))

Added the declaration, its one reader (`drive/scripts/read-deferral.sh`) and its write floor in
`hooks/validate-ticket.sh`, and nothing that consumes them: `list-todo.sh`, `plan-units.sh`,
`claimable-units.sh` and every icebox script were byte-identical after this ticket. The floor
refuses exactly two shapes — a bare `deferred:` and a `[`/`{` collection — and was verified
against the corpus already on disk rather than a fresh fixture.

### 3-2. Name a deferred ticket in the survey exclusions ([cc3ed918](https://github.com/qmu/workaholic/commit/cc3ed9182))

`plan-units.sh` composes that reader at its **exclusion seam** — deliberately not in
`list-todo.sh`'s filter, which is where the invisibility comes from — and names the ticket
`operator_deferred` while still counting it. A declaration the reader could not read is
`deferral_unreadable`: neither a deferral nor a pass.

### 3-3. Stop a deferred-only queue consuming a runner ([760621a7](https://github.com/qmu/workaholic/commit/760621a7c))

`claimable-units.sh` composes the survey's own `excluded[]` and keeps three answers apart in one
reading: a held queue is `claimable: 0` with `deferred: <n>` and no `readable` key, an unreadable
declaration is `readable: false` with null counts, and a queue with claimable work is unchanged.
`allocate-implement.sh` is byte-identical — it already answered correctly once it could tell the
two apart.

## 4. Outcome

An operator holds work with one line and releases it by deleting that line; no command writes or
clears the key. The loop names what holds the queue instead of printing a bare zero, and both
error directions are asserted in one fixture so neither can be collapsed.

## 5. Concerns

### Two local-proof assertions fail on any machine with an installed plugin cache

- **Severity:** moderate
- **Description:** `testInstalledCodexClock`'s "a missing command body names the plugin command layer" and "a missing work skill names the plugin skill layer" fail here, and fail **identically on `origin/main`** — proved by running the same fixture over `git archive origin/main plugins/workaholic`. The launcher recovers a deleted layer through the machine's own plugin cache (`recovered retired plugin tree … -> ~/.claude/plugins/cache/workaholic/workaholic/1.0.384`) and exits 0 where the fixture expects exit 2. CI carries no such cache, so the rows pass there and fail for every developer (see `scripts/test-workflow-scripts.mjs`)
- **How to Fix:** Ticket `20260921195918-prove-a-missing-plugin-layer-where-a-cache-can-recover-it` was minted by this run: bound the fixture to a tree the recovery cannot reach, rather than weakening the assertion or removing the launcher's recovery, which is deliberate behaviour

### A mission member's deferral is not read

- **Severity:** low
- **Description:** The deferral check sits after the `mission_member` branch, so a deferred ticket inside a live mission keeps that reason and its mission's unit drives it anyway (see [cc3ed918](https://github.com/qmu/workaholic/commit/cc3ed9182) in `plugins/workaholic/skills/drive/scripts/plan-units.sh`). Reporting it `operator_deferred` would claim a hold the run does not honour, so the limit is stated in three places rather than hidden
- **How to Fix:** Holding one member of a unit is `verification_handoff:`'s shape; if the operator wants per-member holds on mission work, that is a separate ask against that mechanism

### An unreadable declaration does not forbid `ok`

- **Severity:** low
- **Description:** `deferral_unreadable` rides `backlog_all_excluded`'s counts and sets no top-level trustworthiness field, so a run whose only oddity is one malformed declaration can still report `ok` (see [cc3ed918](https://github.com/qmu/workaholic/commit/cc3ed9182) in `plugins/workaholic/skills/drive/scripts/plan-units.sh`). It is named in every survey until repaired, and the loop still spawns a runner because `claimable-units.sh` treats it as degraded
- **How to Fix:** Adding a sixth `ok`-forbidding survey fact belongs to whichever mission owns `drive/SKILL.md` §7's token table; two missions editing one table is how a table stops meaning one thing

## 6. Successful Development Patterns

- Verifying a tightened constraint by diffing the **old and new hook's exit status over all 1516 tickets on disk** — rather than asserting "no existing ticket carries the key" — is what turned a plausible claim into a measurement, and it caught that the 96 refusals present are all pre-existing.
- Proving three readings in **one** fixture, end to end from the reader into the allocator, rather than three: the whole hazard was that one answer gets mistaken for another, which three separate fixtures cannot fail on.
- Reproducing the defect first (`status: icebox`'s invisibility) decided *where* the change goes — the exclusion seam, not the queue walk — before a line was written.
