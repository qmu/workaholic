## 1. Overview

The loop stops squash-merging: `merge-method.sh` now answers `merge`, so a landed `work-*` branch is an ancestor of `main` and reads as merged. The worktree sweep then reclaims a landed unit's worktree and its local branch, and a new pruner names the squash-era local branches and removes only the ones proved landed.

**Highlights:**

1. One derivation flipped (`merge-method.sh` → `merge`); every merge site already read it, and the composed title/body become the unit's `git log --first-parent` line.
2. `reap-worktrees.sh --apply` removes a reaped worktree's landed local branch with `git update-ref -d <ref> <tip>` — never `git branch -D`.
3. `prune-landed-branches.sh [--apply]` removes local `work-*` branches proved `ancestor` or `content_landed`, and names every other branch (`checked_out`, `not_landed`, `no_base`).

## 2. Motivation

The developer saw ~22 local `work-*` branches and asked whether they were a problem; they only looked unfinished because every pull request was squash-merged, which leaves a landed branch off the base's ancestry. The developer's reply (#1279) was to stop squash-merging. This supersedes the 2026-09-01 squash ruling; its cost (bookkeeping commits reach `main`) is accepted as second-parent history and kept readable through `--first-parent`.

## 3. Changes

### 3-1. Merge every pull request with a merge commit ([13b7e98b2](https://github.com/qmu/workaholic/commit/13b7e98b2))

`merge-method.sh` prints `merge` and its header states the new ruling, its cost and why the claim protocol is unaffected; the prose stating "every merge is a squash" (CLAUDE.md, drive SKILL/routing, implement command, commit skill, script comments) is updated. `attribute-base-red.sh` now walks the first-parent line so its bound is spent on the merge commits the base's checks ran on.

### 3-2. Reclaim landed branches by ancestry ([b1050656a](https://github.com/qmu/workaholic/commit/b1050656a))

The sweep's reaper removes a reaped worktree's local branch when its tip is an ancestor of `origin/<base>`, and the new pruner handles the pre-ruling backlog on an ancestry or content proof. Squash-era headers and docs now state the ancestry reading; the sweep pin moved from "the branch ref survives" to "the tip stays reachable from the base".

## 4. Outcome

Both acceptance items land: every merge site merges with a merge commit, and a landed branch and its worktree read as merged and are reclaimed. Local proof: `ok: true`, `complete: true`, no `not_run`.

## 5. Concerns

### Most squash-era local branches cannot be proved landed

- **Severity:** low
- **Description:** A dry run of `prune-landed-branches.sh` on the main checkout proves 2 of 21 unchecked-out `work-*` branches (`content_landed`); 19 read `not_landed` because `content-reached-base.sh` needs the whole patch to reverse-apply on today's base (see [b1050656a](https://github.com/qmu/workaholic/commit/b1050656a) in `plugins/workaholic/skills/branching/scripts/prune-landed-branches.sh`).
- **How to Fix:** Add a per-branch proof via the merged pull request whose head was that branch (`claim-merged.sh`'s lookup), or let the developer remove the named remainder by hand.

## 6. Successful Development Patterns

- Pin the safety property (commit reachable from the base), not the mechanism (branch ref survives), so a ruling change moves the mechanism without weakening the guarantee.
