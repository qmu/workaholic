## 1. Overview

An `interruptible_parent` continuation now carries the loop only while the parent keeps waiting. `final-response-contract.sh` answers `next_action: wait_interruptibly` whenever that continuation is named, and refuses `continuation_ends_with_turn` for a routine or task-wait turn that declares `turn_ends` while naming it — an ending turn must arm and name a `same_chat_schedule` first.

## 2. Motivation

Issue #1267: a native coordinator persisted `control: running`, named a future-dated `interruptible_parent` continuation, emitted an ordinary progress report and its turn ended; no later tick happened until the operator prompted it. Reproduced: those facts answered `ok: true, path: resume, next_action: null` — every existing rung (`continuation_unproved`, `continuation_lapsed`, `routine_emits_no_final_response`) passed, and nothing told the parent to wait.

## 3. Changes

### 3-1. Keep the work loop alive past a progress report ([0f38b1688](https://github.com/qmu/workaholic/commit/0f38b1688))

New optional fact `turn_ends` (absent means false) and one new refusal `continuation_ends_with_turn` in `final-response-contract.sh`; `next_action` derives from the named `interruptible_parent` as well as the paused-host facts. No closed set widened and existing refusals are unchanged. The rule is stated on `work/SKILL.md`, the `infinite-development` ceiling, `runtime/reference/native-loop.md` and `CLAUDE.md` *Continuation*; hermetic cases added to both suites.

## 4. Outcome

The reported facts are refused by name when the turn ends, a turn that keeps waiting or ends on an armed same-chat schedule still passes, and the parent is now told to wait. Local proof: `ok: true`, `complete: true`, no `not_run` (verify.mjs, validate-metadata.mjs, layout-doctor.sh, agentic-loop tests, test-workflow-scripts.mjs, hermetic loop drill).

## 5. Concerns

### The reader cannot make a run declare that its turn ends

- **Severity:** low
- **Description:** `turn_ends` is the run's own declaration; a run that ends its turn without declaring it still passes (see [0f38b1688](https://github.com/qmu/workaholic/commit/0f38b1688) in `plugins/workaholic/skills/work/scripts/final-response-contract.sh`).
- **How to Fix:** Have the coordinator record the turn's end as an event so the reducer can compare it with the named continuation, rather than trusting a declaration.
