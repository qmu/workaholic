# 部分カバレッジ時に新しいSlackスレッドを見落とさない

## Overview

Slack 観測が部分カバレッジの間は channel delta を最後まで消化し、発見した root と明示 thread URL を監視対象として保持する。

## Policies

- `workaholic:implementation` / `policies/directory-structure.md` — conventional project layout
- `workaholic:implementation` / `policies/coding-standards.md` — style and structure conventions

## Key Files

- `plugins/workaholic/skills/transport/scripts/observe-channel.sh` — delta paging と coverage 証拠の集約。
- `plugins/workaholic/skills/work/` — 発見 thread の永続化と fallback 再読。
- transport/runtime tests — `has_more` と unavailable discovery の回帰 fixture。

## Implementation Steps

1. `list_thread_changes:operation_unavailable` と `has_more:true` が同時に起きる再現を作り、既知 thread だけを読む経路を特定する。
2. channel delta の全ページを bounded に消化し、新規 root と明示 thread URL を durable watch set に追加する。
3. discovery fallback では未消化期間に発見した全対象を再読し、古い固定 thread に限定しない。
4. `has_more:true`、thread coverage `partial`、sender 未検証のいずれかが残る間は quiet/新規返信なし/監視済みを拒否する契約と test を追加する。

## Quality Gate

**Acceptance criteria** — the checkable conditions that must hold:

- partial coverage 中の全 delta page と発見 thread が次回観測にも保持される。
- 不完全な証拠から quiet または監視完了を報告しない。

**Verification method** — the commands/tests/probes that prove them:

- transport observation と native work loop の focused regression を実行する。

**Gate** — what must pass before approval:

- 古い cursor、`has_more:true`、thread discovery unavailable の fixture で新規依頼を見落とさない。

## Considerations

pagination は有限 bound と retryable cursor を保ち、sender identity 未検証を成功状態へ丸めない。
