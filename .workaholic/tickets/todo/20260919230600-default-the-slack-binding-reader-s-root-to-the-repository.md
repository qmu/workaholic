# Default the Slack binding reader's root to the repository

## Overview

`transport/scripts/read-declared-binding.sh` requires `--root` and refuses `no_root` without it. Measured at `daff53802`, from this repository's root, where both `CLAUDE.md` and `AGENTS.md` exist and `AGENTS.md` carries the declaration:

```
$ sh plugins/workaholic/skills/transport/scripts/read-declared-binding.sh
{"ok":false,"declared":false,"reason":"no_root"}      # exit 2
$ sh plugins/workaholic/skills/transport/scripts/read-declared-binding.sh --root .
{"ok":true,"declared":true,"binding":{"workspace":"qmu","channel":"dev-workaholic",…}}
```

**There is no live harm today, and this ticket says so rather than implying one.** Every call site in the tree passes `--root`: `transport/scripts/observe-channel.sh`, `transport/scripts/verify-live-proof.sh`, `workaholify/scripts/check-slack-channel.sh`, `workaholify/scripts/check-slack-binding.sh`, `workaholify/scripts/apply-slack-binding.sh`, `commands/infinite-development.md`, and the two test files. The walk was made for this ticket and found no omission.

What makes it a defect anyway is the **direction of the failure** at the one seam `CLAUDE.md` describes as unconditional — *`/infinite-development` reads it **before** any Slack selection*. The reader is the single source of the repository's declared destination, so one future call site that omits the argument does not fail loudly: it reads as *this repository declares nothing*, and the loop falls through to `WORKAHOLIC_INBOUND_SLACK_CHANNEL` / `WORKAHOLIC_SLACK_WORKSPACE`, which is the exact outcome the declaration mechanism exists to prevent — a routine that runs, does its work, and posts where nobody meant. A required argument whose omission silently disables a whole mechanism is a defect in the reader, not in the caller that forgets it.

The repository already ruled on the adjacent half of this (2026-09-18, ticket `20260918210738`): `ok` is read before `declared`, and `no_root` is reported as `binding_unreadable:<reason>` and never as *this repository declares nothing*. That repair made the refusal legible to consumers. This one removes the commonest way to reach it.

Two runners disagreed about this on 2026-09-19 and one concluded "not a defect" on the strength of the no-harm walk alone. Record the reasoning above in the change so the question is settled by what is written rather than re-argued.

## Quality Gate

**Acceptance criteria** — the checkable conditions that must hold:

- Run from the repository root with no arguments, the reader answers `ok: true`, `declared: true`, `workspace: qmu`, `channel: dev-workaholic` — byte-identical `binding` to the `--root .` reading.
- Run from a subdirectory of the repository with no arguments, the answer is the same (the default is the repository root, not the working directory).
- Run with `cd` into a temporary directory outside any git repository and no arguments, the answer is exactly `{"ok":false,"declared":false,"reason":"no_root"}` with exit status 2.
- Run with `--root /nonexistent-path`, the answer is exactly that same refusal with exit status 2.
- An explicit `--root` pointing at a different repository still wins over the default.

## Considerations

- `git rev-parse --show-toplevel` answers *the tree I am standing in*, so inside a claim worktree it resolves to that worktree — which is correct here: that checkout holds its own `CLAUDE.md`/`AGENTS.md` and is the repository the caller means (`plugins/workaholic/skills/branching/scripts/survey-worktrees.sh` records the same property being load-bearing for a different reason).
- The default must not be `pwd`. A caller standing in a subdirectory would then read no declaration at all and get `declared: false` — the precise failure this ticket removes, reintroduced one level down (`plugins/workaholic/skills/transport/scripts/read-declared-binding.sh` lines 82-84, which compose `$ROOT/CLAUDE.md`).
- `apply-slack-binding.sh` refuses `declaration_unreadable` on an `ok: false` reading and `check-slack-binding.sh` names the refusal alone. Neither behaviour may change here; this ticket removes a way of reaching `no_root`, it does not reclassify it.
