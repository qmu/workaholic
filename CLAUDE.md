# Workaholic

Private, cross-agent distribution of structured development workflows and engineering standards. **AI agents are the primary users** — routines invoking `/implement` and `/specificate`, and sessions running the workflow skills — while the **developer is the operator** who approves pull requests, configures routines, and rules on deferred decisions. Richest on **Claude Code** (plugin marketplace: commands, hooks, the always-on policy lens); portable skills also ship to **Codex** (`.agents/plugins/marketplace.json` → `outputs/workflows`) and to 40+ agents via the Agent Skills standard / `skills` CLI. Authored source lives under `plugins/`; cross-agent artifacts are generated into `outputs/`.

This file states **current behavior only**, as briefly as it can. Decision history, rationale, measurements and rejected alternatives live in `docs/loop-engineering-workflow.md`, `docs/proposal-loop-runbook.md`, `docs/drive-loop-runbook.md`, `docs/loop-drill-runbook.md`, each skill's `SKILL.md` and `reference/` directory, the feedback stream (`.workaholic/feedbacks/`), and this file's own git history. **Do not re-import them here** — a rule belongs here, its story does not.

## Important

- Edit `plugins/`, not `.claude/` — this repo develops plugins; changes go to `plugins/` unless explicitly requested otherwise.
- **Update the docs in the same change.** When a change alters behavior, structure, commands, skills, or conventions, update every affected document (`README.md`, `.workaholic/README.md`, `CLAUDE.md`, `plugins/workaholic/rules/*.md`) in the same commit. Outdated documentation is a defect; `/story` runs `doc-drift.sh` and `area-freshness.sh` only as backstops.
- **Write each surface in the language its audience reads.** Reasoning on the `#dev-workaholic` channel and in Claude Code Web routines is **Japanese**. For Slack posts the rule also ships **in the plugin**, beside the shapes (`rules/interaction.md`, *The language of a post is the language its readers use*): measured 2026-09-01, a consuming repository whose own `CLAUDE.md` carried the Japanese rule still got an English `🔎 Moderation` root, because the ceiling names the only shapes a session may emit and every one of them is written out in English. GitHub artifacts (issues, pull requests, commit messages) and `.workaholic/` artifacts are **English** — the durable, shared record. Code, code comments and this repository's `docs/` tree are untouched by the rule.

### Hooks (all shipped active in hooks.json)

- `validate-ticket.sh` (PostToolUse Write|Edit) — ticket floor on the `todo/` queue only: frontmatter, location, mandatory `## Policies`/`## Quality Gate`, resolvable `mission:` relation.
- `validate-mission.sh` (PostToolUse) — Experience/≥1-acceptance floor on any mission under `missions/active/`; archive never retro-blocked.
- `validate-story.sh` / `validate-trip.sh` / `validate-feedback.sh` / `validate-strategy.sh` (PostToolUse) — OKF `type:` and schema floors on new writes; git-tracked history is grandfathered. `validate-strategy.sh` requires a `YYYY-MM-DD` `target_date`, a **non-empty** `assignees` (the one artifact where empty is a refusal, not team-owned), non-empty `## Aim` / `## Schedule`, and — when present — a `stage:` from the closed set.
- `guard-ticket-structure.sh` (PreToolUse Bash) — blocks non-canonical ticket moves.
- `guard-git-commit.sh` / `guard-git-branch.sh` (PreToolUse Bash) — commit-subject and branch-name gates.
- `guard-askuserquestion-label.sh` (PreToolUse AskUserQuestion) — every question body must open with a `[<project label>]` prefix (`gather/scripts/project-label.sh`).
- `guard-working-directory.sh` (PreToolUse Bash) — denies a top-level cwd-moving `cd`. A `( cd … )` subshell, an absolute path, a `--prefix` form, and a **leading `cd` onto a repository root** (main checkout or worktree, resolved via `git rev-parse --show-toplevel`) all pass. A chained mid-command `cd`, a target carrying unresolvable shell syntax, and bare `cd` are denied. No env-var toggle.
- `guard-repo-confinement.sh` (PreToolUse Write|Edit) — blocks writes outside this repository and its worktrees (the agent's per-project memory store is exempt). Syntactic backstop only; the primary rule lives in `rules/general.md`.
- `policy-lens.sh` (UserPromptSubmit) — injects the engineering-policy index for commands carrying the `workaholic:policy-lens` sentinel; bodies are read on demand from `skills/<pillar>/policies/`. Regenerate `hooks/policy-index.md` with `build.mjs` after editing a pillar's `## Policies` list (CI fails on drift).
- `layout-doctor.sh [path]` — read-only audit of `.workaholic/` against the layout allowlist.

## Architecture Policy

### Component Nesting Rules

| Caller                     | Can invoke                                                                                     | Cannot invoke              |
| -------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------- |
| Command                    | Skill, `general-purpose` subagent                                                              | —                          |
| Skill                      | Skill; (when loaded by a command/main agent) may direct it to spawn `general-purpose` subagents | Command                    |
| `general-purpose` subagent | Skill (via preload)                                                                            | Command, Task (no nesting) |

- **No per-workflow agent files.** The repo ships no agent `.md` files at all. A command spawns `subagent_type: "general-purpose"` subagents whose prompts name the skill to preload, the section, the inputs, and the return schema.
- **One-level fan-out.** A subagent cannot nest `Task` and cannot call `AskUserQuestion`; all fan-out and all user interaction happen at the command/main-agent level. Leaves do non-interactive work and return JSON.
- **One plugin.** `workaholic` has `dependencies: []`. All skill references are same-plugin (`${CLAUDE_PLUGIN_ROOT}/skills/<name>/...`, `workaholic:<name>`). The `workflows` marketplace entry is the generated `outputs/workflows` bundle, not an authored plugin.

### The ticket spine

Everything converges on the **ticket** as the unit of work: *sources* fill `tickets/todo/`, one executor drains it to `tickets/archive/`.

- **Sources**: `/ticket` (human-directed, with discovery), `/mission`'s Creation Interrogation (a mission's whole ordered ticket set), and `/specificate` (from the feedback stream). All publish through a **publish tree** onto a `work-*` branch behind a pull request; the artifact reaches `main` — and the executor's survey — when that PR merges.
- **Mission floor and ceiling**: two or more tickets or it is not a mission (`mission/scripts/check-floor.sh` at the publish seam; a ticketless direction is a feedback record, a one-ticket one is a plain ticket). Ceiling: `## Acceptance` normatively ≤3 items, whole `mission.md` ~60 lines / 2 KB (`mission/scripts/size.sh`, enforced on `/specificate`'s unattended drafts). Write-time floor: `## Experience` + ≥1 acceptance item.
- **One executor, two commands**: `/drive` (attended — asks exactly one thing: which units to take when several are offered) and `/implement` (unattended — no prompt at any step). Same Unified Run: freshen (`sync-main.sh`) → survey (`plan-units.sh`) → partition into PR-units → claim → drive → report → route by effective merge policy → account. `plan-units.sh` emits `backlog_all_excluded` (a derived reading over `backlog_size`/`backlog[]`/`excluded[]`, with a count per exclusion reason) so a queue emptied by claims and one emptied by `owned_by_other` never read alike. Full contract: `skills/drive/SKILL.md` and its `reference/`.
- **Merge policy** (`merge_policy: auto | review`, recorded at creation on missions and tickets; **absent means review**): `auto` ships through `/ship` — which drafts the plan and merges, never deploys — then tears the claim down; `review` merges its PR immediately after `/story` opens it. **No gate is ever overridden**: a `secret` finding hard-stops; a `size`/`leak` block or a missing confirmation method demotes an `auto` unit to the PR path.
- **The `review` route reads the severity tier, never the binary verdict.** `gate-decision.sh` computes `override_only` beside `overridable` — the one derivation of the tier policy — and the route merges on `pass` **or** `override_only`, reporting every finding in the run report and the PR body. `secret` hard-stops; `leak` holds the PR open.
- **An Open Decision is a question to answer, not a ruling that the question is unanswerable.** Writing floor (`create-ticket/reference/ticket-format.md`): three required parts — the question, **the sources consulted and what they said**, and the fork's sides; it may name whose ruling would settle it and may **not** declare the question unanswerable or tell a later session not to decide. Driving floor (`drive/reference/ticket-workflow.md` §1, `reference/failure-contract.md`): before honouring one as a blocker a run **reads the sources the item names**, plus the whole of any page it cites, and a `blocked` outcome **names those sources and what they said**. A block that cannot name a source it read is not a block. Prose contract, not a script gate. `/ticket` never writes one — it asks a human instead.
- **The verification axis is read before merge policy**: a mission or ticket may declare `verification_handoff: <what cannot run here>` **at creation** — a credential, device or third-party account an unattended run does not have. `drive/scripts/verification-handoff.sh` is the one reader, and since 2026-09-01 (issue #793) it also **derives** one the ticket never had to declare: a `## Key Files` entry naming `.claude/` is a handoff because Claude Code classifies that path as sensitive and an unattended run has no one to answer the prompt. **Measured**: seven `[Implement]` runs over five hours all read `requires_action`, each ending at the same permission prompt, while nothing anywhere said so — the resume beats the heartbeat before the edit, so `stalled-units` counted the unit healthy. A **declared** value always wins, the test is syntactic and narrow (prose elsewhere in the ticket is not read), and it is derived rather than declared because the ticket that froze the loop was already in `todo/`. Any member declaring it — or deriving one — carries the whole unit, which takes the **`handoff`** route whatever `merge_policy` says: the PR opens and stays open, the non-droppable `## Handoff` quotes the reason, the claim stays standing, the finish line is `🟡 Handoff` and the token is `pending`. Two writers only — `/ticket`, and `/specificate` (`scaffold-proposed-ticket.sh --verification-handoff`) when the ask states it or an operator-only fork survives the operator-record check; the reader's derived case is not a writer and stamps nothing. A run never declares it for its own unit. Such a fork must never be written as a `## Quality Gate` item, which `/implement` can neither ask about nor override. The claim behind such a unit reads `awaiting_verification` and is not re-offered.
- Retired predecessors (`/monitor`, `/trip`, `/carry`) and their landed ideas: `docs/loop-engineering-workflow.md` I1/I3/I5. `.workaholic/trips/` is read-only legacy history.

### `.workaholic/` runtime conventions

`README.md` and `index.md` are the only files allowed at the `.workaholic/` root.

- **OKF floor**: every knowledge artifact carries a non-empty `type:` (`Story`, `Mission`, `Feedback`, `Strategy`, `Deployment`, `Term`, `Release Note`, `Release`); `okf/scripts/refresh-index.sh` regenerates the bundle indexes before each knowledge commit. **Two exceptions**: `tickets/` (internals, never index-managed) and `moderations/` (an operational log — and since 2026-09-01 not on this branch at all).
- **`moderations/`** — the `/moderate` tick log: one file per UTC day, one `## <tick-id>` section per tick, one line per step, no frontmatter, no `index.md` (the root index links the directory bare). An operational log, not knowledge. `moderate/scripts/log-append.sh` is the only writer (append-only, idempotent per `(tick, step)`, **never prunes** — deleting a day file is the operator's act); `log-read.sh` is the reader a step consults before re-filing. **Since 2026-09-01 (issue #782) the log is not on `main` at all**: it lives on its own orphan branch, derived once in `gather/scripts/log-ref.sh` (`workaholic-log` — matching neither `work-*` nor `release/*`, so the claim scan never sees it), and `.workaholic/moderations/` is **git-ignored** so an ordinary `git add -A` cannot put it back. Measured before the move: three commits an hour, ~50 a day, `main`'s single largest author after the squash-merge change, and **a commit is a change to the development target**. The move has **two halves and neither works alone**: `persist-log.sh` publishes to that branch, and `step-open-log.sh` **hydrates** it into the checkout (`hydrate-log.sh`, newest 30 day files) before any reader runs — without the second, every dedup would answer *no earlier tick ever ran* and re-fire hourly. A hydrate that failed is named in that step's summary and the tick continues, over-reporting rather than under-reporting. The tick still persists as its closing act and **again** after the agent has recorded what it filed; the caller's checkout stays byte-identical, concurrent ticks **union by `(tick, step)`** and line-wise inside a shared section, and a persist that missed the branch is reported `degraded` with the log left for the next tick. **The records take the other road**: `persist-log.sh --record <path>` carries the tick's feedback records to **`main`** in their own commit — a feedback record is knowledge and must not follow the log onto an operational branch — named one by one, never a sweep of the index; each reported `carried` / `already_on_base` / `missing` / `unreadable` / `unlanded`. The existing history stays on `main` (rewriting it would force-push over every clone to tidy a log); `gather/scripts/migrate-moderations-off-main.sh` **seeds the branch and only then untracks**, and that order is the safety property. A `<step>-filed` line does not prove a filing: `filed-records.sh` asks the tree, an `unlanded` record counts as not filed, and `readable: false` is named rather than rendered as an empty set.
- **Mission rolling**: commit seams (archive, ship, report) append `## Changelog` lines and tick `## Acceptance` items via the mission skill's idempotent mutators (`append-changelog.sh` / `tick-acceptance.sh`). Progress (`checked ÷ total`) is computed, never stored. Acceptance items become tickable through their `(#<filename>)` link, stamped only by the emitting seam via `link-acceptance.sh`. The `mission:` relation is many-valued; read it only through `read-relation.sh`.
- **One slug can name two missions, and the audit reports it** (2026-09-01, ticket `20260901070000`): `/specificate` dedups on the ask's **feedback refs**, so two records written for one ask produce two missions whose slugs — derived from the title — collide. `create.sh` already refuses a slug that resolves in either area, and **cannot** catch this: it resolves against the checkout it runs in, so a mission living only on an unmerged publication is invisible, and the collision then arrives by **merge**, where no create runs at all. Measured: both pairs in this repository (`deliver-what-the-loop-already-knows-…`, `say-when-the-loop-has-run-out-of-direction`), in each case the later record's mission driven and archived while the earlier sat in a refused publication and landed days later. `layout-doctor.sh` reports each pair as an **advisory** — never a finding, which would fail the merge gate over history that harms nothing until something tries to move the active copy into an occupied archive. It **deletes nothing and chooses nothing**: both copies are history (one carries the implementation changelog and run hours, the other the verification) and which survives is the operator's ruling. Refusing at the close or the move was rejected — `archive.sh` runs unattended with no person attached.
- **Mission lifecycle**: `status: active | achieved | abandoned | carried` — one in-flight state; `active/` vs `archive/` areas; `mission/scripts/close.sh` is the **only** writer of an end state. Merging the mission's PR is the approval; drivability is derived (active area + plan + queued tickets), never a status word. `archive.sh` closes the one outcome that is arithmetic — `close.sh <slug> achieved` when archiving a ticket leaves acceptance fully checked (`progress.sh`: `checked == total`, `unlinked == 0`) and the queue empty (`queue-size.sh`) — **never `abandoned` or `carried`**, which assert intent. An unreadable reader is not a proof and leaves the mission alone; the close and any refusal are named in the archive output and the run report. A mission finished by a path that archives no ticket is caught by `/moderate`'s `closable-missions` step, which re-proves each candidate in a publish tree and lands the closes (only `achieved`; a rejected re-proof is reported, not closed). That step never reaches `plan-units.sh`, which stages what its living migrations converge.

#### The strategy layer

`.workaholic/strategies/<slug>.md` is the operator's **outbound, resolved direction**: an **Aim**, a **Schedule** (`target_date`), an **Assignee** (non-empty `assignees`) and a **Stage** (`stage:` from the closed set `進行中 | 改良中 | 観察中`, the operator's vocabulary kept verbatim; **absent means 進行中**, resolved in `read.sh` alone). Flat, one file, operator-authored through `workaholic:strategy`; `/drive` never surveys one. The stage is **declared, never derived** — every other reading here is evidence the loop computed, and no reading may compute, move or infer the stage; a reading may suggest a transition and the operator's announcement performs it. Stuckness (a handoff, a block, a stale claim, a queue that will not drain) is orthogonal to the stage and never read as one.

**Three writers and no fourth** (pinned by the suite): `create.sh` creates (`--stage`, refusing `bad_stage` with nothing written), `amend.sh` revises a live direction's `## Aim`, Schedule, Assignee and Stage, `close.sh` ends. `amend.sh` is bounded to those four parts, asserts `slug`/`type`/`status`/`created_at`/`author`/`feedback:` immutable, refuses a closed direction `not_active`, carries the write-time floor itself, writes **nothing** on any refusal, and appends one dated `## Schedule` line naming what moved (a stage move names both ends, e.g. `進行中 → 改良中`, reading the previous value through `read.sh`). `close.sh` is the only writer of an end state; re-opening is offered nowhere. `carry-attribution.sh` is **not** a fourth writer — it writes one `feedback:` line on a **mission**. A run never amends or moves a stage on its own reading; `/specificate` carries the operator's words verbatim.

**Readers** (each composes the ones below it; no second walker, no relation of its own, no field on any artifact):

| Script | Answers |
| ------ | ------- |
| `read.sh` / `list.sh` | the artifact, with the absent-stage default resolved once (`stage_declared` says which answer a caller has) |
| `attributed-work.sh` | which work belongs to a strategy — `strategy.feedback[] ∩ artifact.feedback[]` (`direct`) plus the hop through a mission attributed that way (`via_mission:<slug>`); reports ticket **and** mission grains (`waiting_missions*`, `waiting_kind`/`waiting_describing`/`waiting_advancing` via `work-kind.sh`) |
| `mission-strategy.sh` | the inverse — which strategy a mission belongs to |
| `unattributed-work.sh` | what no direction claims (active missions by slug/path with queued-ticket counts, loose queued tickets) |
| `survey-strategies.sh` | one row per strategy: `refusal`, `pace`, `overdue`, `expiring`, `dormant`, `quiescent`, `landed`, `stage`, `residue`, `target_date`, `days_to_target` |
| `direction-state.sh` | the lifecycle: `live \| arrived \| overdue \| expiring \| dormant \| unreadable`, plus the repository-level `none`; `--with-leaving` attaches the leaving per row by handing that row back through `--state-row` |
| `closing-residue.sh` | what a direction is leaving — the waiting grains, the residue, and its last lifecycle reading, each block carrying its own `readable` and reason |
| `default-target-date.sh` | the operator's one-week default (the constant **7** lives here and nowhere else) |

The lifecycle precedence is fixed: **`unreadable` > `arrived` > `overdue` > `expiring` > `dormant` > `live`**. A sixth value is refused — `stage` rides **beside** the answer and never enters the precedence. Definitions: `overdue` = `days_to_target < 0` (a `null` date is never overdue); `expiring` = `0 <= days_to_target <= window_days`; `dormant` = legible, `active`, `mine`, not overdue, cited, nothing landed in the window, nothing waiting at either grain, no open proposal; `quiescent` = `dormant`'s complement on one term (`landed` non-empty) with **no date term at all**, and **`false` when the residue read was degraded**; `pace` (`late | on_course | unknown`) changes order, never eligibility.

**Degradation is stated, never derived into a verdict.** A walk that could not complete answers `readable: false` with a named reason (`corpus_unreadable`, `patterns_unreadable`, `attribution_unreadable`, `strategy_unreadable`, `waiting_unreadable:<reason>`) and **null** counts — never `no_citing_artifacts`, which means the opposite. **`readable` is absent on a completed walk** (the `merge_policy`/`status:` convention: absent means it completed), so the test is `readable == false`, never `readable // true`. Named empties stay honest: `no_feedback_refs`, `no_citing_artifacts` (*nothing has answered this direction yet* — guaranteed by `/specificate`'s carry floor), `no_activity_in_window`. Attribution is **transitive, lossy and `exhaustive: false`**: work a run never emitted, an ask naming no refs, an unresolved ref and any hand-written artifact stay uncited for ordinary reasons.

**Succession**: a *created* announcement may name a **predecessor slug**; that predecessor's own `feedback:` refs are read through `read.sh`, composed through `feedback/scripts/ask-feedback-line.sh --refs-only` and handed to `create.sh` as the argument it already takes — `create.sh` learns nothing about succession. Refusals: `strategy_not_found`, `predecessor_active`, `no_predecessor`.

**A strategy-touching publication never auto-merges** — the seam's rule, not the caller's: `publish-tree-pr.sh` derives it from the tree and reports `merge_reason: strategy_touching`, whatever `WORKAHOLIC_AUTO_MERGE` says. The operator's merge is the authorship; closing is the refusal.

The retired `strategy:` mission relation and its ownership hop stay retired; `mission/scripts/migrate-strategies.sh` and the `missions_migrate_strategies` seam are retired — **do not re-add them**. Full record: `skills/mission/SKILL.md`, *The strategy layer: retired, then redefined*. **Which direction a mission serves is a render, not a field** (2026-09-01): `mission-strategy.sh` answers it and three mission-facing surfaces state it — the bare `/mission` roadmap, the **Mission Position Report** (`/mission-close` and `/drive`), and `/standup`'s per-strategy digest — each rendering an explicit *no strategy* where nothing could be attributed and naming an unreadable walk as unreadable. Why the field is not the answer is recorded in `mission/reference/schema.md`, beside the frontmatter block where the question recurs.

#### Tickets, ownership, identity

- **Ticket state is a field, the archive is a place**: `tickets/` is **two-state** — `todo/` and `archive/<branch>/`. State is `status:` frontmatter: **absent means queued**, `done` (stamped by `archive.sh`), `abandoned`, `icebox` (deferred and promotable; `promote-icebox.sh` **clears** the field). A ticket never driven lands in the synthetic `archive/unbranched/`. The retired `icebox/` and `abandoned/` directories are still read by every reader while `gather/scripts/migrate-ticket-states.sh` converges them at the write seams; `layout-doctor.sh` reports a survivor as `retired-ticket-state`.
- **Ownership**: plural `assignees` on every artifact; **empty means team-owned/claimable**. One oracle — `gather/scripts/owners.sh`, with `owns.sh` returning `mine`/`unowned`/`other`/`unresolved` (compared by slug, both sides canonicalised).
- **Identity**: `.claude/git-identities` maps `<login>=<canonical>[,<alias>...]` (first field canonical, the rest the same person's other addresses) and `gather/scripts/identity.sh` is its **one reader**, resolving a login *or* an address. It **never guesses**: an absent file, entry or unparseable line answers `resolved: false` and echoes the input back (the identity function), so a caller that resolves unconditionally behaves exactly as before it existed. A line with no comma is what the format always was. The only sanctioned second parser is the web bootstrap's step 0b (`cut -d, -f1`), which runs before the plugin is installed. Already-written artifacts are recovered by `gather/scripts/migrate-assignee-aliases.sh` (a living migration at `/workaholify`'s converge seam: idempotent, **stages and never commits**, leaves canonical entries byte-identical, and touches nothing it cannot resolve, naming every such address). Claim authorship and resumption key on `git config user.email` separately; `WORKAHOLIC_CLAIM_IDENTITY` overrides the scan identity for an executor with none configured (see the claim protocol).
- **Ticket-only tolerance tier**: a queued ticket still at `tickets/todo/<user-slug>/<file>.md` with neither field resolves to `<user-slug>` — the directory that *was* the ownership record. Only that path shape, only when both field tiers are silent, only tickets; a ticket directly in `todo/` answers `unowned`, and `author:` stays out of ownership. Written to be deleted with the layout.
- **Feedback subject**: every new record names **whose opinion it is** — `subject: <kind>[:<identity>]`, kind from `person | meeting | observer_ai | customer | team | other`. Three axes: **subject** = who formed the opinion, **source** = the channel it arrived through, **author** = the git identity that ran the capture. `create.sh` takes `--subject` and **refuses** (`no_subject`) rather than default it. `/specificate` supplies the triggering issue's author; `ship`'s extractor supplies `observer_ai:<author>`; `validate-feedback.sh` floors new writes and grandfathers older ones.
- **Deferred concerns** live in the feedback stream: the story's Concerns section is the durable record (PR body drops `low` blocks at render); `ship`'s `extract-deferred-concerns.sh` persists each as a `kind: concern` record keyed on `concern_id`; the open set is computed — a concern is open until a later record names it in `supersedes`.
- **The red-alert cool-down** expires at the **earlier** of 24 hours after the first report and the start of the next working day (the first hour inside `WORKAHOLIC_WORK_DAYS` at the end of `WORKAHOLIC_QUIET_HOURS`, in `WORKAHOLIC_QUIET_TZ` — the check-in gate's own terms, composed rather than re-derived). A root re-posted at expiry names **how long** it has been failing. The `↳ still failing` reply, the first-report rule and the unreadable-history rule are unchanged (`workaholic:notify`).

#### Areas

- **The two hand-maintained areas** (`deployments/`, `terms/`) each carry a definition (`rules/workaholic.md`) and one upkeep seam: `story/scripts/area-freshness.sh`, read by `/story` beside `doc-drift.sh`. It **reports, it never writes** — two mechanical facts per record: `retired_terms` (it still names a de-listed area or retired namespace) and `stale_days` (thresholded by nobody). `/ship` is the only live *reader* of a deployment record and gates on its `## Confirmation`. Records carry `type: Deployment` / `type: Term`; `terms/inconsistencies.md` is an ordinary term entry.
- **Retired areas**: `.workaholic/policies/`, `guides/` and `specs/` are gone — content deleted, not relocated; reference documentation lives in the repository's own `docs/` tree, and the `"docs" → specs/` request mapping points there. `layout-doctor.sh` classifies them `retired-area`; the content decision stays the owner's.
- **A rename is a row, not a sweep**: `skills/gather/scripts/renames.tsv` declares every rename, read only through `list-renames.sh`. Two kinds. An **`area`** row (a `.workaholic/` top-level directory) is **applied** — `migrate-renamed-areas.sh` `git mv`s it and fixes the generated root index, and `layout-doctor.sh` classifies a survivor `renamed-area` **before** consulting the allowlist. A **`name`** row (a command name, skill namespace, path fragment) is **proposed, never applied** — `rename-conversions.sh` counts survivors outside `.workaholic/` and prints the bulk conversion for the operator to run or decline. A retirement is not a rename and stays out of the table. A row is deleted once the fleet has cut over; an empty `rename_conversions` is the signal that it has. The registry never uses a live token as its own example. `WORKAHOLIC_RENAMES_TABLE` points the chain at another table — a data source, never a gate opt-out.
- **Closed layout**: the permitted top-level `.workaholic/` directories are fixed in **two lockstep sources** — `hooks/workaholic-layout-allowlist.txt` and the table in `plugins/workaholic/rules/workaholic.md`. A new artifact directory must be registered in both **in the same commit** that first writes to it; `layout-doctor.sh` audits and the `Validate Plugins` CI workflow fails the merge on `conforming: false`.

### Claim protocol

The repository is the coordination medium. The model is stated once in `skills/drive/SKILL.md` (**Claims**) with full detail in `skills/drive/reference/claims.md`.

- A runner claims a PR-unit (mission slug or `batch-<ts>`) as a `Claim <unit-id>` commit on a pushed `work-*` branch; **unmerged remote branches are the only claim oracle** (`list-claims.sh`). One unit ↔ one branch ↔ one worktree (`.worktrees/<unit-id>/`) ↔ one PR.
- A merge releases a claim by definition. `release-claim.sh` explicitly discards an unfinished unit (never a recovery path) and sets `CLAIMS_FETCH_OK` after its own fetch, as `claim.sh` does. `claim.sh resume` takes over **your own** claim whose heartbeat lapsed; a colleague's is untouchable at any age. Staleness is reported, never acted on.
- The heartbeat is the branch tip (`heartbeat.sh`, an empty commit built against a scratch index). `archive.sh` pushes the claim branch after each archive commit. **The beat is step 0 of every ticket, not a cadence** (2026-08-31, ticket `20260831150500`): `archive.sh` refreshes the tip for free but only at the **end**, so a unit that is one long ticket runs its whole implementation on the claim commit's own timestamp and loses its own claim to the 30-minute `WORKAHOLIC_CLAIM_HEARTBEAT_STALE_MINUTES` resume window by construction — not the 24-hour `WORKAHOLIC_CLAIM_STALE_HOURS`, which is the *reported* staleness and governs no takeover. Measured on `batch-20260831141002`: resumed by a second tick at 33 minutes, and a complete, validated, locally-committed implementation was discarded rather than force-pushed over a branch another run was actively driving. A **beat inside a per-ticket seam** was refused (the only one that runs early is a pure reader shared with other callers) and so was **making the loss visible instead** (a reading after the fact returns none of the work); a background timer is refused outright, because it would be a second liveness authority beside the branch tip. No store, no cursor, no field, and the suite pins both the behaviour and that the workflow still names the step.
- Worktrees are **claim-born and ship-torn** (`cleanup-mission-worktree.sh` is the sanctioned cleaner; `survey-worktrees.sh` / `reap-worktrees.sh` back the teardowns up). `.worktrees/` and `.publish/` sit inside the repo root — add them to `.dockerignore` and any archiver's ignore list.
- `branching/scripts/ensure-worktree.sh` **refuses** a branch name that already exists on origin rather than minting a local branch at `HEAD` that shadows it; attaching to a published branch is `create-mission-worktree.sh --branch`'s job.

#### Verdicts

| Verdict | Meaning | Resumable | Survey exclusion |
| ------- | ------- | --------- | ---------------- |
| `claim_active` | live claim, heartbeat fresh | no | `claimed_*` |
| `stale` | tip older than `WORKAHOLIC_CLAIM_STALE_HOURS` (default 24) — *look at this*, not *take it* | own claim only | — |
| `superseded` | the unit's tickets reached the base **and the branch is empty against it** | no | `claimed_superseded` (work **resurveyed**) |
| `stranded` | the tickets reached the base and the branch **still holds work found on no other ref** | no | `claimed_stranded` |
| `queue_drained` | drained, story at the tip, PR open — waiting on a person | no | `claimed_reported` |
| `report_incomplete` | drained, **no story** — a dead run's remains | **yes** (re-enters the Unified Run at §5) | `claimed_resumable` |
| `report_undelivered` | the run recorded the transport's refusal into its own branch story | no — the next act is a **merge retry** | `claimed_undelivered` |
| `awaiting_verification` | remaining queued work declares `verification_handoff:` | no | `claimed_awaiting_verification` |
| `parked_with_pr` | reported with follow-up work on the branch | yes | — |
| `heartbeat_lapsed` / `foreign_identity` / `identity_unresolved` / `shallow_history` / `ambiguous_claim` | as named | no | — |

**Proofs and judgements** (`skills/drive/reference/claims.md` — the one home, keyed on the word `lib/claims.sh` emits, with no field on any artifact and no classifier function): a consumer may **act** on a proof and may only **report** or **ask about** a judgement. **`superseded` now proves the branch is empty, not merely that the tickets landed** (2026-09-01, issue #788). `retire-claim.sh` deletes a branch on that strength alone — *what makes a destructive act safe here is the proof, and nothing else* — and offers as recovery that *its content is on the base, that is what `superseded` means*. It did not mean that: the step from *the tickets are archived* to *the branch holds no work* holds only when a branch carries nothing but its own unit's tickets. **Measured**: two branches whose tickets had landed through *different* branches still held ~300 lines of code and a documentation section present on no other ref, and the tick was asking for both to be deleted; only a 403 on `push --delete` had prevented the loss, for five days, while the tick reported that refusal as the problem. `claims_branch_empty_against_base` (one `merge-base`, one `diff --quiet`, no network) now gates the verdict, an unanswerable emptiness answers **`stranded`** rather than `superseded`, and a `stranded` unit is asked about by `/moderate`'s `retire-claims` step and reaches no retirement, no `resurveyed[]` and no delete.

**`superseded` and `report_undelivered` are the only proofs** — readings the tree or a merged pull request established, which cannot become false by looking again. Everything else is a judgement, the absence-of-a-reading words (`shallow_history`, `ambiguous_claim`, `unanswerable`) most of all. Six further vocabularies live there as keyed sub-tables, **none holding a proof**: the base's own checks, whether an operator-facing pull request was acted on, how long a condition has been standing, a branch's mergeability, whether an act the loop took had its effect (`drive/scripts/act-effect.sh`, the one reader for both the retirement and the delivery act, owning the assembly and no act's vocabulary), and **what became of a person's own answer** (`moderate/scripts/answer-outcome.sh` → `settled:nothing_filed` / `settled:issue_closed` / `pending` / `unreadable:<reason>`, composing `question-state.sh`, `log-read.sh` and the one transport at one bounded read per **filed** candidate and none for the rest; an issue can be closed and reopened between two reads, so nothing may merge, close, gate, hold work or re-ask on it, and a question with **no recorded answer** is refused `not_answered:<state>` rather than called `unreadable`). A seventh, differently-keyed table records **which question reads which age** (nothing derives an age twice). Each names its consumers, and `scripts/test-workflow-scripts.mjs` fails when a script emits an unclassified word, a table classifies a word nothing emits, a row is called a proof, or an enumerated consumer reaches an acting call site.

**When a bounded act may read a judgement** (`claims.md`): only when it **re-derives that judgement at the moment of the act**, is **idempotent**, is **reversible**, and **refuses every bound by its own word**. Consumers are enumerated (`catch-up-claim.sh` is the only one). The exception reaches no judgement that is the absence of a reading and none whose next step is a person's judgement. Two gating shapes, one rule: a **licensing** act refuses on an absence, a **gating** act proceeds on one.

**Resolution**: a unit held by two branches resolves to the **live** row, derived once in `lib/claims.sh` (`claims_unit_resolution` / `claims_unit_row` / `claims_unit_live_branches`) and read by every writer; `superseded_only` returns the superseded row for callers that must keep refusing under it. **Two live claims are reported, never picked between** (`ambiguous_claim`, naming both). A `superseded` row beside a live one governs nothing while staying reported; `claim.sh` skips it so a fresh claim over proved-empty work goes through, and `plan-units.sh` names the freed work in `resurveyed: [{kind, id, claim}]`, never in `excluded[]`.

**`superseded` at both grains**: a **batch** claim is answered from the tree, network-free (every one of the unit's tickets archived on the base, matched by filename under any branch directory); a **mission** claim from the claim's own tip (`claims_mission_landed` over `claims_tickets_for_mission`, `every` and never `any`), with `drive/scripts/claim-merged.sh` — the protocol's **one network read** — as the fallback. That lookup is **three-valued**: `unanswerable` leaves the row the verdict it would have had without it and is named in `merged_lookup_unanswered[]`; it is skipped by name when it cannot succeed (`offline`, `disabled` under `WORKAHOLIC_CLAIM_MERGED_LOOKUP=0`).

**Two runs can claim and drive one unit.** `claim.sh resume` contends on one ref (the loser `resume_race_lost`), but a **fresh** claim mints its own `work-*` name, so two runners that survey before either pushes both succeed. One ref per unit cannot be arbitrated in this container (`refs/claims/*` answers 403 over both transports; `refs/heads/*` is the only writable namespace and could never be released), so the damage is bounded later: `archive.sh` **re-derives the claim immediately before the ticket moves** through `drive/scripts/claim-holder.sh`, refusing `claim_taken_over` and `ambiguous_claim` with the tree byte-identical and **proceeding** on any absence. A live race reaches a person through `drive/scripts/list-raced-units.sh` and `/moderate`'s `raced-units` step (`raced-unit:<unit>`); three sibling steps filter and count it through `moderate/scripts/lib/raced-units.sh`. No consumer releases a claim, picks between branches, deletes a branch, closes a PR, reverts, merges, gates or holds work on it.

#### The three acts on a claim

Each acts on a proof, re-derives it at the moment of the act, is idempotent, and refuses every bound by its own word with nothing written and exit 0. Full contracts: `skills/drive/reference/claims.md`.

- **Retirement** — `drive/scripts/retire-claim.sh <unit>` acts on `superseded`: close the pull request, delete the remote branch, reap the worktree, in that order (the local reap last, so a refusal there leaves both remote facts correct). Success words (`already_closed` / `already_gone` / `absent`) and blocked words (`gh_unavailable`, `slug_unresolved`, `pull_request_close_failed`, **`branch_delete_failed`**, `worktree_reap_refused`) are each their own; a refusal reports `not_attempted` for all three; judgements are refused by their own verdict word. It merges nothing, pushes into no branch and touches no `.workaholic/` artifact. **Act 2 is refused in this container** (a session-type refusal both transports agree on), so it runs in **`.github/workflows/claim-retirement.yml`** — `permissions: contents: write` and nothing wider, `push: [main]` + `workflow_dispatch`, a full-history checkout with every remote head — which owns no proof logic: `list-retirable-claims.sh` supplies candidates (only `superseded_only` units; a degraded scan yields no candidates **and its reason**) and `delete-retired-claim-branch.sh` acts, bounded by `not_a_work_branch` / `release_branch` / `not_on_base` / `pull_request_open`. `record-ci-retirement-turn.sh` records the candidate reading and each act's `state`/`reason` as `::notice::` check-run annotations (no permission needed; bounded by `WORKAHOLIC_CI_RECORD_MAX`, default 20, a truncated record saying so), and `read-ci-retirement-record.sh` answers per unit `taken` / `refused:<word>` / `pending` / `unavailable` / `unreadable`, matched on `head_sha`. CI-side scripts run under `lib/runner-identity.sh`, which may set `WORKAHOLIC_CLAIM_IDENTITY` — an **override, not a default** — only with no identity configured, only as an author the committed mapping names, taking that author's own row; the identity-first precedence in `lib/claims.sh` does not move.
- **Delivery retry** — `plan-units.sh` emits `undelivered: [{unit, branch, merge_outcome}]` (a **field**, not a loosened exclusion). `drive/scripts/retry-undelivered.sh <unit>` acts on `report_undelivered`: **one** `PUT .../merge` through the same REST seam that refused it, creating no branch, worktree or claim. Every other verdict is `not_undelivered:<verdict>`; a scan-held PR is refused `scan_held:<tier>` regardless. A still-refused unit has the **new** word recorded back onto its branch with no worktree, through `record-merge-outcome.sh` (still the one writer of that section). `--own-tip` relaxes exactly one term (`WORKAHOLIC_CLAIM_HEARTBEAT_STALE_MINUTES=0`) so a just-caught-up branch is not refused `claim_active`.
- **Catch-up** — `drive/scripts/claim-mergeability.sh` answers `clean | mechanical | content | unanswerable` per branch from `git merge-tree --write-tree` (no worktree, index, ref or extra network call), rendered on every claim row as `mergeability` / `mergeability_reason` / `mergeability_content_files`. **The merge is computed with the repository's own `.gitattributes` out of reach** (2026-09-01, ticket `20260901041500`) — run from an empty directory with `GIT_DIR` set, because git reads merge attributes from the **working tree** and **GitHub applies none of them when it computes `mergeable`**. Measured, same git and the same two commits: from the checkout `merge-tree` exits 0 while a clone with no `.gitattributes` exits 1 on `.workaholic/feedbacks/index.md` and the API answers `mergeable_state: "dirty"`; five open publications read `clean` here and `dirty` there, and the loop attempted the merge and was refused `merge_not_allowed` every hour. The union driver is **not** the defect and is not removed — the **writer** (`catchup-main.sh`, in a real checkout) still resolves such a path with no judgement, which is why `mechanical` is the honest class and why the existing catch-up settles these branches. `drive/scripts/catch-up-claim.sh <unit>` composes `ship/scripts/catchup-main.sh` (never a second merge engine), attaches the worktree through `create-mission-worktree.sh --branch`, regenerates with the repository's own tooling and runs its fast checks before pushing; `already_current` touches no ref. Refusals: `content_conflict`, `not_my_claim`, `foreign_identity`, `identity_unresolved`, `claim_active`, `dirty_worktree`, `scan_held:<tier>`, `not_a_work_branch`, `ambiguous_claim`, `mergeability_unanswerable:<reason>`, `catchup_<class>`, `validation_failed:<check>`, `push_failed`, `pull_request_reviewed` (three-valued — `reviews_unreadable:<reason>` never falls through as *nobody has reviewed*; a bot's review is not a person's). The classification rule lives in **one** place, `ship/scripts/lib/conflict-class.sh`, read by the reader and by `catchup-main.sh`; it covers the generated OKF indexes by path and a flat area's marked region by proof (mechanical only when neither side changed anything outside the `okf:generated` markers). `catchup-main.sh --resolve-mechanical` binds the caller to regenerate (a version manifest is raised to the higher semver and merged, never taken wholesale); without the flag it is byte-for-byte what `land-unit.sh` gets. `list-catchable-claims.sh` answers this identity's **reported** claims whose `mergeability` is `mechanical`; a `content` conflict is refused with the branch byte-identical and reaches its holder through `/moderate`.
- **A publication is not a claim, and has its own reader and act** (2026-08-31): a publish-tree publication carries no `Claim …` commit, so the oracle gives it no row and no catch-up path ever saw one. `branching/scripts/list-stranded-publications.sh` names each open pull request on a `work-*` branch the claim oracle does **not** own and whose publication-refusal word is empty (an operator-facing one is `list-operator-facing-pulls.sh`'s), carrying `claim-mergeability.sh`'s class verbatim; `branching/scripts/settle-stranded-publication.sh <number>` acts on **`mechanical` and `clean`** — a `mechanical` one catches up through `catchup-main.sh --resolve-mechanical`, regenerates, runs the fast checks and pushes before its one REST merge; a **`clean`** one takes none of that (2026-09-01, mission `deliver-a-stranded-publication-that-needs-nothing-but-a-merge`: nothing collides, so `merged`/`regenerated`/`validated`/`pushed` all report `false` and no ref is written before the merge) — re-deriving its verdict at the moment of the act and refusing `not_mechanical:<class>` (`content` waits on a person, `unanswerable` is the absence of a reading) / `content_conflict` / `has_claim_commit` / `not_a_work_branch` / `scan_held:<tier>` / `validation_failed:<check>` / `push_failed` by name, with nothing pushed and no worktree left behind. The gate runs before the merge on **both** paths, and the worktree is attached on both because the scan needs a checkout. Measured before the widening: five of six open publications read `clean`, the oldest six days old, every one green and delivered by nothing. It emits **no claim verdict word** and `reference/claims.md` gains no row. **A publication carries its own age** (2026-09-01, ticket `20260901062000`): `lib/publication-age.sh` is the one derivation — read by the reader, by the act, and by `publication-effect.sh` — rendering `age_hours`, and **null rather than 0** when the timestamp cannot be read, because zero reads as *opened this second*. It is **evidence and never a gate**: the act settles a stale publication exactly as it settles a fresh one, and what the age earns is that a person is told. Measured 2026-09-01: five of six open publications were `clean`, the oldest six days old, and landing them queued ~15 tickets for work the loop had already finished. An age threshold on the **act** was refused by name — it would strand precisely the publications the `clean` widening exists to deliver — and so was a survey-side *already implemented* test, which is a judgement about behaviour rather than a file test.

#### The publish tree

The claim is the only creator of a branch a runner may drive. Artifact writers use the **publish tree**: a checkout of `origin/main` at git-ignored `.publish/` on local branch `publish-main` (`open-publish-tree.sh` → write → `publish-tree-pr.sh` (default, PR path) or `publish-tree-commit.sh` (direct, post-merge seams only) → `close-publish-tree.sh`). The caller's checkout is left byte-identical.

**Two publications never auto-merge, and both refusals are the seam's**: a tree touching `.workaholic/strategies/` reports `merge_reason: strategy_touching`; a tree carrying a **ruling** — a mission that already existed on the base whose `feedback:` line the diff moves, or any touch of `.claude/git-identities` — reports `merge_reason: ruling_touching`. The test is on the **shape of the change**, never a title or label, so a brand-new mission (what every `/specificate` proposal writes) is not caught. `branching/scripts/lib/publication-refusal.sh` holds that test as **one rule**; the seam holds the adapter and the act, and `branching/scripts/publication-effect.sh` reads such publications back for `/moderate`'s `operator-pull:<number>` question.

The claim oracle degrades offline; the writer fails loudly. Under `/implement`, each unit posts **one finish line per unit** into the thread the stateless lookup found (`unit-feedback-stems.sh` + `workaholic:notify`); when several stems match, the first-sorting stem's thread wins; when none does, the run posts the **description root** and replies the finish line into it. Transport: **connector primary** — it is the only transport that can **search**, so it resolves every thread — with the tokened `notify-slack.sh` as the machine fallback. A **directed** post (`/moderate`'s `🙋` question, the `🟡 Handoff` ask) takes the **bot identity** when its mention target resolves to the posting identity, because Slack notifies nobody of their own message; the change is *which account speaks*, never *which transport finds the thread*. The directed set is **enumerated in one place** (`workaholic:notify`, *Which transport carries which shape, and why*) and extending it is a deliberate edit there, never a judgement made at post time. `notify-slack.sh --thread-ts` posts into a resolved thread under the same `chat:write` (refusing `bad_thread_ts` rather than dropping it, byte-identical payload without the flag) and still **cannot search**. `notify-slack.sh` resolves its channel through `workaholic:notify`'s own stated order — an explicit `WORKAHOLIC_SLACK_CHANNEL`, then `WORKAHOLIC_INBOUND_SLACK_CHANNEL`, then the repository's own name (2026-09-01, issue #806: it used to require a second variable for one channel, so the transport designated to survive a connector outage answered `no_channel` during one). With **no bot token** a directed post falls back to the connector and the run **reports the surface that carried it** — never dropped, never silently downgraded. An attended `/drive` run posts nothing to Slack.

### The release tier (`release/*`)

`main` is the continuously auto-merged development branch; **quality is gated at the `release/*` QA window**, not at merge time. A release branch is cut from `main` by `branching/scripts/cut-release-branch.sh` (`release/YYYYMMDD-HHMMSS`, batch-level, explicitly invoked — never a step of the per-unit ship), carries no commits of its own, and is invisible to the claim protocol. `/ship` §5 does not deploy or confirm pre-merge: what a unit branch used to prove before landing is proved here, over the batch, or not at all. The durable ship record is `.workaholic/releases/<release-branch>.md`, written by `ship/scripts/record-release-cut.sh` and `confirm-release.sh`, both derived from git. A promotion's confirmation is never skipped; a failed confirmation deletes nothing — the next attempt cuts a fresh release branch. No `develop`, no `hotfix/*`.

### Design principles

- **Thin commands, comprehensive skills.** Commands are a few lines naming the skill, section, and entry-point contract; knowledge (templates, rules, scripts) lives in skills (~50-150 lines; overflow goes to `reference/`).
- **Common operations go through skills**: git context via `gather/scripts/git-context.sh`, ticket metadata via `gather/scripts/ticket-metadata.sh` — never inline `git branch --show-current` etc. in command/agent markdown.
- **No complex inline shell** in command/subagent markdown (no conditionals, pipes, loops, text processing, defaulting expansions) — extract to a skill script.
- **`${CLAUDE_PLUGIN_ROOT}` for every skill script reference** — relative paths do not resolve at runtime.
- **Plugin boundary**: invoke skills by their loaded `workaholic:` namespace; never read global/marketplace installs on disk to *find* skill content, never guess a namespace. The one sanctioned crossing is `check-deps/scripts/plugin-src.sh`, which resolves the newest plugin tree on the machine so an unattended run whose binding is missing or superseded still executes the workflow — the harness binding is an input, never a precondition (`rules/general.md`). It resolves on **two axes: newest version wins, and an equal version goes to the immutable candidate**; callers read `src_immutable` and either require it or re-resolve after a tree-moving step. If a skill is missing from context in an *attended* session, ask which plugins are loaded.

### Cross-agent exposure and generated outputs

- Script-bearing skills carry `metadata.internal: true` (hides them from the `skills` CLI; Claude Code ignores the field) and keep `${CLAUDE_PLUGIN_ROOT}`, reaching non-Claude agents only through the generated bundle. Pure-prose skills (`design`/`implementation`/`operation`, `write-release-note`, `review-sections`) are intentionally exposed.
- `outputs/workflows/` is the self-contained public bundle: `${CLAUDE_PLUGIN_ROOT}` rewritten relative, internal/preload metadata stripped (`publicizeSkillMd`), `reference/` directories carried with paths rewritten. **Regenerate with argument-less `node scripts/build-plugins/build.mjs` whenever a workflow skill or its script closure changes.** `outputs/` is committed; the `Outputs Freshness` CI workflow rebuilds and fails on any diff.
- The `workflows` marketplace entry keeps **`"strict": false`** (the bundle deliberately has no `.claude-plugin/plugin.json`; do not add one). Codex reads `.agents/plugins/marketplace.json`; `hooks/hooks.json` must keep `hooks` as its only top-level key.
- `outputs/okf/` is the OKF v0.1 policy bundle generated by `okf.mjs`; consumers read it from the repo path. Adoption record: `docs/dependencies/okf.md`.

### `/implement` — the run report

Ends with the `N units: X shipped, Y PR'd, Z blocked` reconciliation and the honest terminal token (`ok` only when nothing claimable remains and the survey was current and readable) — the `/goal /implement ok` contract. A mid-run problem becomes a ticket; a unit ends in `handoff` (the PR body's non-droppable `## Handoff`) when it is half-driven **or** was declared `verification_handoff:` at creation. The report is the **only** surface for everything below — none of it is appended to the finish post.

Per unit:

- **Notification outcome** — the surface the finish line used and whether it landed; an unposted line is reported as unposted and never moves the token.
- **Whose work it was** when the tickets were not the runner's (`drive/scripts/unit-authors.sh` → `foreign`/`unresolved`/`mine`) — disclosure of an existing behaviour (empty `assignees:` is claimable by anyone), never a claim decision.
- **A `review` unit's merge outcome**: `merged`, `merge_refused: <merge-reason.sh word>`, or `merge_not_attempted: <hard|confirm>` when a scan finding held the PR — never collapsed. `merge_refused` **forbids `ok`**, and the withheld token names the unit and the refusal; `merge_not_attempted` still reports `ok` (that PR waits on a person by design).
- **The connector retry** is a numbered step of that route with its own reported outcome: precondition `merge_reason == session_type_cannot_merge` and no other word, one attempt through `mcp__github__merge_pull_request` and no other tool, outcome `merged` or the PR left open with **both** refusals named. A run reporting `session_type_cannot_merge` and no retry outcome is non-conformant on its face.
- **Each `undelivered[]` entry** gets one catch-up and one retry, reported in their own vocabularies: `caught_up` / `already_current` / `catch_up_refused: <word>`, then the **recorded refusal it was retrying** and the new outcome in the merge vocabulary (`merged` / `merge_refused: <word>`), a still-refused unit naming **both** words. Naming an entry and reporting no outcome for it is non-conformant. A delivered retry stops withholding `ok`; a still-refused one keeps withholding it. `catch_up_refused: content_conflict` moves no token (it waits on a person, who is reached by `/moderate`).
- **Each *reported* claim's `mergeability`**, so a decay from `mechanical` to `content` is visible the hour it happens. Evidence, never a verdict.
- **Each stranded publication** (`branching/scripts/list-stranded-publications.sh`, read once per run): its pull request, `mergeability` and `age_hours` (a `null` age named **as unreadable**, never as fresh) whether or not the run acted, and — for each `mechanical` **or `clean`** one it acted on — `settle-stranded-publication.sh`'s own word (`settled` / `already_current` / `settle_refused: <word>`) beside the delivery in the merge vocabulary (`merged` / `merge_refused: <word>` / `not_attempted`). One line shape for both classes; the class is already on it. Naming one and reporting no outcome is non-conformant. A settled-but-refused delivery **forbids `ok`**; a delivered one stops withholding it; a refusal that waits on a person (`content_conflict`, an operator-facing publication) moves no token — that person is reached by `/moderate`'s `stranded-publication:<number>` question.

Once per run (each **moves no token and gates nothing**; the person who must act is reached by a `/moderate` question):

- **`backlog_all_excluded`** — a queue that holds tickets and offers none of them, with a count per exclusion reason, derived from whatever `excluded[]` carries (no hand-maintained list).
- **The base's own health** at the top of the report: `green`, `red` (with the attributed merge and the failing checks, or `unattributable` and its reason), or `unanswerable`. A degraded read is reported as degraded and **never as green**; the attribution walk runs only on `red`.
- **What is waiting on the operator** — each un-acted operator-facing pull request with its number, age and the **refusal word** that made it the operator's. A settled reading is not named; an `unreadable` one is named as unreadable and never as *nothing waiting*.
- **How long each standing blocker has been standing** — for each subject already named (an undelivered unit, a stalled claim, a blocked retirement, an undrivable queued artifact), the age of the **question** about it through `moderate/scripts/condition-age.sh` (`age.ticks` ticks since `age.first_seen`, *at least* that when `age.first_seen_is_floor`; the walk is bounded by `WORKAHOLIC_CONDITION_AGE_MAX_DAYS`, default 30, expressed as the newest N day files, and a cut walk says `truncated` rather than reporting a date it could not establish). An absent age is not mentioned; an unreadable one is named as unreadable.

### `/specificate`

Judges the ask **in hand** — the argument, a record just written, or, on a clock-fired tick with nothing handed in, the **discovered inbound issues** (`list-inbound-issues.sh`: open GitHub issues assigned to the session's own identity through `gather/scripts/gh-rest.sh`, oldest-first, pull requests filtered out, minus those a feedback record already names **on the base or on an unmerged branch**; never unassigned issues, never a title filter). The two capture words are distinct and neither gates anything: `already_captured` (the record is on the base) and `captured_on_branch` (it is on an open proposal's branch, so the ask waits on that pull request). Both halves of the run now read unmerged branches through **one** walk — `specificate/scripts/lib/unmerged-branches.sh`, shared with `list-proposed-refs.sh` — over-reading on every ambiguity, naming a degraded walk on stderr, and never turning a readable inbox into a refusal. `nothing_in_hand` only when that inbox is empty too; an unreadable inbox reports its reason; an issue assigned to someone else is `not_mine`.

The run writes the feedback record into a publish tree, reads base state as constraints (`survey-state.sh`), runs a history-mode discovery pass (diagnosis-first for failure reports), dedups via `list-proposed-refs.sh` (including unmerged branches), and emits in one PR the record plus what the shape selects.

- **The four forms are an ordered rule consulted first**, and *when unsure, record-only* applies only to an ask they did not resolve; the run reports `precedence:<form>` or `unsure:<what>`. Forms: a mission with ≥2 tickets, one loose ticket (mandatory `feedback:` refs), one **strategy**, or the record alone.
- **A strategy is not a mission factory**: intended scale is one mission of ~7–8 tickets plus at most one follow-up mission of 3–4 repair tickets. An ask advancing a strategy whose active mission already exists lands as tickets **into** that mission; a new mission only when the old is closed or its `## Experience` cannot cover the work, reported either way.
- **The strategy form** needs an **owner** (the triggering issue's assignee; unassigned or unmapped is record-only, never the running identity) and an **aim with no decomposable plan**. The date is the one the ask states, else the **one-week default** from `default-target-date.sh`, counted from the **triggering issue's own date**; a stated date this run cannot resolve to a single `YYYY-MM-DD` is `no_target_date` with no date emitted. **Every surface says the date is a default** — the `## Schedule` prose (naming what it was counted from and how to change it), the PR body, and the run report as `target_date:default` / `target_date:stated`. No frontmatter key records it.
- **The operator-record check**: an `active` strategy's Aim and the `subject: person:` records it cites are the operator's *resolved* direction and are **binding** — cited and proceeded on, never reopened. A fork that survives the check is declared `verification_handoff:`, never written as a Quality Gate item. Unrecommendable forks become `## Open Decisions` items under the writing floor above.
- **Lifecycle announcements** are recognised before the four forms and land only on the strategy named by **explicit slug** (read through `list.sh`; a title or paraphrase never matches, an absent slug is record-only naming `strategy_not_found`): *created* → the strategy form (optionally naming a **predecessor**, reported `successor_of:<predecessor>:<n>`); *changed* → `amend.sh` (step 9d) carrying exactly the revision the ask states, record-only under `not_active` or `no_revision`; *ended* → `close.sh` (step 9c), after which the route reads `closing-residue.sh` and names the leaving in the PR body and the run report, a degraded read named as degraded; *answers* (a strategy slug **and** a mission slug) → `carry-attribution.sh` (step 9e), appending that strategy's own `feedback:` refs to that mission and nothing else, refusing `strategy_not_found` / `mission_not_found` / `not_active` / `no_revision` / `immutable_field` and writing nothing on any refusal (`already` on a re-run).
- **An ask that already names a mission is emitted as that mission** — that plan, in that order, never re-derived. Every gate stays over the top of it, and a named plan that breaches one is **demoted and reported by name**, never trimmed to fit.
- **The carry-forward is mechanical, reported and floored**: `read-ask-feedback-refs.sh` reads the ask's own `feedback:` line (the mirror of `read-feedback-relation.sh` on the artifact side) (`{line_found, carried, dropped:[{ref, reason}]}`, exit 0 always); both surfaces name per emitted artifact what was carried and every dropped ref with its reason; `check-carry-floor.sh` refuses at the publish seam, beside the two-ticket floor, when a **resolved** carried ref is missing from the emitted mission (or the loose ticket when there is none) — a run failure with the repair named, never a demotion. A mission's tickets need not repeat its refs (`via_mission:<slug>` reaches them).
- **The direction is judged when the ask names none**: explicit slug, else a judgment against the `active` Aims (step 5b already reads them), else `unattributed`. A line beats a judgment; both surfaces report `direction:<slug>:<line|slug|aim>` or `direction:unattributed`; `check-carry-floor.sh` stays keyed on the ask's own resolved refs; an unreadable strategy set is named rather than collapsed.
- **Assignee**: the triggering issue's assignee rides every artifact (`--assignee`), never the running identity, and **only after it resolves** through `identity.sh` from login to canonical address. An unmapped login gets **no `--assignee`** and is reported `assignee_unmapped: <login>` in the run report and the PR body — a different fact from an unassigned issue, because only the first is repaired by a mapping line.
- Otherwise the PR auto-merges on opening (`WORKAHOLIC_AUTO_MERGE=1`; a scan finding or the seam's own `strategy_touching`/`ruling_touching` leaves it open), titled `[Proposal] …` via `WORKAHOLIC_PR_TITLE`, with `Closes #<N>` when the ask carried an issue number.

### `/moderate`

The hourly, unattended maintenance tick: **thirty-two steps**, one run. Its purpose is the repository's development progress — seeing it, and unblocking it. It **files through the existing seams** (a finding is a feedback record, work is a ticket or a mission, a question is a Slack post) and writes nothing else anywhere but its own log (`.workaholic/moderations/<UTC-day>.md`). **No `AskUserQuestion` at any step**; it never merges a pull request, never pushes into a branch the claim protocol owns, and never edits a live strategy. `run.sh` invokes every step and every step contributes a report line; a degraded read is reported **by name**, never as a step that ran and found nothing, and a step not reached inside `--deadline-seconds` is reported as unreached (the asking step is exempt from the deadline).

**Posting**: one thread an hour — a `🔎 Moderation` root carrying what changed **since the reader last heard from us**, addressed to nobody, with every question as a **mentioned reply inside it** (`🙋 <@U…>`, asked once). Two speech acts, one place to look, told apart by position in the thread. **No printed dedup key reaches a reader.** Each root line names a **repository event**, supplied by the step beside its log-facing `summary`; a step with no `event` renders no line, and **an event names no identifier** — *how many* is news and *which* is a task, so a slug belongs in the question that addresses the person who can act on it, never in a line addressed to nobody (2026-09-01). A change is a **diff against the previous tick's summary for the same step**, read from the log (no cursor, no field), normalising out timestamps, bare hex object names and clock times before comparing. **A root the tick could not deliver is filed, not lost** (2026-09-01, issue #806): when the rendered post says *post* and no transport reaches the channel, the tick files the rendered root as **one** `[FB]` issue through `file-inbound-ask.sh`, carrying it verbatim and naming why each transport was out — measured as 7 change lines, 2 impairment lines and **18 held questions** existing only in a discarded container's log. The **ledger is untouched**: a question that reached nobody is never recorded as asked, so every held question stays held. The repair is **provisioning, not code**, and the issue asks for it.

**Nobody is woken to be told nothing.** Before any gate, the root is held by the **same speaking window that holds the questions** — `WORKAHOLIC_QUIET_HOURS` / `WORKAHOLIC_WORK_DAYS` / `WORKAHOLIC_QUIET_TZ`, derived once in `moderate/scripts/lib/speaking-window.sh` and read by `ask-question.sh` and `render-tick-post.sh` alike (2026-09-01). Measured before it: a root posted at **04:01 JST** reading `質問 0 件` while that same tick held **seventeen** questions, every one refused `quiet_hours` — the loop woke the channel to say something addressed to nobody and held back the only things addressed to someone. **Held is not dropped**: the change diff's baseline is the last tick that **spoke** (read from its own `human-checkin-post` line, no cursor added), so the first working-hour tick says what changed across the whole silence and asks what the window held. The `🔴 Blocked` red alert is untouched — it has its own cool-down and its own reason to break a quiet hour.

**One gate: a question.** `idle`, `no_question`, `no_previous_tick` and `no_log` all post nothing (`no_log` named rather than rendered as quiet); the JST-morning digest, a delivery-failure event and a **changed impairment** are the three further gates on the root.

**Every root names the steps that could not read.** `render-tick-post.sh` derives `impaired[]` (the `degraded` and `blocked` rows in `STEPS` order, each with its own status and reason) and `impaired_count` **on every exit path including the silent ones**: **the head counts no steps** — it read `N step(s) could not read` until 2026-09-01, and a reader of the channel has no model of *steps*, which are this loop's own machinery — and the body carries **each step's own `summary`**, the one field of the four that is a sentence (`the base's checks could not be read (tip_no_checks); a red base is indistinguishable from a green one this tick`), bounded by `WORKAHOLIC_IMPAIRED_MAX` (default 5) with the rest **counted** rather than cut. A step with no summary falls back to `<step> — <status>: <reason>` rather than rendering nothing. `skipped` is deliberately **not** impairment — a step declining to run for a stated, healthy reason did not fail to see. **The statement is outside the change diff and the gate is inside it**: a step degraded the same way for twenty-four ticks has an unchanged summary, so a diff-gated clause would say it once and let it vanish, while an unchanged answer restated hourly is what `📦 Release Preparation` was retired for. A **changed** impairment is therefore the fourth gate — appearing and clearing break silence, persisting does not — and a root earned by it alone reports `ready_impairment`. The set compared is `(step, status, stabilized summary)`, strictly finer than `(step, status)` so it errs toward opening a root; `reason` never reaches the tick log, so it cannot enter the comparison without the store this must not add. It reads **no age** and asks nobody anything. It works **business days as well as business hours** (`WORKAHOLIC_WORK_DAYS`, default `1-5`); held is not dropped.

**Questions** go through `ask-question.sh` — one derivation of the question id (`lib/question-id.sh`) shared by the gate, the writer and the reader, keyed per subject so one subject costs one question however many ticks see it. A question has **three states**: `never_asked` / `asked` / `answered` (`question-state.sh`); `record-answer.sh` is the one writer of an answer. Log lines are `human-checkin-ask-<slug>` / `-answered-` / `-confirmed-` / `-reasked-`. `day_cap` counts the `human-checkin-ask` lines on the current `WORKAHOLIC_QUIET_TZ` day (derived once, from the tick id, passed to `log-read.sh --since`), `max_per_tick` stays with the gate, and `step-human-checkin.sh` hands `held` back ordered by the day each key was **first** held (a proposal by age, not urgency), reporting `delivered` / `held_count` / `candidates` with a named reason when it delivered nothing (`cap_spent` — the budget worked — distinguished from `cap_unbounded`, our own degradation, beside `all_held`, `all_asked_before`, `no_candidates`). #### Release notes and deployment plans

- **The per-target release notes are kept current by CI, not by any tick.** A routine's container cannot write a release by any transport (`gh release` is GraphQL-refused; REST answers *"Creating, editing, or deleting releases is not permitted for this session type"*), so the writer is `.github/workflows/release-note-draft.yml`, which holds `contents: write` and defines its own checkout (`fetch-depth: 0` + tags) rather than inheriting a container's refs. `run-note-cadence.sh` requires `--write`, passed by that workflow and by nothing else. The home is a per-target **GitHub draft release** — outside git, so the draft cannot count itself. Neither store is the source of truth: **the derivation is** (`draft-release-note.sh` over the base state), and `sync-release-note.sh` writes the non-authoritative side as a projection, never a merge, reporting every divergence and never overwriting a *published* release. It refreshes at most once per `Asia/Tokyo` day (a floor derived from the draft release's own `updatedAt`, never a stored cursor), plus immediately whenever the release stage advances (`draft` / `staging` / `confirmed`).
- **The reading half freshens itself**: `report-deploy-status.sh` — the one entry the tick reaches — freshens the base branch and tags before reading them, bounded and never fatal, reporting `refs` / `refs_reason` / `doubtful`. `read-deploy-state.sh` stays a pure local read.
- **The renderer derives the facts; an agent's plan arranges them.** `draft-release-note.sh --plan <path|->` renders a plan's grouping, order, risk notes and held-back set **over** the facts it derives; with no plan the output is byte-identical to the pre-seam render. A plan (`skills/ship/reference/release-plan.md`) may never invent a change, drop a merge or move a derived fact: an unnamed merge renders under *Not arranged by the plan*, a reference outside the range is named rather than fabricated, a plan whose `base_sha` is not the rendered base is shown as **stale**. Its home is the caller's — no well-known path, never inside git. A plan that cannot be applied is not applied.
- **The judgment runs in CI, beside the writer**: `plan-release.sh` authors each due target's plan in the same workflow run and hands it to that run's cadence (`--plan-dir`). The planner command is pluggable (`WORKAHOLIC_PLANNER_CMD`, default `claude -p`), the planner steps are skipped when `ANTHROPIC_API_KEY` is unset, every non-arrival is named (`no_planner` / `planner_failed` / `invalid_plan` / `empty_range` / `no_renderer`), and **the note says on its face** when a plan was expected and did not apply.
- **A target's note carries the whole release life**: `## Deployment Plan` → `## Releases` → `## Deployment Verification`, the last two derived by `read-release-history.sh` (a derivation, not a copy — no third store; `record-evidence.sh` / `confirm-release.sh` remain the single writers of what they own). A release window is **repository-wide**, so a batch confirmation never reads as "this target was checked", and `fail` / `not_run` / `bypassed` render exactly as loudly as `pass`. An empty stage says so in words.
- **A story-less merge keeps its substance**: `## Key Changes` prefers a branch story, falls back to the merge body's pull request title, and adds what that merge **published** as sub-bullets (`resolve-merge-substance.sh`): the feedback record (`Asked for: …`), the mission it planned, the tickets it queued. Local git plus base-tree reads only (`--enrich` stays off by default); neither the `feedback:` nor the `mission:` relation gains a second parser.
- **The deployment-plan refresh rides `[Implement]`'s tick**: every `auto` unit reaches `/ship`'s drafting phase, which refreshes that unit's plan inside the unit's own pull request. Nothing commits to `main` outside a merge, the refresh is idempotent (`draft-deploy-plan.sh` → `changed: false`), and a degraded read is reported and skipped, never half-written. Stated limit: a repository whose units are all `review` sees that plan refreshed only when an `auto` unit ships.

#### Drills

`scripts/e2e/loop-drill.sh` drills the loop's own mechanisms (`seed` / `status` / `reset` / `verify-*`). **`verify-all`** is the aggregate verb, deriving what it runs from the dispatcher's own `case` arms plus the **drill register** (`docs/loop-drill-runbook.md` §9 — one table, one reader, `drive/scripts/drill-register.sh`) and emitting one verdict per drill in the drill's own vocabulary (`pass` / `fail` / `skipped:<reason>`), exiting non-zero **only** on a real failure. `.github/workflows/loop-drills.yml` runs the **hermetic** part on every push and pull request with no credential and no permission beyond the default read, **one matrix leg per drill** so the check run that goes red is named after the drill — which is what lets `/moderate`'s `drill-health` step name it. A drill with no `bearing: "breaker"` row is **`unproved`** and counted outside the passing total; a drill the register does not classify is `skipped:unclassified`, which `test-workflow-scripts.mjs` fails on. Every drill carries a **breaker row written against the behaviour**, not a return shape. Operator procedure, cron race windows and failure-reason→file blame tables: `docs/loop-drill-runbook.md`.

## Enforcement gates

- **Commit trailers** (`skills/commit/SKILL.md`, *The trailer block*): `commit.sh` is the one writer and callers stay trailer-agnostic — `Category:` when `--category` was passed, `Claude-Session: https://claude.ai/code/<id>` whenever the environment carries `CLAUDE_CODE_REMOTE_SESSION_ID`, and `Co-Authored-By:` always. The trailer says which **run**, never which routine — nothing in the container names the standing routine record. Outside a cloud session the session id is omitted, never faked. The **author email is deliberately untouched** (`lib/claims.sh` resolves claim ownership and resumption from it); the web bootstrap sets a repo-**local** `user.name` (guarded on `git config --local user.name`, preferring `gh api user --jq .name`) since GitHub renders the name. A developer's own repo-local name is never overwritten; the repair is forward-only, and the name stays cosmetic to every mechanism.
- **A commit that would be half a rename is refused**: with default staging, a **staged deletion co-existing with an untracked file** is what half a convergent migration looks like. `commit.sh` refuses, names both halves and the concrete repair, commits nothing, and leaves the working tree untouched (no `git reset`). Untracked files alone never trigger it, and it never fires when the caller already named `files...`. **A caller that has just written a NEW file passes it in `files...`** — stated in `workaholic:commit`, referenced by `/story` Phase 4 and `/drive` §5.
- **Commit subject** (present-tense, ≤50 chars, no `feat:`/`[bracket]` prefix — `skills/commit/SKILL.md`): canonical validator `skills/commit/scripts/check-subject.sh`, run by `commit.sh` itself, by `archive.sh` **before it moves the ticket**, by the `PreToolUse` hook `guard-git-commit.sh`, and by the opt-in git-native `hooks/git/commit-msg` (install with `sh ${CLAUDE_PLUGIN_ROOT}/hooks/install-git-hooks.sh`; bypass one commit with `--no-verify`). One rule source; the layers cannot drift.
- **An embedded jq program that does not compile is our defect, never an empty answer** (`rules/shell.md`). These scripts carry readings as jq programs inside single-quoted shell strings under `… | jq -c '…' 2>/dev/null || echo '[]'`, which is right for a data problem and catastrophic for our own; the two are told apart by **jq's own exit status** (3 = compile error, 5 = runtime/input), so every existing fallback keeps its data behaviour. Two halves: at **run** time `skills/moderate/scripts/lib/jq-guard.sh` — a shadowing `jq` function sourced by every script in that skill that embeds a program, calling `command jq`, capturing nothing, redirecting nothing, inert when nothing is listening — *records* the fact, and `run.sh` is the **one** place that reads the record and reclassifies the step `degraded` with reason `jq_compile_error` (`needs_agent` is deliberately not zeroed). At **build** time `test-workflow-scripts.mjs`'s `every embedded jq program compiles` row extracts every `jq` in command position across `plugins/workaholic/`, `scripts/` and `hooks/`, redeclares each `--arg`/`--argjson` name, and compiles with `jq -n` against closed stdin, failing on exit 3 alone; programs built by string interpolation cannot be extracted and are **counted in the assertion's own name**. The `2>/dev/null` is not removed — the fix is to classify, not to shout.
- **Branch names**: exactly two literal patterns — `work-YYYYMMDD-HHMMSS` (named only by `branching/scripts/create.sh`) and `release/YYYYMMDD-HHMMSS` (named only by `cut-release-branch.sh`); `guard-git-branch.sh` blocks everything else.
- **One behaviour per command**: no command's behaviour depends on the first word of its argument (bare-versus-argument is a scope and is kept; `/fb`'s cross-repository mode routes on destination, not a first word). Retired forks: `/mission close` → `/mission-close`; `/mission summary|approve`, `/ticket summary` dropped; `/drive auto|night` → `/implement`.
- **AskUserQuestion**: the label hook enforces the `[<label>]` prefix; *whether* to ask is governed by `rules/interaction.md` — the **Recommended-label test**: if an option could honestly be marked "(Recommended)", don't ask; decide, record, let the developer veto.
- **Repository confinement**: every write lands inside this repository or its worktrees; the only crossing is `/fb`'s issue-opening mode with its verbatim human confirmation. Do not grow the confinement hook toward content matching — vocabulary is a human judgment. The rule only reaches repos that install the plugin; enable it user-level (`~/.claude/settings.json`).
- **Every pull request this loop merges is squash-merged, and the method is one derivation** (2026-09-01): `gather/scripts/merge-method.sh` answers it and the four call sites (`ship/scripts/merge-pr.sh`, `branching/scripts/publish-tree-pr.sh`, `drive/scripts/retry-undelivered.sh`, the `review` route in `workaholic:drive`) **read it, never spell it** — `test-workflow-scripts.mjs` fails on a literal `merge_method=` at a call site. **A commit is a change to the development target**: measured on a consuming repository's `main`, one day, 275 commits — 138 touching only `.workaholic/`, 25 empty, 44 merges, **5 touching only the product**. The claim commit, the heartbeat and a unit's story are correct where they live and are not facts about `main`; a merge commit carried every one of them over verbatim. **The cost is stated, not hidden**: a unit's per-ticket commits collapse into one, and that granularity lives on the pull request, in the branch story and in `archive/<branch>/`. It is **safe** only because `superseded` is derived from the **tree** rather than from ancestry (a squash-merged branch is never an ancestor of the base), and **bounded** only because `delete_branch_on_merge` removes the branch at the merge — which is why the two shipped together.
- **GitHub over REST only** (`rules/shell.md`): every workflow script reaches GitHub through the one transport `gather/scripts/gh-rest.sh` (`slug` / `api` / `available` — the last probes `GET /rate_limit`, which every token type can call including a workflow's installation token; a caller needing a **person** calls `gh api user` itself and answers `identity_unresolved`, and `available`'s `login` is vestigial). Never `gh issue …`, `gh pr …` or `gh repo …`, which are GraphQL-backed and which a Claude Code Web session may 403 mid-run. A bound session refuses `search/*` too, so slug matching uses repository-scoped endpoints and filters locally. `gh release …` is REST-backed and stays. **One qualification**: a REST merge answered `403 "Merging pull requests is not permitted for this session type"` gets `merge_reason: session_type_cannot_merge` (its own rung beside 405 and 409, keyed on the message with a generic `merge_forbidden` behind it), and **that one refusal may be retried through `mcp__github__merge_pull_request`** — a second attempt behind REST, never a replacement, for the one act a script cannot perform at all. Reads, writes and pull-request creation stay REST; the step moves into the calling agent, which reports both outcomes by name. `node scripts/test-workflow-scripts.mjs` fails on any non-comment `gh issue|pr|repo <verb>` under `skills/` or `hooks/`; its allowlist is empty on purpose.

## Release-safety scan

`skills/release-scan/scan-branch-safety.sh` is a deterministic, script-only gate over `git diff <base>..HEAD`, run by `/story` (warn) and `/ship` (block). Three rule families, each finding citing `file:line` + rule:

- **`secret`** (hard, never overridable) — `lib/secret-patterns.sh`: pass 1 unmistakable key shapes; pass 2 matches on the **value** (quoted-alphanumeric or line-ending bare run = literal; identifiers, calls, env reads, HCL `var.`/`local.`/`data.`/`module.` references, templates, annotations are subtracted). Generated paths are exempt from pass 2 (the `Outputs Freshness` CI carries the residual risk).
- **`size`** (overridable) — per-file/branch ceilings plus a per-commit changed-lines rule (`lib/commit-size.sh` — read its header before changing it; it exempts binary rows, lockfiles, generated paths, `.workaholic/` prose, files already over the per-file ceiling, and merge commits, and counts additions only).
- **`leak`** (confirm) — re-introduction of terms from the git-ignored, developer-maintained `.workaholic/leak-denylist`. Read its scope literally: it matches listed terms in the branch diff, nothing more; a `pass` never means "no client context here". The "never name other repos/clients" convention is enforced by confinement + the crossing flow's human confirmation, not by this scan.

The **severity tier** tells the consumer how hard to block; both consumers key on it, never on the binary verdict alone. A branch whose only findings are `override`-tier stays releasable (`gate-decision.sh`'s `override_only`).

## Version Management

Version bumps are manual (no `/release` command). After bumping and pushing to `main`, CI (`.github/workflows/release.yml`) publishes the GitHub Release.

Version files (all at the same semver; `.claude-plugin/marketplace.json` is the source of truth):

1. `.claude-plugin/marketplace.json` — root `version` AND every `plugins[].version` (workaholic, workflows)
2. `plugins/workaholic/.claude-plugin/plugin.json`
3. `plugins/workaholic/.codex-plugin/plugin.json`
4. `outputs/workflows/.codex-plugin/plugin.json` — generated; rebuild with `build.mjs`, never hand-edit

Bump PATCH by default, update 1-3, regenerate 4, commit as `Bump version to v{new_version}`.
