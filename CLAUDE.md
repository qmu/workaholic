# Workaholic

Private, cross-agent distribution of structured development workflows and engineering standards. **AI agents are the primary users** — routines invoking `/implement` and `/specificate`, and sessions running the workflow skills — while the **developer is the operator** who approves pull requests, configures routines, and rules on deferred decisions. Richest on **Claude Code** (plugin marketplace: commands, hooks, the always-on policy lens); portable skills also ship to **Codex** (`.agents/plugins/marketplace.json` → `outputs/workflows`) and to 40+ agents via the Agent Skills standard / `skills` CLI. Authored source lives under `plugins/`; cross-agent artifacts are generated into `outputs/`.

This file states **current behavior only**, as briefly as it can. Decision history, rationale, measurements and rejected alternatives live in `docs/loop-engineering-workflow.md`, `docs/proposal-loop-runbook.md`, `docs/drive-loop-runbook.md`, `docs/loop-drill-runbook.md`, each skill's `SKILL.md` and `reference/` directory, the feedback stream (`.workaholic/feedbacks/`), and this file's own git history. **Do not re-import them here** — a rule belongs here, its story does not.

## Important

- Edit `plugins/`, not `.claude/` — this repo develops plugins; changes go to `plugins/` unless explicitly requested otherwise.
- **Update the docs in the same change.** When a change alters behavior, structure, commands, skills, or conventions, update every affected document (`README.md`, `.workaholic/README.md`, `CLAUDE.md`, `plugins/workaholic/rules/*.md`) in the same commit. Outdated documentation is a defect; `/story` runs `doc-drift.sh` and `area-freshness.sh` only as backstops.
- **Write each surface in the language its audience reads.** Reasoning on the `#dev-workaholic` channel and in Claude Code Web routines is **Japanese**. For Slack posts the rule also ships **in the plugin**, beside the shapes (`rules/interaction.md`, *The language of a post is the language its readers use*): measured 2026-09-01, a consuming repository whose own `CLAUDE.md` carried the Japanese rule still got an English `🔎 Moderation` root, because the ceiling names the only shapes a session may emit and every one of them is written out in English. **And that Japanese must be read on first sight, not decoded** (2026-09-02): the bar is an outcome — *a channel reader understands what is being asked without opening the English record behind the link* — so an established technical term keeps its katakana or English form (ビルド, CI, デプロイ, PR, `terms/` entries), a title's **meaning** is translated rather than its words, and a title that resists translation is paraphrased rather than transliterated. It ships in **one wording** across `rules/interaction.md`, the notify catalog and the four routine-fired command ceilings, pinned byte-identical by `test-workflow-scripts.mjs`; what a run actually emits is checkable by nothing, and the rule says so. GitHub artifacts (issues, pull requests, commit messages) and `.workaholic/` artifacts are **English** — the durable, shared record. Code, code comments and this repository's `docs/` tree are untouched by the rule.

### Hooks (all shipped active in hooks.json)

- `validate-ticket.sh` (PostToolUse Write|Edit) — ticket floor on the `todo/` queue only: frontmatter, location, mandatory `## Policies`/`## Quality Gate`, resolvable `mission:` relation.
- `validate-mission.sh` (PostToolUse) — Experience/≥1-acceptance floor on any mission under `missions/active/`; archive never retro-blocked.
- `validate-story.sh` / `validate-trip.sh` / `validate-feedback.sh` / `validate-strategy.sh` (PostToolUse) — OKF `type:` and schema floors on new writes; git-tracked history is grandfathered. `validate-strategy.sh` requires a `YYYY-MM-DD` `target_date`, a **non-empty** `assignees` (the one artifact where empty is a refusal, not team-owned), non-empty `## Aim` / `## Schedule`, and — when present — a `stage:` from the closed set.
- `guard-ticket-structure.sh` (PreToolUse Bash) — blocks non-canonical ticket moves.
- `guard-git-commit.sh` / `guard-git-branch.sh` (PreToolUse Bash) — commit-subject and branch-name gates.
- `guard-askuserquestion-label.sh` (PreToolUse AskUserQuestion) — every question body must open with a `[<project label>]` prefix (`gather/scripts/project-label.sh`).
- `guard-working-directory.sh` (PreToolUse Bash) — denies a top-level cwd-moving `cd`. A `( cd … )` subshell, an absolute path, a `--prefix` form, and a **leading `cd` onto a repository root** (main checkout or worktree, resolved via `git rev-parse --show-toplevel`) all pass. A chained mid-command `cd`, a target carrying unresolvable shell syntax, and bare `cd` are denied. No env-var toggle.
- `guard-repo-confinement.sh` (PreToolUse Write|Edit) — blocks writes outside this repository and its worktrees (the agent's per-project memory store is exempt). Syntactic backstop only; the primary rule lives in `rules/general.md`.
- `policy-lens.sh` (UserPromptSubmit) — injects the engineering-policy index for commands carrying the `workaholic:policy-lens` sentinel; bodies are read on demand from `skills/<pillar>/policies/`. Regenerate `hooks/policy-index.md` with `build.mjs` after editing a pillar's `## Policies` list (CI fails on drift).
- `layout-doctor.sh [path]` — read-only audit of `.workaholic/` against the layout allowlist.

## Architecture Policy

### Component Nesting Rules

| Caller                     | Can invoke                                                                                     | Cannot invoke              |
| -------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------- |
| Command                    | Skill, `general-purpose` subagent                                                              | —                          |
| Skill                      | Skill; (when loaded by a command/main agent) may direct it to spawn `general-purpose` subagents | Command                    |
| `general-purpose` subagent | Skill (via preload)                                                                            | Command, Task (no nesting) |

- **No per-workflow agent files.** The repo ships no agent `.md` files at all. A command spawns `subagent_type: "general-purpose"` subagents whose prompts name the skill to preload, the section, the inputs, and the return schema.
- **One-level fan-out.** A subagent cannot nest `Task` and cannot call `AskUserQuestion`; all fan-out and all user interaction happen at the command/main-agent level. Leaves do non-interactive work and return JSON.
- **One plugin.** `workaholic` has `dependencies: []`. All skill references are same-plugin (`${CLAUDE_PLUGIN_ROOT}/skills/<name>/...`, `workaholic:<name>`). The `workflows` marketplace entry is the generated `outputs/workflows` bundle, not an authored plugin.

### The ticket spine

Everything converges on the **ticket** as the unit of work: *sources* fill `tickets/todo/`, one executor drains it to `tickets/archive/`.

- **Sources**, each named with **whose input it carries**: `/ticket` (a **human's** direction, with discovery), `/mission`'s Creation Interrogation (a **human's** direction, decomposed into a whole ordered ticket set), and `/specificate` (the feedback stream — **a human's ask, or a strategy a human authored**, never a record the loop wrote about itself). All publish through a **publish tree** onto a `work-*` branch behind a pull request; the artifact reaches `main` — and the executor's survey — when that PR merges. **What may originate a mission is stated once and cited, never restated** — `plugins/workaholic/rules/workaholic.md`, *What May Originate a Mission*: a human's ask or a human-authored strategy may; a record a routine wrote about the loop's own apparatus (`self_authored`) and a proposal refining a prior self-proposal (`self_refining`) may not. `only_the_loop_spoke` remains visible evidence and is no longer an origination refusal.
- **Mission floor and ceiling**: two or more tickets or it is not a mission (`mission/scripts/check-floor.sh` — the one derivation of the number, read at **every** seam that publishes a mission with its ticket set, and no seam spells it; a ticketless direction is a feedback record, a one-ticket one is a plain ticket). **What a mission is, and the scale, are stated once and cited, never restated** — `plugins/workaholic/rules/workaholic.md`, *What a Mission Must Be Able to Hold* (2026-09-03): a mission is the mid-term container between a strategy and a ticket, **rule 1** is that mechanical floor and **rule 2** is a stated judgement — many two- and three-ticket missions is a defect the loop refuses, so it declines to *emit* a mission for an ask with no mid-term plan and names what the ask became instead, while rewriting nothing already on disk. **No cap was added to the ingest path**, deliberately. `layout-doctor.sh` names an already-below-floor mission as an **advisory**, never a finding. Ceiling: `## Acceptance` normatively ≤3 items, whole `mission.md` ~60 lines / 2 KB (`mission/scripts/size.sh`, enforced on `/specificate`'s unattended drafts). Write-time floor: `## Experience` + ≥1 acceptance item.
- **One executor, two commands**: `/drive` (attended — asks exactly one thing: which units to take when several are offered) and `/implement` (unattended — no prompt at any step). Same Unified Run: freshen (`sync-main.sh`) → survey (`plan-units.sh`) → partition into PR-units → claim → drive → report → route by effective merge policy → account. `plan-units.sh` emits `backlog_all_excluded` (a derived reading over `backlog_size`/`backlog[]`/`excluded[]`, with a count per exclusion reason) so a queue emptied by claims and one emptied by `owned_by_other` never read alike, and **`placeholder_identity`** (2026-09-02) so a queue emptied by comparing every artifact against an address that stands for nobody never reads as an empty one — the survey's five `ok`-forbidding facts are `current: false`, `shallow: true`, `backlog_error`, `owner_unresolved` and that one. **And the offer has a derived, stated order** (2026-09-01): `missions[]` came back in walk order with nothing anywhere saying so, which with 30 tickets queued against three directions dated the same day was the difference between converging one direction and touching all three. The terms are **a mission unit before loose backlog** (the shape of the offer, plus `/drive` §3's own preference), then the **nearest `target_date` of the direction the mission serves** — resolved through `mission-strategy.sh`, so no relation, no field and no second walker — then the mission's own ticket order, which is untouched. Ordering changes **order, never eligibility**: which units are offered and every exclusion reason are byte-identical. Each row carries `direction`, `direction_target_date`, `days_to_target` and **`order_reason`**, and the four groups run `direction_date` → `direction_undated` → `unattributed` → **`direction_unreadable`** last, the walk order breaking every tie. A derivation that failed annotates **every** row `direction_unreadable` rather than falling back to an unannotated walk order — a silent non-reorder is the one outcome the reading forbids. Cost, stated: `mission-strategy.sh` measured 21s here, once per survey, and is a **local** read, so the survey stays offline by construction. Full contract: `skills/drive/SKILL.md` and its `reference/`.
- **Merge policy** (`merge_policy: auto | review`, recorded at creation on missions and tickets; **absent means review**): `auto` ships through `/ship` — which drafts the plan and merges, never deploys — then tears the claim down; `review` merges its PR immediately after `/story` opens it. **No gate is ever overridden**: a `secret` finding hard-stops; a `size`/`leak` block or a missing confirmation method demotes an `auto` unit to the PR path.
- **Every merge is bound to one observed head SHA.** `drive/scripts/branch-checks.sh <pr> <expected-head>` owns the check verdict. `checks_red` and `checks_pending` refuse; transport/auth/parse/truncation failures defer; a successful `no_checks` read is a compatibility pass that remains explicitly unverified; `WORKAHOLIC_MERGE_CHECK_GATE=0` is the only disabled form. `gather/scripts/merge-pull.sh` sends that SHA to GitHub and reports success only from merged evidence or a confirming PR reread. Unknown effects retain the claim and delivery record for reconciliation.
- **The `review` route reads the severity tier, never the binary verdict.** `gate-decision.sh` computes `override_only` beside `overridable` — the one derivation of the tier policy — and the route merges on `pass` **or** `override_only`, reporting every finding in the run report and the PR body. `secret` hard-stops; `leak` holds the PR open.
- **An Open Decision is a question to answer, not a ruling that the question is unanswerable.** Writing floor (`create-ticket/reference/ticket-format.md`): three required parts — the question, **the sources consulted and what they said**, and the fork's sides; it may name whose ruling would settle it and may **not** declare the question unanswerable or tell a later session not to decide. Driving floor (`drive/reference/ticket-workflow.md` §1, `reference/failure-contract.md`): before honouring one as a blocker a run **reads the sources the item names**, plus the whole of any page it cites, and a `blocked` outcome **names those sources and what they said**. A block that cannot name a source it read is not a block. Prose contract, not a script gate. `/ticket` never writes one — it asks a human instead.
- **The verification axis is read before merge policy**: a mission or ticket may declare `verification_handoff: <what cannot run here>` **at creation** — a credential, device or third-party account an unattended run does not have. `drive/scripts/verification-handoff.sh` is the one reader, and since 2026-09-01 (issue #793) it also **derives** one the ticket never had to declare: a `## Key Files` entry naming `.claude/` is a handoff because Claude Code classifies that path as sensitive and an unattended run has no one to answer the prompt. **Measured**: seven `[Implement]` runs over five hours all read `requires_action`, each ending at the same permission prompt, while nothing anywhere said so — the resume beats the heartbeat before the edit, so `stalled-units` counted the unit healthy. A **declared** value always wins, the test is syntactic and narrow (prose elsewhere in the ticket is not read), and it is derived rather than declared because the ticket that froze the loop was already in `todo/`. A declaration — or a derived one — takes the **`handoff`** route whatever `merge_policy` says: the PR opens and stays open, the non-droppable `## Handoff` quotes the reason, the claim stays standing, the finish line is `🟡 Handoff` and the token is `pending`. **And it holds the MEMBERS that carry it, not the whole unit** (2026-09-07, mission `hand-off-the-members-that-declare-and-drive-the-rest`): *any member carries the whole unit* is right about the merge and wrong about the work — measured 2026-09-06 on `report-each-tick-in-the-originating-codex-chat`, seven queued tickets, one declaring, six declaring nothing, the claim `awaiting_verification`, the unit excluded whole, and nothing driven for hours. The route partitions from the one reader's own `members[]` (or the claim row's `declared_members`) on the **file test alone**, runs the probe **per declaring member** because the unit-level call answers for the first only, and then: an **empty** declaring set is the ordinary route; **every** member declaring, or the mission's own `mission.md`, is the whole-unit handoff unchanged; anything between drives the non-declaring members and leaves each declaring member stamped and queued in `todo/`, with a `## Handoff` naming only those members and both sets reported. The handoff is not weakened — only the members that declared nothing move. Two writers only — `/ticket`, and `/specificate` (`scaffold-proposed-ticket.sh --verification-handoff`) when the ask states it or an operator-only fork survives the operator-record check; the reader's derived case is not a writer and stamps nothing. A run never declares it for its own unit. **And since 2026-09-03 a declaration may be a PROBE that is re-run at claim time** (mission `make-a-verification-handoff-a-probe-re-run-at-claim-time`): `verification_handoff: probe: <command>` is read by the same one reader (which never runs it) and executed by `drive/scripts/run-verification-probe.sh` when the unit is claimed, answering `clean` / `blocking` / `unmeasured` / `unreadable`. **`clean` is not a handoff** — the unit takes its ordinary route; `blocking` hands it over with the probe's **own output and exit status** as the reason, which goes stale visibly where a sentence does not. **Prose stays exactly as valid and reads `unmeasured`**, standing as it always did: measured before the shape was fixed, **zero** of the 32 queued tickets declared anything and all six declarations in the tree are prose, so a format that replaced prose would have invalidated every one. `unreadable` also leaves the declaration standing — an absence of a reading is never a clean probe. **Why it exists**: a prose declaration cannot be falsified, so a blocker true at creation stays true forever — measured on a consuming repository as four parked pull requests, three of them false when finally probed. **The declaration is derived per unit, through the one reader, and never inherited**: one file read once became a session-wide premise that stopped six tickets, three of which declared nothing at all. Such a fork must never be written as a `## Quality Gate` item, which `/implement` can neither ask about nor override. The claim behind a unit whose declaration is **prose** reads `awaiting_verification` and is not re-offered; a **probe** declaration never reaches that verdict (2026-09-06, mission `finish-the-backlog-without-handing-it-back-to-the-operator`) — the scan is offline by construction and may not run a probe, so the reading stays where the probe is already run, at §6's route, and the claim keeps its ordinary verdict. Measured: a ticket declaring `probe: command -v codex` read `handoff: true` at the oracle while the probe read `clean` on the same machine in the same second, which would have parked the unit forever on a declaration its own probe had falsified.
- **Only a concrete, VERIFIED external limitation may be reported as a handoff** (2026-09-06, mission `finish-the-backlog-without-handing-it-back-to-the-operator`, the operator's own instruction: *routine engineering work must never be handed back to a person*). Every state this loop hands over is classified, once, into two classes: a **verified external limitation** — a credential, device or account the run provably lacks — or an **engineering judgement the loop declined to make**. Only the second class moved. **Unchanged and still stopping the run, each with its evidence**: a `secret` finding (hard, never overridable), a `leak` finding (the denylist is a person's vocabulary judgement), an operator-facing publication (merging **is** the ruling), a `probe:` declaration reading `blocking` (a probe that ran and failed), `pull_request_reviewed` (a person is mid-review and a push resets their approval), and a colleague's claim at any age. **Changed**: a `content_conflict` — the residue after the merge itself was attempted — is now the run's own work, taken at the **agent** level because no script may resolve a hunk by judgement, on the four bounds `skills/drive/SKILL.md` §6 states and reported `conflict_resolved` / `conflict_unresolved: <reason>`; and a **prose** `verification_handoff:` reading `unmeasured` no longer stands on its own words — the run establishes whether the limitation the sentence names is present **here**, takes the handoff route only on one it verified, and otherwise drives the unit reporting what it checked. **Measured**: three of four parked pull requests on a consuming repository had false declarations when finally probed, and on this repository a unit was routed to `handoff` on a derived `.claude/` declaration while its pull request's changed-file list held **zero** such files. **The proof discipline did not move** (`drive/reference/claims.md`) — every act still re-derives its proof at the moment of the act, is idempotent, writes nothing on a refusal and refuses each bound by its own word; nothing bypasses a repository protection, overrides a gate or manufactures a verification. The `claim-arbitrate.sh` leaked lock was **already** the loop's work through `reap`; only its stale "for a person to act on" wording moved.

### `.workaholic/` runtime conventions

`README.md` and `index.md` are the only files allowed at the `.workaholic/` root.

- **OKF floor**: every knowledge artifact carries a non-empty `type:` (`Story`, `Mission`, `Feedback`, `Strategy`, `Deployment`, `Term`, `Release Note`, `Release`); `okf/scripts/refresh-index.sh` regenerates the bundle indexes before each knowledge commit. **Two exceptions**: `tickets/` (internals, never index-managed) and `moderations/` (an operational log — and since 2026-09-01 not on this branch at all).
- **`moderations/`** — the `/moderate` tick log: one file per UTC day, one `## <tick-id>` section per tick, one line per step, no frontmatter, no `index.md` (the root index links the directory bare). An operational log, not knowledge. `moderate/scripts/log-append.sh` is the only writer (append-only, idempotent per `(tick, step)`, **never prunes** — deleting a day file is the operator's act); `log-read.sh` is the reader a step consults before re-filing. **That one reader is scoped by owner and answers moderation by default** (2026-09-07, ticket `20260907063154`): three producers write into one day file under their **own** tick ids — `/moderate` its steps, `/infinite-development` a `loop-finish-<name>` per subagent finish under the **coordinator's** tick id every five minutes, `/propose` its `propose-open`/`propose-close` — so a section holding nothing but a `loop-finish-*` line is the **ordinary** previous section. `--owner <moderate|loop|propose|all>` is **derived from the step id** every line already carries (`loop-finish-*`/`loop-attempt-*` → `loop`, `propose-*` → `propose`, everything else → `moderate`), **per entry rather than per section**, composing with every other filter including `--latest-tick`; there is no new field, no second store and no migration, and an unrecognised step id stays `moderate`, so nothing already written moves. **Repairing the reader repaired two consumers without touching either**: `render-tick-post.sh`'s change baseline was landing on a coordinator section, reading an empty `prev` and counting every eventful step as changed — the diff no longer suppressing an unchanged answer, which is the one property it exists to guarantee — and `step-blocked-tick.sh` was taking one as *the tick before last*, finding `opened == 0` and reporting `the tick before last opened and closed` over a moderate tick that had **stopped**, a false healthy reading from the step whose whole job is that reading. Measured on `2026-09-06.md`: **110** distinct sections, **29** moderate and **79** the coordinator's, with two sections holding exactly one `loop-finish-*` line and nothing else. **The loop's own readers opt in by name** — the three cadence reads (`commands/infinite-development.md`, `skills/work/SKILL.md`, `codex-loop.sh`) and `step-blocked-tick.sh`'s **propose arm**, which is why the owner is a small named set rather than a boolean: *not moderate* is not one class, and a boolean would have silently broken that arm. `condition-age.sh` is the one consumer whose answer the default **changes**, and it changes it to the right one — its `ticks` counts the askings a question has survived, and only a moderate tick asks, so counting coordinator sections inflated a one-hour-old condition roughly fourfold. `log-append.sh` is byte-identical and no line is pruned. **The log is committed nowhere at all** (2026-09-03, the developer's instruction, in those words: *this strategy is never to be taken again*). `.workaholic/moderations/` is **git-ignored** and stays in the checkout that wrote it, which is the checkout the next tick reads. **The orphan `workaholic-log` branch is retired and must not be reintroduced**, and neither may a notes ref, a remote store or any other place a commit could land: `log-ref.sh`, `ensure-log-ref.sh`, `hydrate-log.sh` and `migrate-moderations-off-main.sh` are **deleted**, and `run.sh` no longer makes an opening persist. It existed from 2026-09-01 to 2026-09-03 as a repair for the log's ~50 commits a day on `main`, and it **moved the mess rather than removing it**: 126 commits nobody read, three per tick, a fetch at the head of every tick, and a seed commit pushed by a script that would push to whatever remote it was pointed at — which is how the *hermetic* test suite pushed to the real origin on 2026-09-03. Its premise — *the tick's container is discarded* — stopped being true on 2026-09-02, when the loop moved onto the developer's own server as a session whose working directory persists. **The cost is stated**: a tick running somewhere its state genuinely cannot survive loses its log and its dedups re-fire; the repair is to stop running it there, never to give the log a branch again. **The records take the other road, and that is now `persist-log.sh`'s whole job**: `--record <path>` carries the tick's feedback records to **`main`** in their own commit — a feedback record is knowledge — named one by one, never a sweep of the index; each reported `carried` / `already_on_base` / `missing` / `unreadable` / `unlanded`. #### The strategy layer

`.workaholic/strategies/<slug>.md` is the operator's **outbound, resolved direction**: an **Aim**, a **Schedule** (`target_date`), an **Assignee** (non-empty `assignees`) and a **Stage** (`stage:` from the closed set `進行中 | 改良中 | 観察中`, the operator's vocabulary kept verbatim; **absent means 進行中**, resolved in `read.sh` alone). Flat, one file, operator-authored through `workaholic:strategy`; `/drive` never surveys one. The stage is **declared, never derived** — every other reading here is evidence the loop computed, and no reading may compute, move or infer the stage; a reading may suggest a transition and the operator's announcement performs it. Stuckness (a handoff, a block, a stale claim, a queue that will not drain) is orthogonal to the stage and never read as one.

**Three writers and no fourth** (pinned by the suite): `create.sh` creates (`--stage`, refusing `bad_stage` with nothing written), `amend.sh` revises a live direction's `## Aim`, Schedule, Assignee and Stage, `close.sh` ends. `amend.sh` is bounded to those four parts, asserts `slug`/`type`/`status`/`created_at`/`author`/`feedback:` immutable, refuses a closed direction `not_active`, carries the write-time floor itself, writes **nothing** on any refusal, and appends one dated `## Schedule` line naming what moved (a stage move names both ends, e.g. `進行中 → 改良中`, reading the previous value through `read.sh`). `close.sh` is the only writer of an end state; re-opening is offered nowhere. `carry-attribution.sh` is **not** a fourth writer — it writes one `feedback:` line on a **mission**. A run never amends or moves a stage on its own reading; `/specificate` carries the operator's words verbatim.

**Readers** (each composes the ones below it; no second walker, no relation of its own, no field on any artifact):

| Script | Answers |
| ------ | ------- |
| `read.sh` / `list.sh` | the artifact, with the absent-stage default resolved once (`stage_declared` says which answer a caller has) |
| `attributed-work.sh` | which work belongs to a strategy — `strategy.feedback[] ∩ artifact.feedback[]` (`direct`) plus the hop through a mission attributed that way (`via_mission:<slug>`); reports ticket **and** mission grains (`waiting_missions*`, `waiting_kind`/`waiting_describing`/`waiting_advancing` via `work-kind.sh`) |
| `mission-strategy.sh` | the inverse — which strategy a mission belongs to |
| `unattributed-work.sh` | what no direction claims (active missions by slug/path with queued-ticket counts, loose queued tickets) |
| `survey-strategies.sh` | one row per strategy: `refusal`, `pace`, `overdue`, `expiring`, `dormant`, `quiescent`, `landed`, `stage`, `residue`, `target_date`, `days_to_target` |
| `direction-state.sh` | the lifecycle: `live \| arrived \| overdue \| expiring \| dormant \| unreadable`, plus the repository-level `none`; `--with-leaving` attaches the leaving per row by handing that row back through `--state-row` |
| `closing-residue.sh` | what a direction is leaving — the waiting grains, the residue, and its last lifecycle reading, each block carrying its own `readable` and reason |
| `landing-arithmetic.sh` | what remains against how long is left — `clears` / `does_not_clear` / `no_target_date` / `unreadable`, over `standup/scripts/digest.sh`'s own board reading |
| `default-target-date.sh` | the operator's one-week default (the constant **7** lives here and nowhere else) |

The lifecycle precedence is fixed: **`unreadable` > `arrived` > `overdue` > `expiring` > `dormant` > `live`**. A sixth value is refused — `stage` rides **beside** the answer and never enters the precedence. Definitions: `overdue` = `days_to_target < 0` (a `null` date is never overdue); `expiring` = `0 <= days_to_target <= window_days`; `dormant` = legible, `active`, `mine`, not overdue, cited, nothing landed in the window, nothing waiting at either grain, no open proposal; `quiescent` = `dormant`'s complement on one term (`landed` non-empty) with **no date term at all**, and **`false` when the residue read was degraded**; `pace` (`late | on_course | unknown`) changes order, never eligibility.

**A reading is an observation, and only a MATURE question may become a gate** (2026-09-08, mission `turn-quiescent-blockers-into-mature-decisions-and-resume-work`). `quiescent`, `dormant` and `/propose`'s `no_evolutionary_move` each became a question to a person the moment they fired, whatever state the direction was in, so the loop could neither say *this cannot be answered yet* nor *its premise is gone* — the only outcomes were ask, or end silently in a worker report nobody opens. **The rule and its four words are stated once and cited, never restated** — `plugins/workaholic/rules/workaholic.md`, *When a Human Decision May Block the Loop*, beside the origination rule it forms one model with: `retire` (the assumption is gone — closed, not mine, or declared `観察中`), `prerequisite` (a premise the loop must build first, named as planning work), `defer` (cannot be answered now, or need not be), and `ask_now`, **the only verdict that may become a question**. `moderate/scripts/decision-maturity.sh` is the one derivation — a ladder over fields `survey-strategies.sh` already emits, `premises[]` carrying each premise with whether it held and the evidence, so the outcome stays arguable rather than hidden in a score. It **carries no residue term**, deliberately: `quiescent` already holds one and `dormant` deliberately does not, and re-imposing it here would overturn that decision. It **gates nothing and lifts nothing** — no refusal ladder, precedence, origination gate, sort or token reads it — and `readable: false` is never a verdict: the consumer asks anyway and names the degradation. An immature question is **re-derived every tick**, so the deferral needs no store, no cursor and no flag. **And an answer is evidence, not a lifted gate**: a recorded answer beside a direction that still reads blocked is `resumable` — two existing readings conjoined, matched against the grouped question key's own slug list through `log-read.sh` — and what it licenses is that the next `/propose` turn judges again with the answer in hand.

**Degradation is stated, never derived into a verdict.** A walk that could not complete answers `readable: false` with a named reason (`corpus_unreadable`, `patterns_unreadable`, `attribution_unreadable`, `strategy_unreadable`, `waiting_unreadable:<reason>`) and **null** counts — never `no_citing_artifacts`, which means the opposite. **`readable` is absent on a completed walk** (the `merge_policy`/`status:` convention: absent means it completed), so the test is `readable == false`, never `readable // true`. Named empties stay honest: `no_feedback_refs`, `no_citing_artifacts` (*nothing has answered this direction yet* — guaranteed by `/specificate`'s carry floor), `no_activity_in_window`. Attribution is **transitive, lossy and `exhaustive: false`**: work a run never emitted, an ask naming no refs, an unresolved ref and any hand-written artifact stay uncited for ordinary reasons.

**Succession**: a *created* announcement may name a **predecessor slug**; that predecessor's own `feedback:` refs are read through `read.sh`, composed through `feedback/scripts/ask-feedback-line.sh --refs-only` and handed to `create.sh` as the argument it already takes — `create.sh` learns nothing about succession. Refusals: `strategy_not_found`, `predecessor_active`, `no_predecessor`.

**A strategy-touching publication never auto-merges** — the seam's rule, not the caller's: `publish-tree-pr.sh` derives it from the tree and reports `merge_reason: strategy_touching`, whatever `WORKAHOLIC_AUTO_MERGE` says. The operator's merge is the authorship; closing is the refusal.

The retired `strategy:` mission relation and its ownership hop stay retired; `mission/scripts/migrate-strategies.sh` and the `missions_migrate_strategies` seam are retired — **do not re-add them**. Full record: `skills/mission/SKILL.md`, *The strategy layer: retired, then redefined*. **Which direction a mission serves is a render, not a field** (2026-09-01): `mission-strategy.sh` answers it and three mission-facing surfaces state it — the bare `/mission` roadmap, the **Mission Position Report** (`/mission-close` and `/drive`), and `/standup`'s per-strategy digest — each rendering an explicit *no strategy* where nothing could be attributed and naming an unreadable walk as unreadable. Why the field is not the answer is recorded in `mission/reference/schema.md`, beside the frontmatter block where the question recurs.

#### The planning job

**Planning is a job, and it is not a command or a routine** (2026-09-01, mission
`adjust-the-plan-hourly-not-only-report-it`). The ask that produced it was accurate about the
documents: the loop had three clerks — intake adds, execution drives, bookkeeping reports — and
nothing named planning, so no reader could tell whether *nothing re-plans* was a defect or the
design. It is now five acts, each belonging to a tick that already runs; **no new command, no new
routine and no new artifact**.

| Act | Where it lives | What it does |
| --- | -------------- | ------------ |
| **Hold new divergence** | `/propose`'s `wip_limit` rung (`survey-strategies.sh`) | refuses origination while the repository already carries `WORKAHOLIC_WIP_LIMIT` active missions with queued work; **absent means no limit** |
| **Order the offer** | `plan-units.sh` (`order_reason`) | offers missions by the nearest `target_date` of the direction each serves; changes **order, never eligibility** |
| **Do the arithmetic** | `strategy/scripts/landing-arithmetic.sh` | per direction, what remains against how long is left, at the direction's own measured rate |
| **Escalate a date** | `/moderate`'s `date-will-not-hold` step | asks the assignee, **before** the date, when the board will not clear; `overdue`/`expiring` keep their own cases |
| **Say what moved** | `/moderate`'s `📋` clause (`strategy-pace`'s `plan` block) | one line on the hourly root: how many directions advance, how many are held, and whether the repository's own limit is holding new work |

**Its authority is the repository's existing rule and is cited, never restated**
(`drive/reference/claims.md`, *Proofs and judgements* and *When a bounded act may read a
judgement*): planning may **act** on a proof it re-derives at the moment of the act, idempotently,
refusing every bound by its own word; everything else it may only **report** or **ask about**. Of
the five acts, exactly one refuses work (`wip_limit`, on a declared number) and one reorders an
offer; the other three read and say.

**What planning may not do, each with the rule that forbids it**: it may not **re-date a
direction** (`amend.sh` carries only a revision the operator announced by explicit slug, and a
loop that moves its own deadlines when it misses them is a loop whose dates mean nothing); may not
**merge two missions** (no writer exists and it asserts intent); may not **retire a ticket it
judges mooted** (that is a reading about behaviour, not a file test — a shape refused here
before); and may not **close a mission that is not arithmetic** (`close.sh` is the only writer of
an end state, and `archive.sh` closes only `achieved`). A mission at full acceptance with tickets
still queued is therefore **named and asked about** (`mission-leftovers:<slug>`), never closed.

**So the honest answer to the ask is that the loop plans less than it wanted, and the gaps are
named rather than implied.** What is now the loop's: holding divergence against a number the
operator declared, ordering its own offer, doing the arithmetic, and saying what moved. What
remains the operator's: every date, every end state, and every judgement about whether queued work
still matters. **The ask's fourth item — that a commit is a change to the development target — was
already largely answered** by two changes that shipped for exactly that reason: the tick log came
off `main` (2026-09-01, and off git entirely on 2026-09-03 — the orphan branch it moved to was
itself the mess, and is retired) and every pull request the loop merges is squash-merged
(2026-09-01). What remains there is not re-proposed here.

#### Tickets, ownership, identity

- **Ticket state is a field, the archive is a place**: `tickets/` is **two-state** — `todo/` and `archive/<branch>/`. State is `status:` frontmatter: **absent means queued**, `done` (stamped by `archive.sh`), `abandoned`, `icebox` (deferred and promotable; `promote-icebox.sh` **clears** the field). A ticket never driven lands in the synthetic `archive/unbranched/`. The retired `icebox/` and `abandoned/` directories are still read by every reader while `gather/scripts/migrate-ticket-states.sh` converges them at the write seams; `layout-doctor.sh` reports a survivor as `retired-ticket-state`.
- **Ownership**: plural `assignees` on every artifact; **empty means team-owned/claimable**. One oracle — `gather/scripts/owners.sh`, with `owns.sh` returning `mine`/`unowned`/`other`/`unresolved` (compared by slug, both sides canonicalised).
- **Identity**: `.claude/git-identities` maps `<login>=<canonical>[,<alias>...]` (first field canonical, the rest the same person's other addresses) and `gather/scripts/identity.sh` is its **one reader**, resolving a login *or* an address. It **never guesses**: an absent file, entry or unparseable line answers `resolved: false` and echoes the input back (the identity function), so a caller that resolves unconditionally behaves exactly as before it existed. A line with no comma is what the format always was. The only sanctioned second parser is the web bootstrap's step 0b (`cut -d, -f1`), which runs before the plugin is installed. Already-written artifacts are recovered by `gather/scripts/migrate-assignee-aliases.sh` (a living migration at `/workaholify`'s converge seam: idempotent, **stages and never commits**, leaves canonical entries byte-identical, and touches nothing it cannot resolve, naming every such address). Claim authorship and resumption key on `git config user.email` separately; `WORKAHOLIC_CLAIM_IDENTITY` overrides the scan identity for an executor with none configured (see the claim protocol).
- **Ticket-only tolerance tier**: a queued ticket still at `tickets/todo/<user-slug>/<file>.md` with neither field resolves to `<user-slug>` — the directory that *was* the ownership record. Only that path shape, only when both field tiers are silent, only tickets; a ticket directly in `todo/` answers `unowned`, and `author:` stays out of ownership. Written to be deleted with the layout.
- **Feedback subject**: every new record names **whose opinion it is** — `subject: <kind>[:<identity>]`, kind from `person | meeting | observer_ai | customer | team | other`. Three axes: **subject** = who formed the opinion, **source** = the channel it arrived through, **author** = the git identity that ran the capture. `create.sh` takes `--subject` and **refuses** (`no_subject`) rather than default it. `/specificate` supplies the triggering issue's author; `ship`'s extractor supplies `observer_ai:<author>`; `validate-feedback.sh` floors new writes and grandfathers older ones.
- **Deferred concerns** live in the feedback stream: the story's Concerns section is the durable record (PR body drops `low` blocks at render); `ship`'s `extract-deferred-concerns.sh` persists each as a `kind: concern` record keyed on `concern_id`; the open set is computed — a concern is open until a later record names it in `supersedes`.
- **The red-alert cool-down** expires at the **earlier** of 24 hours after the first report and the start of the next working day (the first hour inside `WORKAHOLIC_WORK_DAYS` at the end of `WORKAHOLIC_QUIET_HOURS`, in `WORKAHOLIC_QUIET_TZ` — the check-in gate's own terms, composed rather than re-derived). A root re-posted at expiry names **how long** it has been failing. The `↳ still failing` reply, the first-report rule and the unreadable-history rule are unchanged (`workaholic:notify`). **A red base rides this cool-down** (2026-09-03, mission `make-a-red-base-impossible-for-the-loop-to-miss`): it was a `base-red:<commit>` question held by `quiet_hours` until morning while the loop built on the broken base all night, and a question is held for a reason that does not apply — a red base asks the operator to decide nothing, it reports that the ground everything lands on is broken. The question is **retired** rather than kept beside the report (two announcements of one fact is what this repository retires roots for), the cool-down is **composed and never re-derived**, and the signature carries **no SHA** — it is the failing check names, so the same suite still failing is one alert however many red commits carry it.

### Claim protocol

The repository is the coordination medium. The model is stated once in `skills/drive/SKILL.md` (**Claims**) with full detail in `skills/drive/reference/claims.md`.

- A runner claims a PR-unit (mission slug or `batch-<ts>`) as a `Claim <unit-id>` commit on a pushed `work-*` branch; **unmerged remote branches are the only claim oracle** (`list-claims.sh`). One unit ↔ one branch ↔ one worktree (`.worktrees/<unit-id>/`) ↔ one PR.
- A merge releases a claim by definition. `release-claim.sh` explicitly discards an unfinished unit (never a recovery path) and sets `CLAIMS_FETCH_OK` after its own fetch, as `claim.sh` does. `claim.sh resume` takes over **your own** claim whose heartbeat lapsed; a colleague's is untouchable at any age. Staleness is reported, never acted on.
- The heartbeat is the branch tip (`heartbeat.sh`, an empty commit built against a scratch index). `archive.sh` pushes the claim branch after each archive commit. **The beat is step 0 of every ticket, not a cadence** (2026-08-31, ticket `20260831150500`): `archive.sh` refreshes the tip for free but only at the **end**, so a unit that is one long ticket runs its whole implementation on the claim commit's own timestamp and loses its own claim to the 30-minute `WORKAHOLIC_CLAIM_HEARTBEAT_STALE_MINUTES` resume window by construction — not the 24-hour `WORKAHOLIC_CLAIM_STALE_HOURS`, which is the *reported* staleness and governs no takeover. Measured on `batch-20260831141002`: resumed by a second tick at 33 minutes, and a complete, validated, locally-committed implementation was discarded rather than force-pushed over a branch another run was actively driving. A **beat inside a per-ticket seam** was refused (the only one that runs early is a pure reader shared with other callers) and so was **making the loss visible instead** (a reading after the fact returns none of the work); a background timer is refused outright, because it would be a second liveness authority beside the branch tip. No store, no cursor, no field, and the suite pins both the behaviour and that the workflow still names the step.
- Worktrees are **claim-born and ship-torn** (`cleanup-mission-worktree.sh` is the sanctioned cleaner; `survey-worktrees.sh` / `reap-worktrees.sh` back the teardowns up). `.worktrees/` and `.publish/` sit inside the repo root — add them to `.dockerignore` and any archiver's ignore list.
- `branching/scripts/ensure-worktree.sh` **refuses** a branch name that already exists on origin rather than minting a local branch at `HEAD` that shadows it; attaching to a published branch is `create-mission-worktree.sh --branch`'s job.

#### Verdicts

| Verdict | Meaning | Resumable | Survey exclusion |
| ------- | ------- | --------- | ---------------- |
| `claim_active` | live claim, heartbeat fresh | no | `claimed_*` |
| `stale` | tip older than `WORKAHOLIC_CLAIM_STALE_HOURS` (default 24) — *look at this*, not *take it* | own claim only | — |
| `superseded` | the unit's tickets reached the base **and the branch is empty against it** | no | `claimed_superseded` (work **resurveyed**) |
| `stranded` | the tickets reached the base and the branch **still holds work found on no other ref** | no | `claimed_stranded` |
| `queue_drained` | drained, story at the tip, PR open — waiting on a person | no | `claimed_reported` |
| `report_incomplete` | drained, **no story** — a dead run's remains | **yes** (re-enters the Unified Run at §5) | `claimed_resumable` |
| `report_undelivered` | the run recorded the transport's refusal into its own branch story | no — the next act is a **merge retry** | `claimed_undelivered` |
| `awaiting_verification` | **every** remaining queued member declares a **prose** `verification_handoff:`, or the mission itself does (a `probe:` declaration never reaches this verdict — 2026-09-06; *every* rather than *any* since 2026-09-07) | no | `claimed_awaiting_verification` |
| `parked_with_pr` | reported with follow-up work on the branch | yes | — |
| `heartbeat_lapsed` / `foreign_identity` / `identity_unresolved` / `shallow_history` / `ambiguous_claim` | as named | no | — |

**Proofs and judgements** (`skills/drive/reference/claims.md` — the one home, keyed on the word `lib/claims.sh` emits, with no field on any artifact and no classifier function): a consumer may **act** on a proof and may only **report** or **ask about** a judgement. **`superseded` now proves the branch is empty, not merely that the tickets landed** (2026-09-01, issue #788). `retire-claim.sh` deletes a branch on that strength alone — *what makes a destructive act safe here is the proof, and nothing else* — and offers as recovery that *its content is on the base, that is what `superseded` means*. It did not mean that: the step from *the tickets are archived* to *the branch holds no work* holds only when a branch carries nothing but its own unit's tickets. **Measured**: two branches whose tickets had landed through *different* branches still held ~300 lines of code and a documentation section present on no other ref, and the tick was asking for both to be deleted; only a 403 on `push --delete` had prevented the loss, for five days, while the tick reported that refusal as the problem. `claims_branch_empty_against_base` (one `merge-base`, one `diff --quiet`, no network) now gates the verdict, an unanswerable emptiness answers **`stranded`** rather than `superseded`, and a `stranded` unit is asked about by `/moderate`'s `retire-claims` step and reaches no retirement, no `resurveyed[]` and no delete.

**`superseded` and `report_undelivered` are the only proofs** — readings the tree or a merged pull request established, which cannot become false by looking again. Everything else is a judgement, the absence-of-a-reading words (`shallow_history`, `ambiguous_claim`, `unanswerable`) most of all. Seven further vocabularies live there as keyed sub-tables, **one of them holding three proofs and the rest none**: what made a branch a retirement candidate (`candidate_reason` — `superseded_only`, `pull_request_merged`, `pull_request_closed_unmerged`, each a proof and each re-derived at the moment of the act), the base's own checks, whether an operator-facing pull request was acted on, how long a condition has been standing, a branch's mergeability, whether an act the loop took had its effect (`drive/scripts/act-effect.sh`, the one reader for both the retirement and the delivery act, owning the assembly and no act's vocabulary), and **what became of a person's own answer** (`moderate/scripts/answer-outcome.sh` → `settled:nothing_filed` / `settled:issue_closed` / `pending` / `unreadable:<reason>`, composing `question-state.sh`, `log-read.sh` and the one transport at one bounded read per **filed** candidate and none for the rest; an issue can be closed and reopened between two reads, so nothing may merge, close, gate, hold work or re-ask on it, and a question with **no recorded answer** is refused `not_answered:<state>` rather than called `unreadable`). An eighth, differently-keyed table records **which question reads which age** (nothing derives an age twice). Each names its consumers, and `scripts/test-workflow-scripts.mjs` fails when a script emits an unclassified word, a table classifies a word nothing emits, a row is called a proof, or an enumerated consumer reaches an acting call site.

**When a bounded act may read a judgement** (`claims.md`): only when it **re-derives that judgement at the moment of the act**, is **idempotent**, is **reversible**, and **refuses every bound by its own word**. Consumers are enumerated (`catch-up-claim.sh` is the only one). The exception reaches no judgement that is the absence of a reading and none whose next step is a person's judgement. Two gating shapes, one rule: a **licensing** act refuses on an absence, a **gating** act proceeds on one.

**Resolution**: a unit held by two branches resolves to the **live** row, derived once in `lib/claims.sh` (`claims_unit_resolution` / `claims_unit_row` / `claims_unit_live_branches`) and read by every writer; `superseded_only` returns the superseded row for callers that must keep refusing under it. **Two live claims are reported, never picked between** (`ambiguous_claim`, naming both). A `superseded` row beside a live one governs nothing while staying reported; `claim.sh` skips it so a fresh claim over proved-empty work goes through, and `plan-units.sh` names the freed work in `resurveyed: [{kind, id, claim}]`, never in `excluded[]`.

**`superseded` at both grains**: a **batch** claim is answered from the tree, network-free (every one of the unit's tickets archived on the base, matched by filename under any branch directory); a **mission** claim from the claim's own tip (`claims_mission_landed` over `claims_tickets_for_mission`, `every` and never `any`), with `drive/scripts/claim-merged.sh` — the protocol's **one network read** — as the fallback. That lookup is **three-valued**: `unanswerable` leaves the row the verdict it would have had without it and is named in `merged_lookup_unanswered[]`; it is skipped by name when it cannot succeed (`offline`, `disabled` under `WORKAHOLIC_CLAIM_MERGED_LOOKUP=0`).

**A claim race is settled at the remote, and where it cannot be, the damage is bounded later.** `claim.sh resume` always contended on one ref (the loser `resume_race_lost`); a **fresh** claim minted its own `work-*` name, so two runners that surveyed before either pushed both succeeded — measured 2026-08-30, two branches drove the same four tickets for over an hour. **Since 2026-09-02** `claim.sh` **§3b** wins one ref per **claimed artifact** (`drive/scripts/claim-arbitrate.sh`, `refs/claims/artifact/<path>`, create-only lease, all-or-nothing) **before §4 creates anything**, so the loser refuses **`claim_race_lost`** holding no branch, worktree or commit. The ref is keyed on the **artifacts, not the unit id** — `batch-<timestamp>` is minted inside the claim act, so a unit-keyed ref would reach one grain only — and its value is **unique per claimant**, because git answers `Everything up-to-date` to a push of the value a ref already holds. **The lock's lifetime is the claim act, not the claim**: `claim.sh` releases it the moment the push lands (the oracle sees the claim from then on) and `abort_claim` releases it on every earlier failure, so a merged, released, retired or `superseded` claim needs no lock handling at all — measured, holding it for the life of the claim broke *a merged stamp is history, not a claim*, because a merge runs nothing in the container. The only other release is the arbiter's **reap**, for an act killed inside its own window — a lock **no live claim stands behind** *and* older than `WORKAHOLIC_CLAIM_ARBITER_STALE_MINUTES` (default 10), run lazily by `claim.sh` only when a take is lost, then the take retried once. `claims_scan` still reads `work-*` refs alone: the contended ref is the **arbiter, not a second oracle**, no verdict word was added and the proofs-and-judgements tables did not move. **Where the transport refuses the ref write it answers `unavailable` and the claim proceeds exactly as before** — the earlier 403 measurements were the **cloud routine's proxy**, re-measured 2026-09-02 over SSH where create, create-only lease, compare-and-swap and delete all succeed — so the bounded-later repair still carries every routine-fired container: `archive.sh` **re-derives the claim immediately before the ticket moves** through `drive/scripts/claim-holder.sh`, refusing `claim_taken_over` and `ambiguous_claim` with the tree byte-identical and **proceeding** on any absence. A live race reaches a person through `drive/scripts/list-raced-units.sh` and `/moderate`'s `raced-units` step (`raced-unit:<unit>`); three sibling steps filter and count it through `moderate/scripts/lib/raced-units.sh`. No consumer releases a claim, picks between branches, deletes a branch, closes a PR, reverts, merges, gates or holds work on it.

#### The three acts on a claim

Each acts on a proof, re-derives it at the moment of the act, is idempotent, and refuses every bound by its own word with nothing written and exit 0. Full contracts: `skills/drive/reference/claims.md`.

- **Retirement** — `drive/scripts/retire-claim.sh <unit>` acts on `superseded`: close the pull request, delete the remote branch, reap the worktree, in that order (the local reap last, so a refusal there leaves both remote facts correct). Success words (`already_closed` / `already_gone` / `absent`) and blocked words (`gh_unavailable`, `slug_unresolved`, `pull_request_close_failed`, **`branch_delete_failed`**, `worktree_reap_refused`) are each their own; a refusal reports `not_attempted` for all three; judgements are refused by their own verdict word. It merges nothing, pushes into no branch and touches no `.workaholic/` artifact. **Act 2 is refused in this container** (a session-type refusal both transports agree on), so it runs in **`.github/workflows/claim-retirement.yml`** — `permissions: contents: write` and nothing wider, `push: [main]` + `workflow_dispatch`, a full-history checkout with every remote head — which owns no proof logic: `list-retirable-claims.sh` supplies candidates and `delete-retired-claim-branch.sh` acts. **Four candidate classes, each carrying its own `candidate_reason` and each a proof** (2026-09-01; the fourth 2026-09-02): `superseded_only` (the oracle's own emptiness), `pull_request_merged` (the tree established it — a squash merge leaves no ancestry, so `--no-merged` lists the branch forever), `pull_request_closed_unmerged` (**a person's recorded decision**, never folded into the second: *the loop delivered this* and *a person discarded this* are different questions), and **`mission_not_active`** (the unit's mission has ended — `close.sh` moved it into `missions/archive/` — read through `drive/scripts/claim-mission-state.sh`, with `mission_status` on the row). The fourth is enumerated from the **oracle's rows** rather than the refs, because the per-ref arm skips every unit the oracle has a row for and a claim branch always has one; it is bounded by resolution `single`, never `claim_active`, and **a pull request that is still open is not offered at all** — the act's `pull_request_open` bound is not widened, because deleting an open pull request's head branch leaves it unmergeable forever (the headless shape measured on #813, #799, #688, #635, #625). A degraded scan yields no candidates **and its reason**, and an unreadable pull request yields no candidate and lands in `pull_request_unreadable[]` — never a bare omission, which reads like an open one. The act re-derives its class at the moment of the act and refuses by its own word: the shape and transport bounds (`not_a_work_branch` / `release_branch` / `not_on_base` / `pull_request_open` / `gh_unavailable` / `slug_unresolved` / `branch_delete_failed`) on all three, plus `not_superseded:<verdict>` (a live row always beats a merged pull request), `pull_request_unreadable:<reason>`, `not_merged:<state>`, `not_closed_unmerged:<state>`, `no_unit_for_mission_class`, `mission_unreadable:<reason>`, `mission_still_active:<state>`, and — on the third and fourth classes, where the emptiness is a **gate** rather than the evidence it is on the row — `branch_holds_work` and `emptiness_unanswerable`. `record-ci-retirement-turn.sh` records the candidate reading and each act's `state`/`reason` as `::notice::` check-run annotations (no permission needed; bounded by `WORKAHOLIC_CI_RECORD_MAX`, default 20, a truncated record saying so), and `read-ci-retirement-record.sh` answers per unit `taken` / `refused:<word>` / `pending` / `unavailable` / `unreadable`, matched on `head_sha`. CI-side scripts run under `lib/runner-identity.sh`, which may set `WORKAHOLIC_CLAIM_IDENTITY` — an **override, not a default** — only with no identity configured, only as an author the committed mapping names, taking that author's own row; the identity-first precedence in `lib/claims.sh` does not move.
- **Delivery retry** — `plan-units.sh` emits `undelivered: [{unit, branch, merge_outcome}]` (a **field**, not a loosened exclusion). `drive/scripts/retry-undelivered.sh <unit>` acts on `report_undelivered`: **one** `PUT .../merge` through the same REST seam that refused it, creating no branch, worktree or claim. Every other verdict is `not_undelivered:<verdict>`; a scan-held PR is refused `scan_held:<tier>` regardless. A still-refused unit has the **new** word recorded back onto its branch with no worktree, through `record-merge-outcome.sh` (still the one writer of that section). `--own-tip` relaxes exactly one term (`WORKAHOLIC_CLAIM_HEARTBEAT_STALE_MINUTES=0`) so a just-caught-up branch is not refused `claim_active`.
- **Catch-up** — `drive/scripts/claim-mergeability.sh` answers `clean | mechanical | content | unanswerable` per branch from `git merge-tree --write-tree` (no worktree, index, ref or extra network call), rendered on every claim row as `mergeability` / `mergeability_reason` / `mergeability_content_files`. **The merge is computed with the repository's own `.gitattributes` out of reach** (2026-09-01, ticket `20260901041500`) — run from an empty directory with `GIT_DIR` set, because git reads merge attributes from the **working tree** and **GitHub applies none of them when it computes `mergeable`**. Measured, same git and the same two commits: from the checkout `merge-tree` exits 0 while a clone with no `.gitattributes` exits 1 on `.workaholic/feedbacks/index.md` and the API answers `mergeable_state: "dirty"`; five open publications read `clean` here and `dirty` there, and the loop attempted the merge and was refused `merge_not_allowed` every hour. The union driver is **not** the defect and is not removed — the **writer** (`catchup-main.sh`, in a real checkout) still resolves such a path with no judgement, which is why `mechanical` is the honest class and why the existing catch-up settles these branches. `drive/scripts/catch-up-claim.sh <unit>` composes `ship/scripts/catchup-main.sh` (never a second merge engine), attaches the worktree through `create-mission-worktree.sh --branch`, regenerates with the repository's own tooling and runs its fast checks before pushing; `already_current` touches no ref. **And since 2026-09-02 it delivers what it made mergeable** (mission `resolve-a-conflicted-pull-request-in-the-tick-not-report-it`): resolving and stopping leaves the pull request open for a claim holder who never comes, so a **`queue_drained`** claim's pull request is merged after the push, through the same REST seam and the same `merge-method.sh` derivation every other caller reads. The delivery rides its own field, **`delivery`** (`merged` / `merge_refused: <word>` / `not_attempted[: <reason>]`), never collapsed into `outcome`: a branch can be genuinely caught up while the merge is held or refused. **The scan runs before the merge** and is read through `gate-decision.sh`'s severity tier — `secret` stops it, `leak` holds the pull request open, only `override_only` proceeds — so no gate is overridden. It delivers **only** `queue_drained`, and the two exclusions have **different** reasons: a `report_undelivered` unit's delivery already belongs to `retry-undelivered.sh`, which `/implement` runs straight after a `caught_up` (two attempts at one pull request in one turn would report the second as a refusal over a merge that had already landed), while an `awaiting_verification` unit's pull request is open precisely so a **person** can satisfy the declared verification — merging it would discharge a handoff nobody discharged — and it is reported `delivery: not_attempted: awaiting_verification`. Refusals: `content_conflict`, `not_my_claim`, `foreign_identity`, `identity_unresolved`, `claim_active`, `dirty_worktree`, `scan_held:<tier>`, `not_a_work_branch`, `ambiguous_claim`, `mergeability_unanswerable:<reason>`, `catchup_<class>`, `validation_failed:<check>`, `push_failed`, `pull_request_reviewed` (three-valued — `reviews_unreadable:<reason>` never falls through as *nobody has reviewed*; a bot's review is not a person's). The classification rule lives in **one** place, `ship/scripts/lib/conflict-class.sh`, read by the reader and by `catchup-main.sh`; it covers the generated OKF indexes by path and a flat area's marked region by proof (mechanical only when neither side changed anything outside the `okf:generated` markers). `catchup-main.sh --resolve-mechanical` binds the caller to regenerate (a version manifest is raised to the higher semver and merged, never taken wholesale); without the flag it is byte-for-byte what `land-unit.sh` gets. `list-catchable-claims.sh` answers this identity's **reported** claims — `report_undelivered`, `queue_drained` and, since 2026-09-07 (ticket `20260907070931`), **`awaiting_verification`** — whose `mergeability` is `mechanical` **or `content`** (2026-09-02, mission `resolve-a-conflicted-pull-request-in-the-tick-not-report-it`). **The third verdict joined because it is the one class guaranteed by design to sit open for a long time**: the handoff route opens the pull request and leaves it open waiting on a person, and it was the one class the catch-up never touched, so its work decayed for exactly as long as the person took (measured 2026-09-07: PR #993, open ~25 hours, six of seven tickets driven and archived on the branch, `mergeability: content`, and the reader offering nothing). It is the **candidate set** that widened and nothing else — `catch-up-claim.sh` gains no verdict, keeps every refusal, reads no declaration and merges no handoff pull request, and the open-pull-request term still costs no lookup because `awaiting_verification` is reachable only under the oracle's own `reported` term. **A `content` reading is a prediction, and the tick now tests it instead of trusting it**: the reader computes with the repository's `.gitattributes` deliberately out of reach — its job is to predict GitHub, which applies no merge driver — while the writer merges in a real checkout where those drivers are in force, so the reader is pessimistic by construction and every branch in that gap was refused without anybody attempting it. The refusal **moved rather than went**: a hunk the merge itself cannot settle still refuses `content_conflict` with the branch byte-identical and nothing pushed, and still reaches its holder through `/moderate`. `unanswerable` keeps its refusal on both paths — it is the absence of a reading. `conflict-class.sh` is untouched, no path was reclassified, no second merge engine exists, and the fast checks still gate every push. The strategy per class — which side wins for a generated file, what a regenerable one does, and what happens to a divergent hand-written hunk — is stated once in `drive/reference/claims.md`, *The resolution strategy, per class*.
- **A publication is not a claim, and has its own reader and act** (2026-08-31): a publish-tree publication carries no `Claim …` commit, so the oracle gives it no row and no catch-up path ever saw one. `branching/scripts/list-stranded-publications.sh` names each open pull request on a `work-*` branch the claim oracle does **not** own and whose publication-refusal word is empty (an operator-facing one is `list-operator-facing-pulls.sh`'s), carrying `claim-mergeability.sh`'s class verbatim; `branching/scripts/settle-stranded-publication.sh <number>` acts on **`mechanical`, `clean` and — since 2026-09-02 — `content`** — a `mechanical` or `content` one catches up through `catchup-main.sh --resolve-mechanical`, regenerates, runs the fast checks and pushes before its one REST merge; a **`clean`** one takes none of that (2026-09-01, mission `deliver-a-stranded-publication-that-needs-nothing-but-a-merge`: nothing collides, so `merged`/`regenerated`/`validated`/`pushed` all report `false` and no ref is written before the merge) — re-deriving its verdict at the moment of the act and refusing `not_mechanical:<class>` (`unanswerable` is the absence of a reading and is never actable) / `content_conflict` (**the writer's residue**, the one place a content collision refuses now: the reader's prediction is attempted, and a hunk the merge cannot settle waits on a person) / `has_claim_commit` / `not_a_work_branch` / `scan_held:<tier>` / `validation_failed:<check>` / `push_failed` by name, with nothing pushed and no worktree left behind. The gate runs before the merge on **both** paths, and the worktree is attached on both because the scan needs a checkout. Measured before the widening: five of six open publications read `clean`, the oldest six days old, every one green and delivered by nothing. It emits **no claim verdict word** and `reference/claims.md` gains no row. **A pull request whose head branch is gone is not a publication either** (2026-09-01, ticket `20260901112558`): GitHub leaves it open and nobody can ever merge it, so `list-stranded-publications.sh` drops it by its own term and counts it (`headless`), and `branching/scripts/list-headless-pulls.sh` — one repository-scoped REST listing of the branches, never the local remote-tracking refs, a fork's head **counted** rather than called gone — is its one reader, asking the operator to close it under `/moderate`'s `headless-pull:<number>`. The loop closes nothing itself. **A publication carries its own age** (2026-09-01, ticket `20260901062000`): `lib/publication-age.sh` is the one derivation — read by the reader, by the act, and by `publication-effect.sh` — rendering `age_hours`, and **null rather than 0** when the timestamp cannot be read, because zero reads as *opened this second*. It is **evidence and never a gate**: the act settles a stale publication exactly as it settles a fresh one, and what the age earns is that a person is told. Measured 2026-09-01: five of six open publications were `clean`, the oldest six days old, and landing them queued ~15 tickets for work the loop had already finished. An age threshold on the **act** was refused by name — it would strand precisely the publications the `clean` widening exists to deliver — and so was a survey-side *already implemented* test, which is a judgement about behaviour rather than a file test.

#### The publish tree

The claim is the only creator of a branch a runner may drive. Artifact writers use the **publish tree**: a checkout of `origin/main` at git-ignored `.publish/` on local branch `publish-main` (`open-publish-tree.sh` → write → `publish-tree-pr.sh` (default, PR path) or `publish-tree-commit.sh` (direct, post-merge seams only) → `close-publish-tree.sh`). The caller's checkout is left byte-identical.

**Two publications never auto-merge, and both refusals are the seam's**: a tree touching `.workaholic/strategies/` reports `merge_reason: strategy_touching`; a tree carrying a **ruling** — a mission that already existed on the base whose `feedback:` line the diff moves, or any touch of `.claude/git-identities` — reports `merge_reason: ruling_touching`. The test is on the **shape of the change**, never a title or label, so a brand-new mission (what every `/specificate` proposal writes) is not caught. `branching/scripts/lib/publication-refusal.sh` holds that test as **one rule**; the seam holds the adapter and the act, and `branching/scripts/publication-effect.sh` reads such publications back for `/moderate`'s `operator-pull:<number>` question.

The claim oracle degrades offline; the writer fails loudly. Under `/implement`, each unit posts **one finish line per unit** into the thread the stateless lookup found (`unit-feedback-stems.sh` + `workaholic:notify`); when several stems match, the first-sorting stem's thread wins; when none does, the run posts the **description root** and replies the finish line into it. Transport: **connector primary** — it is the only transport that can **search**, so it resolves every thread — with the tokened `notify-slack.sh` as the machine fallback. A **directed** post (`/moderate`'s `🙋` question, the `🟡 Handoff` ask) takes the **bot identity** when its mention target resolves to the posting identity, because Slack notifies nobody of their own message; the change is *which account speaks*, never *which transport finds the thread*. The directed set is **enumerated in one place** (`workaholic:notify`, *Which transport carries which shape, and why*) and extending it is a deliberate edit there, never a judgement made at post time. `notify-slack.sh --thread-ts` posts into a resolved thread under the same `chat:write` (refusing `bad_thread_ts` rather than dropping it, byte-identical payload without the flag) and still **cannot search**. `notify-slack.sh` resolves its channel through `workaholic:notify`'s own stated order — an explicit `WORKAHOLIC_SLACK_CHANNEL`, then `WORKAHOLIC_INBOUND_SLACK_CHANNEL`, then the repository's own name (2026-09-01, issue #806: it used to require a second variable for one channel, so the transport designated to survive a connector outage answered `no_channel` during one). With **no bot token** a directed post falls back to the connector and the run **reports the surface that carried it** — never dropped, never silently downgraded. An attended `/drive` run posts nothing to Slack. **A refused call and an absent surface are different outcomes** (2026-09-03, mission `deliver-a-post-the-transport-refused-or-say-it-reached-nobody`): `post_refused` is one call a transport that exists declined — the line is still sendable, so the run **carries it** on the unit's own story (`story/scripts/record-unposted-line.sh`, idempotent, one `## Unposted Line` section replaced rather than stacked; `read-unposted-line.sh` its one reader) and a later tick sends it **once** off `drive/scripts/list-unposted-lines.sh`, clearing the record on a landed send (`clear-unposted-line.sh`) and leaving it standing on a refused one. `no_slack_transport` is this session holding no surface at all, which nothing inside the run can change; a refusal is per call, an absence is per session, and reporting the first as the second is what made a run whose every call was denied say the post did not exist. The retry rides a tick that already runs — no timer, no queue, no cursor, no second liveness authority — and **a unit that merged has no branch left to carry the record**, so its refused line is reported by the run that lost it and carried by nobody. **A directed post carrying no mention token says so in its own line** (`(メンション先未解決: 誰にも通知していません)`): with no `SLACK_BOT_TOKEN` the two-transport model is one transport, so a directed shape whose addressee is the posting identity provably reaches nobody, and an unanswered thread must never be read as silence from the person. One wording across `notify/SKILL.md`, the catalog and the `/implement` and `/moderate` ceilings, pinned by `test-workflow-scripts.mjs`; changing a question's body **never re-asks**, because `already_asked` keys on the step id.

### The release tier (`release/*`)

`main` is the continuously auto-merged development branch; **quality is gated at the `release/*` QA window**, not at merge time. A release branch is cut from `main` by `branching/scripts/cut-release-branch.sh` (`release/YYYYMMDD-HHMMSS`, batch-level, explicitly invoked — never a step of the per-unit ship), carries no commits of its own, and is invisible to the claim protocol. `/ship` §5 does not deploy or confirm pre-merge: what a unit branch used to prove before landing is proved here, over the batch, or not at all. The durable ship record is `.workaholic/releases/<release-branch>.md`, written by `ship/scripts/record-release-cut.sh` and `confirm-release.sh`, both derived from git. A promotion's confirmation is never skipped; a failed confirmation deletes nothing — the next attempt cuts a fresh release branch. No `develop`, no `hotfix/*`.

### Design principles

- **Thin commands, comprehensive skills.** Commands are a few lines naming the skill, section, and entry-point contract; knowledge (templates, rules, scripts) lives in skills (~50-150 lines; overflow goes to `reference/`).
- **Common operations go through skills**: git context via `gather/scripts/git-context.sh`, ticket metadata via `gather/scripts/ticket-metadata.sh` — never inline `git branch --show-current` etc. in command/agent markdown.
- **No complex inline shell** in command/subagent markdown (no conditionals, pipes, loops, text processing, defaulting expansions) — extract to a skill script.

If a skill is missing from context in an *attended* session, ask which plugins are loaded.

## Enforcement gates

- **Commit trailers** (`skills/commit/SKILL.md`, *The trailer block*): `commit.sh` is the one writer and callers stay trailer-agnostic — `Category:` when `--category` was passed, **`Workaholic-Housekeeping: <heartbeat|claim|index|hours>`** when `--housekeeping` was (a closed set; an unlisted kind is refused `bad_housekeeping_kind` with nothing committed), `Claude-Session: https://claude.ai/code/<id>` whenever the environment carries `CLAUDE_CODE_REMOTE_SESSION_ID`, and `Co-Authored-By:` always. The housekeeping marker names the loop's **own memory** — the heartbeat and the claim stamp — so `merge-commit-body.sh` can drop it from a squash body **by marker rather than by title**; a commit carrying a unit's actual work never takes it, and commits already on the trunk carry none and are not rewritten. The trailer says which **run**, never which routine — nothing in the container names the standing routine record. Outside a cloud session the session id is omitted, never faked. The **author email is deliberately untouched** (`lib/claims.sh` resolves claim ownership and resumption from it); the web bootstrap sets a repo-**local** `user.name` (guarded on `git config --local user.name`, preferring `gh api user --jq .name`) since GitHub renders the name. A developer's own repo-local name is never overwritten; the repair is forward-only, and the name stays cosmetic to every mechanism.
- **A commit that would be half a rename is refused**: with default staging, a **staged deletion co-existing with an untracked file** is what half a convergent migration looks like. `commit.sh` refuses, names both halves and the concrete repair, commits nothing, and leaves the working tree untouched (no `git reset`). Untracked files alone never trigger it, and it never fires when the caller already named `files...`. **A caller that has just written a NEW file passes it in `files...`** — stated in `workaholic:commit`, referenced by `/story` Phase 4 and `/drive` §5.
- **Commit subject** (present-tense, ≤50 chars, no `feat:`/`[bracket]` prefix — `skills/commit/SKILL.md`): canonical validator `skills/commit/scripts/check-subject.sh`, run by `commit.sh` itself, by `archive.sh` **before it moves the ticket**, by the `PreToolUse` hook `guard-git-commit.sh`, and by the opt-in git-native `hooks/git/commit-msg` (install with `sh ${CLAUDE_PLUGIN_ROOT}/hooks/install-git-hooks.sh`; bypass one commit with `--no-verify`). One rule source; the layers cannot drift.
- **An embedded jq program that does not compile is our defect, never an empty answer** (`rules/shell.md`). These scripts carry readings as jq programs inside single-quoted shell strings under `… | jq -c '…' 2>/dev/null || echo '[]'`, which is right for a data problem and catastrophic for our own; the two are told apart by **jq's own exit status** (3 = compile error, 5 = runtime/input), so every existing fallback keeps its data behaviour. Two halves: at **run** time `skills/moderate/scripts/lib/jq-guard.sh` — a shadowing `jq` function sourced by every script in that skill that embeds a program, calling `command jq`, capturing nothing, redirecting nothing, inert when nothing is listening — *records* the fact, and `run.sh` is the **one** place that reads the record and reclassifies the step `degraded` with reason `jq_compile_error` (`needs_agent` is deliberately not zeroed). At **build** time `test-workflow-scripts.mjs`'s `every embedded jq program compiles` row extracts every `jq` in command position across `plugins/workaholic/`, `scripts/` and `hooks/`, redeclares each `--arg`/`--argjson` name, and compiles with `jq -n` against closed stdin, failing on exit 3 alone; programs built by string interpolation cannot be extracted and are **counted in the assertion's own name**. The `2>/dev/null` is not removed — the fix is to classify, not to shout.
- **Branch names**: exactly two literal patterns — `work-YYYYMMDD-HHMMSS` (named only by `branching/scripts/create.sh`) and `release/YYYYMMDD-HHMMSS` (named only by `cut-release-branch.sh`); `guard-git-branch.sh` blocks everything else.
- **One behaviour per command**: no command's behaviour depends on the first word of its argument (bare-versus-argument is a scope and is kept; `/fb`'s cross-repository mode routes on destination, not a first word). Retired forks: `/mission close` → `/mission-close`; `/mission summary|approve`, `/ticket summary` dropped; `/drive auto|night` → `/implement`.

## Release-safety scan

`skills/release-scan/scan-branch-safety.sh` is a deterministic, script-only gate over `git diff <base>..HEAD`, run by `/story` (warn) and `/ship` (block). Three rule families, each finding citing `file:line` + rule:

- **`secret`** (hard, never overridable) — `lib/secret-patterns.sh`: pass 1 unmistakable key shapes; pass 2 matches on the **value** (quoted-alphanumeric or line-ending bare run = literal; identifiers, calls, env reads, HCL `var.`/`local.`/`data.`/`module.` references, templates, annotations are subtracted). Generated paths are exempt from pass 2 (the `Outputs Freshness` CI carries the residual risk).
- **`size`** (overridable) — per-file/branch ceilings plus a per-commit changed-lines rule (`lib/commit-size.sh` — read its header before changing it; it exempts binary rows, lockfiles, generated paths, `.workaholic/` prose, files already over the per-file ceiling, and merge commits, and counts additions only).
- **`leak`** (confirm) — re-introduction of terms from the git-ignored, developer-maintained `.workaholic/leak-denylist`. Read its scope literally: it matches listed terms in the branch diff, nothing more; a `pass` never means "no client context here". The "never name other repos/clients" convention is enforced by confinement + the crossing flow's human confirmation, not by this scan.

The **severity tier** tells the consumer how hard to block; both consumers key on it, never on the binary verdict alone. A branch whose only findings are `override`-tier stays releasable (`gate-decision.sh`'s `override_only`).

## Version Management

Version bumps are manual (no `/release` command). After bumping and pushing to `main`, CI (`.github/workflows/release.yml`) publishes the GitHub Release.

Version files (all at the same semver; `.claude-plugin/marketplace.json` is the source of truth):

1. `.claude-plugin/marketplace.json` — root `version` AND every `plugins[].version` (workaholic, workflows)
2. `plugins/workaholic/.claude-plugin/plugin.json`
3. `plugins/workaholic/.codex-plugin/plugin.json`
4. `outputs/workflows/.codex-plugin/plugin.json` — generated; rebuild with `build.mjs`, never hand-edit

Bump PATCH by default, update 1-3, regenerate 4, commit as `Bump version to v{new_version}`.

**A bump is checked against the base twice, because the base moves** (2026-09-02, ticket `20260902135525-bump-the-version-against-the-base-not-the-branch`). `check-version-bump.sh` answers **two** questions — `already_bumped` (did this branch make a bump commit) and **`version_ahead`** (is the number it landed on still greater than the base's, compared field-wise so `1.0.9 < 1.0.10`, three-valued with `null` for an unreadable manifest). `/story` Phase 0 bumps unless **both** hold, and `/drive` §6 re-reads immediately before the merge and **re-bumps** when the base has overtaken the branch. **Measured**: five consecutive merges carried two versions between them (`1.0.285` three times, `1.0.284` twice) — every branch had bumped correctly against *its own* base, and each later squash then carried a bump commit whose content the base already held, so it produced no version diff and nothing reported it. Since the loop's subagents run beside the developer's own sessions, concurrent branches are the normal state. **It is a repair, never a gate**: the merge happens either way and a failed re-bump is reported by name, because a version collision is a bookkeeping fact rather than a defect in the work. **The already-collided numbers are recorded and left**: `1.0.284` and `1.0.285` each name more than one tree, and re-cutting published releases to tidy that is a worse act than the one it would cure — the next bump names the current `main`.
